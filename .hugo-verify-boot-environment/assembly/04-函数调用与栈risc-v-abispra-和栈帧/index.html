函数调用与栈：RISC-V ABI、sp、ra 和栈帧

September 8, 2026

call start 不是一句普通跳转，而是一份调用双方必须遵守的合同：参数放在哪里？结果从哪里取？哪些寄存器可被覆盖？局部变量放哪儿？函数再调用函数时，原先的返回地址怎样保存？这些规则属于 ABI 的调用约定。

理解调用约定与栈，才能理解 xv6 为什么必须先设置 sp 再调用第一个 C 函数。没有栈，跳转本身或许还能发生；但 C 函数的第一段编译结果就可能需要保存寄存器和创建局部变量，于是会立即写向一个未定义地址。

一、ABI：二进制模块间的共同语言

ABI（Application Binary Interface，应用二进制接口）约定独立编译的代码怎样协作，包括：

  • 参数与返回值所在的寄存器或栈位置；
  • 调用者和被调用者各自负责保存哪些寄存器；
  • 栈的增长方向与对齐；
  • 数据类型、结构体和 ELF 的二进制布局。

没有 ABI，C 编译器生成的代码无法可靠调用手写汇编；函数名相同远远不够，双方还必须对调用瞬间的寄存器与栈状态拥有同一理解。

二、call、ra 与 ret

概念上，函数调用做两件事：

ra = 调用点后下一条指令的地址
PC = 被调用函数入口地址

汇编常写：

call    start

返回地址保存于 ra（x1）。函数完成后：

ret

会跳回 ra 指向的位置。

为什么需要保存 ra

若 f 被调用后又调用 g，第二次 call 会改写 ra。所以 f 若还要返回给最初调用者，必须在调用 g 前保存旧 ra：

f:
        addi    sp, sp, -16
        sd      ra, 8(sp)
        call    g
        ld      ra, 8(sp)
        addi    sp, sp, 16
        ret

这就是嵌套调用必须使用栈的最直接理由。

三、栈与 sp：函数的临时工作区

栈通常保存返回地址、局部变量、被调用者保存寄存器、额外参数和临时空间。RISC-V 使用 sp（x2）保存栈顶，并且栈向低地址增长：

高地址：调用前的 sp
  │
  │ addi sp, sp, -32   分配 32 字节栈帧
  ▼
低地址：当前的 sp

若一份可用栈范围为 [low, high)，开始时应令 sp = high。第一次建立栈帧会先减少 sp，随后写入 [sp, old_sp)。把初始 sp 放在 low 会让第一次减法立刻越界。

四、函数序言与尾声

work:
        addi    sp, sp, -32
        sd      ra, 24(sp)
        sd      s0, 16(sp)
        addi    s0, sp, 32

        # 函数主体

        ld      ra, 24(sp)
        ld      s0, 16(sp)
        addi    sp, sp, 32
        ret

前半段是函数序言（prologue），后半段是函数尾声（epilogue）。

指令 作用
addi sp, sp, -32 分配 32 字节栈帧
sd ra, 24(sp) 保存返回地址，允许本函数继续调用其他函数
sd s0, 16(sp) 保存旧 s0，因为 s 寄存器由被调用者恢复
addi s0, sp, 32 可将 s0 作为帧指针
ld、addi sp, sp, 32 恢复寄存器并释放栈帧
ret 使用 ra 返回

优化后的函数不一定有完全相同的形状。叶子函数可能不保存 ra，编译器也可能省略帧指针；ABI 约束的是调用边界的效果，不是要求每个函数机械复制模板。

五、参数、返回值与保存责任

RISC-V 整数调用约定中：

a0–a7：前八个整数或指针参数
a0、a1：返回值

例如 long sum(long left, long right) 调用前通常让 a0=left、a1=right，返回后结果在 a0。

寄存器类别 例子 调用后是否保证原值 谁保存
调用者保存 a0–a7、t0–t6、ra 不保证 调用者若需要则先保存
被调用者保存 s0–s11 保证 被调函数使用时恢复
特殊 sp 返回时必须恢复 函数维护自己的栈帧

这解释了 xv6 为什么能用 a0、a1 做栈地址计算：进入 start() 前并没有需要保留的参数值，且 start() 本来就可覆盖它们。

六、16 字节对齐

RISC-V psABI 要求过程调用边界的栈指针满足：

sp mod 16 = 0

因此栈起始地址和栈帧大小都应保持 16 的倍数。xv6 中 stack0 按 16 字节对齐，每份早期栈大小为 4096（也是 16 的倍数），故每个 hart 得到的栈顶都符合 ABI。

对齐不是视觉整齐。它影响编译器生成的访问、某些数据类型的要求，以及不同模块间的二进制协作。底层代码不应依赖“某次未对齐访问似乎没出错”的偶然现象。

七、回到 xv6：为何顺序不能颠倒

add     sp, sp, a0
call    start

前一句使：

sp = stack0 + 4096 * (mhartid + 1)

即当前 hart 私有栈的高端。此后 start() 的函数序言才可安全减少 sp、保存 ra 和局部变量。若先调用再设置 sp，C 函数最初的栈访问就可能破坏任意内存；它未必立刻崩溃，却更可能将错误延迟到难以关联的位置。

小结

  • call 保存返回地址到 ra 并跳转，ret 使用 ra 返回。
  • 嵌套调用会覆盖 ra，非叶子函数通常先将它保存到栈。
  • 栈向低地址增长，sp 初始化在每份栈的高端。
  • a/t 寄存器通常由调用者保存，s 寄存器由被调用者保存。
  • 调用边界的 sp 必须 16 字节对齐。
  • entry.S 在第一次 C 调用前建立 sp，正是在满足这份 ABI 合同。
