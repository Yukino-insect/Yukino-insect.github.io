操作系统对内存和磁盘的抽象

March 11, 2026

操作系统不会直接把“真实的内存”和“真实的磁盘”暴露给普通程序。它会先做一层抽象：内存被抽象成虚拟地址空间和页，磁盘被抽象成块、文件和目录。

这两个抽象表面上不一样，但它们可以在 虚拟内存 这里汇合。原因很简单：虚拟内存的管理单位也是 页（Page），而操作系统可以把磁盘上的一块交换区域也按页来管理。

内存的抽象：页和虚拟地址空间

操作系统会把内存管理拆成两层：

  • 物理内存：真实的 RAM，会被划分成固定大小的页框（Page Frame）。
  • 虚拟内存：进程看到的地址空间，会被划分成固定大小的页（Page）。

普通程序访问的是虚拟地址，而不是物理地址。每个进程都会以为自己拥有一段连续、独立的地址空间，例如从 0x00000000 到某个很大的地址范围。

这种抽象带来几个重要能力：

  • 地址空间隔离：一个进程不能随便访问另一个进程的内存。
  • 连续地址假象：程序看到的地址可以是连续的，底层物理内存却可以是分散的。
  • 按需加载：程序用到哪一页，操作系统再把哪一页真正放进内存。
  • 换入换出：内存紧张时，暂时不用的页可以先放到磁盘。

也就是说，虚拟内存并不等于物理内存。它是操作系统给进程提供的一套地址空间视图。

磁盘的抽象：块、文件和目录

磁盘硬件最终读写的是扇区或块设备上的固定大小区域。操作系统通常会把磁盘抽象成几层：

  • 逻辑块（Block）：操作系统和文件系统读写磁盘时常用的固定大小单位。
  • 文件（File）：对用户和程序暴露的数据对象。
  • 目录（Directory）：用来组织文件的层级结构。

用户平时看到的是文件和目录，例如 a.txt、/home/user、D:\Project。但在更底层，文件系统会把文件内容映射到磁盘上的一组逻辑块。

所以，内存和磁盘的常见抽象确实不同：

对象 底层管理单位 上层看到的样子
内存 页、页框 虚拟地址空间
磁盘 块 文件、目录

问题就在这里：既然内存按页管理，磁盘按块和文件管理，为什么虚拟内存还能使用磁盘空间？

虚拟内存为什么能使用磁盘

关键在于：操作系统可以在磁盘上准备一块专门区域，并把这块区域也按页来管理。

这块区域通常叫：

  • 交换区（Swap Area）：Linux 等系统常见。
  • 分页文件（Page File）：Windows 等系统常见。

当物理内存不够用时，操作系统可以把暂时不用的内存页写到交换区或分页文件中。这个过程叫 换出（Page Out）。

等程序再次访问那一页时，操作系统再把它从磁盘读回物理内存。这个过程叫 换入（Page In）。

可以把过程理解成这样：

虚拟页
  -> 在物理内存中：直接访问
  -> 不在物理内存中：触发缺页异常，再从磁盘换入

对程序来说，它看到的仍然是自己的虚拟地址空间。某个虚拟页此刻在物理内存里，还是被换出到了磁盘上，程序本身通常并不知道。

页表和 MMU 怎么配合

虚拟地址要变成物理地址，需要依靠 页表（Page Table） 和 MMU（Memory Management Unit，内存管理单元）。

MMU 是 CPU 中负责地址转换的硬件单元。程序发出的虚拟地址会先交给 MMU，MMU 根据页表查找这个虚拟地址对应的物理位置。

页表可以理解成一张映射表。每个进程都有自己的页表，里面记录了虚拟页和真实位置之间的关系：

  • 这个虚拟页是否在物理内存中。
  • 如果在内存中，它对应哪个物理页框。
  • 如果不在内存中，它是否在磁盘交换区或分页文件中。
  • 这个页是否可读、可写、可执行。

一次普通内存访问大致是这样发生的：

  1. 程序访问一个虚拟地址。
  2. CPU 把虚拟地址交给 MMU。
  3. MMU 查询当前进程的页表。
  4. 如果这一页在物理内存中，MMU 得到物理地址，CPU 直接读写内存。
  5. 如果这一页不在物理内存中，MMU 触发 缺页异常（Page Fault）。
  6. 操作系统接管异常处理，把需要的页从磁盘读回内存。
  7. 操作系统更新页表，然后让程序继续执行。

这里有一个容易误解的点：缺页异常不是程序崩溃。它更像是操作系统发现“这一页暂时不在内存里”，于是暂停一下，把页准备好，再让程序继续运行。

什么时候会发生缺页

缺页发生的直接原因是：程序访问的虚拟页当前没有映射到可用的物理页框。

常见情况有三种：

  1. 页面曾经在内存中，后来被换出到磁盘

    内存紧张时，操作系统会选择一些暂时不活跃的页，把它们写到交换区或分页文件。程序再次访问这些页时，就会触发缺页，操作系统再把页换回来。

  2. 页面还没有真正加载进内存

    很多系统会使用按需分页。程序启动或申请内存时，操作系统不一定立刻把所有页面都放入物理内存，而是等程序第一次访问时再加载。

  3. 访问了非法地址

    如果程序访问的地址根本不属于它的虚拟地址空间，或者权限不允许访问，例如向只读页面写入数据，也会触发缺页异常。不过这种缺页通常无法被正常修复，最终可能变成段错误、访问违规等运行时错误。

所以，缺页不一定意味着出错。它可能是虚拟内存机制的正常工作流程，也可能代表程序访问了不该访问的地址。

什么时候会用到交换区

交换区通常在物理内存压力较大时使用，但它不是“内存满了才突然启用”的简单开关。

操作系统会根据页面活跃程度、内存压力、缓存策略等因素，选择一部分暂时不常用的页换出到磁盘。这样可以把物理内存腾出来，用给当前更需要的页面、文件缓存或其他内核数据结构。

需要注意的是，被换出的不是“空闲页”。空闲页本来就没有有效数据，不需要写到磁盘。真正会被换出的，是那些当前不常用、但以后可能还要恢复的页。

总结

内存和磁盘在操作系统里的抽象层次不同：

  • 内存主要被抽象成 虚拟地址空间、页、页框。
  • 磁盘主要被抽象成 块、文件、目录。
  • 虚拟内存能使用磁盘，是因为操作系统把磁盘上的交换区或分页文件也按页来管理。
  • 页表记录虚拟页当前在哪里，MMU 根据页表完成地址转换。
  • 如果虚拟页不在物理内存中，就会触发缺页异常，由操作系统负责把页面换入。

一句话概括：虚拟内存不是简单地把内存和磁盘相加，而是操作系统用“页”这套机制，把物理内存和磁盘交换空间统一纳入同一个地址空间管理模型。
