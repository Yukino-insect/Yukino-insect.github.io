父子进程

January 2, 2026

父子进程是操作系统里很基础、也很容易被误解的一组概念。很多混乱都来自一句话没分清：

父子进程在创建关系上有关联，但在内存地址空间上默认彼此隔离。

下面按“是什么 -> 如何创建 -> 内存关系 -> 共享什么 -> 生命周期 -> 常见误区”的顺序，把这件事讲清楚。

一、什么是父进程和子进程？

从操作系统的角度看：

  • 父进程（Parent Process）：创建其他进程的进程。
  • 子进程（Child Process）：由父进程创建出来的新进程。

在类 Unix 系统中，除了最早被内核创建的进程外，几乎所有进程都有父进程。它们会形成一棵进程树。例如 Linux 中常见的 systemd，就是许多用户态服务的祖先进程。

需要注意的是，“父子”描述的是创建关系，不是说子进程天然依附在父进程的内存里运行。进程的核心特征仍然是独立的地址空间。

二、父子进程是如何产生的？

在 Linux / Unix 系统中，最经典的创建方式是 fork()：

pid_t pid = fork();

fork() 的特点很特别：

  • 代码里只调用一次。
  • 执行结果看起来像返回了两次。
  • 在父进程中，返回值是子进程的 PID。
  • 在子进程中，返回值是 0。
  • 如果创建失败，返回值是 -1。

也就是说，fork() 之后，父进程和子进程会从同一个位置继续向下执行，只是它们看到的返回值不同。

#include <stdio.h>
#include <unistd.h>

int main(void) {
    pid_t pid = fork();

    if (pid == 0) {
        printf("child process\n");
    } else if (pid > 0) {
        printf("parent process, child pid = %d\n", pid);
    } else {
        perror("fork");
    }

    return 0;
}

这也是为什么很多初学者第一次看到 fork() 会觉得奇怪：明明只有一份代码，却突然有两个执行流继续运行。其实不是代码分裂了，而是内核复制出了一个新的进程上下文。

三、父子进程会共享普通变量吗？

结论先说：

父子进程默认不共享普通内存数据。变量名一样、地址值看起来一样，也不代表它们会互相影响。

当父进程调用 fork() 时，内核会为子进程创建一份几乎相同的虚拟地址空间。代码段、数据段、堆、栈等映射关系都会被复制过去。

但这里复制的是“进程看到的地址空间”，不是把父子进程变成同一块可写内存。每个进程仍然有自己的页表和自己的地址空间视图。

四、Copy-On-Write：为什么 fork 不会立刻复制全部内存？

如果 fork() 时把父进程的所有内存页都完整复制一遍，代价会非常高。尤其是很多程序 fork() 之后马上就会 exec()，原来的内存内容很快就没用了。

所以现代操作系统通常使用 Copy-On-Write（写时复制，COW）：

  • fork() 刚完成时，父子进程可以暂时指向同一批物理页。
  • 这些页面会被标记为只读或 COW 状态。
  • 只要双方都只是读取，就不需要真正复制。
  • 一旦某一方尝试写入，内核才会为写入方复制出新的物理页。
  • 写入完成后，父子进程看到的就是各自独立的数据。

可以把它理解成：

读的时候像共享，写的时候才分家。

例如：

#include <stdio.h>
#include <unistd.h>

int main(void) {
    int x = 10;
    pid_t pid = fork();

    if (pid == 0) {
        x = 20;
        printf("child: %d\n", x);
    } else {
        sleep(1);
        printf("parent: %d\n", x);
    }

    return 0;
}

常见输出是：

child: 20
parent: 10

子进程把 x 改成 20，不会改变父进程里的 x。因为子进程写入时触发了 COW，它写的是自己新复制出来的内存页。

五、父子进程到底共享什么？

虽然普通变量默认不共享，但 fork() 后子进程会继承父进程的一些资源或资源引用。准确地说，很多东西不是“共享同一个变量”，而是“复制一份引用”或“继承同一个内核对象”。

资源 fork 后的关系 说明
虚拟地址空间 初始内容相同 写入后通过 COW 分离
代码段 内容相同 通常可共享只读物理页
全局变量、堆、栈 初始值相同 默认互不影响
文件描述符 描述符被复制 通常指向同一个打开文件对象
文件偏移量 可能共享 取决于是否指向同一个打开文件对象
当前工作目录 继承 之后可以各自修改
环境变量 复制 子进程修改不影响父进程
信号处理方式 继承 后续可独立设置

最容易踩坑的是文件描述符。

int fd = open("a.txt", O_WRONLY | O_CREAT, 0644);
fork();

fork() 之后，父子进程都有一个 fd。这个 fd 的数字在两个进程里可能一样，而且它们通常指向内核里的同一个打开文件对象。这意味着：

  • 文件偏移量可能会被父子进程共同推进。
  • 父子进程同时写文件时，内容顺序可能交错。
  • 如果没有同步，日志、输出文件、管道写入都可能出现难以复现的问题。

所以，普通内存变量不共享，不代表所有资源都完全无关。这里的边界要分清，否则排查问题时会很折磨，当然那也是理所当然的。

六、如果确实想共享数据，应该怎么做？

不要指望 fork() 自动帮你共享业务数据。进程间共享数据需要显式使用 IPC（Inter-Process Communication，进程间通信）机制。

常见方式如下：

方式 是否共享内存 适合场景
管道 pipe 否 有亲缘关系进程之间的单向通信
命名管道 FIFO 否 无亲缘关系进程也可通过文件名通信
消息队列 否 结构化消息传递
信号 否 简单事件通知
Socket 否 本机或网络通信
共享内存 是 高性能共享数据
mmap 可共享 文件映射或匿名共享映射

真正意义上的共享内存，一般要通过 mmap、System V shared memory 或 POSIX shared memory 等机制建立。

共享内存速度很快，因为多个进程可以读写同一块物理内存。但它也更危险：

  • 多个进程可能同时修改同一份数据。
  • 需要配合互斥锁、信号量、文件锁或原子操作。
  • 如果同步做得不好，就会出现数据竞争和一致性问题。

共享内存不是“更高级的全局变量”，而是一把很锋利的工具。用得好很快，用得随意就很难看。

七、父子进程的生命周期关系

父子进程在生命周期上也有几个容易混淆的阶段。核心要分清两件事：资源是否已经释放，以及进程的退出状态是否已经由父进程确认并回收。这两件事不是同一个动作。

1. 子进程可以主动释放资源吗？

可以。子进程是独立的进程，当然可以在仍然运行时主动释放自己持有的资源；父进程无须、也通常无法替它逐项释放。

常见例子包括：

  • 用 close(fd) 关闭不再需要的文件描述符、管道端或 Socket；
  • 用 free() 归还动态分配的堆内存。这里的“归还”是归还给该进程的内存分配器，分配器不一定会立刻把物理页还给内核；
  • 用 munmap() 解除内存映射，或用相应接口解除共享内存的映射/附着；
  • 释放锁、信号量、临时文件等需要应用程序显式清理的资源。

fork() 后父子进程的文件描述符表是两份独立的表。因此，子进程 close(fd) 通常只会关闭子进程自己的那份描述符，不会让父进程手中的同号 fd 失效；不过两份描述符可能仍指向同一个打开文件对象，所以在关闭之前，它们的文件偏移量等状态仍可能相互关联。

如果子进程调用 exit()、从 main 返回，或因未处理信号等原因终止，内核还会自动回收绝大多数内核管理的运行资源，例如用户态地址空间、页表、打开文件描述符和调度相关资源。应用程序仍应在合适的时机显式关闭、刷新或提交自己关心的资源：自动回收不等于业务层面的“正确收尾”。例如，文件缓冲区尚未刷新、共享内存中的半成品数据，内核并不会替程序修复。

在 fork() 后的子进程中，如果紧接着 exec() 失败而要直接结束，常见做法是调用 _exit()，而不是 exit()。exit() 会执行继承来的用户态清理函数并刷新 stdio 缓冲；这可能把父进程在 fork() 前已缓冲、但尚未写出的内容再写一次。这个细节不影响资源回收原理，却很影响排错时的心情。

2. 子进程退出后，wait() 到底还要回收什么？

子进程终止时，内核会先释放其绝大多数资源：代码、堆、栈等用户态内存不再保留，打开的文件描述符也会被关闭。因此，父进程调用 wait() 时，子进程并不是还带着完整内存和文件资源在等待。

但内核必须暂时保留一小段退出记录，供父进程获知结果，通常包括：

  • PID；
  • 退出码，或终止它的信号；
  • 少量资源使用/记账信息；
  • 进程表中的必要状态。

此时子进程处于终止但尚未被收割的状态。父进程调用 wait() 或 waitpid() 后，可以取得其 PID 和终止状态；内核随后删除这份残留记录，PID 也最终可以被重新使用。概念上可以把流程看成：

子进程运行
    │
    ├── 主动 close/free/munmap 等：释放仍在运行时不再需要的资源
    │
    └── 终止：内核释放绝大多数运行资源，保留最小退出记录
                                      │
                                      └── 父进程 wait/waitpid：读取状态并清除退出记录

wait() 的重点是取得终止状态并完成最后的收割（reap），而不是替一个仍在运行的子进程释放全部资源。若子进程尚未结束，默认的 wait() 会阻塞；若不希望阻塞，可使用 waitpid(..., WNOHANG)，或通过 SIGCHLD 驱动回收逻辑。

3. 什么是僵尸进程（Zombie Process）？

如果子进程已经退出，但它的父进程尚未调用 wait() / waitpid() 取得状态，它就是僵尸进程。在 Linux 的进程状态显示中，常能看到 Z 或 defunct。

僵尸进程具有三个特征：

  • 它已经终止，不能继续执行代码，也不能被“恢复运行”；
  • 它的绝大多数资源已经释放，不会继续占用完整的用户态内存；
  • 它仍占用一个进程表项和 PID 等少量内核资源，直到被回收。

短暂出现僵尸进程是正常现象：子进程退出和父进程执行 wait() 之间本来就可能有时间差。问题在于父进程长期不回收、并持续创建子进程；僵尸记录会不断累积，最终可能耗尽 PID 或进程表相关资源，导致新进程无法创建。

4. 父进程先结束，子进程会怎样？——孤儿进程

如果父进程先退出，而子进程仍在运行，子进程会成为孤儿进程（Orphan Process）。它不会因为“父亲不在了”就自动退出，而是会继续执行原来的程序；内核会为它重新指定父进程。

在 Linux 中，新父进程通常是最近的、被配置为**子收养进程（subreaper）**的祖先；若没有这类祖先，则通常由 PID 1（常见为 systemd 或 init）收养。收养者随后负责在该子进程退出时调用等待机制，避免其长期成为僵尸。

因此，“父进程退出”与“子进程退出”没有必然关系。只有程序显式建立了这种约束，子进程才会随父进程结束，例如：

  • 父进程主动向子进程发送终止信号；
  • 子进程使用 Linux 的 prctl(PR_SET_PDEATHSIG, ...)，要求在父进程死亡时接收指定信号；
  • 终端作业控制、服务管理器或进程组/会话规则向相关进程发送信号。

不要把孤儿进程与僵尸进程混为一谈：孤儿进程是仍在运行、但父进程已经改变的进程；僵尸进程是已经终止、但退出状态尚未被父进程回收的进程。一个进程在不同阶段甚至可以先成为孤儿，后来退出并短暂成为由新父进程负责回收的僵尸。

5. 父进程退出时，已经是僵尸的子进程怎么办？

若子进程已经退出、原父进程却在回收前退出，那么这条僵尸记录也会被重新交给收养者。收养者会对它执行等待/回收；因此它通常不会因为原父进程消失而永久残留。具体的回收时机由内核和收养进程的行为决定，但应用程序不应依赖这种“善后”：创建子进程的一方仍应自行正确处理 SIGCHLD 并调用 wait() / waitpid()。

6. fork 之后再 exec

很多程序并不是 fork() 之后继续跑同一份代码，而是马上调用 exec() 系列函数加载另一个程序。

常见流程是：

shell -> fork -> child -> exec(program)

例如你在 shell 里输入 ls，shell 通常会先 fork() 出子进程，再让子进程 exec() 成真正的 ls 程序。父进程 shell 则等待它执行结束，然后继续接收你的下一条命令。

八、进程和线程的区别

父子进程经常会和线程混在一起比较。最关键的区别是：进程强调隔离，线程强调共享。

对比 进程 线程
地址空间 默认独立 同一进程内共享
普通变量 默认不共享 通常共享进程内全局数据和堆
创建开销 相对更高 相对更低
通信方式 需要 IPC 可直接访问共享内存
崩溃影响 通常隔离较强 一个线程崩溃可能拖垮整个进程
同步问题 IPC 同步 锁、原子变量、条件变量等

一句话概括：

线程是在同一个进程里共享资源的多个执行流；父子进程是有创建关系、但地址空间默认隔离的两个进程。

九、常见误区

  1. 以为 fork 后变量天然共享

    普通变量不共享。子进程改变量，不会改到父进程的变量。

  2. 以为地址值相同就一定是同一块物理内存

    虚拟地址相同，不代表物理页一直相同。写时复制会让双方分离。

  3. 以为父进程退出，子进程也一定退出

    不一定。子进程可能继续运行，并被其他进程接管。

  4. 忽略文件描述符带来的共享状态

    内存不共享，但文件偏移、管道、Socket 等内核对象可能被父子进程共同使用。

  5. 把进程当成线程理解

    线程默认共享同一进程资源，进程默认隔离。两者的设计目标不同。

十、一句话总结

父进程是创建子进程的进程。fork() 之后，父子进程拥有相似的初始执行环境，但普通内存默认不共享；读时可能暂时共享物理页，写时会通过 COW 分离。如果需要真正共享数据，必须显式使用管道、Socket、共享内存等 IPC 机制，并处理好同步问题。
