DNS

March 23, 2026

DNS，全称 Domain Name System，中文通常叫域名系统。

它的核心作用是：把人类容易记住的域名，解析成计算机通信需要的 IP 地址。

例如我们访问：

www.example.com

浏览器最终需要知道它对应的 IP，才能建立 TCP 连接或 QUIC 连接。

一、为什么需要 DNS

人更容易记住域名：

www.baidu.com
github.com
api.example.com

但网络通信依赖的是 IP 地址：

110.242.x.x
140.82.x.x
93.184.216.34

DNS 就是域名和 IP 地址之间的翻译系统。

没有 DNS，也可以直接访问 IP，但这会带来很多问题：

  1. IP 难以记忆。
  2. 一个域名可能对应多个 IP。
  3. 服务迁移后 IP 可能变化。
  4. CDN、负载均衡、容灾都需要动态解析。

二、DNS 的层次结构

DNS 不是一台服务器，而是一个分布式、层次化的系统。

以域名为例：

www.example.com

从右往左看：

.        根域
com      顶级域
example  二级域
www      主机名或子域名

完整域名理论上可以写成：

www.example.com.

最后的点表示根域，平时通常省略。

三、几个关键角色

1. 根 DNS 服务器

根服务器位于 DNS 层次结构最顶层。

它通常不会直接告诉你 www.example.com 的 IP，而是告诉解析器：

.com 顶级域服务器在哪里。

常说的“13 个根服务器”指的是 13 组逻辑根服务器名称，从 A 到 M。每一组在全球通过 Anycast 部署了很多实例，所以物理服务器数量远不止 13 台。

2. 顶级域 DNS 服务器

顶级域包括：

.com
.cn
.org
.net
.edu

顶级域服务器负责告诉解析器：某个二级域由哪些权威 DNS 服务器管理。

例如 .com 服务器会告诉你：

example.com 由哪些权威 DNS 负责

3. 权威 DNS 服务器

权威 DNS 服务器保存某个域名真正的解析记录。

例如：

www.example.com -> 93.184.216.34
mail.example.com -> 192.0.2.10

当解析器问到权威 DNS 时，通常就能拿到最终答案。

4. 递归解析器

用户电脑一般不会自己一路问根服务器、顶级域服务器、权威服务器。

它通常会把问题交给递归解析器，例如：

  1. 路由器 DNS。
  2. 运营商 DNS。
  3. 企业内部 DNS。
  4. 公共 DNS，例如 8.8.8.8、1.1.1.1。

递归解析器负责帮客户端完成后续查询，并把结果缓存起来。

四、浏览器输入网址后的 DNS 查询过程

假设访问：

www.example.com

解析过程大致如下。

1. 浏览器缓存

浏览器会先检查自己是否缓存过这个域名的解析结果。

如果命中缓存，就可以直接使用。

2. 操作系统缓存和 hosts

如果浏览器没有缓存，会交给操作系统解析。

操作系统可能检查：

  1. DNS 缓存。
  2. hosts 文件。
  3. 本机 DNS 配置。

hosts 文件可以手动指定域名映射：

127.0.0.1      localhost
192.168.1.10   test.example.com

不同系统、浏览器和解析器的具体顺序可能略有差异，但大方向是先查本地可用信息，再向外部 DNS 查询。

3. 请求递归解析器

如果本地没有结果，系统会向配置好的 DNS 服务器发起查询。

这个 DNS 服务器通常就是递归解析器。

4. 递归解析器迭代查询

如果递归解析器也没有缓存，它会开始迭代查询：

递归解析器 -> 根服务器
递归解析器 -> .com 顶级域服务器
递归解析器 -> example.com 权威 DNS

过程可以理解为：

  1. 问根服务器：.com 在哪里？
  2. 问 .com 服务器：example.com 的权威 DNS 在哪里？
  3. 问权威 DNS：www.example.com 的 IP 是多少？

最后权威 DNS 返回记录，递归解析器再把结果返回给客户端。

五、递归查询和迭代查询

1. 递归查询

客户端问 DNS：

请你帮我查出最终答案。

客户端只等最终结果。

2. 迭代查询

DNS 服务器之间查询时，经常是：

我不知道最终答案，但我告诉你下一步该问谁。

递归解析器根据这些线索一步步查下去。

所以整体上常见模式是：

客户端 -> 递归解析器：递归查询
递归解析器 -> 根 / TLD / 权威 DNS：迭代查询

六、常见 DNS 记录类型

记录类型 作用
A 域名解析到 IPv4 地址
AAAA 域名解析到 IPv6 地址
CNAME 域名别名
MX 邮件服务器
NS 指定权威 DNS 服务器
TXT 文本记录，常用于验证、SPF、DKIM
PTR 反向解析，IP 解析到域名

常见例子：

www.example.com.  A      93.184.216.34
api.example.com.  CNAME  gateway.example.com.
example.com.      MX     10 mail.example.com.

七、TTL 是什么

TTL，全称 Time To Live，表示 DNS 记录可以被缓存多久。

例如：

www.example.com  A  93.184.216.34  TTL=300

表示解析结果可以缓存 300 秒。

TTL 越大，缓存越久，解析压力越小，但变更生效更慢。TTL 越小，变更更灵活，但 DNS 查询压力更高。

八、DNS 使用什么协议

传统 DNS 主要使用：

UDP 53

但下面情况可能使用 TCP：

  1. 响应数据较大。
  2. 区域传送。
  3. UDP 响应被截断后重试。

现在也有加密 DNS：

  1. DoH：DNS over HTTPS。
  2. DoT：DNS over TLS。

它们可以降低 DNS 查询被明文监听或篡改的风险，但也会改变排查问题的方式。

九、DNS 常见问题

1. DNS 缓存未刷新

域名记录改了，但本地、递归解析器或浏览器还有旧缓存。

Windows 可以尝试：

ipconfig /flushdns

2. hosts 文件覆盖

本地 hosts 写了固定映射，导致访问不到真实解析结果。

3. 解析到错误 IP

可能是配置错误、缓存污染、CDN 调度异常或运营商 DNS 问题。

4. 内网域名只能在公司网络解析

例如：

nacos.internal.company

这类域名可能只存在于企业内部 DNS。离开公司网络或 VPN 后就无法解析。

十、面试时怎么回答

可以这样说：

DNS 是一个分布式、层次化的域名解析系统，用来把域名转换成 IP。浏览器访问域名前，会先查浏览器缓存、系统缓存和 hosts；如果本地没有结果，就请求递归解析器。递归解析器如果也没有缓存，会依次向根服务器、顶级域服务器和权威 DNS 服务器查询，最终拿到解析记录并返回给客户端。

十一、一句话总结

DNS 的本质是分布式域名解析。根服务器告诉你下一层去哪找，顶级域服务器告诉你权威 DNS 在哪，权威 DNS 才保存真正的域名记录。
