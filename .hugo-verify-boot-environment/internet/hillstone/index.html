Hillstone

January 10, 2026

Hillstone 通常指山石网科的企业安全产品。在公司网络里，它可能以防火墙、VPN 网关、安全网关等形式出现。

如果实习或远程办公时需要通过 Hillstone 才能访问公司内网资源，那么它大概率承担的是 VPN 接入网关 的角色。

一句话概括：

Hillstone 通过 VPN 为外部终端和公司内网之间建立加密隧道，并在认证通过后给终端分配受控的内网访问能力。

一、它解决什么问题

公司内部服务通常不会直接暴露到公网，例如：

Nacos
数据库
测试环境接口
GitLab
Jenkins
内部文档
堡垒机

这些服务只允许公司内网访问。

如果人在公司外部，例如宿舍、家里、出差地点，就不能直接访问这些内网地址。Hillstone 这类 VPN 网关的作用就是：

  1. 验证用户身份。
  2. 建立加密隧道。
  3. 下发内网 IP、DNS 和路由。
  4. 按权限控制用户能访问哪些内网资源。
  5. 记录审计日志。

二、它不是内网穿透

这一点要分清楚。

Hillstone VPN 接入不是把公司内网服务暴露给公网，而是把经过认证的用户安全接入公司内网。

对比项 VPN 内网接入 内网穿透
方向 把外部用户接入内网 把内网服务暴露到公网
工作层级 多数在网络层或传输层 多数在应用层或端口转发层
是否分配内网 IP 通常会 通常不会
是否暴露内部服务端口 不需要直接公网暴露 需要提供公网入口
企业常用性 标准远程办公方案 更多用于调试或临时暴露服务

直观理解：

VPN：把人接进公司内网。
内网穿透：把服务拿到公网入口。

三、基本访问链路

远程访问公司内网时，链路大致如下：

你的电脑
  -> 公网
  -> 加密 VPN 隧道
  -> Hillstone VPN 网关 / 防火墙
  -> 公司内网交换机 / 路由器
  -> 内网服务器

你的电脑在逻辑上会多一个网络入口，也就是 VPN 虚拟网卡。

四、核心组件

1. VPN 网关

VPN 网关通常部署在公司网络边界。

它负责：

  1. 用户认证。
  2. 隧道建立。
  3. 加密和解密流量。
  4. 分配地址和路由。
  5. 访问控制。
  6. 日志审计。

Hillstone 设备就可能承担这个角色。

2. VPN 客户端

客户端安装在你的电脑上。

它通常会：

  1. 连接公司 VPN 网关。
  2. 完成用户名、密码、证书或 MFA 验证。
  3. 创建虚拟网卡。
  4. 接收公司下发的路由和 DNS。
  5. 把特定流量送进 VPN 隧道。

3. 地址池

公司会为 VPN 用户准备一段地址池，例如：

10.10.8.0/24

你连接成功后，可能获得：

VPN IP：10.10.8.56
子网掩码：255.255.255.0
DNS：10.10.0.10

此时你的电脑在逻辑上就像公司内网中的一台受控主机。

4. 路由规则

VPN 客户端会下发路由规则，例如：

10.10.0.0/16 -> 走 VPN
其他流量     -> 走本地网络

这叫分流。只有访问公司内网网段时才走 VPN，访问普通互联网仍走本地网络。

也有全局模式：

0.0.0.0/0 -> 走 VPN

这种模式下几乎所有流量都会进入公司网络，再由公司出口转发。

五、连接建立过程

1. 身份认证

常见认证方式包括：

用户名 + 密码
证书
短信验证码
动态令牌
企业 SSO

认证不通过，就不会进入内网。

2. 建立加密隧道

常见 VPN 类型包括：

  1. SSL VPN。
  2. IPsec VPN。
  3. L2TP/IPsec。

具体使用哪种取决于公司设备、客户端和安全策略。

加密隧道建立后，公网中间链路只能看到加密后的数据，无法直接看到内部访问内容。

3. 创建虚拟网卡

客户端会在系统中创建 VPN Adapter。

这意味着操作系统多了一个网络接口，可以把符合规则的流量发给它。

4. 下发地址、DNS 和路由

VPN 网关向客户端下发：

  1. VPN IP。
  2. 子网掩码。
  3. DNS 服务器。
  4. 路由规则。
  5. 可访问资源范围。

这些配置决定你能访问哪些内网服务。

六、为什么连上 VPN 后能访问内网 IP

假设你访问公司 Nacos：

10.10.0.30:8848

数据包大致是：

源 IP：10.10.8.56
目标 IP：10.10.0.30

流程如下：

操作系统检查路由表
  -> 发现 10.10.0.0/16 要走 VPN
  -> 数据进入 VPN 虚拟网卡
  -> 客户端加密封装
  -> 通过公网发给 Hillstone 网关
  -> 网关解密
  -> 转发到公司内网服务器

内网服务器看到的来源可能是你的 VPN 地址，也可能是网关转换后的地址，具体取决于公司网络配置。

七、为什么有些内网域名只有连 VPN 才能访问

公司内部域名可能依赖内部 DNS，例如：

nacos.dev.company.local
db.test.internal

未连接 VPN 时，你的电脑使用家庭路由器或运营商 DNS，它们不知道这些内部域名。

连接 VPN 后，公司会下发内部 DNS，系统才能把这些域名解析到内网 IP。

所以访问失败时，要区分：

  1. 是域名解析失败。
  2. 是解析成功但连接失败。
  3. 是连接成功但权限不足。

八、常见问题排查

1. VPN 已连接，但访问不了内网 IP

检查：

route print

确认目标网段是否走 VPN。

2. 内网域名解析失败

检查：

ipconfig /all
nslookup nacos.dev.company.local

确认 DNS 是否已经切到公司内部 DNS。

3. 能 ping 通但服务访问不了

可能原因：

  1. 服务端口未开放。
  2. 防火墙策略未授权。
  3. 用户权限不够。
  4. 服务只监听特定地址。
  5. 公司禁止 ICMP 之外的访问。

4. 连上 VPN 后普通网页变慢

可能是开启了全局路由，所有流量都走公司出口。可以确认是否有：

0.0.0.0/0 -> VPN 网关

九、面试或工作中可以这样总结

Hillstone 在企业网络中常作为防火墙或 VPN 网关使用。远程用户通过客户端连接 Hillstone，完成身份认证后建立加密隧道，并获得公司下发的内网地址、DNS 和路由规则。之后访问内网服务时，流量会进入 VPN 虚拟网卡，经公网加密传输到 Hillstone 网关，再由网关转发到公司内网。这属于安全的内网接入，不是内网穿透。

十、一句话总结

Hillstone 这类企业安全网关的价值在于：在不把内网服务直接暴露到公网的前提下，让经过认证和授权的用户安全、可审计地访问公司内部资源。
