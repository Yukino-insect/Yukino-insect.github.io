TCP 三次握手四次挥手

November 21, 2025

TCP 是面向连接的可靠传输协议。

三次握手用于建立连接，四次挥手用于关闭连接。它们解决的不是“能不能发包”这么简单，而是连接状态、序列号同步、双方收发能力确认和全双工关闭问题。

一、三次握手过程

假设客户端主动连接服务端。

1. 第一次握手：客户端发送 SYN

客户端 -> 服务端：SYN, Seq = x

含义：

  1. 客户端希望建立连接。
  2. 客户端发送自己的初始序列号 x。
  3. 客户端进入 SYN_SENT 状态。

2. 第二次握手：服务端回复 SYN + ACK

服务端 -> 客户端：SYN + ACK, Seq = y, Ack = x + 1

含义：

  1. 服务端同意建立连接。
  2. 服务端确认收到了客户端的 SYN。
  3. 服务端发送自己的初始序列号 y。
  4. 服务端进入 SYN_RECEIVED 状态。

3. 第三次握手：客户端回复 ACK

客户端 -> 服务端：ACK, Ack = y + 1

含义：

  1. 客户端确认收到了服务端的 SYN。
  2. 客户端进入 ESTABLISHED 状态。
  3. 服务端收到 ACK 后也进入 ESTABLISHED 状态。

三次握手完成后，双方都知道：

  1. 自己能发送。
  2. 自己能接收。
  3. 对方能发送。
  4. 对方能接收。
  5. 双方初始序列号是多少。

二、为什么需要三次握手

两次握手的问题是：服务端无法确认客户端是否收到了自己的 SYN + ACK。

如果只有两次握手，可能出现这种情况：

  1. 客户端很久以前发过一个 SYN。
  2. 这个旧 SYN 因网络延迟滞留。
  3. 旧 SYN 过了很久才到达服务端。
  4. 服务端误以为客户端要建立新连接。
  5. 服务端分配资源并进入连接状态。

第三次 ACK 可以让服务端确认：

客户端确实收到了服务端的 SYN + ACK，并愿意建立这次连接。

所以三次握手的核心意义是同步初始序列号，并确认双方收发能力。

三、四次挥手过程

TCP 是全双工协议，两个方向的数据流可以独立关闭。

假设客户端主动关闭连接。

1. 第一次挥手：主动关闭方发送 FIN

客户端 -> 服务端：FIN

含义：

客户端不再发送数据了。

但客户端仍然可以接收服务端数据。

2. 第二次挥手：被动关闭方回复 ACK

服务端 -> 客户端：ACK

含义：

服务端知道客户端不再发送数据了。

此时服务端可能还有数据没发完。

3. 第三次挥手：被动关闭方发送 FIN

服务端 -> 客户端：FIN

含义：

服务端也不再发送数据了。

4. 第四次挥手：主动关闭方回复 ACK

客户端 -> 服务端：ACK

含义：

客户端确认服务端也关闭了发送方向。

至此连接关闭。

四、为什么挥手通常是四次

因为 TCP 是全双工的。

收到对方的 FIN 只表示：

对方不会再发数据了。

不表示：

我也不能继续发数据。

所以两个方向要分别关闭：

客户端发送方向关闭
服务端发送方向关闭

如果服务端收到 FIN 后没有数据要继续发送，第二次 ACK 和第三次 FIN 也可能合并发送，这时从抓包上看可能像“三次挥手”。但逻辑上仍然是两个方向分别关闭。

五、TIME_WAIT 是什么

主动关闭方在发送最后一个 ACK 后，会进入 TIME_WAIT 状态，等待一段时间再释放连接。

常见等待时间是 2MSL。MSL 是 Maximum Segment Lifetime，表示报文在网络中可能存活的最长时间。

TIME_WAIT 主要解决两个问题。

1. 确保最后一个 ACK 能被对方收到

如果最后一个 ACK 丢了，服务端会重发 FIN。

主动关闭方还在 TIME_WAIT，就可以再次回复 ACK。

2. 等旧连接报文自然过期

网络中可能还有旧连接残留报文。

等待一段时间可以降低旧报文影响新连接的风险。

六、常见面试追问

1. 为什么不是两次握手

两次握手无法让服务端确认客户端收到了自己的 SYN，也无法可靠同步双方初始序列号。

2. 为什么不是四次握手

三次已经能完成双方初始序列号同步和收发能力确认。再多一次没有必要。

3. 为什么挥手不是三次

因为 TCP 双向数据流独立关闭。被动关闭方收到 FIN 后，可能还有数据要发，所以 ACK 和 FIN 通常分开发。

4. 哪一方进入 TIME_WAIT

主动关闭连接的一方进入 TIME_WAIT。

客户端和服务端都可能主动关闭，所以两者都可能进入 TIME_WAIT。

七、一句话总结

三次握手是为了确认双方收发能力并同步初始序列号；四次挥手是因为 TCP 是全双工协议，两个方向的数据流需要分别关闭；TIME_WAIT 是为了可靠完成关闭并让旧报文过期。
