内网穿透

February 6, 2026

内网穿透是一种让公网用户访问内网服务的技术。它常用于本地开发调试、临时演示、第三方回调测试、远程访问家中设备等场景。

它解决的核心问题是：内网机器没有公网入口，外部用户无法直接连接它。

一、为什么公网访问不到内网服务

大多数家庭网络、办公网络和云内私有网络都在 NAT 后面。内网机器通常使用私有 IP，例如：

192.168.x.x
10.x.x.x
172.16.x.x ~ 172.31.x.x

这些地址只在内网中有效，公网用户无法直接访问。

例如你在本机启动了一个服务：

http://localhost:8080

这个地址只对你自己的电脑有效。即使你把电脑的内网 IP 发给别人：

http://192.168.1.20:8080

对方也大概率访问不了，因为这个地址属于你的局域网，不在公网路由中。

二、内网穿透的基本原理

内网机器虽然不能被公网主动连接，但它可以主动连接公网服务器。

内网穿透正是利用这一点：

外部用户
  -> 公网中转服务器
  -> 内网穿透客户端
  -> 内网服务

一般需要两部分：

  1. 公网中转服务器：拥有公网 IP 或公网域名，负责接收外部请求。
  2. 内网穿透客户端：运行在内网机器上，主动连接公网中转服务器，并维持隧道。

当外部请求到达公网中转服务器后，中转服务器会通过已经建立好的隧道，把请求转发到内网服务。

三、举个例子

假设本地启动了一个接口：

http://127.0.0.1:8080/api/callback

第三方平台要求配置一个公网回调地址。此时可以通过内网穿透得到：

https://demo.example.com/api/callback

访问链路变成：

第三方平台
  -> https://demo.example.com/api/callback
  -> 公网穿透服务器
  -> 本机穿透客户端
  -> http://127.0.0.1:8080/api/callback

这样第三方平台访问的是公网地址，但最终请求会到达你本机的服务。

四、常见工具

常见内网穿透工具包括：

工具 适合场景 特点
frp 自建长期使用 功能完整，可控性强
ngrok 临时调试和演示 上手简单，托管服务方便
ssh -R 简单远程端口转发 不需要额外复杂组件
云厂商隧道服务 云资源集成 配套云平台权限和审计

临时调试时，托管型工具更省事。长期暴露服务时，更推荐自建，并配置认证、TLS、访问控制和日志审计。

五、内网穿透和 VPN 的区别

内网穿透和 VPN 都能让外部访问内部资源，但方向和边界不同。

对比项 内网穿透 VPN 内网接入
核心目标 把某个内网服务暴露给外部 把外部终端接入内网
暴露范围 通常是指定端口或服务 按路由和权限访问内网资源
是否分配内网 IP 通常不分配 通常会分配
常见用途 本地调试、Webhook、临时演示 远程办公、运维、企业内网访问

一句话区分：

内网穿透：把服务拿出去。
VPN：把人接进来。

六、安全注意事项

内网穿透会改变服务的安全边界。原本只在本机或内网可见的服务，一旦通过公网入口暴露，就要按公网服务标准防护。

至少要注意：

  1. 不要暴露数据库、Redis、管理后台、Docker API 等高危端口。
  2. 公网入口必须配置认证和访问控制。
  3. 对外访问建议使用 HTTPS。
  4. 测试完成后及时关闭隧道。
  5. 不要在日志中打印 token、密码、Cookie 等敏感信息。
  6. 对长期使用的隧道配置访问白名单和审计日志。

七、一句话总结

内网穿透解决的是公网到内网服务的可达性问题，不解决服务本身的安全问题。只要服务被暴露到公网，就应该按公网服务来设计认证、权限、加密和审计。
