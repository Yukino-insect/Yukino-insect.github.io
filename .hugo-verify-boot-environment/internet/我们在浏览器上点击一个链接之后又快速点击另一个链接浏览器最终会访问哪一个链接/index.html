我们在浏览器上点击一个链接之后，又快速点击另一个链接，浏览器最终会访问哪一个链接？

March 25, 2026

如果在同一个浏览器标签页中，点击第一个链接后又快速点击第二个链接，通常最终打开的是第二个链接。

更准确地说：同一个标签页的当前导航，一般会以用户最后一次有效导航操作为准。

不过这里要加上“通常”两个字。浏览器行为还会受页面是否已经跳转、是否打开新标签页、脚本是否拦截点击事件、网络响应是否已经提交等因素影响。

一、先给面试版答案

可以这样回答：

通常最终访问的是第二个链接。因为第一次点击会触发一次浏览器导航，第二次点击会启动新的导航任务。浏览器会把旧导航标记为取消或中止，然后提交最新的导航结果。TCP 并不知道用户点击了哪个链接，真正做出取消决策的是浏览器和 HTTP 等上层协议。

这个回答已经足够覆盖大多数面试场景。

二、浏览器层面发生了什么

点击链接后，浏览器会启动一次导航流程：

  1. 处理点击事件。
  2. 确认链接目标。
  3. 检查缓存和安全策略。
  4. 进行 DNS 查询。
  5. 建立 TCP 连接。
  6. 如果是 HTTPS，进行 TLS 握手。
  7. 发送 HTTP 请求。
  8. 接收响应并准备提交新页面。

如果第二次点击发生得很快，浏览器会认为用户的最新意图是第二个链接，于是通常会：

  1. 取消第一次导航。
  2. 发起第二次导航。
  3. 最终把第二个链接对应的页面提交到当前标签页。

从用户视角看，就是“后一次点击覆盖了前一次点击”。

三、第一次请求一定没有发出去吗

不一定。

这取决于第二次点击发生时，第一次导航已经走到了哪一步。

1. 第一次请求还没进入网络层

如果第一次导航还停留在浏览器内部阶段，例如：

  1. 事件还在调度。
  2. 正在解析 URL。
  3. 正在查缓存。
  4. 正在排队等待连接。
  5. 正在等待 DNS。

这时第二次点击发生，浏览器可能直接取消第一次导航任务。

结果是：第一个请求可能根本没有发到服务器。

2. 第一次请求已经发出去了

如果第一个 HTTP 请求已经发到网络中，浏览器不能把已经发出去的数据包“收回来”。

它能做的是：

  1. 不再使用第一个响应。
  2. 关闭承载第一个请求的连接。
  3. 在 HTTP/2 或 HTTP/3 中取消对应的 stream。
  4. 继续发起第二个链接的请求。

所以，服务器日志里可能会看到第一个请求。但页面最终展示的仍然通常是第二个链接。

四、TCP 在这里扮演什么角色

TCP 不知道什么是“点击链接”，也不知道什么是“页面导航”。

TCP 只负责：

  1. 建立连接。
  2. 可靠传输字节流。
  3. 确认和重传数据。
  4. 维护连接状态。

因此，不是 TCP 判断“第二次点击优先”，而是浏览器判断当前标签页应该提交哪一次导航。

TCP 只是把浏览器和服务器之间的数据可靠传输过去。

五、取消旧请求时底层可能怎么做

1. 关闭 TCP 连接

如果第一次请求独占一个 TCP 连接，浏览器可以关闭 socket。

TCP 层可能表现为：

  1. FIN：正常关闭连接。
  2. RST：强制复位连接。

服务器可能看到连接断开、写响应失败，或者请求被客户端取消。

2. 取消 HTTP/2 stream

HTTP/2 支持在一个 TCP 连接上复用多个请求。

这时浏览器不一定会关闭整个 TCP 连接，因为同一连接上可能还有其他请求在用。它可以发送：

RST_STREAM

表示取消某一个请求流。

TCP 连接仍然保持，只有那个具体请求被取消。

3. 取消 HTTP/3 QUIC stream

HTTP/3 基于 QUIC。QUIC 本身支持多路复用，取消请求时也可以取消对应的 stream，而不是关闭整个连接。

六、有哪些例外情况

1. 第一个页面已经提交成功

如果第一个链接响应非常快，页面已经跳转到新文档，那么你后续点击的第二个链接可能已经发生在新页面上。

此时不再是“同一个旧页面里连续点击两个链接”，而是新页面里的另一轮用户操作。

2. 链接打开新标签页

如果链接带有：

target="_blank"

或者用户按住快捷键打开新标签页，那么两个链接可能分别打开在不同标签页里，不存在谁覆盖谁。

3. JavaScript 拦截了点击

前端代码可能通过 preventDefault() 阻止默认跳转，然后自己决定跳转逻辑。

这时最终访问哪个链接，取决于前端代码怎么写。

4. 表单提交、下载、弹窗行为

某些下载、表单提交、弹窗和安全策略会影响最终行为，不能简单套用普通链接导航。

七、面试时可以怎么说

可以组织成下面这段：

通常最终访问第二个链接。因为浏览器会把第二次点击视为用户最新意图，取消当前标签页中的旧导航并启动新导航。第一次请求是否真的到达服务器不一定：如果还没进入网络层，可能完全不会发出；如果已经发出，服务器可能收到，但浏览器会取消连接、取消 HTTP/2 stream，或者忽略旧响应。TCP 本身没有“取消某个页面导航”的语义，它只负责可靠传输字节流，真正决定导航结果的是浏览器和 HTTP 层。

八、一句话总结

同一标签页中快速连续点击两个普通链接，最终通常以第二次点击为准。第一个请求可能没发出，也可能已经到达服务器，但浏览器会优先提交最新导航结果。
