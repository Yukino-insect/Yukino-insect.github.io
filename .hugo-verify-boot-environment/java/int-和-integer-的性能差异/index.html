int[] 和 Integer[] 的性能差异

February 16, 2026

int[] 通常比 Integer[] 更快、更省内存。原因不是“包装类型天生慢”这么简单，而是两者的内存布局完全不同。

一句话概括：

int[] 直接连续保存整数值；Integer[] 连续保存的是引用，真正的 Integer 对象分散在堆中，访问时多了一次间接寻址。

一、内存布局不同

int[] 是基本类型数组，数组元素就是原始的 int 值：

int[]
+----+----+----+----+
|  1 |  2 |  3 |  4 |
+----+----+----+----+

每个 int 占 4 字节，元素连续排列。

而 Integer[] 是引用类型数组，数组里放的是对象引用：

Integer[]
+------+------+------+------+
| ref1 | ref2 | ref3 | ref4 |
+------+------+------+------+
   |      |      |      |
   v      v      v      v
 Integer Integer Integer Integer
 object  object  object  object

数组本身是连续的，但连续的是引用，不是整数值。真正的 Integer 对象在堆上，位置不保证连续。

二、CPU 缓存局部性

CPU 访问内存时，不是每次只取一个 int。它会按 Cache Line 把一整块连续内存加载到缓存中。常见 Cache Line 大小是 64 字节，因此一条 Cache Line 可以放下 16 个 int。

遍历 int[] 时：

读取 arr[i] -> 相邻的 arr[i + 1]、arr[i + 2] 很可能已经在缓存里

这符合空间局部性，CPU 预取也容易生效。

遍历 Integer[] 时，过程变成：

  1. 从数组中读取引用。
  2. 根据引用跳到堆上的 Integer 对象。
  3. 从对象里读取真正的 int value。
  4. 自动拆箱成 int。

这多了一次指针跳转。如果 Integer 对象分布零散，CPU 缓存命中率会下降，流水线也更容易被内存访问拖慢。

三、内存开销不同

int 本身只占 4 字节。

Integer 是对象，除了内部的 int value，还要有对象头、对齐填充，以及数组里的引用。具体大小取决于 JVM、对象对齐、是否开启压缩指针等配置，但通常会明显大于 4 字节。

粗略理解即可：

int[]:
  数组对象头 + N * 4 字节

Integer[]:
  数组对象头 + N * 引用大小 + N 个 Integer 对象

对象越多，GC 需要追踪的引用也越多，内存压力和回收成本都会上升。

四、装箱和拆箱成本

如果代码写成：

Integer[] arr = new Integer[1_000_000];
for (int i = 0; i < arr.length; i++) {
    arr[i] = i; // 自动装箱
}

arr[i] = i 会触发自动装箱。对于不在缓存范围内的值，通常会创建新的 Integer 对象。

读取时：

int sum = 0;
for (Integer x : arr) {
    sum += x; // 自动拆箱
}

sum += x 又会触发自动拆箱。如果数组中存在 null，还会抛出 NullPointerException。

五、什么时候差距明显

差距通常出现在这些场景：

  1. 数组很大。
  2. 频繁顺序遍历。
  3. 做数值计算。
  4. 对延迟和吞吐敏感。
  5. GC 压力已经比较明显。

例如计数、求和、动态规划、图算法中的距离数组，优先使用 int[]、long[]、double[] 这类基本类型数组。

六、什么时候可以用 Integer[]

Integer[] 也不是不能用。它适合需要引用语义的场景：

  1. 需要表示 null，区分“没有值”和“值为 0”。
  2. 必须放入泛型容器，例如 List<Integer>。
  3. API 要求包装类型。
  4. 数据量很小，性能差异不重要。

如果只是普通数值数组，不需要 null，也不需要对象语义，那么 int[] 更合适。

七、总结

int[] 快，主要快在：

  1. 数据连续，缓存命中率高。
  2. 没有对象间接访问。
  3. 没有装箱、拆箱。
  4. 内存占用更小，GC 压力更低。

Integer[] 慢，主要慢在：

  1. 数组里存引用，不直接存值。
  2. 真实对象可能分散在堆上。
  3. 每个元素都是对象，内存成本更高。
  4. 读取时可能涉及拆箱和空值风险。

当然，具体差距要以 JMH 这类基准测试为准。只是从内存布局看，int[] 的优势并不神秘，它只是少绕了很多路。计算机这种东西，有时也意外地诚实。
