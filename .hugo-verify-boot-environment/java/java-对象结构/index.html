Java 对象结构

December 28, 2025

Java 对象在 HotSpot JVM 中通常可以拆成三部分：

  • 对象头
  • 实例数据
  • 对齐填充

数组对象还会在对象头中额外保存数组长度。

普通对象：
┌─────────────────────────┐
│ Mark Word               │
│ Klass Pointer           │
├─────────────────────────┤
│ 实例字段（父类）        │
│ 实例字段（子类）        │
├─────────────────────────┤
│ Padding（对齐填充）     │
└─────────────────────────┘

数组对象：
┌─────────────────────────┐
│ Mark Word               │
│ Klass Pointer           │
│ Array Length            │
├─────────────────────────┤
│ 数组元素                │
├─────────────────────────┤
│ Padding（对齐填充）     │
└─────────────────────────┘

对象头

对象头里最重要的是 Mark Word 和 Klass Pointer。

Mark Word 用来保存对象运行时状态，例如：

  • 哈希码
  • GC 分代年龄
  • 锁状态
  • 偏向锁相关信息，较新的 JDK 中偏向锁已经逐步被废弃

所以讲 synchronized、对象哈希、锁膨胀时，经常会绕回对象头。不是因为它神秘，而是因为这些状态确实放在这里。

Klass Pointer 是对象指向类元数据的指针。JVM 通过它知道这个对象属于哪个类、有哪些字段、有哪些方法。很多资料也会把它叫作类型指针或类指针。

数组对象还会多一个数组长度字段。普通对象不需要这个字段，因为普通对象的字段布局可以从类元数据推导出来；数组长度则是每个数组实例自己的状态。

实例数据

实例数据就是对象真正保存的成员变量。

如果存在继承关系，子类对象里会同时包含父类字段和子类字段。注意，这并不表示“子类对象里套了一个父类对象”，而是同一个对象的内存布局中包含了父类声明的那部分字段。

JVM 可能会为了减少内存占用而调整字段排列顺序，例如把相同大小的字段放得更紧凑。具体布局与 JVM 实现、启动参数、是否开启压缩指针都有关系。

对齐填充

HotSpot 中对象大小通常按 8 字节对齐。对象头和实例字段加起来如果不是 8 的倍数，JVM 会补一些无意义的填充字节。

例如一个对象实际字段很少，也可能因为对象头和对齐规则占用比直觉更大的空间。分析对象大小时，不能只把字段大小简单相加。

压缩指针

在 64 位 JVM 中，引用本来可能占 8 字节。为了节省内存，HotSpot 常见配置会开启压缩指针：

  • UseCompressedOops：压缩普通对象引用。
  • UseCompressedClassPointers：压缩对象头中的类型指针。

开启压缩后，很多对象引用可以用 4 字节表示，再由 JVM 按规则解码成真实地址。

所以“对象头到底多大”没有一个脱离环境的固定答案：

  • 32 位 JVM 通常更小。
  • 64 位 JVM 未开启压缩指针时更大。
  • 64 位 JVM 开启压缩指针时，普通对象头常见为 12 字节，再通过对齐补到 16 字节。

这也是为什么分析对象内存时，经常会看到 JOL 这类工具。靠脑内表格硬算，偶尔可以；长期这么做就显得有些逞强了。

常见结论

  • 普通对象主要由对象头、实例字段、对齐填充组成。
  • 数组对象比普通对象多一个数组长度字段。
  • Mark Word 和锁、哈希、GC 年龄有关。
  • Klass Pointer 指向类元数据，让 JVM 知道对象的类型。
  • 对象实际大小受 JVM 位数、压缩指针、字段布局和对齐规则影响。
