反射

December 13, 2025

Java 反射是指程序在运行时获取类信息，并动态操作构造器、方法、字段和注解的能力。它让代码可以在编译期不知道具体类型的情况下，仍然完成对象创建和方法调用。

一、反射的入口

反射的核心入口是 Class 对象。每个被 JVM 加载的类，在运行时都有一个对应的 Class 对象，用于描述这个类的结构信息。

常见获取方式有：

Class<?> c1 = User.class;
Class<?> c2 = user.getClass();
Class<?> c3 = Class.forName("com.example.User");

拿到 Class 后，就可以获取构造器、字段、方法和注解。

二、常见操作

创建对象：

Constructor<User> constructor = User.class.getDeclaredConstructor();
User user = constructor.newInstance();

调用方法：

Method method = User.class.getDeclaredMethod("setName", String.class);
method.invoke(user, "Tom");

访问字段：

Field field = User.class.getDeclaredField("name");
field.setAccessible(true);
field.set(user, "Tom");

三、Class 和方法区的关系

类加载后，类的元数据会存放在 JVM 的方法区实现中。Class 对象是 Java 代码访问这些类元数据的入口。

可以把它理解为：JVM 内部保存类的结构信息，而 Class 对象提供了一层 Java 层面的访问句柄。反射 API 正是通过这个句柄读取和操作类信息。

四、使用场景

反射常见于：

  1. Spring 创建 Bean。
  2. MyBatis 映射查询结果。
  3. Jackson 序列化和反序列化。
  4. JUnit 执行测试方法。
  5. 注解扫描和框架扩展点。

五、注意点

反射会绕过一部分编译期检查，错误通常延迟到运行时暴露。它也可能破坏封装，例如通过 setAccessible(true) 访问私有成员。

在 Java 9 引入模块系统之后，反射访问非开放模块中的内部成员还可能受到更严格的限制。也就是说，setAccessible(true) 不是一张永久通行证。把它当万能钥匙，迟早会在升级 JDK 时收到一份并不温柔的账单。

反射调用通常也比直接方法调用更难被编译器和 JIT 优化。性能不是完全不能接受，但不适合放在高频热路径里反复做查找和调用。如果确实需要，至少应缓存 Class、Constructor、Method、Field 等元数据。

六、反射和 MethodHandle

除了传统反射，Java 7 之后还提供了 java.lang.invoke.MethodHandle。它也是运行时动态调用的一套机制，但更接近 JVM 的方法调用模型，常用于动态语言、Lambda、框架底层等场景。

简单理解：

  • 反射 API 更偏“检查和操作类结构”，使用方便，语义直观。
  • MethodHandle 更偏“可组合、可优化的方法调用句柄”，门槛更高。

普通业务代码一般不需要主动使用 MethodHandle。框架或基础设施代码如果追求更细的调用控制和性能优化，才会考虑它。

七、总结

反射适合写通用框架、插件机制、注解扫描、对象映射等基础能力。业务代码里如果已经知道明确类型，应优先使用接口、多态和泛型。

反射不是不能用，而是不要把“编译期能确定的事情”推迟到运行时。能让编译器帮你发现的问题，就别抢它的工作。它平时已经够闲了。
