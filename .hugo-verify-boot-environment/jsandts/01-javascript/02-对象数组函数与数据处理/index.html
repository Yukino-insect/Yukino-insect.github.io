对象、数组、函数与数据处理：写业务逻辑的基本功

August 19, 2026

前端业务代码大部分时间都在处理数据：接口返回列表，页面需要筛选、排序、分组、格式化，再交给组件渲染。对象、数组和函数就是这件事的基本工具。

这篇文章的目标很直接：让你能把一批原始数据处理成页面需要的结构。

一、对象是业务实体

对象用来描述一组相关数据。

const post = {
  id: 1,
  title: '第一篇文章',
  author: {
    id: 10,
    name: 'Yuki'
  },
  likeCount: 12
}

读取属性：

post.title
post['title']

动态字段名时使用方括号：

const field = 'title'
console.log(post[field])

二、对象展开

对象展开常用于复制和更新。

const nextPost = {
  ...post,
  likeCount: post.likeCount + 1
}

这不会修改原对象，而是创建一个新对象。前端状态更新里经常使用这种写法，因为它更容易被框架追踪，也更容易回滚。

注意：对象展开是浅拷贝。

const copied = { ...post }
copied.author.name = 'New Name'

这里会影响原对象里的 author.name，因为内层对象仍然是同一个引用。需要深层复制时，要根据业务结构显式处理。

三、数组是列表数据

数组保存有序集合。

const posts = [
  { id: 1, title: 'A', likeCount: 3 },
  { id: 2, title: 'B', likeCount: 8 }
]

常见操作分为两类：

  • 原地修改：push、splice、sort。
  • 返回新数组：map、filter、slice、concat。

在状态管理中，优先使用返回新数组的方式，代码更可预测。

四、map 转换

map 用来把一个数组转换成另一个数组。

const options = users.map(user => ({
  label: user.nickname ?? user.username,
  value: user.id
}))

适合场景：

  • 接口字段改成组件字段。
  • 增加展示用字段。
  • 把后端结构转换成前端结构。

不要在 map 里做复杂副作用。map 的语义是转换，不是顺手改一堆外部变量。

五、filter 过滤

filter 用来保留满足条件的项。

const visiblePosts = posts.filter(post => !post.deleted)

多条件过滤：

const result = posts.filter(post => {
  const matchKeyword = post.title.includes(keyword)
  const matchAuthor = authorId ? post.authorId === authorId : true
  return matchKeyword && matchAuthor
})

复杂过滤要拆变量，否则一行表达式会像故意设置阅读障碍。

六、find 与 some

查找单个元素：

const current = posts.find(post => post.id === currentId)

判断是否存在：

const hasDraft = posts.some(post => post.status === 'draft')

判断全部满足：

const allPublished = posts.every(post => post.status === 'published')

选择方法时先问自己：我要返回元素、返回布尔值，还是返回新数组？

七、reduce 聚合

reduce 用来把数组聚合成一个结果。

统计总数：

const totalLikes = posts.reduce((sum, post) => {
  return sum + post.likeCount
}, 0)

按状态分组：

const grouped = posts.reduce((map, post) => {
  const key = post.status
  if (!map[key]) {
    map[key] = []
  }
  map[key].push(post)
  return map
}, {})

reduce 很强，但不要滥用。简单的 map 和 filter 不要强行写成 reduce，那不是高级，是给维护者增加刑罚。

八、函数是可复用逻辑

普通函数：

function formatCount(count) {
  if (count >= 10000) {
    return `${(count / 10000).toFixed(1)}w`
  }
  return String(count)
}

箭头函数：

const formatCount = count => {
  if (count >= 10000) {
    return `${(count / 10000).toFixed(1)}w`
  }
  return String(count)
}

在业务中，函数应该遵守三个原则：

  • 输入明确。
  • 输出明确。
  • 不偷偷修改外部状态。

九、纯函数

纯函数指相同输入总是得到相同输出，并且不产生外部副作用。

function addLike(post) {
  return {
    ...post,
    likeCount: post.likeCount + 1
  }
}

不纯的写法：

function addLike(post) {
  post.likeCount++
  return post
}

不纯函数并非绝对不能用，但在状态更新、测试和回滚场景中，纯函数更稳。

十、业务数据处理范式

一个常见页面的数据处理流程如下：

接口原始数据
 -> 字段归一化
 -> 过滤无效项
 -> 排序
 -> 增加展示字段
 -> 交给组件渲染

示例：

function buildPostCards(rawPosts) {
  return rawPosts
    .filter(post => post.id && post.title)
    .sort((a, b) => b.createdAt - a.createdAt)
    .map(post => ({
      id: post.id,
      title: post.title.trim(),
      summary: post.summary ?? '暂无摘要',
      authorName: post.author?.name ?? '匿名用户',
      likeText: formatCount(post.likeCount ?? 0)
    }))
}

这个函数比直接在模板里堆判断更好，因为数据整理和页面展示被分开了。

十一、练习

给定评论列表：

const comments = [
  { id: 1, userId: 10, content: '不错', deleted: false },
  { id: 2, userId: 10, content: '', deleted: false },
  { id: 3, userId: 11, content: '学习了', deleted: true }
]

请实现：

  • 过滤已删除评论。
  • 过滤空内容。
  • 按 userId 分组。
  • 每条评论增加 contentLength。

完成后你会发现，业务逻辑并不神秘。它只是对象、数组和函数的组合。真正需要警惕的是把它们写得混乱，然后假装这是复杂业务。
