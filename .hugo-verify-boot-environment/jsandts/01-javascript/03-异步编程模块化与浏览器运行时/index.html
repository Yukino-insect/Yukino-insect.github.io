异步编程、模块化与浏览器运行时：理解前端代码如何动起来

August 19, 2026

前端最容易让初学者困惑的地方是异步。用户点击、网络请求、定时器、文件读取、动画、页面渲染，这些事情不会按你写代码的视觉顺序简单执行。

这一篇解决三个问题：异步代码怎么执行，模块如何组织，浏览器到底提供了哪些运行时能力。

一、同步与异步

同步代码按顺序执行：

console.log('A')
console.log('B')
console.log('C')

输出：

A
B
C

异步代码会把某些任务交给运行环境，等结果回来后再继续。

console.log('A')

setTimeout(() => {
  console.log('B')
}, 0)

console.log('C')

输出：

A
C
B

不是 setTimeout 不守规矩，而是它本来就不是当前调用栈里的同步任务。

二、Promise

Promise 表示一个未来才会完成的结果。

const request = fetch('/api/posts')

request
  .then(response => response.json())
  .then(data => {
    console.log(data)
  })
  .catch(error => {
    console.error(error)
  })

Promise 有三种状态：

  • pending：进行中。
  • fulfilled：成功。
  • rejected：失败。

状态一旦改变，就不会再变。

三、async 与 await

async/await 让异步代码看起来像同步流程。

async function loadPosts() {
  try {
    const response = await fetch('/api/posts')
    const data = await response.json()
    return data
  } catch (error) {
    console.error('加载文章失败', error)
    return []
  }
}

注意：await 只能等待 Promise。async 函数总是返回 Promise。

async function getNumber() {
  return 1
}

getNumber().then(value => {
  console.log(value)
})

四、并发请求

多个互不依赖的请求，不要一个等一个。

const [profile, posts] = await Promise.all([
  fetchProfile(),
  fetchPosts()
])

如果其中一个失败，Promise.all 会整体失败。希望分别拿到成功或失败结果，可以使用 Promise.allSettled。

const results = await Promise.allSettled([
  fetchProfile(),
  fetchPosts()
])

五、异步错误处理

错误分为两类：

  • 技术错误：网络断开、超时、JSON 解析失败。
  • 业务错误：未登录、无权限、余额不足、参数错误。

技术错误通常靠 try...catch 捕获，业务错误通常来自接口响应字段。

async function requestJson(url) {
  const response = await fetch(url)
  const body = await response.json()

  if (!response.ok) {
    throw new Error(body.message ?? '请求失败')
  }

  return body
}

前端工程里不要让每个页面各自处理一套错误，否则提示文案、登录跳转、日志记录都会变得不一致。

六、模块化

现代前端使用 ES Module。

导出：

export function formatDate(value) {
  return new Date(value).toLocaleDateString()
}

export const defaultPageSize = 20

导入：

import { formatDate, defaultPageSize } from './date'

默认导出：

export default function request(url) {
  return fetch(url)
}

默认导入：

import request from './request'

工程中更推荐命名导出，因为重构时更容易追踪。

七、浏览器运行时能力

浏览器不仅执行 JavaScript，还提供大量 Web API。

能力 常见 API
DOM 操作 document.querySelector
网络请求 fetch、XMLHttpRequest
本地存储 localStorage、sessionStorage
定时器 setTimeout、setInterval
路由历史 history.pushState
URL 处理 URL、URLSearchParams
性能信息 performance

框架会封装很多 DOM 操作，但不会取消这些基础能力。理解它们，调试时会冷静很多。

八、事件循环简化理解

可以先用下面这个模型理解：

同步代码先执行
 -> 微任务执行
 -> 浏览器可能渲染
 -> 宏任务执行
 -> 下一轮循环

Promise 回调通常属于微任务，setTimeout 回调属于宏任务。

console.log('start')

Promise.resolve().then(() => {
  console.log('promise')
})

setTimeout(() => {
  console.log('timeout')
}, 0)

console.log('end')

输出：

start
end
promise
timeout

先掌握这个简化模型，之后再深入微任务队列、渲染时机和任务调度。学习也要讲顺序，不能一开始就把脑子扔进规范文本里。

九、工程建议

  • 异步函数要考虑成功、失败、空数据、重复请求。
  • 页面级请求要有 loading 和 error 状态。
  • 公共请求逻辑应该封装，不要复制粘贴。
  • 模块导入路径要稳定，避免层层 ../../../。
  • 能并发的请求并发，确实依赖前一步结果时再串行。

十、练习

实现一个加载首页数据的函数：

async function loadHomeData() {
  // 并发加载用户资料和文章列表
  // 任意一个失败时返回默认结构
}

参考结构：

async function loadHomeData() {
  try {
    const [profile, posts] = await Promise.all([
      fetchProfile(),
      fetchPosts()
    ])

    return {
      profile,
      posts,
      loaded: true
    }
  } catch (error) {
    return {
      profile: null,
      posts: [],
      loaded: false,
      error
    }
  }
}

这就是前端异步业务的核心：不是把请求发出去就结束，而是把不确定的结果整理成页面能表达的状态。
