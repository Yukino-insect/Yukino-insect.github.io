模板字符串详解：反引号、变量插值、多行文本与标签模板

August 20, 2026

模板字符串是 JavaScript 里很常用、也很容易被轻视的语法。它用反引号包裹字符串，支持变量插值、多行文本和标签模板。

看起来只是少写几个加号，但真正的价值不止如此。它让“字符串中混入数据”这件事变得更清楚，也让复杂文本、请求地址、日志、HTML 片段等场景更容易维护。当然，如果用得随意，它也会很安静地制造安全问题。语法本身没有错，错的是人类总觉得自己不会犯错，这一点倒是很稳定。

一、普通字符串的问题

在模板字符串出现之前，拼接字符串通常使用 +。

const name = 'Yuki'
const age = 18

const text = '姓名：' + name + '，年龄：' + age

这段代码能运行，但当变量变多、文本变长后，可读性会迅速下降。

const message =
  '用户 ' +
  user.name +
  ' 在 ' +
  formatDate(order.createdAt) +
  ' 创建了订单，订单金额为 ' +
  order.amount +
  ' 元'

问题不在于 + 不能用，而是它把文本内容和拼接符号混在一起，读者需要在引号、变量、加号之间来回跳。代码不是障碍跑，没必要这样训练眼球。

二、模板字符串基础语法

模板字符串使用反引号：

const name = 'Yuki'
const age = 18

const text = `姓名：${name}，年龄：${age}`

console.log(text)

输出：

姓名：Yuki，年龄：18

${} 里面可以放 JavaScript 表达式。表达式会先计算，再转换成字符串插入当前位置。

const count = 3

console.log(`你有 ${count} 条消息`)
console.log(`下一页是第 ${count + 1} 页`)

模板字符串由两部分组成：

  • 反引号包住整体文本。
  • ${表达式} 插入动态内容。

三、插入表达式

${} 中可以写变量：

const title = 'JavaScript'

const text = `正在学习 ${title}`

可以写运算：

const price = 100
const count = 2

const text = `总价：${price * count} 元`

可以写函数调用：

const createdAt = '2026-08-20T18:24:00+08:00'

const text = `创建时间：${formatDate(createdAt)}`

可以写三元表达式：

const enabled = true

const text = `当前状态：${enabled ? '启用' : '禁用'}`

但不要在 ${} 里塞太复杂的逻辑。

不推荐：

const text = `展示名：${user.nickname?.trim() ? user.nickname.trim() : user.username ? user.username : '匿名用户'}`

推荐：

const displayName = user.nickname?.trim() || user.username || '匿名用户'
const text = `展示名：${displayName}`

模板字符串是为了让字符串更清楚，不是为了把业务逻辑偷偷藏进去。

四、值如何转换成字符串

插值表达式的结果会被转换成字符串。

console.log(`${123}`) // '123'
console.log(`${true}`) // 'true'
console.log(`${null}`) // 'null'
console.log(`${undefined}`) // 'undefined'

对象会调用自己的字符串转换逻辑。

const user = {
  id: 1,
  name: 'Yuki'
}

console.log(`用户：${user}`)

输出：

用户：[object Object]

如果要展示对象，应该显式序列化：

console.log(`用户：${JSON.stringify(user)}`)

日志里尤其要注意这一点。[object Object] 不是信息，它只是对象在用最简短的方式表示自己拒绝沟通。

五、多行字符串

模板字符串可以自然书写多行文本。

const message = `第一行
第二行
第三行`

输出中会保留换行：

第一行
第二行
第三行

这比普通字符串拼接更直观。

const message =
  '第一行\n' +
  '第二行\n' +
  '第三行'

多行模板适合：

  • 构造长日志。
  • 构造邮件正文。
  • 构造 Markdown 文本。
  • 构造测试用例中的大段输入。
  • 构造少量 HTML 片段。

六、多行缩进问题

模板字符串会保留你写下的空格和换行。

function buildMessage(name) {
  return `
    你好，${name}
    欢迎回来
  `
}

这个字符串开头有一个换行，每一行前面也有空格。实际内容不是你肉眼以为的那样干净。

可以这样写得更明确：

function buildMessage(name) {
  return [
    `你好，${name}`,
    '欢迎回来'
  ].join('\n')
}

或者在确实需要多行文本时，把缩进控制好：

const markdown = `# 标题

这是第一段。

这是第二段。`

在代码里写多行文本时，要意识到空白字符也是字符串内容的一部分。它不会因为你觉得它只是排版，就体贴地消失。

七、反引号和特殊字符

模板字符串中如果要写反引号，需要转义。

const text = `这里有一个反引号：\``

如果要写 ${ 本身，也需要避免被当成插值语法。

const text = `模板插值写作：\${name}`

输出：

模板插值写作：${name}

常见转义字符仍然可用：

const text = `第一行\n第二行`

不过如果你已经使用多行模板字符串，就不一定需要手写 \n。

八、构造 URL

模板字符串常用于构造 URL。

const id = 10
const url = `/api/posts/${id}`

但查询参数不建议直接拼接。

可以写：

const keyword = 'JavaScript'
const page = 1

const url = `/api/posts?keyword=${keyword}&page=${page}`

但更稳的写法是：

const params = new URLSearchParams({
  keyword,
  page: String(page)
})

const url = `/api/posts?${params.toString()}`

原因是查询参数可能包含中文、空格、&、? 等特殊字符。URLSearchParams 会处理编码问题。

如果只拼路径片段，模板字符串很合适；如果拼查询参数，优先用结构化 API。

九、构造日志

模板字符串非常适合让日志更清楚。

function logRequest(method, url, status, duration) {
  console.log(`[request] ${method} ${url} ${status} ${duration}ms`)
}

输出：

[request] GET /api/posts 200 83ms

如果日志字段较多，可以先整理变量：

const method = 'POST'
const url = '/api/posts'
const status = 201
const duration = 126

console.log(`[api] ${method} ${url} -> ${status}, cost=${duration}ms`)

日志的关键是可定位。模板字符串不是为了写得像句子，而是为了让关键信息出现在稳定位置。

十、构造 HTML 片段

模板字符串可以构造 HTML。

function renderUser(user) {
  return `
    <article class="user-card">
      <h2>${user.name}</h2>
      <p>${user.bio}</p>
    </article>
  `
}

但这里有一个重要风险：不要直接把不可信用户输入插入 HTML。

如果 user.bio 是：

<img src="x" onerror="alert('xss')">

直接插入页面可能造成 XSS。

危险写法：

container.innerHTML = renderUser(user)

更稳的写法是使用 DOM API 设置文本：

function mountUser(container, user) {
  const article = document.createElement('article')
  const title = document.createElement('h2')
  const bio = document.createElement('p')

  article.className = 'user-card'
  title.textContent = user.name
  bio.textContent = user.bio

  article.append(title, bio)
  container.append(article)
}

textContent 会把内容当作文本，而不是 HTML 执行。

模板字符串可以生成 HTML，但不能替你判断数据是否可信。安全问题不会因为语法好看就自动消失，真遗憾。

十一、构造 CSS 字符串

模板字符串也常用于动态样式。

const width = 120
const color = '#3b82f6'

const style = `
  width: ${width}px;
  color: ${color};
`

在框架里，通常不建议大量拼 CSS 字符串。更常见的方式是使用 class、style 对象或 CSS 变量。

例如：

element.style.setProperty('--card-width', `${width}px`)

模板字符串适合生成简单样式值：

const transform = `translateX(${x}px) translateY(${y}px)`

但如果整段 CSS 都靠字符串拼出来，维护成本会很快升高。

十二、模板字符串与数组方法

模板字符串经常和 map、join 配合使用。

const users = [
  { id: 1, name: 'Yuki' },
  { id: 2, name: 'Hachiman' }
]

const html = users
  .map(user => `<li data-id="${user.id}">${user.name}</li>`)
  .join('')

生成：

<li data-id="1">Yuki</li><li data-id="2">Hachiman</li>

如果需要换行，可以：

const text = users
  .map(user => `- ${user.name}`)
  .join('\n')

输出：

- Yuki
- Hachiman

这在生成 Markdown、命令行输出、简单报表时很有用。

十三、标签模板

模板字符串还有一种进阶用法：标签模板。

function tag(strings, ...values) {
  console.log(strings)
  console.log(values)
}

const name = 'Yuki'
const age = 18

tag`姓名：${name}，年龄：${age}`

这行代码看起来像函数名后面直接跟了一个模板字符串：

tag`姓名：${name}，年龄：${age}`

它不是普通函数调用：

tag(`姓名：${name}，年龄：${age}`)

普通函数调用会先把模板字符串拼成一个完整字符串，然后把这个字符串作为参数传给函数。

标签模板不同。它会把模板拆成两类信息传给 tag：

  • strings：静态字符串片段数组。
  • values：插值表达式的结果。

对于：

tag`姓名：${name}，年龄：${age}`

静态片段是：

['姓名：', '，年龄：', '']

插值结果是：

['Yuki', 18]

所以它大致可以理解成一次特殊调用：

tag(['姓名：', '，年龄：', ''], name, age)

真实运行时第一个参数不是普通手写数组，而是模板对象；学习阶段先这样理解就够了。

函数内部：

function tag(strings, ...values) {
  console.log(strings)
  console.log(values)
}

strings 接收第一个参数。

...values 是剩余参数，负责把后面的所有插值结果收集成数组。

也就是说：

strings[0] // '姓名：'
strings[1] // '，年龄：'
strings[2] // ''

values[0] // 'Yuki'
values[1] // 18

标签模板不是普通函数调用的花哨写法，它能在字符串最终拼接前处理静态片段和动态值。

十四、标签模板如何重新拼接

标签函数可以自己决定最终返回什么。

function tag(strings, ...values) {
  let result = ''

  for (let i = 0; i < strings.length; i++) {
    result += strings[i]

    if (i < values.length) {
      result += values[i]
    }
  }

  return result
}

const name = 'Yuki'
const age = 18

const text = tag`姓名：${name}，年龄：${age}`

console.log(text)

输出：

姓名：Yuki，年龄：18

这里的拼接规律是：

strings[0]
 -> values[0]
 -> strings[1]
 -> values[1]
 -> strings[2]

静态片段数量总是比插值数量多 1。

`A${x}B${y}C`

strings -> ['A', 'B', 'C']
values  -> [x, y]

如果模板以插值结尾，最后一个静态片段就是空字符串。

tag`姓名：${name}`

对应：

strings = ['姓名：', '']
values = ['Yuki']

这个空字符串不是多余错误，而是为了让“静态片段数量比插值数量多 1”这个结构保持稳定。

十五、strings.raw

标签模板的 strings 参数还有一个 raw 属性，可以看到未处理转义的原始字符串片段。

function tag(strings, ...values) {
  console.log(strings[0])
  console.log(strings.raw[0])
}

tag`第一行\n第二行`

输出含义大致是：

strings[0]     -> 包含真实换行符
strings.raw[0] -> 包含反斜杠和 n 两个字符

这也是 String.raw 能工作的基础。普通业务里不常直接用 strings.raw，但理解它有助于看懂标签模板为什么能处理路径、正则、DSL 文本。

十六、标签模板的实际用途

标签模板常用于：

  • SQL 构造。
  • HTML 转义。
  • CSS-in-JS。
  • 国际化文本。
  • GraphQL 查询。

例如实现一个简单 HTML 转义标签：

function escapeHtml(value) {
  return String(value)
    .replaceAll('&', '&amp;')
    .replaceAll('<', '&lt;')
    .replaceAll('>', '&gt;')
    .replaceAll('"', '&quot;')
    .replaceAll("'", '&#39;')
}

function html(strings, ...values) {
  return strings.reduce((result, string, index) => {
    const value = values[index] === undefined ? '' : escapeHtml(values[index])
    return result + string + value
  }, '')
}

使用：

const userInput = '<script>alert(1)</script>'

const output = html`<p>${userInput}</p>`

console.log(output)

输出：

<p>&lt;script&gt;alert(1)&lt;/script&gt;</p>

这只是教学示例。真实项目中的安全处理应该使用成熟库或框架能力，不要因为写了几行转义函数就觉得自己已经赢过了所有攻击者。傲慢通常比较贵。

十七、String.raw

String.raw 是一个内置标签函数，可以获取原始字符串内容。

const path = String.raw`C:\Users\name\documents`

console.log(path)

输出：

C:\Users\name\documents

普通模板字符串中，反斜杠可能被当成转义字符处理。String.raw 会保留原始反斜杠。

它适合：

  • Windows 路径示例。
  • 正则表达式说明。
  • 需要保留反斜杠的文本。

不要滥用。大多数业务字符串用普通模板字符串就够了。

十八、和普通字符串的选择

不是所有字符串都要写成模板字符串。

推荐使用普通引号：

const status = 'success'
const emptyText = '暂无数据'

推荐使用模板字符串：

const message = `欢迎回来，${user.name}`
const url = `/api/posts/${id}`
const log = `[request] ${method} ${url} ${status}`

判断标准很简单：

  • 没有变量、没有多行，用普通字符串。
  • 有变量插值，用模板字符串。
  • 有多行文本，用模板字符串或数组 join。
  • 需要特殊处理插值内容，可以考虑标签模板。

十九、常见误区

1. 用单引号写插值

错误：

const name = 'Yuki'
const text = '你好，${name}'

输出：

你好，${name}

正确：

const text = `你好，${name}`

只有反引号才支持 ${} 插值。

2. 在插值里写太多逻辑

不推荐：

const text = `${list.filter(item => item.visible).map(item => item.name).join(', ')}`

推荐：

const visibleNames = list
  .filter(item => item.visible)
  .map(item => item.name)
  .join(', ')

const text = `可见用户：${visibleNames}`

逻辑拆出来后更容易调试，也更容易复用。

3. 忽略空值

const user = {
  name: undefined
}

console.log(`用户名：${user.name}`)

输出：

用户名：undefined

如果页面上不应该展示 undefined，就要给默认值。

const name = user.name ?? '匿名用户'
const text = `用户名：${name}`

4. 直接拼接不可信 HTML

危险：

const html = `<p>${comment.content}</p>`
container.innerHTML = html

如果 comment.content 来自用户输入，就要考虑 XSS。能用 textContent 时优先用 textContent；必须渲染 HTML 时，使用可信的清洗方案。

二十、练习

实现一个 buildPostSummary(post) 函数，返回文章摘要文本。

要求：

  • 标题为空时使用 未命名文章。
  • 作者为空时使用 匿名用户。
  • 点赞数为空时使用 0。
  • 时间通过 formatDate(post.createdAt) 格式化。

参考结构：

function buildPostSummary(post) {
  const title = post.title?.trim() || '未命名文章'
  const authorName = post.author?.name ?? '匿名用户'
  const likeCount = post.likeCount ?? 0
  const createdDate = formatDate(post.createdAt)

  return `《${title}》由 ${authorName} 发布于 ${createdDate}，当前有 ${likeCount} 个赞。`
}

再实现一个生成 Markdown 列表的函数：

function buildPostMarkdown(posts) {
  return posts
    .map(post => {
      const title = post.title?.trim() || '未命名文章'
      return `- ${title}：${post.summary ?? '暂无摘要'}`
    })
    .join('\n')
}

模板字符串的重点不是“反引号比加号高级”。它真正解决的是：当静态文本和动态数据混在一起时，让代码仍然保持清楚、稳定、可维护。至于安全和边界处理，那就不是语法糖能替你完成的事了。
