可选链、问号与空值合并：JavaScript 如何处理 null 和 undefined

August 20, 2026

JavaScript 里有两个非常常见的空值：null 和 undefined。

  • null：通常表示“这里明确没有值”。
  • undefined：通常表示“这里还没有被赋值”或“属性不存在”。

现代 JavaScript 提供了几个很实用的语法来处理空值：可选链 ?.、空值合并 ??、空值赋值 ??=，以及条件运算符 ? :。它们都带问号，但含义并不一样。只看符号，很容易把它们混成一团。语法本身倒是不复杂，复杂的是人类总喜欢用同一个符号表达好几件事。

一、null 和 undefined

先看两个值的区别。

let a
const b = null

console.log(a) // undefined
console.log(b) // null

undefined 常见于：

let value

const user = {}

function demo(name) {
  console.log(name)
}

console.log(value) // undefined
console.log(user.name) // undefined
demo() // name 是 undefined

null 常见于：

const selectedUser = null

它通常是开发者主动赋的值，用来表示“现在没有选中用户”“查询结果为空”“弹窗当前没有数据”。

在工程里可以粗略这样理解：

undefined -> 没给、没有、还不存在
null      -> 明确为空

但这只是常见约定，不是强制规则。接口返回、第三方库和旧代码可能并不这么讲究，所以使用数据前仍然要处理边界。

二、为什么访问空值会报错

普通属性访问：

const user = null

console.log(user.name)

会报错：

TypeError: Cannot read properties of null

原因很简单：null 不是对象，不能继续读取它的属性。

再看一个更真实的结构：

const post = {
  id: 1,
  author: null
}

console.log(post.author.name)

post 存在，author 是 null，继续访问 author.name 就会报错。

过去常见写法是逐层判断：

const authorName = post && post.author && post.author.name

这能避免报错，但可读性一般，而且对 0、空字符串、false 这种 falsy 值并不总是友好。

三、可选链 ?.

可选链的作用是：如果左侧是 null 或 undefined，就停止继续访问，并返回 undefined。

const post = {
  id: 1,
  author: null
}

const authorName = post.author?.name

console.log(authorName) // undefined

这行代码可以理解成：

const authorName = post.author == null
  ? undefined
  : post.author.name

这里使用 == null 是有意的，因为：

value == null

只会同时匹配：

null
undefined

可选链只关心 null 和 undefined，不会因为 0、''、false 停止。

const data = {
  count: 0,
  enabled: false,
  title: ''
}

console.log(data.count?.toString()) // '0'
console.log(data.enabled?.toString()) // 'false'
console.log(data.title?.length) // 0

这点很重要。可选链不是“遇到假值就停止”，而是“遇到空值才停止”。

四、属性、索引和函数调用

可选链有几种常见形式。

访问属性

const city = user.profile?.address?.city

如果 profile 或 address 是 null / undefined，表达式返回 undefined。

访问动态属性

const key = 'name'
const value = user?.[key]

?.[] 适合属性名来自变量的情况。

访问数组元素

const firstName = users?.[0]?.name

如果 users 不存在，或者第一个元素不存在，都不会报错。

调用函数

onSuccess?.(result)

如果 onSuccess 是 null 或 undefined，不会调用；如果它存在，就调用。

这在可选回调里很常见：

function submitForm(input, options = {}) {
  const result = save(input)

  options.onSuccess?.(result)

  return result
}

注意：fn?.() 只是在 fn 为 null / undefined 时跳过。如果 fn 存在但不是函数，仍然会报错。

const fn = 'not function'

fn?.() // TypeError

它并不会替你把字符串变成函数。JavaScript 已经很宽容了，不必期待它无条件纵容。

五、可选链的短路范围

可选链会短路后续链式访问。

const value = user.profile?.address.city

如果 user.profile 是 null，整个表达式返回 undefined，不会继续访问 address.city。

但如果你用括号中断链条，就不同了：

const value = (user.profile?.address).city

如果 user.profile 是 null，括号里的结果是 undefined，然后外面继续访问 .city，仍然会报错。

所以可选链要写在每个可能为空的访问点上：

const value = user.profile?.address?.city

不要为了少写一个 ?. 把代码写成猜谜。报错时它不会感谢你的节省。

六、空值合并 ??

?? 用来提供默认值。

它的规则是：左侧只有在 null 或 undefined 时，才使用右侧默认值。

const name = user.name ?? '匿名用户'

等价理解：

const name = user.name == null ? '匿名用户' : user.name

它和 || 很像，但边界不同。

const count1 = 0 || 10
const count2 = 0 ?? 10

console.log(count1) // 10
console.log(count2) // 0

|| 会把所有 falsy 值都当作需要兜底：

  • false
  • 0
  • ''
  • NaN
  • null
  • undefined

?? 只处理：

  • null
  • undefined

所以当 0、空字符串、false 是合法值时，应该优先使用 ??。

七、?? 的典型场景

数字默认值

const pageSize = input.pageSize ?? 20

如果 pageSize 是 0，它会保留 0。这是否合理取决于业务，但至少 ?? 不会偷偷把它改成 20。

文本默认值

const nickname = user.nickname ?? '匿名用户'

如果空字符串也应该兜底，需要用业务判断：

const nickname = user.nickname?.trim() || '匿名用户'

这里使用 || 是合理的，因为空字符串确实被视为无效展示名。

布尔默认值

const enabled = config.enabled ?? true

如果用户明确传入 false，结果就是 false。这正是 ?? 比 || 更适合布尔配置的原因。

const enabled = config.enabled || true

上面这种写法会把 false 也改成 true，通常是 bug。

八、可选链和空值合并一起用

最常见组合：

const city = user.profile?.address?.city ?? '未知城市'

含义是：

如果 user.profile.address.city 能拿到值，就使用它
如果中间任何一层是 null / undefined，或者 city 本身是 null / undefined，就使用默认值

再看一个接口响应例子：

function normalizePost(raw) {
  return {
    id: raw.id,
    title: raw.title?.trim() || '未命名文章',
    authorName: raw.author?.name ?? '匿名用户',
    likeCount: raw.stats?.likeCount ?? 0
  }
}

这里刻意用了两种默认策略：

  • title?.trim() || '未命名文章'：空字符串也要兜底。
  • likeCount ?? 0：0 是合法值，不能被兜底覆盖。

空值处理不是死背 ?? 比 || 高级，而是判断哪些值在业务上有效。

九、空值赋值 ??=

??= 表示：左侧为 null 或 undefined 时才赋值。

const config = {}

config.timeout ??= 3000

console.log(config.timeout) // 3000

如果已有值不是空值，就保留：

const config = {
  timeout: 0
}

config.timeout ??= 3000

console.log(config.timeout) // 0

它适合给配置对象补默认值：

function applyDefaultOptions(options) {
  options.timeout ??= 3000
  options.retry ??= 2
  options.enabled ??= true

  return options
}

如果不想修改原对象，可以创建新对象：

function normalizeOptions(options = {}) {
  return {
    timeout: options.timeout ?? 3000,
    retry: options.retry ?? 2,
    enabled: options.enabled ?? true
  }
}

工程里更推荐后者，因为它不会悄悄改变传入对象。

十、条件运算符 ? :

单独的 ? 最常见于条件运算符：

const text = isLogin ? '已登录' : '未登录'

结构是：

条件 ? 条件成立时的值 : 条件不成立时的值

它和空值处理没有必然关系，但经常被一起使用。

const displayName = user
  ? user.name ?? '匿名用户'
  : '游客'

如果逻辑很短，条件运算符很清楚。如果嵌套太多，就应该拆开。

不推荐：

const text = user ? user.vip ? 'VIP 用户' : user.name ? user.name : '普通用户' : '游客'

推荐：

let text = '游客'

if (user) {
  text = user.vip
    ? 'VIP 用户'
    : user.name || '普通用户'
}

短不是唯一价值。可读性也不是会自己从压缩代码里爬出来的。

十一、TypeScript 里的 ?

如果你在 TypeScript 中看到：

type User = {
  name?: string
}

这里的 ? 表示可选属性。它是 TypeScript 类型语法，不是 JavaScript 运行时语法。

函数参数也可以写：

function greet(name?: string) {
  console.log(name ?? '匿名用户')
}

同样，这是 TypeScript 的类型标注。编译成 JavaScript 后，? 不会作为运行时逻辑保留。

JavaScript 处理空值靠的是运行时表达式：

user?.name
user.name ?? '匿名用户'

TypeScript 的 ? 只是帮你在类型层面表达“这个字段可能不存在”。

十二、JS 是通过这些来应对 null 的吗

可以说：现代 JavaScript 很大程度上通过 ?. 和 ?? 改善了空值访问和默认值处理。

但它们不是完整的空值方案。

它们能解决：

  • 访问深层属性时报错。
  • 给 null / undefined 提供默认值。
  • 可选回调调用。
  • 配置对象补默认值。

它们不能解决：

  • 接口返回结构完全错误。
  • 字段类型不对。
  • 空字符串是否有效这种业务判断。
  • 数组为空但仍然访问第一个元素。
  • 需要运行时校验的数据安全问题。

例如：

const count = response.data?.count ?? 0

如果后端返回：

{
  "data": {
    "count": "many"
  }
}

?. 和 ?? 不会报错，但 count 是字符串，不是数字。

更稳的代码仍然需要校验：

const rawCount = response.data?.count
const count = typeof rawCount === 'number' ? rawCount : 0

可选链和空值合并是很好的工具，但不是类型系统，也不是数据校验库。指望两个运算符接管所有边界问题，未免有些过度信任标点符号。

十三、常见误区

1. 把 ?? 当成 ||

const title = post.title ?? '未命名'

如果 post.title 是空字符串，结果仍然是空字符串。

如果空字符串也要兜底：

const title = post.title?.trim() || '未命名'

2. 忘记中间层也可能为空

const city = user.profile.address?.city

这里只保护了 address，没有保护 profile。

更稳：

const city = user.profile?.address?.city

3. 可选链不能用于赋值左侧

错误：

user.profile?.name = 'Yuki'

因为如果 profile 不存在，赋值目标就不存在。

应该先判断或初始化：

if (user.profile) {
  user.profile.name = 'Yuki'
}

或：

user.profile ??= {}
user.profile.name = 'Yuki'

4. 过度使用可选链

const id = order?.user?.profile?.account?.id

如果业务上 order.user.profile.account.id 必须存在，过度可选链会掩盖数据错误。你以为代码更安全，其实只是让错误更安静。

关键数据缺失时，有时应该直接抛错：

if (!order.user) {
  throw new Error('订单缺少用户信息')
}

沉默不是稳定。沉默有时只是错误还没被发现。

十四、练习

把下面代码改成更稳的空值处理：

function getUserSummary(user) {
  return user.profile.name + ' / ' + user.profile.age + ' / ' + user.settings.theme
}

参考写法：

function getUserSummary(user) {
  const name = user.profile?.name?.trim() || '匿名用户'
  const age = user.profile?.age ?? '未知年龄'
  const theme = user.settings?.theme ?? 'default'

  return `${name} / ${age} / ${theme}`
}

再判断下面输出：

console.log(0 || 10)
console.log(0 ?? 10)
console.log('' || 'default')
console.log('' ?? 'default')
console.log(false || true)
console.log(false ?? true)

结果：

10
0
default

true
false

其中第四行输出空字符串，所以视觉上是一行空白。

记住一句话就够了：

?. 负责安全访问，?? 负责只在空值时兜底，? : 负责条件分支。它们都带问号，但并不是同一种问法。
