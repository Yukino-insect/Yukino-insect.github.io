展开语法与剩余参数：理解 JavaScript 中的三个点

August 20, 2026

JavaScript 里的 ... 经常让人困惑，因为它在不同位置表示相反方向的动作。

函数调用里：

fn(...values)

意思是把数组展开成多个参数。

函数定义里：

function fn(...values) {
  console.log(values)
}

意思是把多个参数收集成一个数组。

同样是三个点，一个负责“拆开”，一个负责“收起来”。如果只记符号，不看位置，当然会乱。这不是你的错，至少不全是。语法设计偶尔也会把人当作记忆力很好的生物。

一、函数调用中的展开

先看函数调用。

function add(a, b, c) {
  return a + b + c
}

const numbers = [1, 2, 3]

console.log(add(...numbers)) // 6

这里：

add(...numbers)

等价于：

add(1, 2, 3)

...numbers 把数组中的元素展开为一个个位置参数。

过去可能会用：

add.apply(null, numbers)

现代代码里，展开语法更直观。

二、函数定义中的剩余参数

再看函数定义。

function tag(strings, ...values) {
  console.log(strings)
  console.log(values)
}

这里的 ...values 不是展开，而是剩余参数。

它的意思是：把前面参数接收完之后，剩下的所有实参收集到 values 数组里。

function log(first, ...rest) {
  console.log(first)
  console.log(rest)
}

log('A', 'B', 'C', 'D')

输出：

A
['B', 'C', 'D']

函数内部：

first === 'A'
rest  === ['B', 'C', 'D']

注意，rest 是真正的数组，可以直接使用 map、filter、reduce。

function sum(...numbers) {
  return numbers.reduce((total, value) => total + value, 0)
}

console.log(sum(1, 2, 3)) // 6

三、剩余参数必须放在最后

剩余参数只能放在参数列表最后。

正确：

function fn(a, b, ...rest) {
  console.log(a, b, rest)
}

错误：

function fn(...rest, last) {
  console.log(rest, last)
}

原因很简单：...rest 会收集剩下所有参数。如果它后面还有参数，JavaScript 就不知道该给后面的参数留下多少个。机器虽然能算很多东西，但它不负责读心。

四、剩余参数和 arguments

早期 JavaScript 常用 arguments 获取所有参数。

function sum() {
  let total = 0

  for (const value of arguments) {
    total += value
  }

  return total
}

arguments 看起来像数组，但不是普通数组。它没有数组方法：

function demo() {
  arguments.map // undefined
}

剩余参数更推荐：

function sum(...numbers) {
  return numbers.reduce((total, value) => total + value, 0)
}

它的优点：

  • 是真正数组。
  • 参数含义更明确。
  • 可以只收集剩余部分。
  • 适合箭头函数。

箭头函数没有自己的 arguments：

const sum = (...numbers) => {
  return numbers.reduce((total, value) => total + value, 0)
}

所以现代代码中优先使用剩余参数。

五、调用处展开，定义处收集

看一个完整例子：

function target(a, b, c) {
  console.log(a, b, c)
}

function wrapper(...args) {
  target(...args)
}

wrapper(1, 2, 3)

这里有两个 ...args：

function wrapper(...args)

这是函数定义，表示收集：

args === [1, 2, 3]

然后：

target(...args)

这是函数调用，表示展开：

target(1, 2, 3)

所以这段代码的核心是：

外部散着传进来
 -> wrapper 收集成数组
 -> target 调用时再展开

装饰器、事件包装、日志包装、请求代理里经常看到这种写法。

六、数组字面量中的展开

... 也可以出现在数组字面量中。

const a = [1, 2]
const b = [3, 4]

const result = [...a, ...b, 5]

console.log(result) // [1, 2, 3, 4, 5]

常见用途：

复制数组

const copy = [...items]

这是浅拷贝。数组本身是新的，但内部对象仍然是同一个引用。

const users = [{ name: 'Yuki' }]
const copy = [...users]

copy[0].name = 'Changed'

console.log(users[0].name) // Changed

如果内部对象也要复制，需要更明确的处理。

添加元素

const next = [...items, newItem]

合并数组

const all = [...left, ...right]

把字符串展开成字符

const chars = [...'abc']

console.log(chars) // ['a', 'b', 'c']

数组展开要求右侧是可迭代对象。

const value = 123

const result = [...value] // TypeError

数字不可迭代，所以不能展开。

七、对象字面量中的展开

对象也支持展开。

const base = {
  page: 1,
  pageSize: 20
}

const query = {
  ...base,
  keyword: 'JavaScript'
}

结果：

{
  page: 1,
  pageSize: 20,
  keyword: 'JavaScript'
}

如果属性重复，后面的覆盖前面的。

const config = {
  timeout: 3000,
  retry: 2,
  timeout: 1000
}

console.log(config.timeout) // 1000

对象展开也是浅拷贝。

const user = {
  name: 'Yuki',
  profile: {
    city: 'Tokyo'
  }
}

const copy = {
  ...user
}

copy.profile.city = 'Kyoto'

console.log(user.profile.city) // Kyoto

不要把对象展开误认为深拷贝。它只是复制第一层属性。

八、剩余属性与剩余元素

... 还可以用于解构赋值里的“剩余部分”。

数组：

const [first, ...rest] = [1, 2, 3, 4]

console.log(first) // 1
console.log(rest) // [2, 3, 4]

对象：

const user = {
  id: 1,
  name: 'Yuki',
  age: 18
}

const { id, ...profile } = user

console.log(id) // 1
console.log(profile) // { name: 'Yuki', age: 18 }

这里的 ...rest 同样是收集剩余内容，而不是展开。

你可以把规则记成：

在“创建新值”或“调用函数”时，... 多半是展开
在“接收数据”时，... 多半是收集

例如：

const next = [...items] // 创建数组，展开
fn(...args) // 调用函数，展开

function fn(...args) {} // 定义函数，收集
const [first, ...rest] = items // 解构接收，收集

九、tag(strings, …values) 中的 values

回到你提到的例子：

function tag(strings, ...values) {
  console.log(strings)
  console.log(values)
}

这里的 ...values 是剩余参数，表示：

第一个参数由 strings 接收
后面所有参数收集进 values 数组

如果普通调用：

tag(['姓名：', '，年龄：', ''], 'Yuki', 18)

函数内部就是：

strings === ['姓名：', '，年龄：', '']
values === ['Yuki', 18]

标签模板调用：

tag`姓名：${name}，年龄：${age}`

本质上也是让 tag 函数接收这些参数，只是参数由模板字符串语法自动拆出来。

所以在这个函数定义中，...values 不是“把输入展开”，而是“把多个输入收集为数组”。展开发生在调用处，收集发生在定义处。位置不同，方向相反。

十、常见误区

1. 以为 ... 永远是展开

function fn(...args) {}

这是收集。

fn(...args)

这是展开。

同一个符号，不同位置。JavaScript 没有帮你换个符号，只能靠我们自己清醒一点。

2. 以为对象展开是深拷贝

const copy = { ...user }

这只是浅拷贝。嵌套对象仍然共享引用。

3. 剩余参数后面继续写参数

错误：

function fn(...args, options) {}

剩余参数必须是最后一个参数。

4. 把数组展开传给参数数量固定的函数

function createUser(name, age) {
  return { name, age }
}

const values = ['Yuki', 18, 'extra']

createUser(...values)

多出来的参数不会自动报错，它只是被函数忽略。这可能掩盖数据结构错误。

十一、练习

实现一个日志包装函数：

function withLog(fn) {
  return function (...args) {
    console.log('args:', args)
    const result = fn(...args)
    console.log('result:', result)
    return result
  }
}

使用：

function add(a, b) {
  return a + b
}

const loggedAdd = withLog(add)

loggedAdd(1, 2)

再判断下面每个 ... 是展开还是收集：

function fn(...args) {}

fn(...items)

const next = [...items, value]

const [first, ...rest] = items

const user = { ...baseUser, name: 'Yuki' }

const { id, ...profile } = user

答案：

function fn(...args)           -> 收集
fn(...items)                   -> 展开
[...items, value]              -> 展开
[first, ...rest] = items       -> 收集
{ ...baseUser, name: 'Yuki' }  -> 展开
{ id, ...profile } = user      -> 收集

记住方向即可：

调用处和字面量里通常是展开；函数定义和解构接收里通常是收集。
