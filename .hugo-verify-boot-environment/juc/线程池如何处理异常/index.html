线程池如何处理异常

March 21, 2026

线程池中的异常处理，最容易被 execute 和 submit 的差异绊倒。两者都能提交任务，但异常传播方式完全不同。

一、execute 的异常

使用 execute() 提交 Runnable 时，任务抛出的未捕获异常会从工作线程中抛出：

executor.execute(() -> {
    throw new RuntimeException("execute failed");
});

如果线程设置了 UncaughtExceptionHandler，可以在这里捕获到异常。否则异常通常会被打印到标准错误输出，当前工作线程会结束，线程池再按需补充新的工作线程。

二、submit 的异常

使用 submit() 提交任务时，异常会被封装到返回的 Future 中：

Future<?> future = executor.submit(() -> {
    throw new RuntimeException("submit failed");
});

try {
    future.get();
} catch (ExecutionException e) {
    Throwable cause = e.getCause();
    cause.printStackTrace();
}

如果从不调用 future.get()，这个异常就很容易被静默吞掉。它不是没发生，只是被安静地收进 FutureTask 里了。并发代码里这种“安静”通常不是什么美德。

三、任务内部处理

最稳妥的方式，是在任务边界捕获异常并记录必要上下文：

executor.execute(() -> {
    try {
        doBusiness();
    } catch (Exception e) {
        log.error("Async task failed, taskId={}", taskId, e);
    }
});

这种方式适合业务任务，因为日志里可以带上业务标识、请求参数、用户信息等排障所需内容。

四、线程工厂设置异常处理器

可以通过 ThreadFactory 给线程设置名称和未捕获异常处理器：

ThreadFactory threadFactory = new ThreadFactory() {
    private final AtomicInteger index = new AtomicInteger(1);

    @Override
    public Thread newThread(Runnable r) {
        Thread thread = new Thread(r, "biz-worker-" + index.getAndIncrement());
        thread.setUncaughtExceptionHandler((t, e) -> {
            log.error("Uncaught exception in {}", t.getName(), e);
        });
        return thread;
    }
};

这对 execute 有效，但对 submit 不够。因为 submit 的异常被 FutureTask 捕获了，不会直接变成线程的未捕获异常。

五、重写 afterExecute

如果想在线程池层面对异常做统一兜底，可以继承 ThreadPoolExecutor 并重写 afterExecute：

ThreadPoolExecutor executor = new ThreadPoolExecutor(
        4,
        8,
        60,
        TimeUnit.SECONDS,
        new ArrayBlockingQueue<>(200),
        threadFactory,
        new ThreadPoolExecutor.AbortPolicy()
) {
    @Override
    protected void afterExecute(Runnable r, Throwable t) {
        super.afterExecute(r, t);

        Throwable error = t;
        if (error == null && r instanceof Future<?>) {
            try {
                Future<?> future = (Future<?>) r;
                if (future.isDone()) {
                    future.get();
                }
            } catch (CancellationException e) {
                error = e;
            } catch (ExecutionException e) {
                error = e.getCause();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }

        if (error != null) {
            log.error("Thread pool task failed", error);
        }
    }
};

这个写法能同时处理 execute 和 submit。但它仍然只是兜底，业务上下文最好还是在任务内部记录。

六、实践建议

  • 业务异步任务优先在任务内部捕获异常并记录上下文。
  • 使用 submit 时一定要处理返回的 Future，否则异常可能被隐藏。
  • 线程工厂要设置可读线程名，排查问题时能省很多时间。
  • afterExecute 可以做统一兜底，但不要把全部业务异常处理都塞进去。
  • 不要在任务中吞掉异常后什么都不做，这只会让问题从“错误”变成“谜题”。
