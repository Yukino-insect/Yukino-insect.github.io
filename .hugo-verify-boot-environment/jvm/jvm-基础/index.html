JVM 基础

September 10, 2025

JVM 是 Java 程序的运行时环境。Java 源码先被编译成 .class 字节码，JVM 再负责加载字节码、管理运行时内存、执行指令、即时编译热点代码，并在需要时进行垃圾回收。

这篇文章只做整体地图：先知道 JVM 由哪些部分组成，每部分解决什么问题。类加载、GC、调优和逃逸分析会在独立文章里展开。把所有内容塞进一篇文章，除了显得很勤奋以外，并不会让理解更清楚。

一、JVM 的整体结构

JVM 可以粗略分成五个部分：

             .java 源码
                 |
                javac
                 |
             .class 字节码
                 |
        +--------v---------+
        |   Class Loader   |
        +--------+---------+
                 |
        +--------v---------+
        | Runtime Data Area|
        |  Heap            |
        |  Method Area     |
        |  Java Stack      |
        |  Native Stack    |
        |  PC Register     |
        +--------+---------+
                 |
        +--------v---------+
        | Execution Engine |
        | Interpreter      |
        | JIT Compiler     |
        | Garbage Collector|
        +--------+---------+
                 |
        +--------v---------+
        | JNI / Native Lib |
        +------------------+

各部分职责如下：

  • 类加载器子系统：把 .class 文件加载进 JVM，并完成验证、准备、解析、初始化。
  • 运行时数据区：管理 Java 程序运行时需要的内存。
  • 执行引擎：解释执行字节码，或把热点代码编译成本地机器码。
  • 垃圾回收器：自动回收不再使用的对象，降低手动管理内存的成本。
  • JNI 与本地方法库：让 Java 调用操作系统或 C/C++ 等本地代码。

二、字节码是什么

JVM 不直接运行 .java 文件，而是运行 .class 字节码文件。只要一门语言能编译成 JVM 认可的字节码，它就可以运行在 JVM 上，例如 Kotlin、Scala、Groovy。

.class 文件本质上是按 JVM 规范组织的一段二进制数据，里面包含：

  • 魔数、版本号。
  • 常量池。
  • 类、父类、接口信息。
  • 字段表。
  • 方法表。
  • 属性表，例如 Code、LineNumberTable。

可以用下面的方式查看字节码：

javac Demo.java
javap -c -p Demo.class

示例输出：

public class Demo {
  public Demo();
    Code:
       0: aload_0
       1: invokespecial #1
       4: return

  public static void main(java.lang.String[]);
    Code:
       0: getstatic     #7
       3: ldc           #13
       5: invokevirtual #15
       8: return
}

这些指令不是给人直接编写的，而是给 JVM 执行的。我们阅读它，通常是为了理解语法糖、方法调用、对象创建、异常处理等 Java 代码背后的真实执行方式。

三、类加载器子系统

类加载器负责把类的二进制字节流加载到 JVM 中，并形成可被运行时使用的类元数据。

类加载生命周期通常包括：

加载 -> 验证 -> 准备 -> 解析 -> 初始化 -> 使用 -> 卸载

其中验证、准备、解析合称为连接。

类加载器通常有这些层次：

Bootstrap ClassLoader
          |
Platform ClassLoader / Extension ClassLoader
          |
Application ClassLoader
          |
Custom ClassLoader

这里要注意 JDK 版本差异：

  • JDK 8 及以前常说 Bootstrap、Extension、Application。
  • JDK 9 引入模块系统后，Extension ClassLoader 被 Platform ClassLoader 替代。

默认的类加载机制遵循双亲委派模型：一个类加载器收到加载请求后，先委派给父加载器，父加载器无法完成时，子加载器才尝试自己加载。

这样做主要有两个价值：

  • 防止核心类被应用代码随意替换，例如自定义一个 java.lang.String。
  • 保证类加载路径稳定，减少同名类冲突。

类加载的完整细节可以放到单独的类加载文章里看，基础篇只要先记住一句话：JVM 运行代码之前，必须先把类加载成运行时可理解的数据结构。

四、运行时数据区

JVM 运行时数据区可以分成线程共享区域和线程私有区域。

区域 是否线程共享 主要内容 常见问题
堆 是 对象实例、数组 OutOfMemoryError、GC 频繁
方法区 是 类元数据、运行时常量池、静态变量等 元空间 OOM、类卸载困难
虚拟机栈 否 栈帧、局部变量表、操作数栈 StackOverflowError
本地方法栈 否 Native 方法调用栈 栈溢出或本地内存问题
程序计数器 否 当前线程下一条字节码指令地址 几乎不会 OOM

1. 程序计数器

程序计数器是每个线程私有的一小块内存，用来记录当前线程下一条要执行的字节码指令地址。

Java 多线程通过线程切换来共享 CPU。当线程被切走再切回来时，JVM 需要知道它上次执行到哪里，程序计数器就承担这个职责。

如果线程正在执行 Java 方法，程序计数器记录字节码指令地址；如果正在执行 Native 方法，它的值在 JVM 规范中是未定义的。

2. 虚拟机栈

虚拟机栈描述 Java 方法调用的内存模型。每调用一个方法，JVM 都会创建一个栈帧并压入当前线程的虚拟机栈；方法执行结束后，栈帧出栈。

一个栈帧通常包含：

  • 局部变量表：方法参数和局部变量。
  • 操作数栈：字节码计算过程中的临时操作区。
  • 动态链接：指向运行时常量池中方法引用的信息。
  • 方法返回地址：方法结束后回到哪里继续执行。

递归过深或调用链过长时，虚拟机栈可能抛出 StackOverflowError。线程栈大小可以通过 -Xss 调整，但它不是越大越好，因为单个线程栈越大，同一进程能创建的线程数量通常越少。

3. 本地方法栈

本地方法栈服务于 Native 方法调用。HotSpot JVM 中，虚拟机栈和本地方法栈在实现上通常合并处理，但从规范概念上仍然可以区分。

Native 方法常用于：

  • 调用操作系统能力。
  • 复用已有 C/C++ 库。
  • 与 JVM 外部资源交互。

4. 堆

堆是 JVM 管理的最大一块内存，主要存放对象实例和数组。它被所有线程共享，也是 GC 最主要的工作区域。

常用堆参数：

-Xms512m
-Xmx512m
  • -Xms：初始堆大小。
  • -Xmx：最大堆大小。

服务端应用中经常把 -Xms 和 -Xmx 设置成相同值，用来避免运行期间堆扩缩容带来的额外波动。

从分代收集的角度看，堆通常会被理解为新生代和老年代：

  • 新生代：大多数新对象先在这里分配。
  • 老年代：长期存活对象或大对象更可能进入这里。

不过现代收集器的实现不一定都严格使用连续的新生代、老年代布局。例如 G1 会把堆划分成多个 Region，再动态决定哪些 Region 承担年轻代或老年代角色。

5. 方法区

方法区存放类级别的信息，例如：

  • 类名、父类、接口。
  • 字段和方法元数据。
  • 运行时常量池。
  • 静态变量。
  • JIT 编译后的代码缓存相关信息。

方法区是 JVM 规范中的概念。HotSpot 的实现经历过变化：

  • JDK 7 及以前主要使用永久代 PermGen。
  • JDK 8 开始移除永久代，改用本地内存中的元空间 Metaspace。

如果大量动态生成类，或者类加载器无法释放，可能导致元空间持续增长，最终出现 OutOfMemoryError: Metaspace。

五、对象创建过程

一次普通的 new 大致会经历这些步骤：

类加载检查
 -> 分配对象内存
 -> 对象内存清零
 -> 设置对象头
 -> 执行 <init> 构造初始化

对象内存清零很重要。它解释了为什么实例字段即使没有显式赋值，也会有默认值：

  • 数值类型默认是 0 或 0.0。
  • boolean 默认是 false。
  • char 默认是 \u0000。
  • 引用类型默认是 null。

所以，static 字段初始化属于类初始化过程；实例字段默认值和构造赋值属于对象创建过程。两者不是同一件事。

六、执行引擎

执行引擎负责真正执行字节码，主要包括解释器、JIT 编译器和垃圾回收器。

1. 解释执行

解释器逐条读取字节码并执行。它启动快，适合程序刚运行时快速开始执行。

2. JIT 编译

JIT 编译器会把热点代码编译成本地机器码，提高后续执行效率。

常见优化包括：

  • 方法内联。
  • 逃逸分析。
  • 锁消除。
  • 标量替换。
  • 循环优化。

JIT 的存在解释了一个现象：Java 程序刚启动时可能还没达到最佳性能，运行一段时间后，热点代码被编译优化，性能才逐渐稳定。

3. 垃圾回收

垃圾回收器负责找出不再可达的对象并回收内存。GC 降低了内存管理成本，但也会带来停顿、CPU 消耗和吞吐量变化。

因此 JVM 性能问题通常离不开三个视角：

  • 对象分配速度。
  • 对象存活时间。
  • GC 停顿是否影响业务请求。

七、JVM 与 JMM 的区别

JVM 和 JMM 名字相似，但解决的问题不同。

名称 关注点 解决的问题
JVM Java 程序如何运行 类加载、内存区域、执行引擎、GC
JMM 多线程如何访问共享变量 可见性、原子性、有序性

JMM 即 Java Memory Model，描述线程之间如何通过主内存和工作内存交互。它关心的是并发语义，不是 JVM 运行时数据区的物理划分。

JMM 主要处理三个问题：

  • 可见性：一个线程修改共享变量后，其他线程什么时候能看到。
  • 原子性：一个操作是否会被线程切换打断。
  • 有序性：代码执行顺序是否会被编译器或 CPU 重排序影响。

常见手段包括：

  • volatile：保证可见性，并通过内存屏障限制特定重排序。
  • synchronized：通过锁保证互斥、可见性和有序性。
  • 原子类：通过 CAS 等机制实现无锁原子操作。

八、学习路径

学习 JVM 时，不必一上来就背参数。更稳妥的顺序是：

  1. 先理解 JVM 整体结构和运行时数据区。
  2. 再理解类加载与对象创建。
  3. 接着学习 GC 如何判断对象存活、如何回收对象。
  4. 然后看 JIT、逃逸分析等运行时优化。
  5. 最后结合 GC 日志、线程栈、堆转储去做调优和故障排查。

总结一下：JVM 的核心不是参数表，而是“类如何进入 JVM、对象如何分配、代码如何执行、内存如何回收”这条运行链路。把这条链路理顺，后面的 GC、调优和排障才不是靠记忆硬撑。
