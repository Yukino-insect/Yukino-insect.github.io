FTP 服务器

February 19, 2026

FTP 是 File Transfer Protocol 的缩写，即文件传输协议。FTP 服务器就是运行 FTP 服务端程序的机器或服务，用来让客户端远程上传、下载和管理文件。

它曾经是网站部署、公共资源下载、企业内部文件共享的常见方案。现在很多场景已经被 HTTP 下载、对象存储、网盘、Git、CI/CD 发布系统取代，但理解 FTP 仍然有意义，因为不少旧系统和内网工具还在使用它。

基本模型

FTP 使用客户端和服务器模型：

FTP 客户端
  -> 连接 FTP 服务器
  -> 登录账号
  -> 浏览目录
  -> 上传或下载文件

常见操作：

  • 上传文件
  • 下载文件
  • 查看目录
  • 创建目录
  • 删除文件
  • 重命名文件

服务器端本质上是在监听端口，并把 FTP 命令转换成对服务器文件系统的操作。

客户端
  -> FTP 协议
  -> FTP 服务端程序
  -> 服务器磁盘文件系统

端口与连接

FTP 比较特殊，它通常需要两条连接：

连接 作用 常见端口
控制连接 登录、发送命令、返回状态 21
数据连接 真正传输文件或目录数据 主动模式常见 20，被动模式使用临时端口

控制连接负责说“我要下载这个文件”，数据连接负责真正把文件传过去。

主动模式

主动模式中，客户端先连接服务器 21 端口，然后告诉服务器自己开放了哪个端口。服务器再主动连接客户端的数据端口。

客户端 -> 服务器 21 端口
服务器 -> 客户端数据端口

问题是客户端通常在防火墙或 NAT 后面，服务器主动连回来很容易被拦截。所以主动模式在现代网络环境里经常不顺利。

被动模式

被动模式中，客户端先连接服务器 21 端口。服务器告诉客户端一个可用的数据端口，客户端再主动连接服务器的数据端口。

客户端 -> 服务器 21 端口
客户端 -> 服务器被动数据端口

现在更常用的是被动模式。部署 FTP 服务时，通常需要在服务端配置被动端口范围，并在防火墙或安全组里放行这些端口。

示例：

控制端口：21
被动端口范围：30000-30100

如果只开放 21 端口，登录可能成功，但目录列表和文件传输可能失败。这个现象很典型，并不神秘，只是数据连接没通。

FTP 的安全问题

传统 FTP 是明文协议：

  • 用户名明文传输。
  • 密码明文传输。
  • 文件内容明文传输。
  • 命令明文传输。

在不可信网络中直接使用 FTP 风险很高。抓包工具可以看到账号密码和传输内容，这一点并不会因为“只是临时传一下”就变得温柔。

FTPS 与 SFTP

FTPS 是 FTP over SSL/TLS，可以理解为给 FTP 加密。

FTPS = FTP + TLS

SFTP 不是 FTP 的加密版，而是基于 SSH 的文件传输协议。

SFTP = SSH File Transfer Protocol

对比：

协议 默认端口 底层协议 说明
FTP 21 FTP 明文传输
FTPS 21 或 990 FTP + TLS FTP 的加密版本
SFTP 22 SSH 基于 SSH，不等于 FTP

如果只是需要安全地远程传文件，SFTP 通常比 FTP 更简单，因为它只需要 SSH 端口，网络配置也更直接。

常见服务端软件

软件 平台 说明
vsftpd Linux 轻量、常见、安全性较好
ProFTPD Linux 功能丰富，配置灵活
FileZilla Server Windows 图形化管理方便
IIS FTP Windows Server 和 IIS 体系集成

Linux 服务器上常见选择是 vsftpd。

部署注意事项

部署 FTP 服务时，至少要确认：

  • 是否允许匿名访问。
  • 用户根目录是否被限制。
  • 上传目录是否有写权限。
  • 被动端口范围是否配置并放行。
  • 是否启用 TLS。
  • 是否限制单用户连接数和传输速率。
  • 日志是否记录登录和文件操作。

对于公网环境，不建议开放传统 FTP。更稳妥的选择是 SFTP、对象存储签名 URL，或经过认证的 HTTP 文件服务。

适用场景

FTP 仍可用于：

  • 内网旧系统文件交换。
  • 设备或软件只支持 FTP 上传。
  • 临时迁移历史文件。
  • 受控网络中的批量文件同步。

不建议用于：

  • 公网传输敏感文件。
  • 新系统的主要文件上传链路。
  • 需要强审计和权限模型的业务文件管理。

总结

FTP 的核心是远程文件传输。它的历史包袱也很明显：明文传输、双连接模型、防火墙配置麻烦。

如果维护旧系统，理解控制连接、数据连接、主动模式和被动模式就足够排查大多数问题。如果设计新系统，优先考虑 SFTP、对象存储或 HTTP 文件服务。
