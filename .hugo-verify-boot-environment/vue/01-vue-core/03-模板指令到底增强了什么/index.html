模板指令到底增强了什么：从静态 HTML 到状态驱动页面

August 21, 2026

学习 Vue 模板语法时，很容易产生一个判断：属性绑定、事件绑定这些东西，是不是就是把原来标签里写死的值改成动态的？而 v-if、v-for 这种指令，是不是给 HTML 提供了额外能力？

这个理解大体是对的，但还不够精确。更准确地说，Vue 模板做了三件事：

  • 把静态内容变成由状态决定的内容。
  • 把静态结构变成由状态决定的结构。
  • 把用户操作变成可以修改状态的事件入口。

也就是说，Vue 模板不是单纯给 HTML 加语法糖，而是在 HTML 的基础上建立了一套“状态驱动页面”的描述方式。

一、先看普通 HTML 的限制

普通 HTML 本身描述的是一个确定的页面结构：

<button class="primary" disabled>提交</button>

这段代码表达得很清楚：

  • 按钮文字是 提交。
  • class 固定是 primary。
  • 按钮固定不可点击。

如果页面永远不变化，这当然够用。但真实页面通常不会这么安分：

  • 用户登录前后，按钮文字不同。
  • 表单校验通过后，按钮才可点击。
  • 请求提交中，按钮要显示加载状态。
  • 数据为空时显示空状态，有数据时显示列表。

普通 HTML 没有“根据状态变化”的能力。它只负责呈现当前写好的结果，不负责根据业务状态重新判断页面应该长什么样。

Vue 模板补上的，正是这一层能力。

二、插值：把静态文本变成动态文本

静态 HTML：

<h1>文章列表</h1>

Vue 模板：

<template>
  <h1>{{ title }}</h1>
</template>

这里的变化很朴素：原来写死在标签里的文本，现在来自变量 title。

如果 title 变化，页面上的标题也会跟着变化。它不是你手动找到 h1 再改 innerText，而是 Vue 根据状态自动更新视图。

可以把它理解成：

页面文本 = 当前状态计算出来的结果

这就是插值最核心的作用。

三、属性绑定：把静态属性变成动态属性

属性绑定用 v-bind，简写是 :。

静态 HTML：

<img src="/avatar/default.png" alt="默认头像">

Vue 模板：

<template>
  <img :src="avatarUrl" :alt="username">
</template>

这确实就是把原来标签上静态的属性值，改成了动态表达式。只是别小看这件事。页面里大量变化，本质上都是属性变化。

比如按钮是否禁用：

<button :disabled="submitting">
  提交
</button>

比如链接地址：

<a :href="postUrl">查看文章</a>

比如可访问性属性：

<button :aria-pressed="liked">
  点赞
</button>

这些都可以归为同一类：

元素属性 = 当前状态计算出来的结果

所以，你说“把静态值修改成动态值”，这个判断是成立的。只是要再补一句：属性绑定不是只让代码更方便，而是让 DOM 属性变成状态的一部分表现。

四、class 和 style：动态外观不是手动切换样式

class 和 style 也是属性，但它们太常用，所以 Vue 对它们做了更友好的支持。

静态写法：

<button class="like-button active">已点赞</button>

问题是，active 不应该永远存在。它应该由 liked 决定：

<button class="like-button" :class="{ active: liked }">
  {{ liked ? '已点赞' : '点赞' }}
</button>

这段模板表达的是：

  • like-button 是固定样式。
  • active 是否存在，由 liked 决定。
  • 按钮文字也由 liked 决定。

再比如根据状态切换多个 class：

<article
  class="post-card"
  :class="{
    featured: post.featured,
    muted: post.archived
  }"
>
  {{ post.title }}
</article>

这比手动写 DOM 操作清楚得多：

状态是什么，页面就表现成什么样

如果用原生 DOM 写，往往会变成：

if (post.featured) {
  element.classList.add('featured')
} else {
  element.classList.remove('featured')
}

不是不能写，只是当状态多起来时，很快就会变成一团需要人工维护的分支。人类并不擅长长期维护一团分支，这也不是什么令人意外的事实。

五、事件绑定：把用户操作接回状态

事件绑定用 v-on，简写是 @。

静态 HTML 可以写按钮，但按钮被点击后要做什么，需要 JavaScript 处理：

<button>点赞</button>

Vue 模板：

<button @click="toggleLike">
  {{ liked ? '已点赞' : '点赞' }}
</button>

事件绑定和属性绑定的方向不同。

属性绑定是：

状态 -> 页面

事件绑定是：

用户操作 -> 修改状态

完整闭环是：

状态 -> 页面 -> 用户操作 -> 修改状态 -> 页面自动更新

比如：

<script setup lang="ts">
import { ref } from 'vue'

const liked = ref(false)
const likes = ref(10)

function toggleLike() {
  liked.value = !liked.value
  likes.value += liked.value ? 1 : -1
}
</script>

<template>
  <button :class="{ active: liked }" @click="toggleLike">
    {{ liked ? '已点赞' : '点赞' }} · {{ likes }}
  </button>
</template>

这段代码里：

  • :class 负责根据 liked 切换样式。
  • {{ liked ? '已点赞' : '点赞' }} 负责根据 liked 切换文本。
  • {{ likes }} 负责显示点赞数。
  • @click 负责在用户点击时修改状态。

所以事件绑定不是“让 HTML 多了一个点击语法”这么简单。它是状态循环里的入口。

六、v-if：让结构由状态决定

属性绑定改变的是元素上的值，v-if 改变的是元素是否存在。

静态 HTML：

<p>加载中</p>
<section>文章内容</section>

它无法表达“加载时显示加载中，加载完成后显示内容”。Vue 可以这样写：

<template>
  <p v-if="loading">加载中</p>
  <section v-else>文章内容</section>
</template>

这里已经不是单纯修改属性值了，而是在控制 DOM 结构：

loading 为 true  -> 创建加载提示
loading 为 false -> 创建内容区域

再复杂一点：

<template>
  <p v-if="loading">加载中</p>
  <p v-else-if="error">加载失败</p>
  <p v-else-if="posts.length === 0">暂无文章</p>
  <section v-else>
    文章列表
  </section>
</template>

这类写法表达的是页面状态分支：

  • 加载中。
  • 加载失败。
  • 空数据。
  • 正常内容。

真实业务页面几乎都离不开这些状态。只写“正常内容”的页面，通常只是还没被现实认真对待。

七、v-show：元素还在，只是显示隐藏

v-show 和 v-if 都能控制显示，但含义不同。

<div v-show="visible">
  弹窗内容
</div>

v-show 不会销毁元素，它只是切换 CSS 的 display。

简单区别：

指令 元素是否创建 适合场景
v-if 条件为假时不创建或销毁 切换不频繁、结构较重
v-show 始终存在，只切换显示 切换频繁、结构较轻

所以 v-if 和 v-show 都是结构展示能力，但控制粒度不同。

八、v-for：根据数据生成重复结构

普通 HTML 写列表，只能把每一项都写出来：

<article>
  <h2>第一篇文章</h2>
</article>
<article>
  <h2>第二篇文章</h2>
</article>
<article>
  <h2>第三篇文章</h2>
</article>

但真实列表来自数据：

const posts = [
  { id: 1, title: '第一篇文章' },
  { id: 2, title: '第二篇文章' },
  { id: 3, title: '第三篇文章' }
]

Vue 使用 v-for 根据数组生成结构：

<article v-for="post in posts" :key="post.id">
  <h2>{{ post.title }}</h2>
</article>

这不是把某个静态值改成动态值，而是把“一组数据”映射成“一组 DOM”：

数组中的一项数据 -> 页面中的一个节点结构

列表渲染最重要的是 key：

<article v-for="post in posts" :key="post.id">
  {{ post.title }}
</article>

key 用来告诉 Vue：每一项的稳定身份是什么。

不要随手使用数组下标：

<article v-for="(post, index) in posts" :key="index">
  {{ post.title }}
</article>

如果列表会新增、删除、排序，用下标做 key 容易导致组件复用错位。输入框内容串到另一行这种问题，看起来玄学，其实只是身份标识写错了。

九、v-model：表单值和状态互相同步

v-model 常被称为双向绑定。

<input v-model="username">

它可以理解为下面两件事的合并：

<input :value="username" @input="username = $event.target.value">

当然，在 Vue 里对 ref 和编译结果会有更具体的处理。作为学习阶段的心智模型，这样理解已经够用了。

也就是说：

状态变化 -> 输入框内容变化
用户输入 -> 状态变化

例子：

<script setup lang="ts">
import { ref } from 'vue'

const keyword = ref('')
</script>

<template>
  <input v-model.trim="keyword" placeholder="搜索文章">
  <p>当前关键字：{{ keyword }}</p>
</template>

输入框内容改变后，keyword 会变化；keyword 变化后，下面的文本也会更新。

这正是 Vue 页面常见的数据流。

十、这些指令可以分成三类

把常见模板语法放在一起看，会更清楚。

类型 语法 作用 本质
内容绑定 {{ value }} 显示动态文本 状态决定文本
属性绑定 :src、:disabled、:class 设置动态属性 状态决定属性
事件绑定 @click、@input 响应用户操作 操作修改状态
条件渲染 v-if、v-else 控制元素是否存在 状态决定结构分支
显示控制 v-show 控制元素显示隐藏 状态决定可见性
列表渲染 v-for 根据数组生成节点 数据集合映射成结构
表单绑定 v-model 同步输入值和状态 状态和输入互相更新

所以，回到最开始的问题：

属性绑定、事件绑定等，是不是把原来标签静态的值修改成动态的？

答案是：属性绑定确实主要是在做这件事，插值、class、style 绑定也属于这一类；但事件绑定更准确地说，是把用户操作接入状态更新流程。

v-if、v-for 是不是提供了增强能力？

答案是：是的。它们让 HTML 拥有了根据状态决定结构、根据数据生成结构的能力。

不过更完整的总结应该是：

Vue 模板 = HTML 结构 + 状态表达式 + 指令增强

它让你不再手动描述“怎么一步步改 DOM”，而是描述“在当前状态下页面应该是什么样”。

十一、用一个例子串起来

下面这个例子把插值、属性绑定、事件绑定、条件渲染、列表渲染和表单绑定放在一起。

<script setup lang="ts">
import { computed, ref } from 'vue'

type Post = {
  id: number
  title: string
  author: string
  liked: boolean
}

const keyword = ref('')
const loading = ref(false)

const posts = ref<Post[]>([
  { id: 1, title: 'Vue 模板语法', author: 'Yuki', liked: false },
  { id: 2, title: '响应式状态', author: 'Haruno', liked: true },
  { id: 3, title: '组件通信', author: 'Hikigaya', liked: false }
])

const filteredPosts = computed(() => {
  const text = keyword.value.trim().toLowerCase()
  if (!text) {
    return posts.value
  }

  return posts.value.filter((post) => {
    return post.title.toLowerCase().includes(text)
      || post.author.toLowerCase().includes(text)
  })
})

function toggleLike(post: Post) {
  post.liked = !post.liked
}
</script>

<template>
  <main>
    <input v-model="keyword" placeholder="搜索文章">

    <p v-if="loading">加载中</p>

    <p v-else-if="filteredPosts.length === 0">
      没有匹配文章
    </p>

    <section v-else>
      <article v-for="post in filteredPosts" :key="post.id">
        <h2>{{ post.title }}</h2>
        <p>作者：{{ post.author }}</p>
        <button
          :class="{ active: post.liked }"
          :aria-pressed="post.liked"
          @click="toggleLike(post)"
        >
          {{ post.liked ? '已点赞' : '点赞' }}
        </button>
      </article>
    </section>
  </main>
</template>

逐行拆开看：

  • v-model="keyword"：用户输入会修改 keyword。
  • filteredPosts：根据 keyword 和 posts 计算显示列表。
  • v-if="loading"：加载时显示加载状态。
  • v-else-if="filteredPosts.length === 0"：没有结果时显示空状态。
  • v-for="post in filteredPosts"：根据搜索结果生成文章列表。
  • :key="post.id"：告诉 Vue 每篇文章的稳定身份。
  • {{ post.title }}：显示动态标题。
  • :class="{ active: post.liked }"：根据点赞状态切换样式。
  • :aria-pressed="post.liked"：根据点赞状态设置语义属性。
  • @click="toggleLike(post)"：点击按钮后修改当前文章状态。

这就是 Vue 模板的核心工作方式。

十二、不要把模板指令理解成零散语法

初学时当然要一个个记：

  • : 是属性绑定。
  • @ 是事件绑定。
  • v-if 是条件渲染。
  • v-for 是列表渲染。
  • v-model 是表单绑定。

但真正写页面时，不应该把它们当作零散技巧。你应该问的是：

这个页面有哪些状态？
每个状态会影响哪些文本、属性、样式和结构？
用户做了什么操作后，应该修改哪个状态？

只要沿着这三个问题思考，模板指令就会变得很自然。

十三、总结

你的理解可以整理成更准确的版本：

  • 插值和属性绑定：把写死的文本、属性、样式，改成由状态决定。
  • 事件绑定：把用户操作接回 JavaScript，让操作能够修改状态。
  • v-if 和 v-show：让页面展示由状态决定。
  • v-for：让重复结构由数据集合生成。
  • v-model：让表单输入和状态保持同步。

所以 Vue 模板真正增强的不是 HTML 标签本身，而是 HTML 和状态之间的关系。

静态 HTML 写的是：

页面现在长这样

Vue 模板写的是：

当状态是这样时，页面应该长这样

这一点想明白后，模板语法就不再是一堆需要死记的符号。它们只是同一个目标的不同表达方式：让页面忠实地呈现当前状态，并允许用户操作改变状态。嗯，听起来很普通，但普通的东西如果想真正写稳，通常才最考验基本功。
