## 面试官想问什么

Python 在 AI 生态里非常强，LangChain、LlamaIndex、RAGAS、各类解析和模型工具都更早出现。面试官问这个问题，不是要你否定 Python，而是看你能否根据系统定位选择技术栈。

一个好回答应该说明：Python 适合哪些部分，Java 适合哪些部分，项目为什么把主链路放在 Java。

## 可以这样回答

我们没有否定 Python。Python 在文档解析、模型实验、评测脚本和算法验证上效率很高，很多工具生态也更成熟。项目里如果需要复杂 PDF 解析、OCR、模型实验或离线评测，完全可以用 Python 服务承担。

但 RAG 的在线主链路不仅是算法问题，它还要接入用户体系、权限校验、知识库管理、数据库事务、对象存储、分布式限流、审计日志、SSE 长连接、任务取消、模型路由和后台调度。这些能力在我们现有系统里主要由 Java 和 Spring 生态承载。

因此主链路选择 Java，是为了和已有后端架构、部署体系、监控体系和团队技能保持一致。Python 更适合作为旁路能力服务，例如文档解析服务或评测工具，通过 HTTP、消息队列或任务回调和 Java 主系统集成。

这种划分的好处是：在线链路稳定、权限和事务边界清楚，AI 辅助能力可以独立演进；代价是跨语言调用会增加部署、网络、序列化和故障处理复杂度。

## Java 主链路的优势

Java 在企业后端中适合承载：

- 用户和权限体系。
- 数据库事务和 MyBatis/JPA 集成。
- Spring Web、SSE 和异步任务。
- 定时任务、分布式锁和限流。
- 审计日志、监控和告警。
- 统一配置和发布流程。

这些不是 AI 算法本身，却决定系统能否在线上稳定运行。

## Python 适合的位置

Python 更适合：

- 复杂文档解析和 OCR。
- 机器学习实验。
- 自定义 Embedding 或 Rerank 服务。
- 离线评测和数据分析。
- 快速验证新算法。

Ragent 接入本地文档解析与自定义 Rerank 服务，就是一种合理边界：Java 负责主流程和治理，Python 或外部服务负责专门模型能力。

## 不要这样答

不要说“Python 不适合生产”。很多生产系统用 Python 跑得很好，这样答只会暴露偏见。

不要说“Java 性能一定比 Python 好”。RAG 瓶颈常在模型、网络、检索和外部服务，不是语言本身。

不要说“团队只会 Java”。这可以是现实因素，但不能作为唯一技术理由。

不要忽略跨语言成本。只说 Python 做 AI 强，却不说明部署和治理问题，也不完整。

## 延伸追问

如果面试官问“未来会不会把更多能力迁到 Python”，可以回答：

会根据边界判断。在线请求编排、权限、审计和状态管理仍适合留在 Java；高计算、强算法、快速迭代的能力可以独立成 Python 服务。关键不是语言之争，而是把实时主链路和算法辅助服务解耦。

## 小结

Java 和 Python 不是对立关系。RAG 项目里，Java 适合承载企业在线系统的稳定主链路，Python 适合承载 AI 工具和实验能力。能把边界讲清楚，比争论哪门语言“更高级”有意义得多。
