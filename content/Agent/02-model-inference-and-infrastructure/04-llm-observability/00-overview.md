很多初学者把“可观测性”理解成记录日志，直到用户说“刚才那次回答为什么这么慢、为什么收费变高、为什么明明返回成功却答错了”，才发现日志里只有一行 `200 OK`。这门课从这个具体问题出发：让一条请求留下能被人读懂、被机器聚合、并能跨服务关联的证据。

课程讨论的是通用的应用可观测性方法，LLM 只是让问题更明显：它有输入输出、流式首字节、模型与提示词版本、token 用量、调用成本、工具调用和质量评分。客服机器人、内容生成、模型网关、内部 Copilot 都能使用这些方法；不要求读者正在做 RAG 或 Agent。

## 你会实际完成什么

完成课程后，你将从零写出一个小型 Python 服务的观测代码，能在终端看到一条请求的 trace，能把它发送到自托管的 Langfuse，能比较两个模型版本，并能为队列积压和存储故障准备恢复步骤。

```text
浏览器或调用方
  -> HTTP 请求日志（发生了什么）
  -> 指标聚合（整体是否变差）
  -> trace / span（这一次为什么变慢）
  -> 观测平台、队列和存储（保存、查询与告警）
```

这里的箭头不是业务架构规定，而是同一事实的三种观察方式。日志保留细节，指标显示趋势，trace 还原因果顺序；三者相互链接，不能相互替代。

## 前置条件与实验原则

准备 Python 3.10 或更高版本、Docker Desktop（用于第二讲）和一个空目录。前两讲不需要真实模型账号：我们会用一个固定返回文本的函数模拟模型调用，因此结果可重复，也不会把密钥或用户内容写进教程。

建议创建独立虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

每个实验都应在个人电脑或隔离测试环境完成。示例中的 `example.invalid`、`<TOKEN>`、`<密钥>` 都是占位符；不要把真实 API Key、完整提示词、身份证号或客户对话复制进代码、终端历史或观测属性。

## 可跳过的项目对照

有些工程会将 Langfuse 与列式分析数据库、关系数据库、Redis 队列和对象存储一起部署。这只是自托管平台常见的一种组合，不是本课程的前提，也不应把这些组件误认为某个业务项目专属。完成通用实验后，读者可以再把自己的 Compose 文件逐项映射到第五讲的“接入、排队、持久化、查询”职责。

## 小结

- 可观测性的目标是回答运行中的问题，而不是收集越多数据越好。
- 先用可重复的假模型学会信号与 trace，再接入真实模型。
- Langfuse 是一个可选的 LLM 观测后端；OpenTelemetry 的基本概念仍然通用。
