面试里问 RAG 项目，通常不只是问“你用了什么技术”。真正要考的是：你是否理解方案边界，是否能解释取舍，是否遇到过工程问题，是否能用数据和结构化语言说明自己的设计。

这一章整理三个高频问题。回答时请避免“因为我们项目就是这么做的”这类句式。项目这样做不代表你理解这样做。这个区别不大声，却很致命。

## 学习目标

- 能解释为什么没有直接套用 Spring AI 或 LangChain4j。
- 能说明 Java 主链路和 Python 辅助服务的边界。
- 能比较 Milvus 和 PGVector 的适用场景。
- 能把技术选型讲成权衡，而不是偏好。

## 回答模板

一个好的选型回答通常按四段组织：

1. 先承认候选方案的价值。
2. 再说明当前项目的约束。
3. 然后解释最终选择和代价。
4. 最后补一句未来演进条件。

能讲清楚代价的人，比只会说“这个更好”的人可信得多。
