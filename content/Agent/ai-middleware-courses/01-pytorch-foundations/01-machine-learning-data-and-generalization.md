在普通程序中，我们把规则写死：`如果温度低于 10 度，就提醒穿外套`。机器学习换了一种分工：我们给程序很多过去的例子和正确答案，让它自己找出一组近似规则。它并不会凭空“懂得”问题；数据里没有的信息，它也无从获得。先把这个边界讲清楚，后面才不会把 PyTorch 当成一个输入数据便能产生真相的按钮。

## 从一个具体问题开始

我们尝试根据一套房子的面积和房龄，预测它是否属于“高价房”。为避免一开始被真实房价的小数、单位和异常值分散注意力，我们先只回答“是”或“否”。

一条历史记录可以写成：

```text
输入：面积 89 平方米，房龄 5 年
答案：是高价房（1）
```

在机器学习中，一条这样的记录叫做**样本**：

- **特征（feature）**：模型在做预测时能够拿到的输入，例如面积、房龄；
- **标签（label）**：这条样本的正确答案，例如 `1` 代表高价房、`0` 代表非高价房；
- **模型（model）**：把特征转换成预测的计算规则；
- **参数（parameter）**：模型内部可以在训练中调整的数值。

常把一条样本写为 $(x, y)$：$x$ 表示特征，$y$ 表示标签。这个符号只是简写，不是额外的难题。对于上面的例子，$x$ 是两个数字组成的输入，$y$ 是 `1`。

## 先分清三种常见任务

不要因为都能调用 PyTorch 就把不同问题混在一起。最常见的区别来自答案的类型：

| 任务 | 想预测什么 | 标签例子 | 生活中的例子 |
| ---- | ---------- | -------- | ------------ |
| 回归 | 一个连续数值 | `235.6` | 预测房价、销量、温度 |
| 二分类 | 两种可能中的一种 | `0` 或 `1` | 是否违约、是否为垃圾邮件 |
| 多分类 | 多个类别中的一个 | `0`、`1`、`2` | 图片是猫、狗还是鸟 |

本课程末尾使用二分类，因为它的标签最直观。真实项目中必须先问“正确答案到底是什么”，再选择输出层、损失函数和指标；反过来从某个熟悉的 API 开始凑任务，只会使问题变得漂亮而无用。

## 模型如何从例子中学习

训练刚开始时，模型内部的参数通常是随机的，因此猜得很差。对每一批样本，它会经历下面的过程：

```text
输入特征 x ──→ 模型 ──→ 预测值 y_hat
                              │
正确标签 y ───────────────────┘
                              ↓
                       损失：错得有多严重
                              ↓
                 调整参数，让下一次损失更小
```

预测值常写作 $\hat y$，读作“y hat”，意思是“模型猜出的 y”。例如标签是 `1`、模型输出的概率是 `0.2`，就说明它把一个高价房猜成了不太可能高价，损失应当较大。训练的目的不是让某一条样本完美，而是让大量样本上的平均错误逐渐下降。

回归任务中，常用的均方误差（MSE）是：

$$
\operatorname{MSE}=\frac{1}{n}\sum_{i=1}^{n}(\hat y_i-y_i)^2
$$

现在无需推导它。只要读出两个意思：每条样本都比较“预测减答案”，平方使正负误差不会互相抵消，最后再求平均。不同任务会使用不同损失函数，但损失承担的角色始终相同：为“错得如何”提供一个可优化的数字。

## 为什么数据必须分成三份

如果老师把练习题和期末题完全相同，背下练习题的人能得高分，却不能证明他会解决新问题。模型也一样：只看训练时用过的数据，不能证明它对新数据有效。这种对没见过的数据仍然表现良好的能力叫做**泛化（generalization）**。

因此，准备数据时通常先切分：

```text
原始数据
  ├─ 训练集 train：模型反复查看，用它计算梯度并更新参数
  ├─ 验证集 validation：比较不同方案，决定训练多久、学习率多大等
  └─ 测试集 test：所有决定完成后，最后检查一次真实效果
```

一个常见比例是 `70% / 15% / 15%`，但没有任何数字适合所有项目。数据很少时，验证集和测试集会更珍贵；数据按时间发生时，切分顺序比比例更重要。重点不是记住百分比，而是**同一份样本不应同时负责学习、挑选方案和最终验收**。

例如你尝试十种网络结构，每次都选验证分数最高的那一个。即使没有直接用验证集更新参数，你也已经根据它做了选择。此时验证集被“间接熟悉”了，所以还需要一份独立测试集来估计最终表现。反复查看测试集再改方案，测试集也会失去意义；这种道理并不玄妙，只是实验公平性不允许例外。

## 过拟合与欠拟合：两种不同的失败

训练后可以分别观察训练集和验证集的损失。它们的组合比单看一个数字更有信息：

| 观察到的现象 | 常见含义 | 应先检查什么 |
| ------------ | -------- | ------------ |
| 两边损失都高 | 模型还没学会规律，或数据/标签有问题 | 标签对齐、特征质量、训练是否真正更新 |
| 训练损失低，验证损失明显高 | 记住训练细节，不能推广 | 切分是否合理、是否泄漏、模型是否过复杂 |
| 两边都低且接近 | 在当前数据上看起来较健康 | 用独立测试集和真实场景继续确认 |

第二种情况叫做**过拟合**，可以理解为“会背练习题，却不会做新题”。第一种常被叫作**欠拟合**，表示模型连训练集中的基本规律也没有捕捉到。它们的处理方式不同：遇到过拟合就盲目多训练几轮，通常只会让记忆更牢，颇有一种以毒攻毒的朴素勇气。

## 数据泄漏：模型不该提前看到的答案

假设要预测用户是否会还款，却把“催收状态”作为输入；这个字段往往在逾期后才出现，已经暴露了答案。离线分数会非常漂亮，上线时却没有这个字段可用。这就是**数据泄漏**：模型从本不该拥有的信息中得到了帮助。

检查每个特征时，请依次问：

1. 在做出预测的那一刻，这个字段真的已经存在吗？
2. 它会不会直接或间接包含标签、未来信息或人工处置结果？
3. 训练、验证、测试的预处理是否互相隔离？

第三点容易遗漏。例如归一化需要均值和方差，应该只用训练集计算，再把同一套数值应用到验证集、测试集。若先对全部数据求平均再切分，验证和测试的信息已经偷偷参与了训练准备。

## 把四条样本放进 PyTorch

下面暂时不训练，只把“样本表”变成 PyTorch 能处理的数据。运行后先观察每个 `shape`，不要跳过输出。

```python
import torch
from torch.utils.data import DataLoader, TensorDataset

# 四行代表四条样本；每行有两个特征：面积、房龄。
features = torch.tensor(
    [[68.0, 12.0], [89.0, 5.0], [45.0, 28.0], [120.0, 3.0]],
    dtype=torch.float32,
)

# 第 i 个标签必须对应第 i 行特征。
labels = torch.tensor([0.0, 1.0, 0.0, 1.0], dtype=torch.float32)

dataset = TensorDataset(features, labels)
loader = DataLoader(dataset, batch_size=2, shuffle=True)

for batch_features, batch_labels in loader:
    print('特征：', batch_features)
    print('标签：', batch_labels)
    print('形状：', batch_features.shape, batch_labels.shape)
```

`DataLoader` 像一个按份发放练习册的助手。`batch_size=2` 表示每次给模型两条样本；因此特征形状是 `[2, 2]`，前一个 `2` 是本批样本数，后一个 `2` 是每条样本的特征数。`shuffle=True` 会在每轮训练前打乱训练样本顺序，减少模型依赖固定排列的风险；验证和测试无需为了“看起来随机”而打乱。

## 小结

- 一条监督学习样本由特征 $x$ 和正确标签 $y$ 组成；模型输出的是预测 $\hat y$。
- 回归、二分类和多分类的答案类型不同，不能把标签和损失函数随意交换。
- 训练集用来更新，验证集用来选择方案，测试集用于最终检查；它们分开是为了检验泛化。
- 先检查是否泄漏和标签是否对齐，再讨论更复杂的模型。一个偷看答案的简单模型，永远不会因名字更复杂而变得可信。
