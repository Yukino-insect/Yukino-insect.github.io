使用 PyTorch 前，首先要澄清一件比 API 更重要的事：**模型不是从“代码”中学习，而是从带有某种反馈的数据中调整参数。** 如果输入、目标和评价方式没有定义清楚，再熟练地调用 `nn.Module` 也只是在更快地执行一个含糊的问题。

本文以“根据房屋面积和房龄预测价格”为例解释监督学习。这个例子没有 Transformer 的光环，却能把机器学习中最常见的概念放在正确位置；基础问题本来就不需要靠复杂名词证明自身存在。

## 一个学习任务由什么组成

一条样本通常写成 $(x, y)$：

- $x$ 是 **feature（特征）**，即模型可见的输入。例如面积、房龄、城区编码。
- $y$ 是 **label / target（标签或目标）**，即希望模型给出的正确答案。例如成交价格。
- $f_\theta(x)$ 是模型：它根据输入给出预测 $\hat y$；$\theta$ 表示所有可学习参数。

若目标是连续数值，这是**回归**；若目标是有限类别，例如“是否违约”“图片是不是猫”，这是**分类**。同一份 PyTorch 训练骨架可用于两者，但输出层、标签类型、损失函数和指标不能随意互换。

| 任务 | 标签示例 | 常见输出 | 训练时常用损失 | 常见评价指标 |
| ---- | -------- | -------- | -------------- | ------------ |
| 回归 | `235.6` 万元 | 实数 | MSE、MAE | MAE、RMSE |
| 二分类 | `0` 或 `1` | logit 或概率 | `BCEWithLogitsLoss` | Precision、Recall、F1、AUC |
| 多分类 | `0` 到 `K-1` | 每类一个 logit | `CrossEntropyLoss` | Accuracy、F1 |

### 模型只会利用你交给它的信息

预测房价时，把成交后的“最终评估价”放进特征，离线指标可能极好，但上线前根本拿不到这个字段。这是**数据泄漏**：模型并没有学会预测，只是偷看了答案或未来信息。时间序列任务更要警惕这一点：训练集应来自较早时间，验证和测试来自较晚时间，不能先随机打散再假装它们互不影响。

另一个常见误解是“特征越多越好”。无关、错误、缺失机制不同，或只在训练期存在的字段，都可能让模型学到脆弱关联。先确认每个字段在预测时真实可得、含义稳定，再谈模型复杂度，顺序不能倒置。

## 训练集、验证集与测试集为什么要分开

模型参数由训练集更新；验证集用于选择学习率、网络宽度、训练轮数等超参数；测试集只在方案确定后用于一次最终评估。三者的角色不同，因此不能用同一份数据同时担任。

```text
原始样本
  ├─ 训练集 train：计算梯度，更新参数
  ├─ 验证集 validation：选模型、选超参数、决定早停
  └─ 测试集 test：最后估计对未知数据的表现
```

设模型在训练数据上的平均损失为 $L_{train}$，在未见数据上的损失为 $L_{test}$。理想状态是两者都较低且差距不大。若 $L_{train}$ 很低、$L_{test}$ 明显高，模型记住了训练样本的细节却不能推广，称为**过拟合**。若两者都高，则可能是特征无效、模型能力不足、训练不充分或标签质量差，称为**欠拟合**。

验证集并不是“可反复试到满意为止的测试集”。每次根据验证分数更换方案，都在间接适配验证集；最终仍需保留未参与任何决策的测试集。数据很少时可以使用交叉验证，但测试集独立这一原则不会因此失效。

## 损失函数：训练时到底在最小化什么

损失函数把“预测得好不好”变成可计算的标量。以回归为例，均方误差为：

$$
\operatorname{MSE}=\frac{1}{n}\sum_{i=1}^{n}(\hat y_i-y_i)^2
$$

误差平方会更严厉地惩罚很大的偏差。若异常值很多，平均绝对误差 $\operatorname{MAE}=\frac{1}{n}\sum |\hat y_i-y_i|$ 往往更稳健。不存在脱离业务的“最好损失函数”：如果大额误差代价极高，MSE 的强调可能合理；如果希望误差以金额直观解释，MAE 更便于沟通。

二分类中，模型通常先输出一个没有固定范围的 **logit** $z$，再由 sigmoid 转为概率：

$$
p=\sigma(z)=\frac{1}{1+e^{-z}}
$$

`BCEWithLogitsLoss` 会把这两步以数值更稳定的方式合在一起，因此输入应是原始 logit，不应提前手动 `sigmoid`。而 `CrossEntropyLoss` 接收每个类别的原始 logit 和整数类别编号，也不应先做 `softmax`。损失函数的输入契约若弄错，代码可能继续运行，学习却已经失去意义；这比语法错误更麻烦。

## 指标和损失不是同义词

训练直接优化的常是可导损失，业务关心的却可能是另一个指标。例如欺诈检测中，正类很少；如果 99% 样本都不是欺诈，永远预测“否”就有 99% accuracy，却完全没有实际价值。此时至少要结合：

- **Precision（精确率）**：判为正的样本中，有多少真的为正；
- **Recall（召回率）**：真实为正的样本中，找回了多少；
- **F1**：Precision 与 Recall 的调和平均；
- 阈值、人工复核成本和漏判代价。

因此，不要只因为一个 loss 下降就断言模型“更好”。应在验证集上观察与任务一致的指标，并保留少量具体样本做误差分析：哪些人群、时间段或输入类型容易失败，往往比总分本身更能指出问题。

## 用 PyTorch 表达一批监督学习数据

以下代码只演示数据的形状和类型，不训练模型。`features` 的每一行是一条样本，`labels` 的第 $i$ 项就是该行对应标签；这个对齐关系不可破坏。

```python
import torch
from torch.utils.data import DataLoader, TensorDataset

# 四条样本，每条有“面积、房龄”两个 float 特征。
features = torch.tensor(
    [[68.0, 12.0], [89.0, 5.0], [45.0, 28.0], [120.0, 3.0]],
    dtype=torch.float32,
)
# 二分类标签用 0.0 / 1.0，以匹配后续 BCE 损失的浮点输入。
labels = torch.tensor([0.0, 1.0, 0.0, 1.0], dtype=torch.float32)

dataset = TensorDataset(features, labels)
loader = DataLoader(dataset, batch_size=2, shuffle=True)

for batch_features, batch_labels in loader:
    print(batch_features.shape, batch_labels.shape)
```

预期会打印两次 `torch.Size([2, 2]) torch.Size([2])`。`shuffle=True` 只应作用于训练集：它减少模型记住数据原始排列的机会。验证集和测试集通常不需要打乱来“提高分数”，因为它们并不更新参数。

真实项目还应在训练集上计算归一化所需的均值和方差，再将同一组统计量应用到验证集和测试集。若对每个集合单独归一化，验证/测试的信息就参与了预处理；看似细微，仍然属于泄漏。

## 小结

- 监督学习要先定义样本 $(x, y)$、任务类型、预测时可用的特征与成功标准。
- 训练集更新参数，验证集参与选择，测试集用于最后估计；不要让未来信息或答案进入特征。
- 损失是优化器看到的目标，指标是业务评价的语言；二者应相关，但不必相同。
- 过拟合不是“训练不够久”的同义词，而是训练表现和未知数据表现出现了明显分叉。
