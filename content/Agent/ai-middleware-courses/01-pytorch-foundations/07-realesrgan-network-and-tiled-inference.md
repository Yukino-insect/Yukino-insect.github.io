超分辨率的输入是一张低分辨率图，输出是一张尺寸更大、视觉细节更丰富的图。它不是把每个像素简单放大；最近邻、双线性或 Lanczos 插值只能根据已有像素平滑或复制，而 Real-ESRGAN 会根据训练中学到的统计规律**推测**线条、边缘和纹理。这里的“推测”是必须保留的限定：输出可以在视觉上更自然，却不能被解释为真实丢失细节的证据。

CleanCanvas Studio 的 `backend/enhance/realesrgan.py` 包含两套预训练模型：`RealESRGAN Anime` 使用 RRDBNet，偏向二次元线条；`RealESRGAN General` 使用紧凑的 SRVGG 网络，面向通用图像。它们共享相同的工程包装：图片预处理、权重加载、设备选择、`inference_mode`、分块推理和 RGB/BGR 转换。

## 卷积：图像网络为什么不使用全连接层

一个彩色图像张量常为 `[N, C, H, W]`。若直接把 `H×W×3` 的所有像素拉直连接到下一层，参数量会随着分辨率急剧增长，而且模型失去“相邻像素相关”的结构信息。二维卷积层 `nn.Conv2d` 用小窗口在图像上滑动，更适合学习边缘、纹理、角点等局部模式。

项目第一层是：

```python
self.conv_first = nn.Conv2d(3, 64, 3, 1, 1)
```

这表示输入 3 通道 RGB，输出 64 个特征通道，卷积核为 `3×3`，步长 `1`，padding `1`。对输入 `[N, 3, H, W]`，输出形状为 `[N, 64, H, W]`；padding 保证空间尺寸不变。此处的 64 不是“64 张图片”，而是模型学习到的 64 组中间特征图。

输出空间尺寸一般可由下面公式计算：

$$
\left\lfloor\frac{H + 2P - K}{S}\right\rfloor + 1
$$

其中 $H$ 是输入高度、$K$ 是卷积核大小、$P$ 是 padding、$S$ 是步长。代入 `H, K=3, P=1, S=1`，恰好仍是 $H$。你不必每次手算，但要能够解释为何 `3, 1, 1` 通常不改变高宽。

## 激活函数与非线性

代码使用 `nn.LeakyReLU(negative_slope=0.2)` 或 `nn.PReLU`。没有激活函数时，无论串联多少个线性卷积，整体仍可化为一个线性变换，无法表达复杂的图像映射。激活函数在每层后引入非线性，使网络可以拟合复杂纹理与边缘关系。

LeakyReLU 的直觉是：正数保持，负数不完全归零，而是乘上一个很小斜率（这里为 `0.2`）。这样可降低普通 ReLU 长期输出 0、梯度也难以传播的风险。PReLU 则让负半轴斜率本身成为可学习参数。

## RRDB：残差连接和稠密连接解决什么

Anime 模型的 `_build_rrdb_net()` 由 `ResidualDenseBlock`、`RRDB` 和 `RRDBNet` 构成。初看 `torch.cat((x, x1, x2), 1)` 很可怕，其实只做了一件事：沿通道维把前面各层的特征拼起来。

```text
x ──conv1──> x1
│             │
├─ concat(x, x1) ──conv2──> x2
│                         │
├─ concat(x, x1, x2) ──conv3──> x3
└─ ...
```

这叫**稠密连接（dense connection）**。后面层能直接看到早期特征，而不必等待信息穿过所有中间层；特征复用更充分，也有助于梯度在训练时传播。注意拼接维度是 `1`，即 `[N, C, H, W]` 中的 `C`；因此 `conv2` 的输入通道数从 `64` 增至 `64 + 32`，代码中的构造参数正是这样写的。

模块的末尾还有：

```python
return transformed * 0.2 + x
```

这叫**残差连接（residual connection）**：网络学习输入的增量，而不是从头重新生成全部特征。`0.2` 是残差缩放，能让深网络初期更稳定。三层稠密残差块再组成一个 RRDB，RRDB 外又有一次残差，因而称为 Residual-in-Residual Dense Block。可以这样概括其工程价值：稠密连接促进特征复用，残差连接给信息和梯度提供较短路径，二者都使深网络更容易训练；在本项目中我们只推理，但网络的结构来自这些训练需求。

## 4×放大是怎样发生的

RRDBNet 先在低分辨率特征图上提取特征，随后两次：

```python
functional.interpolate(feat, scale_factor=2, mode='nearest')
```

每次高宽变为 2 倍，两次便为 4 倍。`interpolate` 先把特征图扩大，后面的卷积负责修正和生成更有意义的高分辨率特征，最后 `conv_last` 输出 3 个 RGB 通道。因此输入 `[1, 3, H, W]` 会变为 `[1, 3, 4H, 4W]`。

General 模型的 `SRVGGNetCompact` 使用另一种上采样：最后卷积输出 `3 × 4 × 4 = 48` 个通道，然后 `nn.PixelShuffle(4)` 重新排列通道中的数值，使其进入空间维，输出 `[N, 3, 4H, 4W]`。`PixelShuffle` 不凭空增加元素总数；它只是将 `[48, H, W]` 重排为 `[3, 4H, 4W]`。用于重建的细节由前面卷积产生。

它还将最近邻插值后的原图加回输出：

```python
return learned_detail + functional.interpolate(x, scale_factor=4, mode='nearest')
```

这也是残差思想：保留容易得到的低频主体，让网络集中学习插值无法提供的高频修正。

## 为什么用户选 2×，项目却先推理 4×

两个权重的原生输出固定为 4×。当用户选择 1×、1.5×、2×或 3×时，项目仍先生成 4×结果，再用 `cv2.INTER_LANCZOS4` 缩到目标尺寸。这样不必为每个倍率维护不同权重，模型输入输出契约也更简单。

代价是 2×并不等于“只做 2×计算”：网络仍产生 4×中间结果，时间与显存成本接近 4×。如果要优化这一点，需要不同倍率的模型，或能原生指定倍率的网络结构，而不是把 `scale` 参数改小便能解决。

## 分块推理：用空间换时间与边界处理

高分辨率图在 4×后面积是原来的 16 倍，特征图更多，显存很容易不足。项目默认 `tile_size=512`：将大图拆为多个小 tile 分别推理，再写入预先分配的输出张量。

```text
原图切块时，每块额外带 tile_pad=10 像素边缘
        ↓
每块独立 4×推理
        ↓
丢弃各块放大后的冗余边缘
        ↓
只把中心有效区写回完整输出图
```

为什么不能直接把 512×512 小块首尾拼接？卷积在边界附近看不到块外上下文，容易产生接缝。重叠边缘让每块在计算中心区域时仍能看见邻居的一小部分；输出时只保留不受边缘影响的中心，接缝风险显著下降。

项目的坐标计算遵守一个重要规则：输入坐标乘以原生倍率 4。例如输入 tile 的 `[left:right, top:bottom]`，输出写入 `[left*4:right*4, top*4:bottom*4]`。这正是张量形状与空间坐标必须同时检查的原因；少乘一次或多乘一次都可能让图片“能生成但拼错位置”。

`tile_size=0` 表示整图推理。它减少循环和边界拼接，却使峰值显存最高；降低 `tile_size` 会降低单次模型输入与中间特征的大小，但通常增加循环次数，速度更慢。正确的排障顺序是：先减小 tile，再降低输入分辨率，最后才考虑 CPU；不能把“显存不足”误诊为模型权重坏了。

## 一次完整的超分张量旅程

`enhance()` 中的简化数据流：

```text
OpenCV BGR uint8 [H, W, 3]
  → BGR 转 RGB，float32 / 255
  → NumPy RGB [H, W, 3]
  → transpose + unsqueeze
  → Tensor [1, 3, H, W]，位于 CPU 或 CUDA
  → Real-ESRGAN 前向推理
  → Tensor [1, 3, 4H, 4W]
  → squeeze、CPU、clamp、NumPy、transpose
  → RGB uint8 [4H, 4W, 3]
  → BGR uint8，必要时 Lanczos 缩至用户倍率
```

这里的 `.clamp(0, 1)` 不应省略：网络输出可能略小于 0 或略大于 1，直接乘 255 并转 `uint8` 会发生不符合期望的截断/环绕风险。先限制合法色彩范围，再量化为整数，是视觉模型后处理的基本步骤。

## 面试速答

**问：RRDB 中 `torch.cat(..., 1)` 的 1 是什么？**

答：在 NCHW 张量中 `1` 是通道维。稠密连接把前面层的特征通道拼接起来，因此后续卷积的输入通道数随之增加；空间高宽和 batch 大小不变。

**问：残差连接有什么作用？**

答：它让模块学习“对输入的修正”而不是完全重建输入，为信息和梯度提供短路径，通常能改善深网络训练稳定性。在超分中也能让网络保留插值/低频主体，聚焦学习高频细节。

**问：为什么分块需要 overlap？**

答：卷积块边缘缺少块外上下文。带重叠边缘推理后裁掉冗余区，只保留每块中心，可减少独立推理造成的接缝。

## 小结

- 卷积通过局部感受野和参数共享处理图像，NCHW 中的通道维承载多组特征图。
- RRDB 的稠密连接复用特征，残差连接让深网络学习增量并更易训练。
- Real-ESRGAN 原生输出 4×；非 4×是后处理缩放，而非更低成本的原生推理。
- 大图分块与重叠裁剪是控制显存且避免接缝的工程折中。
