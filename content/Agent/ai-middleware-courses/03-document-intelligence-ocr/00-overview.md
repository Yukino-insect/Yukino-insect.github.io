一份 PDF 能不能被复制文字，并不能说明程序就真的“读懂”了它。扫描合同、拍照的发票、带复杂表格的报告、Word 导出的 PDF，表面上都是文件，机器面对的却可能分别是字符、像素、坐标、表格线和阅读顺序。**OCR（Optical Character Recognition，光学字符识别）**解决的是把图像中的文字变成机器可处理文字；文档智能则继续回答：这些文字在页面什么位置、谁属于同一段、哪些格子构成一张表、答案能否回到原页核验。

本课程不假定你接触过深度学习或某个业务项目。目标是让你能从零完成一个小实验，逐步理解 OCR 的每一个输出字段、错误从哪里来，以及什么时候才有必要把脚本做成服务。代码以 Python、PaddleOCR 和常见命令行为例；原理并不依赖某个仓库、固定端口或某份 Compose 文件。

## 学完后能做什么

完成课程后，你应能做到：

- 判断输入是可提取文本的 PDF、扫描 PDF，还是普通图片，并选择合适的处理路径；
- 对一张本地图片完成文字检测、文字识别和方向校正，保存可检查的结果；
- 解释 `bbox`、置信度、阅读顺序、表格单元格、页码与来源信息的意义；
- 使用 PaddleOCR 解析简单图片和多页文档，知道表格、公式、印章等能力的代价与边界；
- 将 Office 文档稳定地归一化为 PDF，保留可追溯的页级产物；
- 用通用的异步任务模型封装解析过程，并用 CER/WER、吞吐量、失败率与人工抽样评估它；
- 为部署、隐私、容量、重试和备份建立基本的运行规则。

这并不意味着模型会“理解合同含义”。OCR 输出的是证据和结构化候选：例如第 2 页坐标 `(120, 330, 500, 366)` 附近识别到“总计：128.00”，置信度为 0.93。字段是否合法、金额是否应付款、表格是否能直接入库，仍要由业务规则或人工复核决定。

## 先建立共同语言

### 三类常见输入

**文本层 PDF**内部已经保存了字符和位置。浏览器能选中并复制文字，`pdftotext` 往往能直接取得内容。这时先提取文本通常更快、更准确，也避免 OCR 重新猜一遍。

**扫描 PDF**本质是多页图片被装进 PDF 容器；你拖选到的可能只是整张页图。它必须先渲染成页面图像，再 OCR。

**图片**如 JPG、PNG、手机照片和截图，直接进入图像预处理与 OCR。照片常有透视、阴影、模糊和旋转，通常比扫描仪输出更难处理。

不要只凭扩展名猜类型。`.pdf` 只是容器格式，同一个 PDF 既可能有文字层，也可能一半是文字、一半是扫描页。

### OCR 实际输出什么

最小 OCR 结果至少应包含四部分：

| 信息 | 示例 | 用途 |
| --- | --- | --- |
| 文本 | `增值税普通发票` | 搜索、展示、后续规则 |
| 位置 | 四个顶点或矩形框 | 高亮、排序、回页核验 |
| 置信度 | `0.97` | 发现疑似错误，不是正确性证明 |
| 页/图来源 | `invoice.pdf` 第 3 页 | 追溯、重跑、审计 |

复杂文档还会有方向、语言、段落、标题、图片、表格单元格、公式和阅读顺序。将它们保存为结构化 JSON，而非只拼成一大段文本，是可靠系统与一次性脚本的分界线。

### 一次识别经过哪些步骤

```text
文件
  -> 判断类型（文本 PDF / 扫描 PDF / 图片）
  -> 必要时渲染页面、校正方向、改善图像
  -> 文本检测：哪里有字？
  -> 文本识别：每块写了什么？
  -> 排序与版面分析：应该怎样阅读？
  -> 保存文本 + 坐标 + 置信度 + 来源
  -> 规则校验、人工复核或下游使用
```

“检测”和“识别”是两个不同问题。检测模型画出文字区域，识别模型读取裁出的区域。漏掉一行通常是检测问题；把 `8` 读成 `B` 通常是识别、图像质量或语言模型问题。后面排错时必须先分清这一点。

## 准备环境

建议使用 Python 3.10 或 3.11，并单独创建虚拟环境。CPU 足够完成课程中的小样本实验；若处理大量高分辨率页面或使用视觉语言模型，再考虑 GPU。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install paddleocr paddlepaddle pymupdf pillow opencv-python jiwer fastapi uvicorn python-multipart
```

若安装 GPU 版本的 PaddlePaddle，请以与你的操作系统、Python 和 CUDA 版本匹配的官方安装说明为准；不要在已经能运行的 CPU 环境里随意混装多个 wheel。先验证解释器与包来自同一个环境：

```powershell
python -c "import sys, paddle; print(sys.executable); print(paddle.__version__); print(paddle.device.get_device())"
```

预期会打印虚拟环境中的 Python 路径、Paddle 版本和 `cpu` 或 `gpu:0`。若出现 `ModuleNotFoundError`，最常见原因不是 OCR 模型坏了，而是终端尚未激活虚拟环境。

## 使用自己的样本时的底线

- 不要把真实身份证、病历、合同和密钥提交到公共在线 OCR；先使用脱敏样本。
- 原件、渲染页图和识别结果都可能含个人数据；设置访问权限与清理期限。
- 保存源文件的哈希、页码和模型版本。结果被质疑时，才能回答“它从哪一页来的、由哪次处理产生”。
- 置信度低不必然错误，置信度高也不保证正确。关键字段应有格式校验、交叉校验和人工抽检。

## 本课程的验收方式

每一章都会给出一个可观察结果，而不是让你只看代码。最小验收是：输入一张含中文或英文的清晰图片，得到文字、坐标和置信度；再故意旋转或模糊图片，能说明结果为什么变差。最后，你能把多页文件交给服务，并追溯某条字段回到具体页面。

## 小结

- PDF、扫描件和图片不能用同一条“读文件”路径粗暴处理。
- OCR 是检测与识别的组合；文档智能还要恢复页面结构与来源。
- 文本本身不够，位置、页码、置信度和原始文件身份同样重要。
- 从一张本地图片开始，再扩展到复杂文档和服务化，学习成本最低、错误也最容易定位。
