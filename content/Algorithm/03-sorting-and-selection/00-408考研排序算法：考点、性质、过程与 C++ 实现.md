排序并不只是把一列数字排成递增序。408 更关心的是：给定某个排序过程，能否判断它做了什么；给定一种排序，能否说明它是否稳定、最坏情况下会不会退化、需要多少辅助空间；给定一段代码，能否看出下标、循环边界和比较条件是否正确。把这些问题分开处理，排序题就不必依赖临场猜测。

本文讨论内部排序中最常考的直接插入、折半插入、希尔、冒泡、简单选择、堆、快速、归并和基数排序。默认按关键字非递减顺序排列，所有下标均从 `0` 开始。文末给出考场判断框架和 C++17 代码模板；快速排序、归并排序、堆排序与快速选择的细节也可继续阅读[快速排序](快速排序.md)、[归并排序](归并排序.md)、[堆排序](堆排序.md)和[快速排序：找到第 k 大的数字](快速排序%20找到第%20k%20大的数字.md)。

## 一、先建立判断坐标：稳定性、空间与比较模型

### 1. 什么叫稳定排序

若两个记录的排序关键字相等，排序前在前的记录排序后仍在前，则该算法是**稳定的**。稳定性讨论的是“带相同关键字的不同记录”，而不是数值是否相同。

例如下列记录按分数升序排序：

```text
(70, A), (70, B), (60, C)
```

稳定排序的结果必须是：

```text
(60, C), (70, A), (70, B)
```

若变成 `(60, C), (70, B), (70, A)`，虽然分数有序，却不稳定。数据库按“部门”排序后仍希望同部门员工保留原录入顺序，正是稳定性有实际意义的场景。

要注意两点：

- “这次样例没有交换相等元素”不能证明算法稳定；稳定性是算法对**所有输入**的性质。
- 实现细节会影响稳定性。归并时相等元素若优先取左段，使用 `<=`，可以稳定；若改为严格 `<`，右段的相等元素可能先被取走，稳定性便被破坏。

### 2. 内部排序、外部排序与原地排序

408 此处通常默认讨论**内部排序**：待排记录可全部放入内存。外部排序则面向磁盘或磁带上的大文件，核心是生成有序段和多路归并，不能简单套用数组排序的空间结论。

“原地”常指只使用常数级额外存储，或不额外开与输入同规模的数组。它与稳定性没有必然关系：插入排序原地且稳定，堆排序原地却不稳定；归并排序稳定，但数组实现通常需要 `O(n)` 辅助数组。

### 3. 比较排序与非比较排序

比较排序只通过诸如 `a < b` 的比较获取顺序信息，典型代表是插入、冒泡、选择、堆、快排和归并。任何基于比较的排序，在最坏情况下都不可能突破：

$$
\Omega(n\log n)
$$

直观地说，`n` 个互异元素共有 $n!$ 种排列；一次比较至多提供两种分支，要区分全部排列，决策树至少要有 $n!$ 个叶子，其高度至少为 $\log_2(n!)=\Omega(n\log n)$。

基数排序不靠记录之间的整体比较，而按“某一位的取值”分配，所以可写成 `O(d(n + r))`：`d` 是关键字位数，`r` 是每一位的可能取值数量或基数。它并没有推翻比较排序下界，因为它使用了更强的前提：关键字必须可以按位拆开，且位值范围可控。

## 二、408 必背性质表

下表中，时间复杂度以常见实现和一般输入为准；希尔排序的精确复杂度依赖增量序列，考题若未指定增量，不能随意写成某个唯一结论。

| 算法 | 最好 | 平均 | 最坏 | 辅助空间 | 稳定性 | 关键特点 |
| ---- | ---- | ---- | ---- | -------- | ------ | -------- |
| 直接插入 | `O(n)` | `O(n^2)` | `O(n^2)` | `O(1)` | 稳定 | 初始序列接近有序时很快 |
| 折半插入 | `O(n log n)` 比较 | `O(n^2)` | `O(n^2)` | `O(1)` | 稳定 | 少比较，不少移动 |
| 希尔 | 与增量有关 | 与增量有关 | 常按 `O(n^2)` 记 | `O(1)` | 不稳定 | 分组插入，先消除远距离逆序 |
| 冒泡 | `O(n)` | `O(n^2)` | `O(n^2)` | `O(1)` | 稳定 | 每趟把极值“冒”到边界 |
| 简单选择 | `O(n^2)` | `O(n^2)` | `O(n^2)` | `O(1)` | 不稳定 | 比较次数固定、交换次数少 |
| 堆排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(1)` | 不稳定 | 建堆是 `O(n)`，整体不退化 |
| 快速排序 | `O(n log n)` | `O(n log n)` | `O(n^2)` | 平均 `O(log n)` | 不稳定 | 平均性能好，枢轴决定划分质量 |
| 归并排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` | 稳定 | 分治后合并，适合外部排序思想 |
| 基数排序 | `O(d(n+r))` | `O(d(n+r))` | `O(d(n+r))` | `O(n+r)` | 稳定 | 按位分配与收集，非比较排序 |

这里的“折半插入最好为 `O(n log n)` 比较”说的是在每一趟仍执行二分定位的实现中，比较次数的量级；即便元素已排好，数组中插入位置后的元素搬移很少，整体时间仍常按实现细节讨论。考场上最稳妥的表述是：**折半插入降低比较次数，移动次数仍为 `O(n^2)`，故总时间复杂度并未从 `O(n^2)` 降到 `O(n log n)`。**

稳定口诀可以记为：**插入、冒泡、归并、基数稳定；选择、希尔、快排、堆排序不稳定。** 口诀只用于快速回忆，真正遇到变体时仍要回到“相等记录能否跨越彼此”这一判断标准。

## 三、插入类排序：有序区如何扩张

### 1. 直接插入排序

直接插入排序把前缀 `[0, i - 1]` 视为已经有序，把 `a[i]` 暂存为 `value`，从右向左寻找插入位置。所有大于 `value` 的元素向右移动一位，最后把 `value` 放入空位。

```text
初始：5 | 2 4 1
插入 2：2 5 | 4 1
插入 4：2 4 5 | 1
插入 1：1 2 4 5
```

循环不变式是：每一轮开始前，`a[0..i-1]` 已有序且包含原先的同一批元素。向右移动不会丢失元素，因为待插入值保存在 `value`；插入后有序前缀长度增加一。这也是说明算法正确性的标准写法。

```cpp
void insertionSort(std::vector<int>& a) {
    for (int i = 1; i < static_cast<int>(a.size()); ++i) {
        int value = a[i];
        int j = i - 1;

        // 严格大于才右移；相等元素不跨越 value，因此稳定。
        while (j >= 0 && a[j] > value) {
            a[j + 1] = a[j];
            --j;
        }
        a[j + 1] = value;
    }
}
```

若原序列已递增，每轮只比较一次便停止，总比较次数为 `n - 1`，故最好时间为 `O(n)`。若原序列递减，第 `i` 个元素要越过前面 `i` 个元素，总工作量为：

$$
1+2+\cdots+(n-1)=\frac{n(n-1)}{2}=O(n^2)
$$

因此，题干中的“基本有序”“逆序对较少”通常是直接插入排序的信号。

### 2. 折半插入排序：少比不等于少移

折半插入排序只改进“找插入位置”的步骤：在已有序前缀中二分搜索位置；找到位置后，仍必须把中间元素逐个右移，给新元素让出空位。

```cpp
void binaryInsertionSort(std::vector<int>& a) {
    for (int i = 1; i < static_cast<int>(a.size()); ++i) {
        int value = a[i];
        int left = 0;
        int right = i;  // 半开区间 [left, right)

        // 寻找第一个大于 value 的位置；相等元素留在 value 前面，保持稳定。
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (a[mid] <= value) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        for (int j = i; j > left; --j) {
            a[j] = a[j - 1];
        }
        a[left] = value;
    }
}
```

高频陷阱是“二分查找使插入排序变成 `O(n log n)`”。这是错误的：二分只把第 `i` 趟的比较由 `O(i)` 降到 `O(log i)`，但最坏情况下仍要移动 `O(i)` 个元素。移动总量仍是 `O(n^2)`。

### 3. 希尔排序：为什么能比插入排序更快

希尔排序按一个增量 `gap` 把数组分为若干子序列，并分别做插入排序；随后缩小 `gap`，最后以 `gap = 1` 完成一次普通插入排序。前几轮让相距很远的逆序元素快速接近正确位置，所以最后一轮面对的是“更接近有序”的数组。

```cpp
void shellSort(std::vector<int>& a) {
    const int n = static_cast<int>(a.size());
    for (int gap = n / 2; gap > 0; gap /= 2) {
        for (int i = gap; i < n; ++i) {
            int value = a[i];
            int j = i;
            while (j >= gap && a[j - gap] > value) {
                a[j] = a[j - gap];
                j -= gap;
            }
            a[j] = value;
        }
    }
}
```

它不稳定的原因是：同关键字记录可能在某一趟以较大间隔跨越。例如标记相等记录为 `2A`、`2B`，它们可能分别落在不同的 `gap` 子序列中，较后的 `2B` 可先于 `2A` 被移动到前面。增量序列决定实际效率，题目给出特定增量时，应按该过程手工模拟，而不是背一个固定复杂度。

## 四、交换与选择：每一趟究竟确定了什么

### 1. 冒泡排序：相邻交换带来稳定性

从左到右比较相邻元素，若前者大于后者就交换。第一趟结束后，最大元素到达末尾；第二趟只需处理更短的前缀。若某一趟没有发生交换，数组已经有序，可提前结束。

```cpp
void bubbleSort(std::vector<int>& a) {
    for (int end = static_cast<int>(a.size()) - 1; end > 0; --end) {
        bool changed = false;
        for (int i = 0; i < end; ++i) {
            if (a[i] > a[i + 1]) {
                std::swap(a[i], a[i + 1]);
                changed = true;
            }
        }
        if (!changed) {
            return;
        }
    }
}
```

只有 `>` 才交换，两个相等元素不会互相越过，所以稳定。若代码写成 `>=`，数值仍能排好，但稳定性就没有了。未做“提前结束”优化的朴素版本，即使输入已有序，也会完成全部趟数，时间为 `O(n^2)`；题目应以给出的具体代码为准。

### 2. 简单选择排序：比较少不了，交换确实不多

第 `i` 趟在无序区 `[i, n)` 中选出最小元素，与 `a[i]` 交换。因此每一趟结束时，位置 `i` 上的元素已最终确定。

```cpp
void selectionSort(std::vector<int>& a) {
    const int n = static_cast<int>(a.size());
    for (int i = 0; i < n - 1; ++i) {
        int minIndex = i;
        for (int j = i + 1; j < n; ++j) {
            if (a[j] < a[minIndex]) {
                minIndex = j;
            }
        }
        if (minIndex != i) {
            std::swap(a[i], a[minIndex]);
        }
    }
}
```

第 `i` 趟需要比较 `n-i-1` 次，与输入是否有序无关，总比较次数精确为：

$$
(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}
$$

它至多进行 `n-1` 次交换，因此在“写入或交换代价高、比较代价相对低”的语境中有意义。但它不稳定：

```text
初始：2A, 2B, 1
第 1 趟选出 1，与 2A 交换：1, 2B, 2A
```

`2A` 与 `2B` 的相对顺序被颠倒。不要因为它每趟只交换一次，就误判为稳定。

## 五、堆排序：建堆为何不是 O(n log n)

### 1. 二叉堆的数组下标

对从 `0` 开始存储的完全二叉树，结点 `i` 的关系为：

- 左孩子：`2 * i + 1`；
- 右孩子：`2 * i + 2`；
- 父结点：`(i - 1) / 2`，仅当 `i > 0` 时有效；
- 最后一个非叶结点：`n / 2 - 1`。

升序堆排序使用**大根堆**。先将数组建成大根堆，根是当前最大值；把根交换到无序区末尾，缩小堆范围，再对根执行向下调整。每一轮都把当前最大值固定到最终位置。

```cpp
void siftDown(std::vector<int>& a, int root, int heapSize) {
    while (true) {
        int largest = root;
        int left = 2 * root + 1;
        int right = 2 * root + 2;

        if (left < heapSize && a[left] > a[largest]) {
            largest = left;
        }
        if (right < heapSize && a[right] > a[largest]) {
            largest = right;
        }
        if (largest == root) {
            return;
        }
        std::swap(a[root], a[largest]);
        root = largest;
    }
}

void heapSort(std::vector<int>& a) {
    const int n = static_cast<int>(a.size());

    // 自底向上建大根堆。
    for (int i = n / 2 - 1; i >= 0; --i) {
        siftDown(a, i, n);
    }

    for (int end = n - 1; end > 0; --end) {
        std::swap(a[0], a[end]);
        siftDown(a, 0, end);
    }
}
```

最常见的误区是“有约 `n/2` 个非叶结点，每个调整 `O(log n)`，所以建堆是 `O(n log n)`”。这个上界不紧：越靠近叶子的结点越多，但它们可下沉高度越小。把每层结点数与最大下沉高度相乘并求和，结果为 `O(n)`。建堆后还要进行 `n-1` 次、每次 `O(log n)` 的调整，所以整体仍为 `O(n log n)`。

堆排序不稳定。根与末尾元素交换时，可能让相等记录跨越很长距离；同时它没有像归并那样的“左段优先”机制维持相等记录顺序。

## 六、快速排序：分区条件、退化与递归边界

快速排序的核心不是“递归”二字，而是**一次分区后枢轴处于最终位置**。对区间 `[left, right]` 选取一个枢轴 `pivot`，重排后满足：

```text
[left, pivotPos - 1] <= pivot
a[pivotPos] = pivot
[pivotPos + 1, right] >= pivot
```

左右两部分各自不一定有序，但可独立递归。下面使用 Lomuto 风格分区，并用三数取中减轻接近有序输入的退化风险：

```cpp
int medianIndex(const std::vector<int>& a, int left, int mid, int right) {
    if ((a[left] <= a[mid] && a[mid] <= a[right]) ||
        (a[right] <= a[mid] && a[mid] <= a[left])) {
        return mid;
    }
    if ((a[mid] <= a[left] && a[left] <= a[right]) ||
        (a[right] <= a[left] && a[left] <= a[mid])) {
        return left;
    }
    return right;
}

int partition(std::vector<int>& a, int left, int right) {
    int mid = left + (right - left) / 2;
    int pivotIndex = medianIndex(a, left, mid, right);
    std::swap(a[left], a[pivotIndex]);
    int pivot = a[left];
    int nextLess = left + 1;

    for (int i = left + 1; i <= right; ++i) {
        if (a[i] < pivot) {
            std::swap(a[i], a[nextLess]);
            ++nextLess;
        }
    }
    std::swap(a[left], a[nextLess - 1]);
    return nextLess - 1;
}

void quickSort(std::vector<int>& a, int left, int right) {
    if (left >= right) {
        return;
    }
    int pivotPos = partition(a, left, right);
    quickSort(a, left, pivotPos - 1);
    quickSort(a, pivotPos + 1, right);
}
```

`left >= right` 是递归终止条件：区间长度为 `0` 或 `1` 时无需再排。空数组时也应避免直接让无符号的 `a.size() - 1` 参与运算：

```cpp
if (!a.empty()) {
    quickSort(a, 0, static_cast<int>(a.size()) - 1);
}
```

若每次分区都接近平衡，递归树高约为 `log n`，每层扫描总规模约为 `n`，时间为 `O(n log n)`。若每次都选到最小或最大元素，例如有序数组总取首元素作枢轴，递归式会退化为：

$$
T(n)=T(n-1)+O(n)=O(n^2)
$$

因此“快排平均快”不能写成“快排一定是 `O(n log n)`”。随机枢轴、三数取中可降低坏输入概率；大量重复元素时，三路划分把 `< pivot`、`= pivot`、`> pivot` 分开，能避免等值元素反复进入递归。

快速排序不稳定，因为分区过程中远距离交换的两个元素可能让相等记录跨越彼此。题目若问“一趟快排后哪些元素已在最终位置”，答案是：**本次使用的枢轴已在最终位置；左右区间只满足相对枢轴的大小关系，并未整体有序。**

## 七、归并排序：合并条件决定正确性与稳定性

归并排序将区间不断二分，直到只剩一个元素；单元素区间天然有序，再将相邻的两个有序区间合并。它的正确性建立在一个简单事实之上：两个有序序列各取当前较小者写入结果，写出的下一个元素一定是全部未处理元素中的最小者。

```cpp
void merge(std::vector<int>& a, int left, int mid, int right,
           std::vector<int>& buffer) {
    int i = left;
    int j = mid + 1;
    int k = left;

    // 关键：两边都尚有元素时才能比较 a[i] 与 a[j]。
    while (i <= mid && j <= right) {
        if (a[i] <= a[j]) {  // 相等时先取左边，保证稳定。
            buffer[k++] = a[i++];
        } else {
            buffer[k++] = a[j++];
        }
    }
    while (i <= mid) {
        buffer[k++] = a[i++];
    }
    while (j <= right) {
        buffer[k++] = a[j++];
    }
    for (int p = left; p <= right; ++p) {
        a[p] = buffer[p];
    }
}

void mergeSortImpl(std::vector<int>& a, int left, int right,
                   std::vector<int>& buffer) {
    if (left >= right) {
        return;
    }
    int mid = left + (right - left) / 2;
    mergeSortImpl(a, left, mid, buffer);
    mergeSortImpl(a, mid + 1, right, buffer);
    merge(a, left, mid, right, buffer);
}

void mergeSort(std::vector<int>& a) {
    if (a.empty()) {
        return;
    }
    std::vector<int> buffer(a.size());
    mergeSortImpl(a, 0, static_cast<int>(a.size()) - 1, buffer);
}
```

每层合并会线性处理全部 `n` 个元素，递归深度约为 `log n`，所以任意输入下都是 `O(n log n)`。数组实现需要辅助数组 `buffer`，空间为 `O(n)`；这正是它与快排、堆排序常被放在一起比较的原因。

常见代码错误有三类：

- 终止条件误写为 `left <= right`，会使正常区间直接返回；正确条件是 `left >= right`。
- 合并主循环只写 `i <= mid`，却仍访问 `a[j]`；右段用尽后会越界，必须同时检查 `j <= right`。
- 相等时取右段，或比较改为 `<`；数值可能仍正确，但稳定性被破坏。

## 八、基数排序：为什么每一趟都必须稳定

以最低有效位优先（LSD）为例，先按个位分配与收集，再按十位、百位继续。后一趟按更高位分组时，必须保留先前低位已经建立的相对次序，这正是每一趟稳定的必要性。

对十进制非负整数 `170, 45, 75, 90, 802, 24, 2, 66`：

```text
按个位稳定收集：170, 90, 802, 2, 24, 45, 75, 66
按十位稳定收集：802, 2, 24, 45, 66, 170, 75, 90
按百位稳定收集：2, 24, 45, 66, 75, 90, 170, 802
```

例如在十位相同的记录中，个位排序的结果要被保留下来；若“收集”阶段不稳定，低位信息会丢失，最终不一定整体有序。

```cpp
void radixSortNonNegative(std::vector<int>& a) {
    if (a.empty()) {
        return;
    }

    int maxValue = *std::max_element(a.begin(), a.end());
    std::vector<int> output(a.size());

    for (long long exp = 1; maxValue / exp > 0; exp *= 10) {
        int count[10] = {};
        for (int value : a) {
            ++count[static_cast<int>((value / exp) % 10)];
        }
        for (int digit = 1; digit < 10; ++digit) {
            count[digit] += count[digit - 1];
        }

        // 倒序写入，使相同 digit 的元素保持原先相对顺序。
        for (int i = static_cast<int>(a.size()) - 1; i >= 0; --i) {
            int digit = static_cast<int>((a[i] / exp) % 10);
            output[--count[digit]] = a[i];
        }
        a.swap(output);
    }
}
```

这里假定输入为非负整数；含负数时需要额外处理符号，字符串则要约定字符集、长度和缺失位。不要把基数排序描述成“任何类型都能 `O(n)` 排序”：它依赖位数 `d` 与基数 `r` 足够小的条件。

## 九、排序过程题：从一趟结果反推算法

过程题的关键不是看见“局部有序”就猜算法，而是检查每一趟确定了什么边界与结构。

| 一趟后的典型现象 | 更可能的算法 | 判断理由 |
| ---------------- | ------------ | -------- |
| 前缀长度逐步增加且有序 | 直接 / 折半插入 | 每轮把一个新记录插入有序区 |
| 末尾依次固定最大值 | 冒泡 | 相邻交换将最大值向右推进 |
| 前缀依次固定最小值 | 简单选择 | 每趟在无序区选最小者交换到前端 |
| 整体满足堆序，随后末尾逐步有序 | 堆排序 | 根与末尾交换并重新调整堆 |
| 某元素左侧不大于它、右侧不小于它 | 快排的一次分区 | 枢轴已定位，左右未必分别有序 |
| 长度为 1、2、4、8 的相邻有序段逐步合并 | 归并排序 | 有序子段两两归并 |
| 先按个位、再十位等分配与收集 | 基数排序 | 从低位到高位的稳定排序 |

一道题若只给出“第一趟结果”，可能有多种算法都能产生相同状态。此时应避免过度断言，优先寻找题目是否给出了比较方式、分组间隔、堆序、枢轴或下一趟结果等额外证据。

## 十、考场高频判断与易错点

### 1. 关于比较次数与移动次数

- 简单选择排序的比较次数与初始序列无关，固定为 `n(n-1)/2`；交换次数至多为 `n-1`。
- 冒泡排序、直接插入排序会受初始有序程度影响；加入提前结束标志的冒泡在已排序时可为 `O(n)`。
- 折半插入减少比较次数，但元素后移仍可能是二次量级。
- 快排的比较与移动取决于每次枢轴划分是否平衡；不能只因它叫“快速”便忽略最坏情况。

### 2. 关于稳定性

稳定性常由一个很小的符号决定：

- 插入排序从右向左移动时，使用 `a[j] > value`，不能使用 `>=`。
- 冒泡排序使用 `a[i] > a[i + 1]`，不能使用 `>=`。
- 归并排序相等时应优先取左段，即 `a[i] <= a[j]`。
- 简单选择、堆、快排、希尔即使刻意避免某些相等元素交换，也无法保证所有输入均不发生跨越，因此通常仍是不稳定排序。

### 3. 关于空间复杂度

- 递归快排的栈空间平均为 `O(log n)`，极端划分会达到 `O(n)`。
- 递归归并除辅助数组外还有 `O(log n)` 调用栈，但总辅助空间仍按 `O(n)` 计。
- 堆排序一般只用少数变量，辅助空间 `O(1)`；不要把“堆”误解成必须另开一个堆数组。

### 4. 关于“哪种算法更好”

不存在脱离条件的最优排序。

```mermaid
flowchart TD
    A[先看题目约束] --> B{关键字能按位处理且范围可控？}
    B -- 是 --> C[考虑基数排序]
    B -- 否 --> D{要求稳定？}
    D -- 是 --> E{内存允许 O(n) 辅助数组？}
    E -- 是 --> F[归并排序]
    E -- 否 --> G[小规模或近乎有序时考虑插入排序]
    D -- 否 --> H{必须保证最坏 O(n log n)？}
    H -- 是 --> I[堆排序]
    H -- 否 --> J[快速排序通常平均性能优良]
```

这张图是在说明取舍，不是在替代题目条件。实际选择还要考虑数据规模、是否近乎有序、写入成本、递归深度和实现复杂度。

## 十一、最后一页复习清单

进入考场前，至少能不看资料回答下面的问题：

- 稳定排序是哪四种：直接插入、冒泡、归并、基数；不稳定排序为什么可能让相等记录跨越。
- 为什么折半插入没有把总复杂度降为 `O(n log n)`：移动次数仍可能为 `O(n^2)`。
- 为什么建堆是 `O(n)`：大量结点在低层，可下沉高度很小。
- 为什么快排最坏为 `O(n^2)`：连续产生规模为 `n-1` 的单边子问题。
- 为什么归并排序稳定：合并时相等元素优先取左段。
- 为什么 LSD 基数排序的每一趟必须稳定：高位排序不能破坏已建立的低位次序。
- 为什么同一排序算法的“最好时间”有时取决于代码：例如冒泡是否有 `changed` 提前退出标志。

排序题真正可靠的解法是把“本趟已确定什么”“未处理区间满足什么不变式”“相等元素会不会跨越”“复杂度由比较、移动还是递归深度决定”逐项写清。这样即使题目换了数组、改了代码风格，结论也不会跟着漂移。
