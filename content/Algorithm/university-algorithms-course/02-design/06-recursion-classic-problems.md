排列、整数划分和汉诺塔表面上没有多少共同点：一个枚举顺序，一个数方案数，一个移动圆盘。但它们都要求先回答同一个问题：**一个递归调用究竟代表什么子问题？**

递归正确性来自“规模更小的同类问题已经被正确解决”；复杂度则来自“每层分出多少分支、递归到多深”。把这两个事实说清楚，代码才不只是碰巧通过样例。

## 一、排列：用交换固定当前位置

给定 $n$ 个互不相同的元素，排列问题要求枚举它们所有可能的顺序，共有 $n!$ 个。定义 `dfs(pos)` 为：数组下标 `[0, pos)` 已经固定，枚举其余位置的所有排列。第 `pos` 个位置可从 `[pos, n)` 任取一个元素，与它交换后递归处理下一个位置。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

void dfs(vector<int>& a, int pos) {
    if (pos == static_cast<int>(a.size())) {
        for (int x : a) cout << x << ' ';
        cout << '\n';
        return;
    }

    for (int i = pos; i < static_cast<int>(a.size()); ++i) {
        swap(a[pos], a[i]);
        dfs(a, pos + 1);
        swap(a[pos], a[i]);
    }
}

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int& x : a) cin >> x;
    dfs(a, 0);
}
```

第二次 `swap` 不是装饰，它负责恢复父调用进入本轮循环前的状态。没有恢复，下一次循环会在被前一分支污染的数组上继续，枚举便无法保证正确或完整。

### 正确性与复杂度

在 `dfs(pos)` 中，循环让每个尚未固定的元素恰好一次成为 `pos` 位置的元素；之后递归按归纳假设枚举剩余元素的全部排列。首元素不同的两组排列互不重叠，因此既不遗漏也不重复。到 `pos=n` 时，所有位置均已固定，输出一个完整排列。

搜索树第 0 层有 $n$ 个选择，第 1 层有 $n-1$ 个，直到叶子，因此有 $n!$ 个叶子。若将一次排列输出的 $n$ 个元素也计入时间，总时间为 $\Theta(n\cdot n!)$；若只计生成每个叶子的搜索开销，常写上界 $O(n!)$。递归栈深度为 $O(n)$，原地交换的辅助空间也是 $O(n)$（主要是调用栈）。

元素有重复时，上述程序会产生重复排列。可在每层使用集合记录已尝试的值，或先排序并跳过同层相同元素；“不同输入元素”和“不同排列结果”不可混为一谈。

## 二、整数划分：先规定“顺序不重要”

正整数 $n$ 的**整数划分**是把它写成若干个正整数之和，并且加数顺序不区分。例如 $4$ 有五种划分：

$$
4;\quad3+1;\quad2+2;\quad2+1+1;\quad1+1+1+1
$$

若把 $3+1$ 和 $1+3$ 算作不同结果，那是有序分拆，不是通常所说的整数划分。为了杜绝重复，定义 $p(n,m)$ 为“把 $n$ 划分为不超过 $m$ 的正整数之和”的方案数。对 $m>n$，显然 $p(n,m)=p(n,n)$。

当 $1\le m\le n$ 时，方案按“是否使用至少一个 $m$”分为互斥两类：

- 不使用 $m$：方案数为 $p(n,m-1)$；
- 至少使用一个 $m$：先取走一个 $m$，剩余 $n-m$ 仍只能用不超过 $m$ 的数，方案数为 $p(n-m,m)$。

于是有：

$$
p(n,m)=p(n,m-1)+p(n-m,m)
$$

边界是 $p(0,m)=1$（恰有一种“什么也不再加”的完成方式）和 $p(n,0)=0$（正数无法由不超过 0 的正整数构成）。这个 `1` 十分关键；若把它写成 0，所有方案数都会被悄悄抹掉。

### 记忆化实现

纯递归会反复计算同一个 `(remaining, maxPart)`，例如 `p(5,3)` 可经不同路径多次到达。下面使用记忆化，将每个状态只计算一次。

```cpp
#include <iostream>
#include <vector>
using namespace std;

long long countPartitions(int remaining, int maxPart,
                          vector<vector<long long>>& memo) {
    if (remaining == 0) return 1;
    if (maxPart == 0) return 0;
    if (maxPart > remaining) return countPartitions(remaining, remaining, memo);

    long long& answer = memo[remaining][maxPart];
    if (answer != -1) return answer;
    answer = countPartitions(remaining, maxPart - 1, memo)
           + countPartitions(remaining - maxPart, maxPart, memo);
    return answer;
}

int main() {
    int n;
    cin >> n;
    vector<vector<long long>> memo(n + 1, vector<long long>(n + 1, -1));
    cout << countPartitions(n, n, memo) << '\n';
}
```

状态数至多为 $(n+1)^2$，每个状态只做常数次转移，时间和辅助空间均为 $O(n^2)$。这里的“递归”与“动态规划”并不冲突：递归给出自然的状态分解，记忆化用表格消除重叠子问题。

## 三、汉诺塔：先移动阻挡，再移动目标

汉诺塔有三根柱子和大小不同的 $n$ 个盘子。初始盘子从小到大叠在起点，目标是在不把大盘放在小盘上的前提下移到终点。要移动最大的第 $n$ 个盘子，必须先把上面的 $n-1$ 个盘子全部移到辅助柱；随后移动最大盘；最后再把那 $n-1$ 个盘子移到终点。

```cpp
#include <iostream>
using namespace std;

void hanoi(int n, char from, char auxiliary, char to) {
    if (n == 0) return;
    hanoi(n - 1, from, to, auxiliary);
    cout << "move disk " << n << " from " << from << " to " << to << '\n';
    hanoi(n - 1, auxiliary, from, to);
}

int main() {
    int n;
    cin >> n;
    hanoi(n, 'A', 'B', 'C');
}
```

### 为什么 $2^n-1$ 步不可避免

最大盘移动前，上面的 $n-1$ 个盘子必须离开起点；最大盘移动后，这 $n-1$ 个盘子必须再叠到它上面。因此任何合法方案至少需要两次解决规模为 $n-1$ 的同类问题，再加一次移动最大盘：

$$
H(n)\geq2H(n-1)+1
$$

上面的算法恰好按这个次数完成，故为最优。配合 $H(0)=0$，解得：

$$
H(n)=2^n-1
$$

这也是一道重要的规模直觉课：$n=20$ 已需要 1,048,575 步；若每秒移动一次，64 个盘子需要的时间远超过人类历史。递归栈却仅为 $O(n)$，再次说明低空间不能挽救指数级时间。

## 四、三道题背后的统一检查表

| 问题 | 递归状态 | 分支 | 终止条件 | 关键风险 |
| ---- | -------- | ---- | -------- | -------- |
| 排列 | 已固定到哪个位置 | 选择下一个元素 | 所有位置固定 | 忘记撤销交换、重复元素 |
| 整数划分 | 剩余和与最大允许加数 | 用或不用当前最大加数 | 剩余为 0 | 把顺序不同误算为不同划分 |
| 汉诺塔 | 移动前 $n$ 个盘子 | 先移上层、再移最大盘、再复原上层 | $n=0$ | 低估指数级移动次数 |

写递归前，先用一句话写清函数的输入、输出和它所代表的子问题。随后列出：规模如何变小、所有选择是否被枚举、共享状态如何恢复、基例是否真能停止。这比先敲出 `dfs` 更可靠，尽管后者看起来往往更省事。

## 五、总结

- 排列是回溯枚举：每层固定一个位置，恢复状态保证分支独立。
- 整数划分利用“是否使用最大部件”的互斥分类；记忆化把重复递归降为 $O(n^2)$ 状态计算。
- 汉诺塔的递归不仅可行，而且由最大盘的约束可证明最少移动次数就是 $2^n-1$。

递归不是“函数调用自己”这一句语法描述，而是一种将答案按规模更小、结构相同的子问题拆开的证明方式。理解这一点后，分治、回溯与动态规划之间的关系也会清楚得多。
