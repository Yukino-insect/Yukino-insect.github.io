线性表、栈和队列常被误认为是最简单的一章，因而最容易在选择题和代码题里丢掉不该丢的分。它们的难点不在 API 名字，而在于区分**逻辑结构**和**存储结构**：栈、队列规定的是访问规则；顺序存储、链式存储规定的是如何把结点放进内存。不要把“栈”直接等同于“数组”，就像不能把“排队”误解成必须站成某一种队形。

## 一、线性表：顺序表与链表如何取舍

线性表是具有相同数据类型的有限序列，除首尾元素外，每个元素有唯一直接前驱和后继。顺序表用连续内存保存元素；链表用结点指针建立逻辑相邻关系。

| 操作 | 顺序表 / `std::vector` | 单链表（已知头指针） | 原因 |
| ---- | ----------------------- | -------------------- | ---- |
| 按第 `i` 位访问 | `O(1)` | `O(n)` | 连续地址可直接计算；链表必须逐个走 |
| 已知位置插入/删除 | `O(n)` | `O(1)` | 顺序表要移动元素；链表只改相邻指针 |
| 查找值 | `O(n)` | `O(n)` | 都可能需要遍历 |
| 尾部追加 | 均摊 `O(1)` | 有尾指针时 `O(1)` | `vector` 扩容时偶尔整体搬迁 |

“链表插入是 `O(1)`”必须带前提：你已经拿到了插入位置的前驱结点。若题目给的是第 `i` 个位置，先定位前驱本身就是 `O(n)`。这是考试很喜欢省略、也很喜欢追问的一句前提。

## 二、栈：后进先出与括号匹配

栈（stack）只允许在一端进行插入和删除，插入叫入栈 `push`，删除叫出栈 `pop`，遵循后进先出（LIFO）。递归调用、表达式求值、括号匹配都依赖这一性质。

括号匹配的规则是：遇到左括号入栈；遇到右括号时，栈顶必须是配对左括号，然后出栈；扫描结束后栈还必须为空。下面是可运行的 C++17 示例：

```cpp
#include <iostream>
#include <stack>
#include <string>

bool isMatched(char left, char right) {
    return (left == '(' && right == ')') ||
           (left == '[' && right == ']') ||
           (left == '{' && right == '}');
}

bool validBrackets(const std::string& expression) {
    std::stack<char> st;

    for (char ch : expression) {
        if (ch == '(' || ch == '[' || ch == '{') {
            st.push(ch);
        } else if (ch == ')' || ch == ']' || ch == '}') {
            if (st.empty() || !isMatched(st.top(), ch)) {
                return false;
            }
            st.pop();
        }
    }

    return st.empty();
}

int main() {
    std::cout << std::boolalpha;
    std::cout << validBrackets("a * (b + [c - d])") << '\n';  // true
    std::cout << validBrackets("([)]") << '\n';                // false
}
```

时间复杂度是 `O(n)`，辅助空间最坏是 `O(n)`。不能只在遇到右括号时判断栈不空；`([)]` 的栈当然不会空，但嵌套次序错了。栈的价值正是保存最近尚未配对的左括号。

## 三、队列：循环队列中 `front`、`rear` 的含义

队列（queue）在队尾入队、队头出队，遵循先进先出（FIFO）。顺序队列若只让下标递增，即使数组前面已有空位也可能“假溢出”；循环队列把数组看成首尾相接的环，用取模运算复用位置。

下面的实现约定：`front` 指向队头元素，`rear` 指向下一个可插入位置，另用 `count` 区分空和满。因此容量为 `capacity` 的数组可以存满 `capacity` 个元素。

```cpp
#include <iostream>
#include <stdexcept>
#include <vector>

class CircularQueue {
public:
    explicit CircularQueue(std::size_t capacity)
        : data_(capacity) {
        if (capacity == 0) {
            throw std::invalid_argument("capacity must be positive");
        }
    }

    bool empty() const { return count_ == 0; }
    bool full() const { return count_ == data_.size(); }

    void push(int value) {
        if (full()) {
            throw std::overflow_error("queue is full");
        }
        data_[rear_] = value;
        rear_ = (rear_ + 1) % data_.size();
        ++count_;
    }

    int pop() {
        if (empty()) {
            throw std::underflow_error("queue is empty");
        }
        const int value = data_[front_];
        front_ = (front_ + 1) % data_.size();
        --count_;
        return value;
    }

private:
    std::vector<int> data_;
    std::size_t front_ = 0;
    std::size_t rear_ = 0;
    std::size_t count_ = 0;
};

int main() {
    CircularQueue queue(3);
    queue.push(10);
    queue.push(20);
    std::cout << queue.pop() << '\n';  // 10
    queue.push(30);
    queue.push(40);                     // rear 回绕到数组开头
    std::cout << queue.pop() << ' ' << queue.pop() << ' ' << queue.pop() << '\n';
}
```

另一种教材常见方案不设 `count`，而是故意浪费一个数组单元：空队列条件为 `front == rear`，满队列条件为 `(rear + 1) % maxSize == front`。此时实际容量是 `maxSize - 1`。两种方案都正确，但公式来自不同约定，绝不能混写。

## 四、易错点与考点归纳

- 逻辑结构强调元素关系；存储结构强调内存实现。栈可以顺序存储，也可以链式存储。
- 顺序表插入时应先检查容量，再从后向前移动元素；删除时从前向后移动后继元素。方向写反会覆盖未搬走的数据。
- 单链表删除目标结点 `p` 时，通常需要其前驱 `pre` 才能写 `pre->next = p->next`；仅知道 `p` 并不能普遍做到删除。
- 栈为空时不能调用 `top` 或 `pop`，队列为空时不能出队；这是下溢。固定容量结构满时再入是上溢。
- 循环队列的取模是为了下标回绕，不表示元素已经按数值排序。

## 五、总结

线性表题先问“是否需要随机访问”，再问“是否频繁在已知位置插删”；栈题先找最后一个未完成的任务；队列题先找最早等待的任务。复杂度结论不是标签，而是由连续存储、指针跳转和受限访问这些约束推出来的。把前提写清楚，简单的数据结构就不会再用细节给你出难题。
