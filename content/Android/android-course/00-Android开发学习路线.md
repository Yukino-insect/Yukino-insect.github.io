你已经会 Java，接下来最重要的并不是立刻记住某个控件有哪些属性。Android 是一个由操作系统托管的应用平台：系统创建组件、调度生命周期、分发输入事件，并把资源、权限、打包和安装纳入同一套规则。先看清这些角色，XML、`R`、`Activity`、监听器和 APK 才会成为同一条链路上的对象，而不是一堆需要背诵的名词。

本系列以 **Java + 传统 View/XML** 为主线。这是理解 XML、`R.id`、`Activity`、布局和监听器最直接的路径。现代 Android 同样支持 Kotlin 与 Jetpack Compose；它们改变的是 UI 的表达方式，并没有取消 Android 的组件、资源、生命周期、线程、权限和构建边界。先把底层约定学明白，再选择新工具，通常更省时间。

## 学完以后能够做什么

完成本系列并跟着最后一篇动手后，你应当能够：

- 画出 Android 应用进程、系统、`Activity`、窗口、`ViewGroup` 与 `View` 的基本关系，并解释桌面图标为什么不是一个普通 Java `main` 方法启动的。
- 看懂 Android Studio 创建的项目：Gradle、Manifest、源代码、`res/`、`assets/` 分别由谁使用、在什么时候生效。
- 使用 XML 描述界面，理解资源 ID 如何由构建过程生成并被 `R` 类引用；也能判断何时适合在 Java 中动态创建 View。
- 为图片、字符串、尺寸、颜色、主题和不同屏幕/语言版本组织资源，而不是把所有文件随意堆进同一个目录。
- 写出生命周期安全的 `Activity`，让按钮、输入框、键盘和异步任务在正确的线程与正确的时机协作。
- 安全地嵌入 `WebView`，正确声明网络权限，并知道它不是可以对不可信网页放任自流的浏览器。
- 理解布局、事件分发、回调、主线程消息队列、Gradle 构建、APK 签名及重新打包各自解决的问题。

## 课程地图

### 第一部分：先建立 Android 的对象模型

1. [Android 应用架构与 UI 对象树](01-Android应用架构与UI对象树.md) 从桌面启动、`Activity`、`Window` 到 `View` 树解释一个屏幕究竟由谁显示；同时认识常用基础控件与 XML/代码两种创建方式。
2. [Android 工程结构与 Gradle 配置](02-Android工程结构与Gradle配置.md) 拆开 Android Studio 项目，说明模块、Manifest、SDK 版本、依赖、构建变体和 Gradle 各自的职责。
3. [Android 资源系统、XML 与 R 类](03-Android资源系统、XML与R类.md) 将 `res/` 的限定目录、资源编译、`R` 类、`@` 引用与 Java 访问方式连成一条可验证的编译链。
4. [Android 视图属性、ID 与布局 XML](04-Android视图属性、ID与布局XML.md) 解释 XML 的固定语法、命名空间、`id`、`layout_width`、`layout_height` 与运行时 `findViewById` 的关系。

### 第二部分：让屏幕成为受系统管理的组件

5. [WebView、网络权限与安全边界](05-WebView网络权限与安全边界.md) 用一个最小网页加载示例说明 `INTERNET` 权限、WebView 设置、生命周期处理与不可信内容的边界。
6. [Activity 生命周期与组件通信](06-Activity生命周期与组件通信.md) 解释 Activity 为什么是应用界面的关键组件，并把启动、恢复、暂停、保存状态、Intent 和结果回传放进同一个时间线。
7. [Android 事件分发、监听器与键盘输入](07-Android事件分发、监听器与键盘输入.md) 从触摸到点击、从焦点到软键盘，理解监听器不是“自动执行”的魔法，而是系统事件循环中的回调。
8. [回调接口与异步 UI 更新](08-回调接口与异步UI更新.md) 把 Java 接口回调、网络/耗时任务、主线程和生命周期收敛到一个可避免泄漏与崩溃的写法。

### 第三部分：布局、构建与一个完整闭环

9. [Android 布局：约束、线性、帧与定位](09-Android布局：约束、线性、帧与定位.md) 将 Android 的布局模型和 CSS 对照，重点掌握 `ConstraintLayout`、`LinearLayout`、`FrameLayout` 与少量必要的定位。
10. [Android 工具链、构建与 APK 签名](10-Android工具链、构建与APK签名.md) 认识 SDK、ADB、模拟器、Logcat、Gradle、debug/release、APK/AAB、签名和“重新打包”的真实边界。
11. [从点击到渲染：事件循环与主线程](11-从点击到渲染：事件循环与主线程.md) 将监听、回调和生命周期再向下连接到 Looper、MessageQueue 与 UI 渲染节奏，建立排查卡顿的基础。
12. [Android 入门项目：待办清单闭环](12-Android入门项目：待办清单闭环.md) 把前面的界面、资源、事件、状态、生命周期和异步更新组合为一个小应用，检验是否已能独立完成最小闭环。

## 开始前的环境约定

建议安装 Android Studio 的稳定版，并在 SDK Manager 中安装一个近期稳定的 Android SDK Platform、Build-Tools、Platform-Tools 和一个模拟器系统镜像。示例中的确切版本号会随 Android Studio 更新而变化，因此不要为了和文章截图一致而刻意安装过期版本；应在新项目向导或官方兼容性提示中选择彼此兼容的版本。

本系列假设你已理解 Java 类、接口、继承、异常、集合和基本线程概念。若某段 Java 语法陌生，先停下来在一个普通 Java 程序中验证它；Android 只是把 Java/Kotlin 代码放进更严格的系统运行环境，并不会替语言本身补课。

## 推荐的学习方法

每篇文章都按“对象是什么 → 为什么需要它 → 最小代码如何运行 → 边界在哪里”的顺序展开。请先运行最小示例，再有目的地修改一两个值，例如资源名称、布局约束或回调时机，并观察 Logcat 与界面变化。直接复制一大段代码而不验证输入、输出和发生时机，最后只会得到一个看起来能运行、实际无法解释的工程。

尤其要反复区分下面几组概念：

- `Activity` 是受系统调度的界面组件；`View` 是屏幕上可测量、可绘制、可接收事件的对象。二者不是同一种东西。
- XML 是声明 UI 或资源的数据；`R` 是构建期生成的资源索引；它不是运行时万能资源管理器，也不是手写业务类。
- 监听器和回调描述“以后发生某事时调用我”；它们不会把耗时工作自动移出主线程。
- `debug` 包便于开发，`release` 包需要稳定签名与收缩策略；修改他人的 APK 与构建自己的应用是性质不同的事情。

## 总结

- Android 入门的主线是：**系统托管组件 → 资源和 UI 描述 → 生命周期与输入事件 → 主线程与异步 → 构建、签名和交付**。
- 课程刻意使用传统 View/XML，因为它能把 `R`、`res`、`id`、布局和监听器完整地显露出来；理解后再迁移到 Compose 会更从容。
- 完成第 12 篇时，不要只保存代码。请尝试给待办清单增加一个字段、一个资源限定符或一次横竖屏恢复逻辑；能够解释自己改动经过了哪些系统与构建环节，才算真正入门。
