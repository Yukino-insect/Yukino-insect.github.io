前面已经写过 `OnClickListener` 和回调接口。若只停在“给按钮设置监听器”，你仍很难解释为什么网络请求后更新 TextView 会崩溃、为什么一个循环会让界面卡住。本章把这些现象放回 Android 的事件循环：**主线程持续从消息队列取出任务，执行后再处理下一件事。**

## 一次点击的时间线

```text
触摸屏产生输入
  -> 系统把输入递交给应用窗口
  -> View 树执行触摸事件分发
  -> Button 识别一次有效点击
  -> 调用 OnClickListener.onClick
  -> 代码修改状态或请求后台工作
  -> 下一帧测量/布局/绘制，屏幕显示新状态
```

在这条链路中，`onClick` 默认运行在主线程。主线程既要处理输入、生命周期回调、动画和绘制，也要调度大多数 UI 回调；它被一段耗时工作占住时，队列后面的触摸与绘制只能等待。因此“点击没反应”不一定是监听器没注册，可能是它注册了，却迟迟没有机会执行。

## Looper、MessageQueue 与 Handler

每个线程都可以有消息循环，应用启动时 Android 会为主线程准备 `Looper` 和 `MessageQueue`。`Looper` 不断取出队列中的消息/任务并执行；`Handler` 是向某个 Looper 投递任务的接口。下面的写法把 UI 修改明确投递回主线程：

```java
Handler mainHandler = new Handler(Looper.getMainLooper());

ExecutorService executor = Executors.newSingleThreadExecutor();
executor.execute(() -> {
    String result = loadFromNetwork(); // 后台线程：可能耗时
    mainHandler.post(() -> {
        titleView.setText(result);      // 主线程：安全更新 UI
    });
});
```

这里 `ExecutorService` 执行耗时任务，`Handler` 只负责把一个短小的 UI 更新排回主队列。两者不要混为一谈。更现代的项目常使用 Kotlin 协程、`ViewModel` 和 `LiveData`/`StateFlow` 管理异步状态，但它们仍需要遵守“UI 在主线程更新、耗时工作不堵主线程”的原则。

## 为什么不能从后台线程随便改 View

View 树的测量、布局、绘制和事件处理由主线程串行协调。若多个线程同时改同一棵树，会产生难以确定的竞争：一个线程正在布局，另一个线程改变了文本或移除了 View，系统无法保证一致性。因此 Android 会对许多 View 操作检查线程，常见结果是 `CalledFromWrongThreadException`。

“使用 `runOnUiThread` 就好了”也不是完整答案。它只能解决一次 UI 更新的线程归属，不能解决：Activity 是否已经销毁、请求是否过期、任务是否应取消、同一数据是否乱序返回。第 8 篇会用生命周期与状态把这些边界收好。

## 卡顿、ANR 与帧预算

屏幕通常以约 60Hz 或更高刷新率工作；以 60Hz 为例，一帧的时间预算约为：

$$
\frac{1000\ \text{ms}}{60} \approx 16.7\ \text{ms}
$$

这里的 $1000\ \text{ms}$ 是一秒，60 是每秒 60 帧。若主线程在一帧中执行的输入、布局、绘制和业务代码超过这个量级，系统可能跳过一帧，用户就会感到不连续。连续执行数据库、大图解码、网络 I/O 或大循环还可能触发 ANR（应用无响应）提示。

优化第一步不是到处开线程，而是确认工作在哪里发生、耗时多少、是否真的需要发生。使用 Android Studio Profiler、System Trace 或 Logcat 的慢调用线索，先测量再决定是否缓存、分批、降采样或移到后台。

## 一个容易写错的例子

```java
button.setOnClickListener(v -> {
    String data = downloadLargeFile(); // 错：主线程网络与磁盘工作
    resultView.setText(data);
});
```

正确的最小改写是把下载移到后台，并在回到主线程前检查页面仍是否有效：

```java
button.setOnClickListener(v -> executor.execute(() -> {
    try {
        String data = downloadLargeFile();
        runOnUiThread(() -> {
            if (!isFinishing() && !isDestroyed()) {
                resultView.setText(data);
            }
        });
    } catch (IOException error) {
        runOnUiThread(() -> showError(error.getMessage()));
    }
}));
```

这仍只是教学中的最小版本：真实项目还应处理取消、加载态、重试、超时、配置变更和状态保存。重点是数据工作与呈现工作被明确分开，且异常不会悄悄丢失。

## 总结

- 监听器回调通常在触发它的线程执行；按钮点击默认在主线程，不会自动变成后台任务。
- 主线程以消息队列串行处理输入、生命周期和 UI；`Handler` 可以把短任务投递到指定 Looper。
- 后台线程处理网络、磁盘和重计算，主线程处理短小的 UI 状态更新。
- 卡顿是时间预算被占满的结果；先测量、再定位、最后才选择并发或算法优化。
