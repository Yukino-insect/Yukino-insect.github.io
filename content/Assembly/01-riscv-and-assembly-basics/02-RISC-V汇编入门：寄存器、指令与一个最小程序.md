如果你从未写过汇编，可以先把它当作一种直接写给 CPU 的极简语言：一条指令通常只做一件小事，例如“两个寄存器相加”“从某个地址读 8 字节”“条件成立就跳到另一行”。它没有 C 语言的变量、数组名和 `if` 替你遮住细节；代价是更啰嗦，收益是每一步发生了什么都能被准确说清。

RISC-V 不是某一颗具体 CPU 的品牌，而是一套公开的**指令集架构**（Instruction Set Architecture，ISA）。ISA 是软件与硬件之间的合同：它规定软件能看见哪些寄存器、每条指令做什么、机器码怎样编码，以及特权状态怎样组织。不同厂商的芯片或 QEMU 这样的模拟器，可以有完全不同的内部实现；只要遵守同一 ISA，程序可见的机器语言规则就相同。

| 名称 | 是什么 | 类比 |
| --- | --- | --- |
| RISC-V ISA | 指令与状态的规范 | 汉语的语法和字典 |
| CPU 实现（芯片、QEMU） | 依规范取指并执行的硬件或模拟器 | 说汉语的具体人 |
| 汇编器、链接器 | 将汇编文本组织为机器码的工具 | 把稿子排版、装订成书的工具 |

本文学习读 xv6 `entry.S` 所需的 RISC-V 基础：寄存器、算术指令、内存读写、立即数、跳转与 CSR。目标不是背下整张指令表，而是拿到一段代码时能回答四个问题：**数据在哪里？这一条读什么？改什么？下一条会到哪里？** 若还不知道 CPU 怎样取指和执行，可先读 [CPU 怎样执行程序：从内存、寄存器到取指译码执行](01-CPU怎样执行程序：从内存、寄存器到取指译码执行.md)。

## 一、RV64 与扩展名

常见的目标名是：

```text
rv64imac
```

| 部分 | 含义 |
| --- | --- |
| `rv64` | 通用整数寄存器的主要宽度为 64 位；指针和普通长整数通常按 64 位处理 |
| `i` | 基础整数指令集 |
| `m` | 乘除法扩展，例如 `mul` |
| `a` | 原子操作扩展 |
| `c` | 压缩指令扩展；部分指令可以编码为 16 位 |

因此 xv6 中的 `mul` 并不是“所有 RISC-V 必然都有”的指令，而依赖 M 扩展。xv6/QEMU 目标包含它，所以可以直接乘法计算栈偏移。`RV32I` 与 `RV64I` 都有 32 个通用寄存器，主要区别在每个寄存器的宽度是 32 位还是 64 位；浮点 `F`/`D`、向量 `V` 等也都是扩展，只是本篇暂不需要它们。

## 二、执行汇编时，持续追踪寄存器、内存和 PC

CPU 执行一条指令时，最常处理三类状态：

- **寄存器**：CPU 内部数量很少、读取很快的小格子；RV64 的整数寄存器每个保存 64 位比特。
- **内存**：大量按地址编号的字节；程序的指令和数据都放在这里。
- **PC（程序计数器）**：保存下一条要取的指令地址。普通执行后前进，分支和跳转会改变它。

汇编里的 `a0`、`sp` 不是内存变量名，而是寄存器别名。`addi a0, a0, 1` 意为读取 `a0` 的旧值、加一、写回同一寄存器。若要触碰内存，必须明确写加载（load）或存储（store）指令；这正是 RISC-V 的 **load/store 架构**。以后分析一段程序，请在纸上至少画出“关键寄存器、关键内存地址、PC/下一标签”三栏，不要用“它大概在初始化”代替推理。

## 三、32 个通用寄存器与 ABI 别名

RISC-V 的通用整数寄存器编号为 `x0` 到 `x31`。汇编更常使用 ABI 名称，因为名称说明其在函数调用中的惯例角色。

| 编号 | ABI 名 | 常见职责 |
| --- | --- | --- |
| `x0` | `zero` | 恒为 0，写入无效 |
| `x1` | `ra` | 返回地址；`call` 通常把“回来该去哪”放在这里 |
| `x2` | `sp` | 栈指针；指向当前函数可用的栈区域 |
| `x5`–`x7` | `t0`–`t2` | 临时寄存器 |
| `x8`–`x9` | `s0`/`fp`、`s1` | 被调用者保存寄存器 |
| `x10`–`x17` | `a0`–`a7` | 参数寄存器，`a0`/`a1` 也用于返回值 |
| `x18`–`x27` | `s2`–`s11` | 被调用者保存寄存器 |
| `x28`–`x31` | `t3`–`t6` | 临时寄存器 |

`a0`、`t0`、`s0` 的硬件能力并无本质不同：都能放一个 64 位值或地址。不同点是 ABI 约定谁负责保留旧值：`a` 和 `t` 通常可被被调用函数覆盖，`s` 若被函数使用则需要在返回前恢复。`sp` 和 `ra` 则有特殊的函数调用意义。

这份“谁保存”的规则不是硬件自动施加的保护。函数若使用 `s0`，必须在进入时把旧 `s0` 存到栈上、返回前恢复；它却可自由覆盖 `t0`、`a0`。所以看见 `a0` 不要只念“第十号寄存器”，而应想到它常承载第一个参数或返回值。函数调用与栈帧会在 [函数调用与栈：RISC-V ABI、sp、ra 和栈帧](<04-函数调用与栈：RISC-V ABI、sp、ra 和栈帧.md>) 中完整说明。

### `zero` 为什么很有用

`x0` 总是读为 0：

```asm
add     a0, a1, zero  # a0 = a1
beq     a0, zero, L   # 若 a0 为 0 则跳转
```

硬件提供这个固定零值，让复制、比较零和构造某些伪指令更简单。

## 四、怎样读一条 RISC-V 指令

很多算术指令遵循：

```text
操作  目标寄存器, 源寄存器 1, 源寄存器 2/立即数
```

### 寄存器算术

```asm
add     sp, sp, a0
mul     a0, a0, a1
```

分别是：

```text
sp = sp + a0
a0 = a0 * a1
```

目的寄存器写在前面，源和目的可以是同一个寄存器。CPU 会先读取旧操作数，再将结果写入目的寄存器。

### 带立即数的运算

```asm
addi    a1, a1, 1
```

即：

```text
a1 = a1 + 1
```

末尾 `i` 表示 immediate，立即数直接编码在指令中。`addi` 的立即数字段按 **12 位有符号数**解释，范围是 `-2048` 到 `2047`：

```asm
addi    t0, zero, -1   # t0 = -1
```

寄存器本身只保存比特，没有“正数”“负数”或“地址”的类型标签。RV64 中 `-1` 的补码表示是 `0xffffffffffffffff`；同一串位按有符号数或无符号数读取，会得到不同的数学意义。比较指令也因此分为 `blt`（有符号小于）和 `bltu`（无符号小于）。特别大的常量通常写作 `li t0, 4096`，但这一行可能被汇编器展开为两条或更多真实机器指令。

### 加载与存储

RISC-V 使用 load/store 指令读写内存：

```asm
ld      a0, 8(sp)    # a0 = 内存[sp + 8] 的 64 位值
sd      ra, 8(sp)    # 内存[sp + 8] = ra 的 64 位值
```

`ld`/`sd` 中的 `d` 表示 doubleword（64 位）；32 位常见 `lw`/`sw`。`8(sp)` 表示地址 `sp + 8`，不是“调用名为 sp 的函数”。这是**基址加偏移**寻址。

| 指令 | 读/写宽度 | 加载后如何放进 64 位寄存器 |
| --- | --- | --- |
| `lb` / `sb` | 1 字节 | `lb` 符号扩展；`lbu` 零扩展 |
| `lh` / `sh` | 2 字节 | `lh` 符号扩展；`lhu` 零扩展 |
| `lw` / `sw` | 4 字节 | `lw` 符号扩展；`lwu` 零扩展 |
| `ld` / `sd` | 8 字节 | 64 位原样读写 |

若内存的一个字节为 `0xff`，`lbu` 会得到 `255`，`lb` 会把它当作有符号 8 位数，得到 `-1`。读错数据宽度或符号，往往不是华丽的灾难，却足够让底层代码静悄悄地错下去。

### 分支与跳转

```asm
beq     a0, zero, done
```

若 `a0` 等于 0，PC 跳到标签 `done`；否则顺序执行。`beq` 的名称可读为 branch if equal。标签只是一种供汇编器计算地址的名字，不会单独变成一条 CPU 指令。

```asm
bne     a0, zero, loop      # a0 != 0 时跳转
blt     a0, a1, smaller     # 按有符号数比较
bltu    a0, a1, usmaller    # 按无符号数比较
j       spin                # 无条件跳转，不保存返回位置
```

分支通常不修改参与比较的寄存器，却会决定“下一条”在哪里。分析循环时，最容易遗漏的不是算术，而是 PC 走了哪个分支。

## 五、`li`、`la`、`call` 是什么

下列写法常是汇编器伪指令，表达意图而非固定的一条硬件编码：

```asm
li      a0, 4096     # a0 = 4096
la      sp, stack0   # sp = stack0 这个符号的地址
call    start        # 保存返回地址并跳到 start
j       spin         # 无条件跳到 spin
```

`li` 是 load immediate，`la` 是 load address。关键区别是：

```text
la sp, stack0：取得 stack0 在内存中的地址
ld a0, 0(sp)：读取该地址处保存的数据
```

不要把“装入地址”误解为“读取地址中的内容”。例如：

```asm
la      sp, stack0   # sp = 地址(stack0)，没有访问该地址保存的数据
ld      t0, 0(sp)    # t0 = 地址 stack0 处的 8 字节数据
```

`call` 和 `j` 也可能根据目标距离展开为不同基础指令；如果需要确认真实机器码，应查看反汇编。`call` 的核心语义是把返回位置写进 `ra`，再将 PC 改为 `start` 的地址；它不是“CPU 特别认识 C 函数”的魔法。

### 为什么反汇编和源代码长得不完全一样

源代码里既有真实 CPU 指令，也有汇编器提供的伪指令。伪指令表达意图，汇编器根据常量大小、目标距离和链接结果选择实际编码：

| 源代码 | 意图 | 常见的真实形式（概念上） |
| --- | --- | --- |
| `mv rd, rs` | 复制寄存器 | `addi rd, rs, 0` |
| `nop` | 什么也不做 | `addi zero, zero, 0` |
| `li rd, 7` | 装小常量 | 一条 `addi` |
| `li rd, 4096` | 装较大常量 | 常为 `lui` 配合 `addi` |
| `la rd, symbol` | 取符号地址 | 多条 PC 相对指令和重定位 |
| `j label` | 无返回跳转 | `jal zero, label` |

因此“我写了一行，为什么 `objdump -d` 显示两行”并不是编译器背叛了你。读源代码时先理解意图；调试地址、异常和性能时再以最终反汇编为准，例如 `riscv64-unknown-elf-objdump -d kernel/kernel`。

## 六、CSR：CPU 的控制状态寄存器

`mhartid` 并不位于 `x0`–`x31` 通用寄存器中，而属于 CSR（Control and Status Register）。CSR 保存处理器控制与状态，如当前硬件线程 ID、异常入口、特权级状态和地址转换配置。

```asm
csrr    a1, mhartid
```

读作：

```text
a1 = CSR[mhartid]
```

这条指令从 CPU 控制状态读取当前 hart 的编号。CSR 是否可读写与当前特权级有关；xv6 最早期入口位于 M 模式，因而可以访问这类机器态信息。CSR 不是普通内存，不能以为 `ld a1, mhartid` 会得到相同效果；它们有单独的访问指令和权限规则。

## 七、一个最小例子：逐行跟踪寄存器

```asm
li      a0, 7
li      a1, 5
add     a2, a0, a1
addi    a2, a2, 1
```

| 指令执行后 | `a0` | `a1` | `a2` |
| --- | --- | --- | --- |
| 初始 | 未知 | 未知 | 未知 |
| `li a0, 7` | 7 | 未知 | 未知 |
| `li a1, 5` | 7 | 5 | 未知 |
| `add a2, a0, a1` | 7 | 5 | 12 |
| `addi a2, a2, 1` | 7 | 5 | 13 |

这就是读汇编最可靠的基本方法：对关键片段画表，逐条更新寄存器。不要过早把连续多条指令压缩成“它大概是在初始化”，因为那正是错误最容易藏起来的地方。

### 再进一步：带内存和分支的可手工执行程序

下面的程序计算内存中两个 64 位数之和，将结果写到第三个位置；若和为零则走 `zero_sum` 路径。假设 `a0` 已经保存数组首地址，三个连续位置依次是 `left`、`right`、`result`：

```asm
    ld      t0, 0(a0)            # t0 = left
    ld      t1, 8(a0)            # t1 = right
    add     t2, t0, t1           # t2 = left + right
    sd      t2, 16(a0)           # result = t2
    beq     t2, zero, zero_sum   # 结果为零则跳转
    li      a0, 1                # 非零路径
    j       done
zero_sum:
    li      a0, 0                # 零路径
done:
```

设初始 `a0 = 0x1000`，`Mem64[0x1000] = 7`，`Mem64[0x1008] = -7`。`—` 表示尚未写入或与本步无关。

| 执行完的指令 | `a0` | `t0` | `t1` | `t2` | `Mem64[0x1010]` | 下一位置 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 初始 | `0x1000` | — | — | — | 未知 | 第一条 `ld` |
| `ld t0, 0(a0)` | `0x1000` | 7 | — | — | 未知 | 下一条 |
| `ld t1, 8(a0)` | `0x1000` | 7 | -7 | — | 未知 | 下一条 |
| `add t2, t0, t1` | `0x1000` | 7 | -7 | 0 | 未知 | 下一条 |
| `sd t2, 16(a0)` | `0x1000` | 7 | -7 | 0 | 0 | 下一条 |
| `beq t2, zero, zero_sum` | `0x1000` | 7 | -7 | 0 | 0 | `zero_sum` |
| `li a0, 0` | 0 | 7 | -7 | 0 | 0 | `done` |

这张表包含读汇编的全部基本动作：`a0` 开始是**地址**，最后又被改为普通数值 0；真正改变内存的是 `sd`；`beq` 不改 `t2`，却让 CPU 越过了 `li a0, 1`。寄存器不自带类型，值的意义取决于指令如何使用它。能手工填出这类表格，你已经在分析程序，而不只是朗读助记符。

## 八、代回 xv6 的栈初始化代码

```asm
la      sp, stack0
li      a0, 1024*4
csrr    a1, mhartid
addi    a1, a1, 1
mul     a0, a0, a1
add     sp, sp, a0
```

到这里你已能直接翻译为：

```text
sp = 地址(stack0)
a0 = 4096
a1 = 当前 hart ID
a1 = a1 + 1
a0 = 4096 * a1
sp = sp + a0
```

若 `stack0 = 0x80010000`、当前 `mhartid = 1`，最后 `sp = 0x80010000 + 4096 × 2 = 0x80012000`。不同 hart 因硬件编号不同而得到不同的栈顶。为什么这个结果恰好是正确的栈顶、为什么 `sp` 必须先设好再 `call`，会在函数调用与栈一文中得到解释。

## 九、常见陷阱

1. **把 ABI 名称当成硬件类型。** `a0`、`t0`、`s0` 都能做算术；区别只是跨函数调用时谁必须保留值。
2. **把 `la` 当作读内存。** `la` 得到地址，`ld` 才读取地址中的数据。
3. **忽略 RV64 的宽度和符号扩展。** `lw` 只读 4 字节并符号扩展；无符号 32 位数应使用 `lwu`，指针与 64 位数据通常使用 `ld`。
4. **以为 `add` 会操作内存。** 它只读写寄存器；内存读写必须显式 `ld`/`sd`。
5. **忘记 `x0` 写不进去。** `addi zero, zero, 1` 的结果会被硬件丢弃。
6. **把分支当函数调用。** `beq` 不保存返回位置；回到哪里完全由程序控制流安排。
7. **相信伪指令必为一条机器指令。** `li`、`la`、`call` 的展开取决于常量与链接结果，精确分析时看反汇编。
8. **把数值天然看成有类型。** `0x1000` 可被当作整数也可被当作地址；`-1` 与 64 位全 1 是同一比特模式的不同解释。

## 十、练习与答案

### 练习 1：零寄存器

```asm
li      t0, 3
addi    t0, t0, -5
add     a0, t0, zero
addi    zero, zero, 9
```

最后 `t0`、`a0`、`zero` 分别是多少？

### 练习 2：地址和数据

假设 `sp = 0x2000`，`Mem64[0x2008] = 42`。执行：

```asm
ld      a0, 8(sp)
addi    a0, a0, 1
sd      a0, 16(sp)
```

最后哪个地址被写入了什么？

### 练习 3：分支路径

```asm
li      a0, 0
beq     a0, zero, yes
li      a1, 1
j       done
yes:
li      a1, 2
done:
```

最后 `a1` 是多少？哪些指令没有执行？

### 答案

1. `t0 = -2`，`a0 = -2`，`zero = 0`；最后一条试图写入 `x0`，其结果被丢弃。
2. `ld` 从 `0x2008` 读到 `42`，所以 `a0 = 43`；`sd` 把 64 位值 `43` 写到 `0x2010`。
3. `a1 = 2`；`beq` 跳到 `yes`，所以 `li a1, 1` 和随后的 `j done` 都没有执行。

## 小结

- RISC-V 是 ISA；`rv64imac` 表示位宽和目标实现的扩展。
- `sp`、`ra`、`a0`、`a1` 是通用寄存器的 ABI 名称，约定了常见职责。
- `add`、`addi`、`mul` 操作寄存器；`ld`、`sd` 在寄存器与内存间搬运数据。
- `li`、`la`、`call`、`j` 通常是伪指令，帮助表达常见意图。
- `csrr a1, mhartid` 从 CSR 读取当前硬件线程编号。
- 初学阶段最有效的分析工具不是背指令表，而是逐行写出寄存器的新值。
