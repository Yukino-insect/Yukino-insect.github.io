在 C 中写下 `answer = add(3, 4);` 时，你看见的只是一句表达式。对 CPU 来说，这是一次必须严格遵守的交接：参数交给谁？跳去哪里？之后又回到哪里？调用过程中被覆盖的寄存器由谁挽回？局部变量放在哪里？

答案的核心是**调用约定**（calling convention）和**栈**（stack）。它们不是 C 语言的黑魔法，而是编译器、手写汇编与库代码之间的共同合同。读完后，你应能跟踪一次 RISC-V 函数调用，并明白 xv6 为什么必须先设置 `sp`，再 `call start`。

> 本文以 xv6 的 RV64 环境为例。所以 `sd` / `ld` 分别表示「存储 / 读取 8 字节」；RV32 中常用 `sw` / `lw`，但调用和栈的观念不变。

## 1. 函数调用的本质：保存回程、改变 PC

CPU 用 **PC**（program counter，程序计数器）记录下一条将被取指、译码和执行的指令地址。普通指令执行完后，PC 往后走；但调用函数时，CPU 还必须知道以后怎样继续执行调用者的代码。

RISC-V 把返回地址放在 `ra`（return address，`x1`）。当汇编写：

```asm
call    add
# add 返回后从这里继续
```

可以先把它理解成这两个效果：

```text
ra = 当前 call 的下一条指令地址
PC = add 函数入口地址
```

函数末尾的：

```asm
ret
```

则让 `PC = ra`，即跳回调用点之后。`call` 和 `ret` 都是伪指令，汇编器会将它们翻成 `jal` 或 `jalr` 等真实指令。初学时不用急着记它们的编码，先记住：**`call` 带着一张回程地址的纸条跳过去，`ret` 按纸条跳回来。**

### 为什么 `ra` 必须保存

考虑调用链：

```text
main 调用 f
f    调用 g
g 返回 f
f 返回 main
```

`main` 调用 `f` 后，`ra` 里是「回 main 的地址」。但 `f` 执行 `call g` 时，新的返回地址会直接覆盖 `ra`。为了最终仍回到 `main`，`f` 要在再次 `call` 之前保存旧 `ra`，等 `g` 返回后再恢复。

不调用其他函数的函数叫**叶子函数**（leaf function），通常不需为 `ra` 建栈帧；会调用其他函数的叫**非叶子函数**（non-leaf function），通常必须保存 `ra`。「通常」很重要：编译器可以内联函数或做尾调用优化，ABI 要求的是结果，不是每个函数都复制一份模板。

## 2. 栈是一段内存，`sp` 是它的边界

「栈」不是 CPU 内一个神秘的小箱子。它是内存中一段连续区域，用于保存返回地址、局部变量、需要恢复的寄存器、放不下的参数以及临时对象。`sp`（stack pointer，`x2`）保存当前栈帧的低端。

RISC-V 的栈向**低地址**生长。假设可用栈区间是 `[0x8000, 0x9000)`，那么空栈时应设 `sp = 0x9000`：

```text
高地址  0x9000  <--- 空栈时的 sp（高端）
          0x8ff8  ┌--- 之后分配的栈帧
             ...  │
低地址  0x8000  └--- 这个边界之下不可再用
```

若函数要一块 32 字节的栈帧，它先执行：

```asm
addi    sp, sp, -32      # 0x9000 -> 0x8fe0
```

这一刻函数合法占有的范围是 `[0x8fe0, 0x9000)`。这时 `sd ra, 24(sp)` 写入的是 `[0x8ff8, 0x9000)` 这 8 个字节。函数结束前再执行 `addi sp, sp, 32`，就把整块空间还给调用者。

所以栈的重点不是「把数据压进去」这个模糊比喻，而是：**先通过修改 `sp` 声明自己占用一段内存，再只访问这段内存。**若 `sp` 初值错误或越过下界，保存 `ra` 的写入就会破坏未知内存。

### 为什么向下生长？

这是一个历史上广泛采用的约定，不是 CPU 的必然属性。常见的地址布局让堆（`malloc` 的动态内存）向上增长，栈向下增长，两者从两端利用空间。对我们而言，更重要的是遵守 RISC-V psABI 已经定下的方向。

## 3. ABI 中的参数、返回值和保存责任

ABI（Application Binary Interface，应用二进制接口）规定的是「机器代码怎样协作」，不是「源代码怎样写」。它使得 C 编译出的函数能被手写汇编正确调用，也使不同目标文件能一起链接。

对普通整数和指针，最常用的规则是：

```text
a0 – a7     依次传递前 8 个整数/指针参数
a0（必要时 a0,a1）  放回返回值
sp            在函数调用边界必须 16 字节对齐
```

第 9 个及之后的整数参数需由**调用者**放在栈上。请注意：被调函数可能一进门就减小 `sp` 建立自己的栈帧，所以它访问栈传参时要越过自己的栈帧或使用帧指针；不是「永远从当前 `sp` 的 0 偏移取」。

寄存器不够让每个函数随意独占，所以 ABI 分配了保存责任：

| 类别 | 寄存器 | 调用后原值是否保证还在 | 若要保留，谁保存 |
| --- | --- | --- | --- |
| 调用者保存（caller-saved） | `a0`–`a7`、`t0`–`t6`、`ra` | 不保证 | 调用者 |
| 被调用者保存（callee-saved） | `s0`–`s11` | 保证 | 被调用者（使用它时） |
| 特殊 | `sp` | 返回时必须恢复到入口值 | 被调用者 |

「保存」绝不是 CPU 自动帮你备份。如果 `f` 打算在 `call g` 之后继续使用 `t0`，那是 `f` 自己先存好 `t0` 的责任；`g` 可以合法地改它。反过来，如果 `g` 要用 `s1`，`g` 必须先保存旧 `s1`，返回前恢复，才能使 `f` 安心依赖 `s1`。

`ra` 属于 caller-saved 容易困惑。当 `f` 执行 `call g`，`f` 就是这次调用的 caller，它需要保住「之后如何回到自己的 caller」的地址。因此「非叶子函数保存 `ra`」与「`ra` 是 caller-saved」完全不矛盾。

## 4. C 到伪汇编：跟踪一次真实调用

先看 C 代码：

```c
long twice(long x) {
    return x * 2;
}

long twice_then_add_one(long x) {
    long y = twice(x);
    return y + 1;
}
```

按 RV64 ABI，调用 `twice_then_add_one(10)` 前，调用者放 `a0 = 10`；结果也会回到 `a0`。忽略编译器的优化细节后，这段 C 可用下列「讲解版伪汇编」表示：

```asm
# long twice(long x)
# 入口：a0 = x，ra = 要返回的地址
twice:
        slli    a0, a0, 1        # a0 = x << 1，即 x * 2
        ret                       # 结果已在 a0

# long twice_then_add_one(long x)
twice_then_add_one:
        addi    sp, sp, -16      # 分配 16 字节栈帧
        sd      ra, 8(sp)        # 保存「回上一层」的返回地址
        call    twice             # a0 既是 x，也用来接收 y
        addi    a0, a0, 1        # a0 = y + 1
        ld      ra, 8(sp)        # 恢复最初的返回地址
        addi    sp, sp, 16       # 释放栈帧
        ret
```

`twice` 是叶子函数：它不会 `call`，所以不会覆盖 `ra`，可以立即 `ret`。`twice_then_add_one` 则必须先存 `ra`。

假设进入 `twice_then_add_one` 时 `sp = 0x9000`、`ra = 0x1048`、`a0 = 10`：

| 步骤 | 指令效果 | `sp` | `ra` | `a0` | 栈中状态 |
| --- | --- | --- | --- | --- | --- |
| 入口 | 调用者准备完毕 | `0x9000` | `0x1048` | `10` | 尚无本函数的栈帧 |
| 1 | `addi sp, sp, -16` | `0x8ff0` | `0x1048` | `10` | 拥有 `[0x8ff0, 0x9000)` |
| 2 | `sd ra, 8(sp)` | `0x8ff0` | `0x1048` | `10` | `0x1048` 存在 `[0x8ff8,0x9000)` |
| 3 | `call twice` | `0x8ff0` | 改为回到本函数的地址 | `10` | 旧 `ra` 仍安全在栈中 |
| 4 | `twice` 返回 | `0x8ff0` | 不需再依赖 | `20` | 不变 |
| 5 | `addi a0,a0,1` | `0x8ff0` | 不变 | `21` | 不变 |
| 6 | 恢复 `ra` 、`sp`，再 `ret` | `0x9000` | `0x1048` | `21` | 栈帧已释放 |

这张表里最关键的事是：第 3 步必然改写 `ra`，但第 2 步已经把旧值放进了每层调用专属的栈帧。这正是嵌套调用可靠的原因。

> 不要把 `a0` 误认为「只能装参数」。在函数入口它是第一参数，在函数出口它又是第一返回值。同一个寄存器在不同时刻承担不同角色。

## 5. 函数序言、尾声和栈帧

若函数还要使用 `s0`（常作为帧指针 `fp`）和局部变量，它的讲解版反汇编常类似于：

```asm
work:
        addi    sp, sp, -32      # 函数序言：分配栈帧
        sd      ra, 24(sp)       # 保存返回地址
        sd      s0, 16(sp)       # 使用 s0 前，先保存旧 s0
        addi    s0, sp, 32       # s0 指回入口时的 sp

        # 函数主体：[sp, sp+16) 可放局部数据

        ld      ra, 24(sp)       # 函数尾声：先恢复
        ld      s0, 16(sp)
        addi    sp, sp, 32       # 再还回整块栈帧
        ret
```

前半段叫**函数序言**（prologue），后半段叫**函数尾声**（epilogue），中间这块当前函数专属的空间叫**栈帧**（stack frame）。布局并非死规定：编译器可能省略帧指针、重排变量、甚至不创建栈帧。但 ABI 的底线不会变：

1. 若使用了 `s0`–`s11`，返回前必须恢复它们的旧值。
2. 函数返回时 `sp` 必须恢复为入口时的值。

帧指针的好处是以固定位置索引栈帧、帮助调试器回溯。但 `s0/fp` 是可选的；优化后的代码没有 `s0` 不表示没有栈。

## 6. 16 字节对齐为什么必须遵守

RISC-V psABI 要求过程调用边界上：

```text
sp mod 16 = 0
```

这不是为了让地址看着整齐。编译器会以此为前提安排某些数据的访问和传递；对齐访问也更容易被硬件高效处理。如果你只为保存一个 8 字节的 `ra` 就分配 8 字节，例如从 `0x9000` 改为 `0x8ff8`，那么在 `call` 前已经违反了这份合同。因此上面例子会分配 16 字节。

xv6 中 `stack0` 按 16 字节对齐，每个 hart 的栈大小是 4096 字节（`4096 = 256 × 16`）。因此：

```text
sp = stack0 + 4096 * (mhartid + 1)
```

无论 `mhartid` 是几，都是 16 字节对齐的栈顶。

## 7. 嵌套、递归与栈溢出

在 `main -> f -> g` 中，后进入的 `g` 会在更低地址建立自己的栈帧：

```text
高地址
  [ main 的栈帧 ]
  [ f 保存的 ra、局部变量 ]  <--- g 入口时的 sp
  [ g 保存的 ra、局部变量 ]  <--- g 当前的 sp
低地址
```

`g` 先返回并释放自己的栈帧，然后 `f` 才能返回。这种后进先出的结构正是「堆叠」。

递归只是一种特殊的嵌套调用。`fact(4)` 调用 `fact(3)` 时，每一层都有不同的 `n`、不同的返回地址和不同的栈帧，因而它们不会混在一起。若递归没有终止条件，或局部数组过大，`sp` 会不断突破栈的低地址下界，这就是**栈溢出**（stack overflow）。
操作系统常在线程栈边界放保护页，尽早把越界变成异常。但 xv6 早期启动时的栈是静态数组切分的 4 KiB 区间，完整的虚拟内存保护还未建立。此时树立正确 `sp` 只是前提；代码还必须自己避免超出那 4 KiB。

## 8. 回到 xv6：为什么先设栈再进 C

xv6 最早期入口的关键结尾是：

```asm
add     sp, sp, a0        # sp = stack0 + 4096 * (mhartid + 1)
call    start
```

第一行把 `sp` 放在当前 hart 专属栈的高端。第二行才转入 C 的 `start()`。即使 `start()` 的源码看起来很简单，也不能在 `sp` 未定义时调用它：编译器可能为局部变量、调试信息或嵌套调用生成栈访问。一旦执行了类似 `sd ra, 8(sp)` 的指令，就会向未知地址写入。
多 hart 也是原因。所有 hart 都从同一个 `_entry` 开始，却必须根据 `mhartid` 切分 `stack0`。若两个 hart 共享同一块栈，它们会互相覆盖返回地址和局部变量，错误是必然的，只是何时爆发的问题。

## 9. 常见误解速查

| 误解 | 正确理解 |
| --- | --- |
| `call` 会自动把所有寄存器压栈 | 不会。它的核心是设置返回地址并跳转；保存动作需要 `sd` 等指令。 |
| `ret` 会自动恢复栈 | 不会。必须在 `ret` 前显式恢复寄存器和 `sp`。 |
| `a0` 只能是参数 | 它在入口是第一参数，在出口是第一返回值。 |
| 叶子函数永远不需要栈 | 它不需为再次 `call` 保存 `ra`，但大局部对象或编译策略仍可能需栈。 |
| 放到 `s1` 就被 CPU 自动保护 | 不会。「被调用者保存」是编写者必须用栈实现的 ABI 责任。 |
| 未对齐的 `sp` 只要暂时能运行就没问题 | 这是偶然，会在其他函数或编译选项下变成 ABI 违约。 |

## 10. 练习（含答案）

### 练习 1：地址跟踪

已知某函数入口时 `sp = 0x8020`、`ra = 0x1234`，它执行：

```asm
addi    sp, sp, -16
sd      ra, 8(sp)
call    helper
ld      ra, 8(sp)
addi    sp, sp, 16
ret
```

1. `sd` 写入的 8 个字节位于哪个区间？
2. `call helper` 后原本的 `ra` 丢了吗？
3. `ret` 前 `sp` 为多少？

### 练习 2：谁应该保存 `t0`？

函数 `f` 把中间结果放在 `t0`，接下来要 `call g`，且返回后仍需使用此值。谁应在调用前保存 `t0`？

### 练习 3：修复函数

下面的 `f` 会调用 `g`，但不能正确回到自己的调用者。请补上最小且保持 16 字节对齐的栈操作。

```asm
f:
        call    g
        addi    a0, a0, 1
        ret
```

### 答案

1. 第一行后 `sp = 0x8010`，所以 `sd ra, 8(sp)` 写入 `[0x8018, 0x8020)`。原 `ra` 没丢，它已经在栈里；执行恢复后 `sp = 0x8020`。
2. `f` 保存。`t0` 是 caller-saved，`g` 可以合法改写它。`f` 可把它存在自己的栈帧，或移入 `s` 寄存器（此时也要保存旧 `s` 值）。
3. 一个正确答案：

```asm
f:
        addi    sp, sp, -16
        sd      ra, 8(sp)
        call    g
        addi    a0, a0, 1
        ld      ra, 8(sp)
        addi    sp, sp, 16
        ret
```

## 小结：读函数汇编时的四个问题

遇到一个 RISC-V 函数，先问自己：

1. 它会不会再 `call` 别人？若会，旧 `ra` 被存在哪里？
2. 它分配了多少栈帧？出口时 `sp` 是否恢复？
3. 它修改了哪些 `s` 寄存器？它们是否恢复？
4. 参数从哪里来，结果又到哪里去？

xv6 的 `entry.S` 在第一次 C 调用前先为每个 hart 准备独立、对齐的栈顶，正是在回答第 2 个问题。有了它，`start()` 才能像任何正常 C 函数那样遵守 ABI 并安全工作。
