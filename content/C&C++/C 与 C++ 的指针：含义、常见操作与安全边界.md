指针并不是“内存地址的数字版”，更不是 C/C++ 中专门用来制造段错误的仪式道具。更准确地说，**指针是一个值：它可以指向某个对象或函数，也可以是空指针；数组遍历中还允许形成不指向元素的尾后位置。指针类型同时告诉编译器应把目标按什么类型、什么宽度解释。**

从这个定义出发，许多看似零碎的规则会连成一条线：`&` 取得对象的地址，`*` 通过地址访问对象，`p + 1` 按目标类型的大小前进，空指针不能解引用，而对象生命周期结束后原先指向它的指针不再可用。

```text
对象 value          指针 p                 解引用 *p
┌───────────┐       ┌───────────┐          ┌───────────┐
│ int: 42   │ <───  │ 地址 value│  ──────> │ 访问 value │
└───────────┘       └───────────┘          └───────────┘
       ↑                    ↑                      ↑
     对象本身             “在哪里”              “那个对象”
```

本文先讨论对象指针及其常见操作。函数指针、Lambda 与 `std::function` 有自己的类型与调用规则，适合单独讨论；不要因为名字里都有“指针”就强行把它们揉成一团。

## 一、先分开三个东西：对象、地址和指针

```cpp
int value = 42;
int *p = &value;
```

这两行中有三个不同层次的概念：

| 写法 | 类型/角色 | 含义 |
| --- | --- | --- |
| `value` | `int` 对象 | 存放整数 `42` 的对象 |
| `&value` | `int *` 值 | 取得 `value` 的地址，得到指向它的指针值 |
| `p` | `int *` 对象 | 保存这个指针值的变量 |
| `*p` | `int` 左值 | 通过 `p` 找到并访问 `value` |

因此：

```cpp
std::cout << value;  // 42：直接访问对象
std::cout << *p;     // 42：通过指针访问同一对象

*p = 99;             // 修改 p 指向的对象
// 此时 value 也是 99
```

`p` 和 `*p` 不可互换。前者是“对象在哪里”的指针值，后者是“该地址处的对象”。这一点看似朴素，却是理解参数传递、数组、动态内存和空指针的地基；地基若省略，后面的花样只会建得很有高度地倒塌。

### 1. 指针类型不是装饰

`int *`、`double *`、`Widget *` 是不同的指针类型。它们至少表达两件事：

1. 解引用后按什么类型读取、写入或调用成员；
2. 指针算术每移动一个元素，应跨过多少字节。

```cpp
int    *ip;
double *dp;

// ip + 1 前进 sizeof(int) 个字节
// dp + 1 前进 sizeof(double) 个字节
```

现代机器上指针本身的表示常常同样宽，但这不是让类型失去意义的理由。对错类型指针的强制转换和解引用，可能引发对齐错误、别名规则问题、访问宽度错误，或直接落入未定义行为。

## 二、声明、初始化与两种基本操作

### 1. 如何读指针声明

```cpp
int *p;
```

从变量名开始读：`p` 是一个指针，指向 `int`。星号属于声明符，不属于类型名左边那个 `int` 的某种神秘尾缀；这解释了下面的常见陷阱：

```cpp
int *first, second;
// first  是 int *
// second 是 int，不是 int *
```

实际项目中应一行只声明一个变量，避免读者和编译器在同一行承担不同难度的工作：

```cpp
int *first = nullptr;
int second = 0;
```

C 使用空指针宏 `NULL`，现代 C++ 优先使用类型明确的 `nullptr`：

```c
int *c_pointer = NULL;       /* C */
```

```cpp
int *cpp_pointer = nullptr;  // C++11 起
```

`nullptr` 不会像整数 `0` 或某些 `NULL` 定义那样参与令人困惑的整数重载匹配，因此 C++ 不应再把 `NULL` 当作默认选择。

### 2. `&`：取地址

一元 `&` 运算符取得一个有地址对象的地址：

```cpp
int value = 42;
int *p = &value;
```

可取地址的对象包括局部变量、全局变量、数组元素、结构体成员以及动态分配的对象。字面量和临时值通常不应被当作可长期保存地址的对象：

```cpp
// int *bad = &42; // 错误：字面量不是可取地址的 int 对象
```

C++ 中临时对象和引用有更多精细规则，但“不要保存一个即将消失对象的地址”是更实用的总原则。

### 3. `*`：解引用

一元 `*` 将指针表达式转换为其目标对象的左值：

```cpp
int value = 42;
int *p = &value;

int copy = *p;  // 读取 value
*p = 100;       // 写入 value
```

若指针是空指针、悬空指针、未初始化指针，或不正确地指向了另一种对象，解引用就是未定义行为。编译器通常不会在运行前替你拦住它；地址看起来像个十六进制数，并不意味着它突然获得了合法身份。

## 三、空指针、未初始化指针与有效性

### 1. 空指针表示“当前不指向对象”

```cpp
int *p = nullptr;

if (p != nullptr) {
    *p = 1;
}
```

空指针可以复制、比较和作为“没有结果”的返回值；**不能解引用**，也不能做没有意义的指针算术。

```cpp
// *p = 1; // 未定义行为
```

空指针检查不是万能护身符：它只能区分空和非空，不能证明一个非空指针仍然指向有效、足够大且类型正确的对象。

### 2. 未初始化指针比空指针更危险

```cpp
int *p;     // 值不确定
// *p = 1;  // 未定义行为
```

这种指针既不表示“无对象”，也不表示某个可靠地址。应在声明时初始化为实际对象地址、`nullptr`，或由明确的 API 返回：

```cpp
int value = 0;
int *p1 = &value;
int *p2 = nullptr;
```

### 3. 有效指针的四项检查

在解引用前，概念上需要同时满足：

```text
1. 非空：它确实指向某处，而非“没有对象”
2. 存活：目标对象的生命周期尚未结束
3. 范围：访问位置位于目标对象/数组允许范围内
4. 类型与对齐：按当前指针类型访问是允许的
```

这四项不是一段每次都手写的 `if`，而是 API 设计、所有权、容器边界和类型系统共同应维持的不变量。只写 `if (p)` 便放心解引用，大约相当于只确认门没有关，就断定屋里没有楼梯。

## 四、数组与指针算术：相关，但不相同

### 1. 数组表达式常会衰变为首元素指针

```cpp
int numbers[] = {10, 20, 30, 40};
int *p = numbers; // 多数表达式中等价于 &numbers[0]
```

数组名在多数表达式中会转换（常称“衰变”）为指向首元素的指针。因此：

```cpp
numbers[2] == *(numbers + 2); // 都是 30
p[2]       == *(p + 2);       // 都是 30
```

下标运算 `a[b]` 的定义本质上就是 `*(a + b)`。这解释了数组为何能用指针遍历，却不表示数组和指针是同一种东西。

### 2. 数组不是指针

```cpp
int numbers[4] = {10, 20, 30, 40};
int *p = numbers;

// numbers = p; // 错误：数组不是可赋值的指针变量
```

至少有三处关键差异：

| 问题 | 数组 `numbers` | 指针 `p` |
| --- | --- | --- |
| 自身能否重新指向/赋值 | 否 | 可以 |
| `sizeof` 的含义 | 整个数组字节数 | 指针对象自身大小 |
| 是否携带元素数量 | 在定义处可由 `sizeof` 推得 | 通常不携带 |

```cpp
std::size_t count = sizeof(numbers) / sizeof(numbers[0]); // 4
std::size_t pointer_size = sizeof(p); // 不是元素个数
```

数组作为函数参数时会调整为指针，长度信息随之丢失：

```cpp
void print_all(const int values[]) { // 实际按 const int * 接收
    // sizeof(values) 是指针大小，不能得出数组长度
}
```

在 C 中应额外传入长度；现代 C++ 更应优先用 `std::span`、`std::array`、`std::vector` 或范围接口，让元素范围成为类型或对象的一部分。

### 3. 合法的移动范围

若 `p` 指向同一个数组的元素，则 `p + n` 可以指向数组内另一个元素；还允许得到“尾后指针”（one-past-the-end），用于比较或迭代终止，但**不能解引用**：

```cpp
int numbers[] = {10, 20, 30};

int *begin = numbers;
int *end = numbers + 3; // 合法：尾后位置

for (int *it = begin; it != end; ++it) {
    std::cout << *it << '\n';
}

// *end; // 错误：尾后位置不是元素
```

越过尾后位置、在不相关对象之间做指针减法或比较大小，都不应视为普通整数运算。指针算术只在同一个数组对象（单个对象可视作长度为 1 的数组）范围内才有定义良好的意义。

### 4. `&array` 与 `array`：首元素和整个数组的地址

```cpp
int numbers[4] = {10, 20, 30, 40};

int       *element = numbers;   // int *，指向 numbers[0]
int (*whole)[4] = &numbers;     // 指向“4 个 int 的数组”的指针
```

二者打印出来的数值地址在许多机器上可能相同，类型和算术却不同：

```cpp
element + 1; // 前进一个 int
whole + 1;   // 前进整个 int[4] 数组
```

不要因为地址数值碰巧相同就忽略类型。指针的用途不仅是保存一个数字，也是让编译器了解该数字对应的对象布局。

## 五、指针作为函数参数：让函数访问或修改调用方对象

C/C++ 的参数传递本身始终是按值进行；把指针作为参数，是把“对象地址这个值”复制给函数，从而让函数能访问原对象。

```c
void increment(int *value) {
    if (value != NULL) {
        ++*value;
    }
}

int main(void) {
    int count = 0;
    increment(&count);
    // count == 1
}
```

调用方传入 `&count`，函数形参 `value` 得到这个地址的副本；`++*value` 修改的是地址处的 `count`，不是形参指针变量本身。

### 1. 想改变调用方的指针，需要二级指针或 C++ 引用

以下函数无法让调用方的 `p` 改为指向新地址：

```c
void reset_wrong(int *p) {
    p = NULL; // 只修改形参副本
}
```

C 可传入指向指针的指针：

```c
void reset(int **p) {
    if (p != NULL) {
        *p = NULL;
    }
}

int value = 42;
int *p = &value;
reset(&p); // p 现在为 NULL
```

C++ 也常用“指针的引用”：

```cpp
void reset(int *&p) {
    p = nullptr;
}
```

选择二级指针还是引用，取决于语言与接口风格；二者都不转移资源所有权。若函数还要负责创建、释放或转交动态对象，应把所有权约定写进 API，并在 C++ 中优先使用智能指针。

### 2. 用 `const` 表达只读输入

```cpp
int sum(const int *values, std::size_t count) {
    int result = 0;
    for (std::size_t i = 0; i < count; ++i) {
        result += values[i];
    }
    return result;
}
```

`const int *` 表示函数不能通过该指针修改元素。只读参数应尽可能使用 `const`：它让调用方了解意图，也让编译器阻止许多无意修改。

## 六、`const` 与指针：到底谁不能改

这三种声明常被看成标点练习，实际上表达三种不同契约：

```cpp
const int *p1;       // 指向 const int：不能通过 p1 修改目标
int *const p2 = ...; // const 指针：p2 自己不能改指向
const int *const p3 = ...; // 目标和指针自身都不能通过此声明改变
```

可从变量名向外读：

| 声明 | 能否改 `*p` | 能否改 `p` |
| --- | --- | --- |
| `const int *p` | 否 | 可以 |
| `int *const p` | 可以 | 否 |
| `const int *const p` | 否 | 否 |

`const` 约束的是“通过这条路径能做什么”。若原对象本身确实是 `const`，强制去掉 `const` 后再写入会产生未定义行为；不要将类型转换误当成获得写权限的许可证。

## 七、结构体、成员访问与 `void *`

### 1. `->` 是“解引用后访问成员”的简写

```cpp
struct Point {
    int x;
    int y;
};

Point point{1, 2};
Point *p = &point;

p->x = 10;      // 等价于 (*p).x = 10
std::cout << p->y;
```

括号不可省略：`*p.x` 会先解析为 `*(p.x)`，而 `p` 不是对象时显然不符合意图。使用 `->` 不是为了少写一个字符，而是为了避免运算符优先级把代码带去不该去的地方。

### 2. `void *`：C 的通用对象指针，不是无类型万能钥匙

在 C 中，`void *` 可以保存任意**对象指针**，转换到/从其他对象指针通常不需要显式强制转换：

```c
int value = 42;
void *raw = &value;
int *p = raw;
```

但 `void *` 不带目标对象大小和成员布局信息，不能直接解引用或做标准意义上的指针算术：

```c
// *raw;    // 错误：void 没有可访问对象大小
// raw + 1; // 标准 C/C++ 中没有按 void 大小移动的定义
```

必须先转换回正确类型：

```c
int copy = *(int *)raw;
```

C++ 对 `void *` 更严格：从 `void *` 转回具体对象指针需要显式转换，并且现代 C++ 中裸 `void *` 多见于 C API、底层分配器或 ABI 边界。泛型需求通常应优先使用模板、容器、`std::variant` 等类型安全工具。

## 八、动态内存：地址、所有权和生命周期必须一起考虑

### 1. C：`malloc`/`free` 配对

```c
#include <stdlib.h>

int *values = malloc(10 * sizeof *values);
if (values == NULL) {
    /* 分配失败 */
    return;
}

values[0] = 42;
free(values);
values = NULL; // 当前作用域避免继续误用这个变量
```

`malloc` 返回的是一段未初始化存储的地址；`free` 结束该存储的使用。`sizeof *values` 比手写 `sizeof(int)` 更不易在元素类型变更后出错。每一份成功分配的资源都必须由约定的唯一责任方恰好释放一次。

不要在 C 中强制转换 `malloc` 返回的 `void *`：它既不需要，也可能掩盖漏包含 `<stdlib.h>` 导致的声明问题。

### 2. C++：默认不要用裸 `new`/`delete` 管理所有权

```cpp
auto value = std::make_unique<int>(42);
std::cout << *value;
// 离开作用域后自动释放
```

现代 C++ 中，拥有对象应优先放在局部对象、`std::vector`、`std::string`、`std::array` 等值类型容器中；确需动态且唯一所有权时使用 `std::unique_ptr`，确需共享所有权时才审慎使用 `std::shared_ptr`。原始指针通常只表达“我可以访问它”，而不表达“我负责 `delete` 它”。

```cpp
void print(const Widget *widget); // 借用：不负责释放
std::unique_ptr<Widget> make_widget(); // 转移唯一所有权
```

这种区分让生命周期从注释中的猜测变成类型的一部分。`new` 与 `delete` 仍是语言工具，但在业务代码里手动配对它们，通常没有比 RAII 更好的理由。

### 3. 释放后为什么仍要小心

```c
int *p = malloc(sizeof *p);
free(p);
// p 的数值可能仍保留旧地址，但它已是悬空指针
```

`free(p)` 或 `delete p` 不会自动把所有副本变为空。将当前变量设为 `NULL`/`nullptr` 能降低该变量被再次误用的风险，却不能修复已复制到其他位置的别名。解决悬空指针的根本方法是清楚的所有权、有限的别名和正确的生命周期管理，而不是在每个指针后面机械补一行赋空。

## 九、常见错误：它们为什么错

### 1. 返回局部对象的地址

```cpp
int *bad() {
    int value = 42;
    return &value; // 函数返回后 value 的生命周期结束
}
```

返回后得到的是悬空指针。应按值返回 `int`，让调用方提供存储，或在 C++ 中以能表达所有权的对象返回。

### 2. 越界与尾后解引用

```cpp
int values[3] = {1, 2, 3};
int *end = values + 3;

// int x = *end; // 尾后指针可比较，不能解引用
```

数组越界不一定立刻崩溃；它更可能沉默地覆盖邻近内存，直到很晚以后以毫不相干的方式失败。没有即时爆炸并不能证明访问有效，这一点也许不够浪漫，但很有用。

### 3. 重复释放与释放错误对象

```c
int *p = malloc(sizeof *p);
free(p);
free(p); // 未定义行为：重复释放
```

同样，不能释放栈对象地址、全局对象地址，或数组中间元素的地址。释放操作必须与创建该资源的分配 API、返回的起始地址及所有权约定匹配。

### 4. `new[]`/`delete[]`、`malloc`/`delete` 混用

```cpp
int *a = new int[10];
delete[] a; // 必须匹配

// free(a); // 错误：不能混用 C 与 C++ 分配/释放体系
```

数组形式和单对象形式也必须配对。最好的规避方式仍然是不用裸数组 `new`，改用 `std::vector` 或 `std::array`。

### 5. 指针不是整数索引

把指针强转为整数、保存后再转回指针，只有平台明确支持且确有底层需求时才应考虑；一般业务代码不应这样做。需要以整数形式保存指针值的底层接口可使用实现提供的 `uintptr_t`，但它解决的是表示宽度，并不让任意地址可解引用，也不延长对象生命周期。

## 十、实践选择：什么时候应使用指针

| 需求 | C 的常见选择 | 现代 C++ 的优先选择 |
| --- | --- | --- |
| 函数可修改调用方对象 | `T *`，并约定可否为 `NULL` | `T &` 表示必有对象；`T *` 表示可空/可重绑定 |
| 只读访问一段连续元素 | `const T *` + 长度 | `std::span<const T>`、范围或容器引用 |
| 可选对象 | `T *`，用 `NULL` 表示无 | `T *`/`nullptr`，或按语义使用 `std::optional` |
| 唯一拥有动态对象 | 明确的 `malloc`/`free` 责任 | `std::unique_ptr<T>` 或值语义容器 |
| 共享拥有动态对象 | 明确引用计数或所有权协议 | 仅在确需共享时使用 `std::shared_ptr<T>` |
| 操作硬件寄存器 | 合适宽度的 `volatile T *` 与平台 API | 同左；不将其当线程同步工具 |

指针很适合表达“借用一个可能不存在、可重新指向、或需要按地址操作的对象”。若对象一定存在且函数只需访问它，C++ 引用往往能表达更强的前置条件；若需要拥有资源，则选择 RAII 类型。让类型表达意图，远比要求每位调用者从命名猜测所有权可靠。

## 十一、总结：把每次解引用当作一份契约

`*p` 的语法只需要一个星号，但它隐含的契约至少包括：

```text
p 非空
p 指向仍然存活的对象
目标位置处于允许访问的范围
按 p 的类型访问该对象是合法且对齐的
调用方与被调用方对所有权和可修改性有一致约定
```

指针的常见操作可以归纳为：

- 用 `&object` 取得对象地址；
- 用 `*pointer` 读取或写入目标对象；
- 用 `pointer->member` 访问结构体/类成员；
- 在同一数组范围内用 `+`、`-`、`[]` 遍历元素；
- 用 `const` 约束可修改性，用 `nullptr`/`NULL` 表示无目标；
- 用指针参数借用或修改调用方对象；
- 将动态对象的所有权交给正确的资源管理机制。

当“地址”“对象”“所有权”“生命周期”始终一起考虑时，指针并不难懂。真正危险的不是星号本身，而是在没有说明对象从何而来、由谁负责、何时失效的情况下就急着解引用——那种代码通常很有自信，直到它没有。
