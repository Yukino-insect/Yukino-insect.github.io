`std::deque` 的名字来自 double-ended queue，即“双端队列”。它允许在头部和尾部都高效地插入、删除和查看元素，因此比只能 FIFO 的 `queue` 多了一层自由，也因此需要更明确地维护自己的规则。

```cpp
#include <deque>

std::deque<int> values{2, 3};
values.push_front(1);  // {1, 2, 3}
values.push_back(4);   // {1, 2, 3, 4}
values.pop_front();    // {2, 3, 4}
values.pop_back();     // {2, 3}
```

最能说明 `deque` 价值的例子是“滑动窗口最大值”：窗口每向右移动一步，左侧元素失效，右侧元素进入；我们既要从前端淘汰过期元素，又要从后端淘汰不可能成为最大值的较小元素。普通队列只能处理前端，栈只能处理一端，`deque` 才与这个过程吻合。

## 一、基本接口与底层特性

`std::deque<T>` 定义在 `<deque>` 中。它是一个真正的顺序容器，不是 `std::queue` 那样的适配器，因此支持迭代器、下标和两端操作。

| 操作 | 含义 | 典型复杂度 |
| ---- | ---- | ---------- |
| `front()` / `back()` | 查看两端元素 | `O(1)` |
| `push_front(x)` / `push_back(x)` | 两端插入 | `O(1)` |
| `pop_front()` / `pop_back()` | 两端删除 | `O(1)` |
| `values[i]` | 按下标访问 | `O(1)` |
| 中间 `insert` / `erase` | 插入或删除中间位置 | `O(n)` |

`deque` 不要求所有元素位于单一连续内存块中；典型实现会用分段存储。因此它能避免 `vector` 在头部插入、删除时整体搬移元素的代价，却也不应被当成“更强的 vector”随手替换。若你需要将整个数据交给只接受连续地址的 C API，或者更关注末尾追加与缓存局部性，`vector` 往往仍是更自然的选择。

## 二、滑动窗口最大值：先理解朴素解

给定整数数组 `nums` 和窗口宽度 `k`，每次窗口向右移动一个元素，求每个窗口中的最大值。例如：

```text
nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3

[1, 3, -1]  -> 3
[3, -1, -3] -> 3
[-1, -3, 5] -> 5
[-3, 5, 3]  -> 5
[5, 3, 6]   -> 6
[3, 6, 7]   -> 7
```

直接对每个窗口扫描 `k` 个元素，时间复杂度为 `O(nk)`。当 `k` 接近 `n` 时，这接近二次复杂度，而且相邻窗口之间大量重复比较：离开的只是一项，进入的也只是一项，没有必要每次从零找最大值。

## 三、单调递减队列保存的是候选下标

解决方案使用一个 `std::deque<int>` 保存数组**下标**，并维护两个不变量：

1. 队头到队尾的下标递增，便于从前端判断元素是否过期。
2. 对应的值严格递减：`nums[indices[0]] > nums[indices[1]] > ...`，因此队头始终是当前窗口最大值的下标。

为什么保存下标而不是数值？因为算法不仅要知道谁最大，还要知道它是否已经滑出窗口；相同的值在不同位置，过期时间不同，单存值没有足够的信息。

完整实现如下：

```cpp
#include <deque>
#include <stdexcept>
#include <vector>

std::vector<int> maxSlidingWindow(const std::vector<int>& nums, int k) {
    if (k <= 0 || static_cast<std::size_t>(k) > nums.size()) {
        throw std::invalid_argument("k must be within the input range");
    }

    std::deque<int> candidates;
    std::vector<int> result;
    result.reserve(nums.size() - static_cast<std::size_t>(k) + 1);

    for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
        // 1. 队头若已在窗口左侧之外，先移除。
        while (!candidates.empty() && candidates.front() <= i - k) {
            candidates.pop_front();
        }

        // 2. 当前值更大或相等时，队尾较小/较早的候选再无机会成为最大值。
        while (!candidates.empty() && nums[candidates.back()] <= nums[i]) {
            candidates.pop_back();
        }

        candidates.push_back(i);

        // 3. 第一个完整窗口形成后，队头就是最大值。
        if (i >= k - 1) {
            result.push_back(nums[candidates.front()]);
        }
    }

    return result;
}
```

### 1. 过期判断为什么是 `<= i - k`

处理下标 `i` 时，当前窗口是：

```text
[i - k + 1, i]
```

因此任何下标小于 `i - k + 1` 的元素都已过期，也就是下标满足：

```text
index <= i - k
```

例如 `i = 4`、`k = 3`，窗口是 `[2, 4]`，下标 `1` 及之前都应移除。边界写错成 `< i - k` 会把恰好过期的元素多留一轮，结果自然会错一位；这种错误并不深奥，只是没有先把窗口写成闭区间。

### 2. 为什么可以从队尾删除较小值

假设队尾下标为 `j`，当前下标为 `i`，且 `j < i`、`nums[j] <= nums[i]`。当前元素在 `j` 右边，过期时间更晚，值又不小于 `j`。在 `j` 仍处于任何未来窗口期间，`i` 也一定仍在窗口中且至少同样大；所以 `j` 永远不可能成为最大值，可以永久删除。

这就是单调队列的本质：它不保存全部窗口元素，只保存仍有资格在未来成为答案的候选者。

使用 `<=` 会删除较早出现的相等值，保留更新、更晚过期的当前下标；使用 `<` 也能得到正确最大值，只会保留更多相等候选。前者通常更精简，关键是你应理解两种不等号对“相等值保留策略”的影响。

### 3. 为什么总复杂度是 `O(n)`

虽然代码里有两个 `while`，却不是 `O(n^2)`。每个下标：

- 只会从队尾入队一次；
- 最多从队头删除一次，或从队尾删除一次；
- 删除后不可能再回来。

因此所有 `push_back` 与 `pop_front`/`pop_back` 的次数合计都是 `O(n)`。这种按元素计数的分析称为均摊分析；看到循环嵌套时，先问每个元素能被内层循环处理几次，比机械相乘更可靠。

## 四、`deque` 与 `queue` 的关系

`queue` 默认以 `deque` 为底层容器，但两者承担的职责不同：

```cpp
std::queue<int> fifo;  // 只允许尾进头出
std::deque<int> both;  // 两端都能进出，也可按下标访问
```

若算法只需要 FIFO，优先用 `queue`。它的受限接口能让读代码的人立刻知道：元素不会从队尾被撤回，也不会从中间访问。只有当算法确实要维护两端状态，例如单调队列、0-1 BFS、回文检查，才使用 `deque`。

### 1. 0-1 BFS：边权只有 0 或 1 的最短路

若图中每条边的权重只可能为 `0` 或 `1`，可以用 `deque` 代替通用最小堆：走权重为 `0` 的边时把新节点放到队头，走权重为 `1` 的边时放到队尾。这样待处理节点仍按当前距离的非递减顺序出现。

```text
权重为 0：新距离与当前相同，应尽快处理 -> push_front
权重为 1：新距离多 1，可以稍后处理     -> push_back
```

这不是“deque 能做 Dijkstra 的所有事”。权重一旦出现 2、5 或其他值，就需要按更一般的优先级排序，此时应使用 `priority_queue`。

## 五、常见错误与边界

### 1. 空容器访问

`front()`、`back()`、`pop_front()`、`pop_back()` 都要求 `deque` 非空。单调队列代码中的每个访问前都有 `!candidates.empty()`，这不是多余样板，而是容器操作的前置条件。

### 2. 中间插入并不高效

`deque` 在两端表现好，不表示任意位置也好：

```cpp
values.insert(values.begin() + middle, value);  // 通常 O(n)
```

若主要需求是按中间位置频繁插删，也许应重新审视数据模型；`list` 虽可在已知位置常数时间插删，却没有高效随机访问，且常因内存分散而不如直觉中快。

### 3. 不要轻率保存迭代器或引用

对 `deque` 的两端插入和删除，迭代器失效规则比 `vector` 更容易令人误判；不同操作对引用、指针和迭代器的影响也不完全相同。工程中最稳妥的原则是：若后续会修改 `deque`，不要长期保存指向其中元素的迭代器或引用；需要标识位置时优先保存稳定的业务 ID 或重新查找。算法局部代码若只在单次访问后立刻使用，则不必把这个问题夸大成禁忌。

## 六、总结

- `std::deque` 是双端顺序容器，支持两端 `push`/`pop` 与 `O(1)` 随机访问。
- 它适合两端状态都会变化的问题，不应因为功能更多就无差别取代 `vector` 或 `queue`。
- 滑动窗口最大值中保存的是下标：队头处理过期，队尾删除被新元素支配的较小候选。
- 单调递减队列保证队头对应最大值；每个下标至多进出一次，算法总时间为 `O(n)`。
- `queue` 表示 FIFO，`deque` 则开放两端操作；边权仅为 0 或 1 的最短路可以利用 `deque` 的前后入队。
- 两端操作前必须检查非空；中间插删仍是线性开销，修改容器后也应谨慎持有旧迭代器。

`deque` 的真正价值不是“比队列多几个方法”，而是它能把“过期元素在前、被支配候选在后”的双向淘汰过程写得直接而清楚。若你的问题没有这两个方向，选择更受限的容器通常反而更好。
