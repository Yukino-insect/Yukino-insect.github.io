理解汉明码的公式是一回事，真正实现时还要处理位序、索引和校验范围。本文固定采用最常见的 `(7,4)` 汉明码、偶校验和“位置从 1 开始编号”的约定，先手算一个完整例子，再给出可以直接运行的 Python 实现。

如果你还不熟悉校验位为何放在二的幂次位置，可以先阅读[《汉明码：从奇偶校验到单比特纠错》](汉明码：从奇偶校验到单比特纠错.md)。

## 一、先固定位序约定

`(7,4)` 汉明码共有 7 位，其中 4 位数据、3 位校验：

```text
位置： 1  2  3  4  5  6  7
角色： P1 P2 D1 P4 D2 D3 D4
```

本文把位置 1 写在左边，位置 7 写在右边；代码数组则使用 `code[0]` 表示位置 1。很多资料把最高位写成位置 7，或者把数据 `1011` 从右向左填入。只要编码和解码使用同一约定，结果都可以正确；真正危险的是读题时混用了两套位序。

### 1. 三个校验组为什么正好能报出位置

`P1`、`P2`、`P4` 不是任意取名。它们检查的位置由位置编号的二进制位决定：

| 校验位 | 覆盖的位置 | 对应的位置编号位 |
| --- | --- | --- |
| `P1` | 1、3、5、7 | 最低位为 1 |
| `P2` | 2、3、6、7 | 次低位为 1 |
| `P4` | 4、5、6、7 | 第三位为 1 |

因此位置 6 的编号是 `110₂`，它只会破坏 `P2` 与 `P4` 两个校验组。接收端写出 `S4S2S1 = 110` 后，并不是“从公式猜出 6”，而是在读位置 6 原本携带的三位标签。后续手算的每一步都依赖这个规则；如果它没有被固定下来，综合征就只是一串没有解释的 `0` 和 `1`。

## 二、手算编码：数据 `1011`

把数据位依次放到 `D1、D2、D3、D4`：

```text
位置： 1 2 3 4 5 6 7
内容： P P 1 P 0 1 1
```

采用偶校验，每个校验组包含校验位自己：

| 校验位 | 覆盖的位置 | 计算式 | 结果 |
| --- | --- | --- | --- |
| `P1` | 1、3、5、7 | `P1 ⊕ 1 ⊕ 0 ⊕ 1 = 0` | `P1 = 0` |
| `P2` | 2、3、6、7 | `P2 ⊕ 1 ⊕ 1 ⊕ 1 = 0` | `P2 = 1` |
| `P4` | 4、5、6、7 | `P4 ⊕ 0 ⊕ 1 ⊕ 1 = 0` | `P4 = 0` |

所以编码结果为：

```text
0110011
```

### 1. 逐位验证

不要只验证数据位。完整码字的三组异或都应为 `0`：

```text
位置 1、3、5、7：0 ⊕ 1 ⊕ 0 ⊕ 1 = 0
位置 2、3、6、7：1 ⊕ 1 ⊕ 1 ⊕ 1 = 0
位置 4、5、6、7：0 ⊕ 0 ⊕ 1 ⊕ 1 = 0
```

## 三、手算解码：综合征指向错误位

假设发送的 `0110011` 在位置 6 发生翻转，接收到 `0110001`。接收方对同样三组位置进行偶校验：

```text
S1 = 0 ⊕ 1 ⊕ 0 ⊕ 1 = 0
S2 = 1 ⊕ 1 ⊕ 0 ⊕ 1 = 1
S4 = 0 ⊕ 0 ⊕ 0 ⊕ 1 = 1
```

将检查结果写成 `S4 S2 S1`，即 `110₂ = 6`。这说明位置 6 出错。把位置 6 翻转后得到 `0110011`，再读取数据位置 3、5、6、7，恢复 `1011`。

如果综合征是 `000`，表示没有发现单比特错误；如果大于 7，则不可能由一个 `(7,4)` 码字中的单比特错误产生，通常意味着位序实现不一致或输入并非合法的 7 位码字。

## 四、用 Python 实现编码和解码

下面的实现有意把“位置编号”和“数组下标”分开：函数内部统一把位置 1 映射到 `code[0]`，这样校验范围就可以直接按教材中的位置书写。

### 1. 编码函数

```python
def hamming74_encode(data: str) -> str:
    """按位置 1..7 编码，data 的顺序为 D1、D2、D3、D4。"""
    if len(data) != 4 or any(bit not in "01" for bit in data):
        raise ValueError("data 必须是 4 位二进制字符串")

    code = [0] * 8  # 忽略下标 0，直接使用位置 1..7
    code[3], code[5], code[6], code[7] = map(int, data)

    # 偶校验：校验组所有位异或后应为 0
    code[1] = code[3] ^ code[5] ^ code[7]
    code[2] = code[3] ^ code[6] ^ code[7]
    code[4] = code[5] ^ code[6] ^ code[7]

    return "".join(str(code[position]) for position in range(1, 8))
```

这里的 `code[1]`、`code[2]` 和 `code[4]` 分别是 `P1、P2、P4`。异或式中没有把校验位自己写进去，是因为我们正在反推它；代入后，完整校验组自然会得到 0。

### 2. 解码函数

```python
def hamming74_decode(word: str) -> tuple[str, int]:
    """返回 (恢复后的 4 位数据, 综合征)。综合征为 0 表示未发现错误。"""
    if len(word) != 7 or any(bit not in "01" for bit in word):
        raise ValueError("word 必须是 7 位二进制字符串")

    code = [0] + [int(bit) for bit in word]

    s1 = code[1] ^ code[3] ^ code[5] ^ code[7]
    s2 = code[2] ^ code[3] ^ code[6] ^ code[7]
    s4 = code[4] ^ code[5] ^ code[6] ^ code[7]
    syndrome = s1 | (s2 << 1) | (s4 << 2)

    if syndrome != 0:
        if syndrome > 7:
            raise ValueError("综合征超出 (7,4) 汉明码的位置范围")
        code[syndrome] ^= 1

    data = "".join(str(code[position]) for position in (3, 5, 6, 7))
    return data, syndrome
```

`syndrome = s1 | (s2 << 1) | (s4 << 2)` 把三个检查结果按二进制权重拼起来：`S1` 是最低位，`S2` 权重为 2，`S4` 权重为 4。不要把它写成字符串后再凭视觉判断，位运算更能直接表达“校验组编号就是位置编号”。

### 3. 运行几个测试

```python
word = hamming74_encode("1011")
print(word)  # 0110011

received = "0110001"  # 第 6 位翻转
data, syndrome = hamming74_decode(received)
print(data, syndrome)  # 1011 6
```

这段代码能够纠正单比特错误，但不能凭空获得多位错误的信息。若同时翻转两个位置，综合征仍可能是某个 1 到 7 的数，函数会把其中一位“修正”，从而输出错误数据。生产代码不应把这个函数当作任意错误模式下的安全恢复器。

## 五、实现时最容易踩的坑

### 1. 位置从 0 还是从 1 开始

教材中的校验组依赖位置的二进制表示，因此必须从 1 开始编号。数组可以从 0 开始，但需要明确转换；直接拿数组下标判断 `(index & parity_position)`，通常会把校验范围整体错开。

### 2. 数据顺序与显示顺序相反

有的资料把 `D1` 放在最低有效位，有的资料把它放在最左侧。编码后的比特串可能看起来不同，但只要双方约定一致，码距和纠错逻辑并未改变。写协议或接口时，应明确“第几个字符对应哪个码字位置”。

### 3. 忘记检查输入是否为合法二进制

纠错算法默认每个输入位都是 `0` 或 `1`。如果把空格、十六进制字符或长度错误的数据直接转成整数，得到的综合征没有语义，排查起来只会徒增一些并不必要的神秘感。

## 六、总结

- `(7,4)` 汉明码把 4 位数据放到位置 3、5、6、7，把校验位放到 1、2、4。
- 偶校验要求三组覆盖范围的异或结果都为 0；解码时三个失败标志拼成综合征。
- 综合征 `6` 就表示第 6 位出错，翻转该位后再读取数据位即可恢复原文。
- 代码实现时最重要的是固定位序、区分 1-based 位置与 0-based 数组下标。
- 经典 `(7,4)` 汉明码只对单比特纠错有严格保证；多位错误需要 SEC-DED 或更强的 ECC。
