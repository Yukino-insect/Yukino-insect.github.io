在 8086 汇编中，`ADD` 和 `SUB` 不只是把两个十六进制数相加或相减。指令执行后，CPU 还会更新标志寄存器中的 `CF`、`OF`、`SF`、`ZF` 等状态位，后续的条件转移指令会根据这些标志决定是否跳转。

其中最容易混淆的是：

- `CF` 主要描述无符号运算中的进位或借位；
- `OF` 主要描述补码有符号运算是否超出表示范围；
- 同一次运算可能同时出现 `CF=1` 和 `OF=1`，也可能只有其中一个为 1；
- `SUB` 用补码加法实现时，内部最终进位与 8086 对外提供的 `CF` 极性相反。

本文以 8086 的固定宽度整数运算为主线，总结 `ADD` 和 `SUB` 执行后 `CF`、`OF` 的更新规则，并给出适合做题的快速判断方法。

## 一、先区分位模式、无符号数和补码数

寄存器中只有固定宽度的二进制位。例如，16 位 `AX` 中的：

```text
9FD7H = 1001 1111 1101 0111B
```

CPU 不会给这串位附带“无符号”“补码”或“原码”标签。它可以被解释为：

- 无符号数：

  $$
  9FD7H=40919
  $$

- 16 位补码有符号数：

  $$
  9FD7H=40919-65536=-24617
  $$

`ADD` 和 `SUB` 首先只是对位模式进行固定宽度的二进制运算；`CF` 和 `OF` 则分别为无符号解释和补码有符号解释提供判断依据。

对于 `n` 位运算，写回寄存器的通常是低 `n` 位：

$$
R=(A\mathbin{\operatorname{op}}B)\bmod 2^n
$$

超出 `n` 位的进位不会写入普通目的操作数，但可能被记录到 `CF`，或者参与 `OF` 的生成。

## 二、ADD 指令的标志位规则

### 1. ADD 的基本语义

```asm
ADD dest, src
```

执行：

```text
dest ← dest + src
```

结果写回 `dest`，并更新相关标志位。本文重点讨论 `CF` 和 `OF`。

### 2. ADD 的 CF：最高位之外的进位

对于 `n` 位无符号加法，如果完整结果产生第 `n+1` 位，则：

$$
CF=1
$$

否则：

$$
CF=0
$$

因此，做题时可以直接把操作数当作无符号数比较和计算：

$$
CF=1\iff A+B\geq2^n
$$

例如，8 位运算：

```text
  1111 1111    255
+ 0000 0001      1
-----------
1 0000 0000    完整结果 256
```

写回低 8 位后：

```text
结果 = 0000 0000
CF   = 1
```

这里 `CF=1` 表示无符号结果超出 8 位范围 `0～255`。

### 3. ADD 的 OF：同号相加得到异号结果

8086 的 `OF` 面向补码有符号数。对于加法，判断口诀是：

> 两个操作数符号相同，而结果符号与它们不同，发生有符号溢出。

令：

- `SA` 为被加数的符号位；
- `SB` 为加数的符号位；
- `SR` 为结果的符号位。

则：

$$
OF=\neg(S_A\oplus S_B)\land(S_A\oplus S_R)
$$

也可以用加法器的进位表示。若 `C_{n-1}` 是进入符号位的进位，`C_n` 是离开符号位的最终进位，则：

$$
OF=C_{n-1}\oplus C_n
$$

### 4. ADD 的四种符号组合

| 被加数 | 加数 | 结果符号 | `OF` |
| --- | --- | --- | ---: |
| 正数 | 正数 | 变负 | 1 |
| 正数 | 正数 | 仍为正 | 0 |
| 负数 | 负数 | 变正 | 1 |
| 负数 | 负数 | 仍为负 | 0 |
| 正数 | 负数 | 任意 | 0 |
| 负数 | 正数 | 任意 | 0 |

正负数相加时，结果一定落在两个数之间，不会超出补码范围，所以不会发生有符号溢出。

### 5. ADD 示例：`CF=0` 而 `OF=1`

考虑 16 位运算：

```text
  42C0
+ 608A
-------
  A34A
```

两个操作数最高位都是 `0`，按补码解释为正数；结果 `A34A` 的最高位为 `1`，按补码解释为负数。因此：

```text
OF = 1
```

但完整结果没有超过 `FFFFH`，没有第 17 位进位：

```text
CF = 0
```

这说明 `OF` 和 `CF` 分别回答有符号和无符号问题，不能互相替代。

## 三、SUB 指令的标志位规则

### 1. SUB 的基本语义

```asm
SUB dest, src
```

执行：

```text
dest ← dest - src
```

8086 的减法器可以利用加法器完成：

$$
A-B=A+\overline{B}+1
$$

也就是对减数按位取反、加 1，再与被减数相加。

但是要注意：这只是硬件实现或数学等价形式，不代表 CPU 会先判断操作数采用了哪种编码。寄存器中的位模式本身没有“类型标签”。

### 2. SUB 的 CF：发生无符号借位

对于 8086 的 `SUB`：

$$
CF=1\iff A<B
$$

这里的比较是**无符号比较**。

也就是说：

- 被减数小于减数：发生借位，`CF=1`；
- 被减数大于或等于减数：没有借位，`CF=0`。

这与 `ADD` 的 `CF` 不能简单理解成同一件事：

- `ADD` 的 `CF=1`：最高位之外产生进位；
- 8086 `SUB` 的 `CF=1`：无符号减法发生借位。

### 3. 为什么补码加法没有最终进位时，SUB 的 CF 反而是 1

减法用补码加法实现时，内部加法器计算：

$$
A+\overline{B}+1
$$

设这次加法器的最终进位为 `C_n`，则：

$$
CF_{\text{SUB}}=\neg C_n
$$

原因是：

- 有最终进位，表示没有借位；
- 没有最终进位，表示发生借位。

例如 4 位计算：

```text
3 - 5
```

转成补码加法：

```text
  0011       ; 3
+ 1011       ; -5 的补码
------
  1110       ; -2
```

没有第 5 位进位，但无符号角度下 `3<5`，确实发生借位，所以 `SUB` 的 `CF=1`。

反过来：

```text
5 - 3
```

```text
  0101
+ 1101       ; -3 的补码
------
1 0010
```

有最终进位，表示没有借位，所以 `CF=0`。

### 4. SUB 的 OF：异号相减，结果与被减数异号

对于补码有符号减法，判断口诀是：

> 被减数和减数符号不同，而结果符号与被减数不同，发生有符号溢出。

公式为：

$$
OF=(S_A\oplus S_B)\land(S_A\oplus S_R)
$$

也可以继续使用进入、离开符号位的进位：

$$
OF=C_{n-1}\oplus C_n
$$

因为 `SUB` 已经被转换为 `A + NOT(B) + 1`，这个 `OF` 公式仍然适用。

### 5. SUB 的四种符号组合

| 被减数 | 减数 | 结果符号 | `OF` |
| --- | --- | --- | ---: |
| 正数 | 正数 | 任意 | 0 |
| 负数 | 负数 | 任意 | 0 |
| 正数 | 负数 | 变负 | 1 |
| 正数 | 负数 | 仍为正 | 0 |
| 负数 | 正数 | 变正 | 1 |
| 负数 | 正数 | 仍为负 | 0 |

同号相减不会发生有符号溢出；异号相减时，才需要观察结果符号。

## 四、适合做题的判断流程

### 1. ADD 的判断流程

执行 `ADD A, B` 后：

1. 先计算低 `n` 位结果；
2. 把 `A` 和 `B` 当作无符号数相加，判断是否超过 `2^n-1`，得到 `CF`；
3. 看 `A`、`B`、结果的最高位：同号相加而结果异号，则 `OF=1`；
4. 不要因为有 `CF` 就直接认为有符号溢出，也不要因为没有 `CF` 就认为没有溢出。

### 2. SUB 的判断流程

执行 `SUB A, B` 后：

1. 先计算低 `n` 位结果；
2. 把 `A` 和 `B` 当作无符号数比较：`A<B` 则 `CF=1`，否则 `CF=0`；
3. 看 `A`、`B`、结果的最高位：异号相减且结果与 `A` 异号，则 `OF=1`；
4. 若用补码加法验证，记住没有最终进位表示发生借位，因此 `SUB` 的 `CF=1`。

### 3. 标志位快速对照表

| 指令 | `CF=1` 的含义 | `OF=1` 的含义 |
| --- | --- | --- |
| `ADD A, B` | 最高位之外产生进位 | 同号相加，结果异号 |
| `SUB A, B` | 无符号被减数小于减数，发生借位 | 异号相减，结果与被减数异号 |

## 五、完整例题：`ADD` 后再执行 `SUB`

考虑如下程序段：

```asm
ADD AX, BX
JNO L1
JNC L2
SUB AX, BX
JNC L3
JNO L4
JMP L5
```

初始：

```text
AX = D023H
BX = 9FD7H
```

### 1. ADD 阶段

```text
  D023
+ 9FD7
--------
1 6FFA
```

16 位 `AX` 只保留低 16 位：

```text
AX = 6FFAH
```

两个操作数最高位都为 `1`，结果最高位为 `0`，所以：

```text
CF = 1
OF = 1
```

因此：

```asm
JNO L1    ; OF=1，不跳转
JNC L2    ; CF=1，不跳转
```

### 2. SUB 阶段

此时执行的是：

```text
6FFAH - 9FD7H
```

直接计算低 16 位：

```text
  6FFA
- 9FD7
--------
  D023
```

因此：

```text
AX = D023H
```

判断 `CF`：

```text
6FFAH < 9FD7H
```

这是无符号比较，被减数小于减数，所以发生借位：

```text
CF = 1
```

判断 `OF`：

```text
6FFA：正数
9FD7：负数
D023：负数
```

这是正数减负数，结果却变成负数，所以：

```text
OF = 1
```

因此：

```asm
JNC L3    ; CF=1，不跳转
JNO L4    ; OF=1，不跳转
JMP L5    ; 跳转到 L5
```

最终程序转向：

$$
\boxed{L5}
$$

## 六、常见错误

### 错误一：把 `CF` 和 `OF` 都叫“溢出标志”

`CF` 与无符号进位、借位有关；`OF` 与补码有符号溢出有关。它们服务于两种不同的数值解释。

### 错误二：认为最高位有进位就一定 `OF=1`

最高位之外的进位只能直接说明 `CF`。例如负数加正数可能有 `CF`，但不一定有 `OF`。

### 错误三：认为 `SUB` 的补码加法没有最终进位，所以 `CF=0`

对于 8086 的 `SUB`，没有最终进位表示发生借位，因此：

```text
补码加法最终进位 = 0  →  SUB 的 CF = 1
```

### 错误四：把负数的补码再次取反加一后直接当作原操作数

例如，`9FD7H` 作为 16 位补码位模式本身已经表示负数。对它取反加一得到 `6029H`，是在求它的相反数或绝对值，不能在原来的 `ADD` 中直接用 `6029H` 替代 `9FD7H`。

### 错误五：忽略指令执行顺序

如果先执行 `ADD AX, BX`，后面的 `SUB AX, BX` 使用的是 `ADD` 写回后的新 `AX`，不是最初的 `AX`。同时，`SUB` 会重新更新 `CF` 和 `OF`，后面的条件跳转检查的是 `SUB` 的新标志位。

## 七、总结

- `ADD` 的 `CF`：最高位之外产生进位时为 1。
- `SUB` 的 `CF`：无符号被减数小于减数、发生借位时为 1。
- `ADD` 的 `OF`：两个操作数同号而结果异号时为 1。
- `SUB` 的 `OF`：两个操作数异号而结果与被减数异号时为 1。
- 加法和减法都可以用“进入符号位的进位 XOR 离开符号位的进位”判断 `OF`。
- `SUB` 转换为 `A+\overline{B}+1` 后，若加法器没有最终进位，恰好说明原减法发生借位，因此 8086 的 `CF=1`。
- 做题时，判断 `CF` 最快的方法通常是无符号比较；判断 `OF` 最快的方法通常是观察操作数和结果的符号位。

只要把“无符号的进位或借位”和“有符号补码的范围溢出”分开，`ADD` 与 `SUB` 的标志位就不再容易混淆。
