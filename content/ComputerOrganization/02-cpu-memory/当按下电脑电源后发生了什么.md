按下电脑电源键之后，屏幕亮起来、系统进入桌面，看起来只是几十秒的等待。实际上，这中间发生了一串非常精密的接力：

```text
供电稳定 -> CPU 复位 -> 执行固件 -> 初始化硬件 -> 找到启动设备 -> 加载 Bootloader -> 加载内核 -> 启动用户空间
```

这篇文章按时间顺序，把这条启动链路从硬件讲到操作系统。

## 一、电源按钮按下后，首先发生的是供电

电源按钮本身并不是“直接给 CPU 通电”的开关。它更像是一个信号按钮。

按下电源键后，大致流程是：

1. 主板上的电源管理电路收到开机信号。
2. 主板通知电源供应器开始输出各路电压。
3. 主板上的 VRM 等供电模块为 CPU、内存、芯片组等部件提供稳定电压。
4. 当电压稳定后，电源会向主板发送 `Power Good` 信号。

`Power Good` 的含义很简单：

> 电源已经稳定，核心硬件可以开始工作。

在这个信号稳定之前，CPU 不应该随意执行指令。否则电压还没准备好，系统状态就可能不可预测。硬件不讲情面，这一点比人类诚实得多。

## 二、CPU 复位并跳到固定入口

供电稳定后，CPU 会从复位状态开始运行。

这里要注意一个细节：CPU 上电后并不是“所有寄存器都清零”。更准确的说法是：

> CPU 会进入架构规定的复位状态，一些寄存器会被设置为规定的初始值，然后从固定的复位入口开始取指令。

在 x86 平台上，CPU 复位后会从一个固定地址附近开始执行指令。这个地址会被平台硬件映射到主板上的 ROM / Flash 芯片，里面存放的是固件程序：

- 传统机器上常见的是 BIOS。
- 现代 PC 上通常是 UEFI。

BIOS / UEFI 不依赖硬盘，也不依赖操作系统。它的任务是把一台刚刚通电、几乎什么都还没准备好的机器，带到“可以加载操作系统”的状态。

## 三、固件开始执行：POST 和硬件初始化

CPU 执行到固件代码后，BIOS / UEFI 会开始做早期初始化。

最常听到的一个词是 **POST（Power-On Self-Test，上电自检）**。

POST 和早期初始化大致包括：

- 检查 CPU 基本状态。
- 初始化芯片组和主板关键控制器。
- 初始化内存控制器并训练内存。
- 检测内存容量。
- 初始化显卡或基础显示输出。
- 检测键盘、存储控制器、USB 控制器等设备。
- 建立固件自己的运行环境。

这里的“初始化内存”非常关键。刚上电时，内存并不是天然就能被 CPU 随意使用。固件需要完成内存控制器配置、时序训练等工作，系统才能稳定访问 DRAM。

如果这一步失败，你可能会看到黑屏、蜂鸣声、主板错误码，或者机器反复重启。

## 四、UEFI 和 BIOS 的启动方式有什么区别？

硬件初始化完成后，固件会根据启动顺序查找可启动设备，例如：

```text
NVMe SSD -> SATA SSD -> USB -> Network
```

传统 BIOS 和现代 UEFI 的启动方式不同。

### 1. 传统 BIOS + MBR

传统 BIOS 通常会读取启动磁盘的第一个扇区，也就是 MBR（Master Boot Record）。

MBR 只有 512 字节，其中包含：

- 一小段启动代码。
- 分区表。
- 启动签名。

BIOS 会把这段启动代码加载到内存中的固定位置，然后跳转执行。由于 MBR 空间很小，它通常只负责加载更完整的下一阶段 Bootloader。

### 2. UEFI + EFI System Partition

UEFI 的方式更现代。

UEFI 通常会读取磁盘上的 EFI System Partition（ESP），在其中查找 `.efi` 启动程序。例如：

- Windows Boot Manager。
- GRUB。
- systemd-boot。
- 其他厂商或操作系统提供的 UEFI bootloader。

UEFI 可以理解文件系统，也能直接加载 PE 格式的 `.efi` 程序。它不需要像传统 BIOS 那样只能从第一个扇区里挤出一点点启动代码。

UEFI 还可能参与 Secure Boot，校验启动程序签名，防止未授权的启动代码在系统加载前运行。

## 五、Bootloader 的职责

Bootloader 是固件和操作系统内核之间的中间人。

它的核心职责是：

> 找到操作系统内核，把它加载到内存，并把控制权交给它。

不同操作系统、不同平台的细节不完全一样，但 Bootloader 通常会做这些事：

- 读取内核镜像。
- 读取 initramfs / initrd 等早期根文件系统。
- 读取启动参数。
- 准备内存布局信息。
- 准备设备树、ACPI 表或其他硬件描述信息。
- 设置 CPU 运行模式，例如从实模式进入保护模式或长模式。
- 跳转到内核入口点。

例如在 Linux 启动中，GRUB 会把 Linux kernel 和 initramfs 加载到内存中，然后把启动参数传给内核，最后跳转到内核入口。

从这一刻开始，操作系统内核正式接管启动流程。

## 六、内核初始化

内核刚开始运行时，系统还远没有进入“可用桌面”的状态。内核需要先把自己的地基搭起来。

典型步骤包括：

1. 建立分页和内存管理。
2. 初始化中断和异常处理。
3. 初始化调度器。
4. 初始化时钟和定时器。
5. 识别 CPU、内存和总线拓扑。
6. 加载或初始化关键驱动。
7. 建立设备模型。
8. 挂载根文件系统。

在 Linux 中，如果使用 initramfs，内核会先挂载一个临时的早期根文件系统，用它加载必要驱动、识别真正的根分区，然后再切换到真实根文件系统。

这一步完成后，内核已经能管理内存、调度任务、处理中断、访问设备，也能启动用户态程序。

## 七、第一个用户态进程启动

内核初始化到一定阶段后，会启动第一个用户态进程。

在 Linux 中，它通常是：

- `init`
- `systemd`

在 Windows 中，早期用户态启动链路会涉及：

- Session Manager，也就是 `smss.exe`
- Windows 子系统和登录相关进程
- 服务控制管理器等系统组件

第一个用户态进程之后，会继续拉起系统服务：

- 设备管理服务。
- 网络服务。
- 日志服务。
- 登录服务。
- 图形界面。
- 桌面环境。

当图形系统启动、登录流程完成后，我们才看到熟悉的桌面、窗口、鼠标指针和应用程序。

这些东西看起来是“电脑启动好了”的标志，但从操作系统视角看，它们只是用户空间里陆续运行起来的一批程序。

## 八、固件是否彻底退场？

更准确的说法是：启动控制权交给内核后，固件不再主导启动流程，但它留下的信息和部分接口仍然可能被操作系统使用。

例如：

- ACPI 表会告诉操作系统硬件拓扑、电源管理、设备信息等。
- UEFI Runtime Services 可能在运行时仍被操作系统调用。
- SMBIOS 等表会提供硬件厂商、主板、内存等信息。

所以，不能简单说“固件彻底消失”。它更像是完成了主线任务，把舞台交给内核，但某些资料和接口还留在后台。

## 九、完整流程总结

按时间顺序，可以把电脑启动过程概括为：

1. 按下电源键，主板电源管理电路收到开机信号。
2. 电源和主板供电模块输出稳定电压。
3. `Power Good` 信号通知系统供电稳定。
4. CPU 从复位状态开始执行固件入口代码。
5. BIOS / UEFI 执行 POST 和硬件初始化。
6. 固件按启动顺序查找可启动设备。
7. BIOS 读取 MBR，或 UEFI 读取 EFI 分区中的 `.efi` 程序。
8. Bootloader 加载操作系统内核和必要启动文件。
9. Bootloader 把控制权交给内核。
10. 内核初始化内存、中断、调度器、驱动和文件系统。
11. 内核启动第一个用户态进程。
12. 用户态服务、登录界面和桌面环境陆续启动。

## 十、一句话总结

> 按下电源键后，电脑会先完成供电稳定和 CPU 复位，然后由 BIOS / UEFI 初始化硬件并找到启动设备，再由 Bootloader 加载操作系统内核。内核接管后初始化系统资源，启动第一个用户态进程，最后用户空间服务和桌面环境陆续运行起来。
