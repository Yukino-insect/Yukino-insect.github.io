学习 8086 时，常会见到“内存分为奇存储体和偶存储体”的说法。它听上去像是把地址人为切成了两半，然而真正的原因并不神秘：**8086 按字节编址，却有一条 16 位数据总线。**把相邻的偶地址字节和奇地址字节分别接到总线的低、高 8 位，CPU 就能在一个总线周期内读写一个对齐的 16 位字，同时仍然保留逐字节访问的能力。

因此，奇偶存储体不是为了让地址有“奇、偶两种性质”而额外发明的规则，而是一种用两片 8 位存储体配合 16 位数据总线的组织方法。理解 `A0` 和 `BHE#` 各自到底表示什么，许多看似反常的题目便不必死记硬背了。

## 一、先分清：8086 的地址单位和数据总线宽度并不相同

8086 有 20 位物理地址，可寻址 `2^20 = 1 MiB` 的空间；它采用**字节编址**，所以地址 `00000H`、`00001H`、`00002H` 分别表示相邻的三个字节位置。一个 16 位字占两个连续字节。

另一方面，8086 的数据总线宽度是 16 位：数据线 `D15` 到 `D0` 能在一次总线传送中并行传输 16 个二进制位，即两个字节。若只使用一片普通的 8 位宽存储器，无论 CPU 的总线有多宽，一次也只能从这片芯片得到 8 位；要真正利用 16 位数据总线，就需要让两组 8 位数据同时参与传送。

8086 的常见内存组织如下：

```text
CPU 数据总线                         内存中的字节地址

D15 ........ D8  <──> 奇存储体  <──> 00001H、00003H、00005H、...
D7  ........ D0  <──> 偶存储体  <──> 00000H、00002H、00004H、...
```

- **偶存储体**保存偶数物理地址的字节，并连接到低 8 位数据线 `D7:D0`。
- **奇存储体**保存奇数物理地址的字节，并连接到高 8 位数据线 `D15:D8`。

这里“奇”“偶”说的是**每个字节的物理地址**，不是一个 16 位字本身。地址 `00000H` 与 `00001H` 是相邻两字节，恰好分别位于偶、奇两个存储体；它们可以同时送到数据总线的低半部和高半部。

## 二、为什么两个存储体能让一次传送得到一个字

以小端序的 8086 为例，16 位数 `1234H` 放在起始地址 `00000H` 时，低字节 `34H` 位于低地址，高字节 `12H` 位于高地址：

```text
物理地址       存储体        内容        对应数据线
00000H          偶存储体      34H         D7:D0
00001H          奇存储体      12H         D15:D8
```

CPU 读取从 `00000H` 开始的一个字时，同时选中两个存储体。偶存储体把 `34H` 放到 `D7:D0`，奇存储体把 `12H` 放到 `D15:D8`，CPU 便在一个总线周期内得到 `1234H`。

这就是设计的收益：对连续的两个字节，**不是先读低字节、再读高字节，而是让两片 8 位存储体并行工作。**若没有奇偶分体，8086 仍可以实现 16 位数据类型，但每次取一个字都要进行两次 8 位传送，16 位外部总线也就没有充分发挥作用。

需要强调的是，两个存储体并不保存两份相同的内存内容。它们是交错保存一条连续字节地址空间：偶存储体保存第 0、2、4……个字节，奇存储体保存第 1、3、5……个字节。程序看到的地址空间仍是一维、连续的。

## 三、`A0` 与 `BHE#`：一个是地址位，一个是高字节使能

8086 用两个信号说明本次总线周期要使用哪一半数据总线：

- `A0` 是物理地址的最低位。`A0 = 0` 表示当前地址是偶地址，`A0 = 1` 表示当前地址是奇地址。
- `BHE#` 是 **Bus High Enable**，即“高字节使能”。末尾的 `#` 表示低有效：`BHE# = 0` 时，允许 `D15:D8` 这 8 条高位数据线参与本次传送。

偶存储体与低 8 位数据线对应，是否应参与由 `A0 = 0` 表明；奇存储体与高 8 位数据线对应，是否应参与由 `BHE# = 0` 表明。下表是最重要的选择关系：

| `BHE#` | `A0` | 本周期启用的数据线 | 被选中的存储体 |
| --- | --- | --- | --- |
| 1 | 0 | `D7:D0` | 偶存储体 |
| 0 | 1 | `D15:D8` | 奇存储体 |
| 0 | 0 | `D15:D0` | 奇、偶存储体同时启用 |
| 1 | 1 | 无有效字节传送 | 一般不用于正常内存数据传送 |

一个特别容易混淆的说法是“`A0` 是偶存储体的地址、`BHE#` 是奇存储体的地址”。这不准确。

`A0` 首先且始终是**完整物理地址的一部分**：它的值正是地址最低位，告诉我们访问的起始字节是偶还是奇。`BHE#` 则根本不是地址位，而是总线控制信号。对于两片 8 位存储器而言，芯片内部用来定位单元的地址线通常从 CPU 的 `A1` 开始连接：CPU 地址 `00000H` 和 `00001H` 对两片芯片而言都对应各自芯片内的“第 0 个字节位置”，差别在于本次到底选中偶体、奇体还是两者。于是 `A0` 在外部连接中也承担了“低字节是否有效”的选择作用，但它并没有变成一个脱离物理地址的“bank 地址”。

```text
CPU 物理地址：... A3 A2 A1 A0
                         │  │
                         │  └─ 地址奇偶性；A0=0 时低字节/偶体有效
                         └──── 两片存储体用作其内部地址的一部分

BHE#（控制信号）= 0  ─────> 高字节/奇体有效
```

更精确地说，具体存储器电路还会把 `A0`、`BHE#` 与读写控制、片选信号经过逻辑门组合成各芯片的最终选通信号；但软件和汇编层面应掌握的含义，就是“`A0` 反映低地址字节是否使用，`BHE#` 反映高数据字节是否使用”。

## 四、四种典型访问：字节、对齐字和非对齐字

只要按“起始地址奇偶性”和“访问 1 字节还是 2 字节”分析，就能推出 8086 的常见总线周期。

### 1. 读取偶地址的一个字节

读取地址 `00000H` 的一个字节，只需要偶存储体：

```text
地址：00000H
A0 = 0，BHE# = 1
启用：D7:D0（偶存储体）
```

读出的字节经低 8 位数据线进入 CPU。高 8 位没有必要参与。

### 2. 读取奇地址的一个字节

读取地址 `00001H` 的一个字节，只需要奇存储体：

```text
地址：00001H
A0 = 1，BHE# = 0
启用：D15:D8（奇存储体）
```

此时数据虽然出现在 `D15:D8` 上，CPU 会按“字节访问”的语义取出它；不应误以为奇地址字节在程序中天然是一个“高字节数”。它只是因为硬件接线而走高半条数据总线。

### 3. 读取偶地址开始的一个字

读取从 `00000H` 开始的 16 位字，需要地址 `00000H` 和 `00001H` 两个字节，正好分处两个存储体：

```text
地址：00000H，访问范围：00000H～00001H
A0 = 0，BHE# = 0
启用：D15:D0（两个存储体同时工作）
```

这是**对齐字访问**。两个字节恰好构成同一组“偶地址 + 随后的奇地址”，所以一个总线周期即可完成。这里所谓“对齐”，对 16 位字而言就是起始地址为偶数，即地址能被 2 整除。

### 4. 读取奇地址开始的一个字

现在读取从 `00001H` 开始的一个字。它覆盖的字节是 `00001H` 与 `00002H`：前者在奇存储体，后者却在下一个偶地址位置的偶存储体中。

```text
第一个总线周期：读取 00001H
A0 = 1，BHE# = 0
启用：D15:D8（奇存储体）

第二个总线周期：读取 00002H
A0 = 0，BHE# = 1
启用：D7:D0（偶存储体）
```

CPU 再把这两个字节按小端序组合成一个 16 位值。也就是说，**奇地址开始的字访问跨越了两个相邻的“偶+奇”配对，不能在同一个总线周期中用 `A0=0、BHE#=0` 同时取到。**它必然需要两个总线周期，性能通常比偶地址字访问差。

用地址图看会更直观：

```text
                一次可并行取的配对
偶地址字访问： [00000H（偶体） | 00001H（奇体）]  → 1 个周期

奇地址字访问：  00001H（奇体） | 00002H（偶体）  → 跨两个配对，2 个周期
```

写一个字时道理相同。偶地址开始时，CPU 可在一次总线周期中把低字节送往偶体、高字节送往奇体；奇地址开始时，必须拆成两个字节写周期。8086 因而支持非对齐访问，却会为它付出额外的总线时间。

## 五、这与 8088、现代 CPU 中的“对齐”有什么关系

8088 与 8086 的指令集基本兼容，却只有 8 位外部数据总线。因此即使一个字从偶地址开始，8088 也不能让两个 8 位存储体同时传输一个 16 位数据；它通常仍需两个总线周期。奇偶存储体的并行优势，正是 8086 的 16 位外部总线所带来的。

现代 x86 CPU 的缓存、内存控制器和总线组织早已远比 8086 复杂。例如缓存通常以几十字节的缓存行搬运数据，DRAM 也会按通道、bank、行列和突发传送工作。今天的处理器多半能处理许多未对齐访问，有时只会略慢；但若访问跨越缓存行或页边界，代价仍可能明显增加。8086 的奇偶存储体是这一类问题最直观的早期模型：**数据大小与硬件一次方便处理的边界一致时，工作可以并行完成；跨过边界时，硬件就需要额外步骤。**

## 六、总结

- 8086 是字节编址机器，却有 16 位数据总线；奇、偶两个 8 位存储体让它能并行传送相邻两字节。
- 偶存储体保存偶地址字节并接到 `D7:D0`；奇存储体保存奇地址字节并接到 `D15:D8`。它们交错组成同一段连续内存，并非两份副本。
- `A0` 是物理地址的最低位，表示起始地址的奇偶；`BHE#` 是低有效的高字节使能控制信号，**不是地址位**。
- 偶地址字节、奇地址字节、偶地址字分别使用低半总线、高半总线、全 16 位总线；奇地址开始的字跨越两个配对，必须拆成两个总线周期。
- 因此，8086 区分奇偶存储体的根本目的，是在不放弃字节寻址的前提下，提高 16 位数据总线的利用率；而“字地址最好从偶地址开始”正是这套硬件组织自然导出的结果。
