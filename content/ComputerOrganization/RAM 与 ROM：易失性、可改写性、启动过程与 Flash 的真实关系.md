“RAM 可以读写，ROM 只能读”是入门时方便记忆的一句话，却不足以解释现代计算机。固件通常放在可升级的 Flash 里；CPU 会把磁盘上的程序读入 RAM 后执行；代码段在运行期常被映射为只读；而缓存、寄存器、SSD 也都能保存比特。若只用“能不能写”给它们分类，概念很快就会打结。

更可靠的方式是分开问四个问题：**断电后数据还在吗？正常运行时谁能写？写入粒度和代价是什么？它在启动和执行过程中扮演什么角色？**RAM、ROM 和 Flash 的区别便会清楚得多。

## 一、先给结论：RAM、ROM 不是同一维度的反义词

| 维度 | RAM 的典型答案 | 传统 ROM 的典型答案 | 现代 Flash 的典型答案 |
| --- | --- | --- | --- |
| 断电后内容 | 丢失，易失性 | 保留，非易失性 | 保留，非易失性 |
| 正常工作时写入 | 可按字节/字等细粒度随机读写 | 出厂后通常不能写 | 能写，但先擦除再编程，粒度和寿命受限 |
| 主要用途 | 程序运行、数据、栈、堆、页缓存 | 固定启动代码、永久查找表 | 可升级固件、嵌入式程序、持久配置、SSD 存储介质 |
| 访问特征 | 低延迟、适合频繁读写 | 适合稳定内容 | 读取快于擦写；擦除通常按块，写入有磨损限制 |

因此，以下说法分别只对一部分场景成立：

- **“ROM 只能读”**：对 mask ROM 这类传统只读芯片基本成立；对主板固件常用的 Flash 则不成立，它可以更新，只是不适合当普通内存频繁覆写。
- **“RAM 就是内存，ROM 就是硬盘”**：不成立。RAM 和 ROM/Flash 描述的是半导体存储的性质与用途；硬盘、SSD 是更大容量的持久存储设备，内部可使用磁介质或 NAND Flash。
- **“只读代码一定放 ROM”**：不成立。程序文件可能在 SSD 上，装载后代码页通常在 RAM 中，只是页表把它标记成不可写。

## 二、存储层次：RAM 和 ROM 各处在哪一层

一台计算机并没有一块叫作“内存”的单一器件，而是有速度、容量、易失性不同的层次：

```text
更快、更小、单位比特成本更高

寄存器
  -> CPU Cache（通常 SRAM）
    -> 主内存（通常 DRAM，也就是日常所说的 RAM）
      -> 持久存储（SSD / HDD）
        -> 远程存储 / 备份

更慢、更大、断电后通常仍保留数据
```

固件存储并不总在这条“容量层次”线上：它常位于板上的 SPI NOR Flash 或 SoC 内部 Boot ROM 中，容量较小，但在 CPU 刚复位、DRAM 甚至还不能正常使用时就必须可读。

| 名称 | 常见物理实现 | 易失性 | CPU 是否直接频繁访问 | 典型角色 |
| --- | --- | --- | --- |
| 寄存器 | CPU 触发器/寄存器堆 | 易失 | 是 | 当前指令操作数、PC、状态 |
| Cache | SRAM | 易失 | CPU 自动管理 | 隐藏 DRAM 延迟 |
| 主内存 | DRAM | 易失 | 是，通常经缓存与内存控制器 | 正在运行的代码和数据 |
| Boot ROM | mask ROM 或 SoC 内置 ROM | 非易失 | 复位后可读 | 最早的可信启动代码 |
| 固件 Flash | NOR Flash 等 | 非易失 | 可映射读取或经控制器读取 | UEFI/BIOS、设备固件、嵌入式程序 |
| SSD | NAND Flash + 控制器/DRAM | 非易失 | 通常经块设备协议访问 | 文件、程序、交换区、数据库 |

注意“CPU 是否直接访问”也不是二元问题。有些 Flash 可以 memory-mapped，CPU 像读地址一样读其中的字节；有些必须通过 SPI、eMMC、NVMe 等控制器协议读取。能从 CPU 地址空间读到，不表示它就具备 DRAM 那样的随机写性能。

## 三、RAM：为什么主内存通常是 DRAM

RAM 是 Random Access Memory，核心含义是：访问某个位置不需要像磁带那样从头顺序走到那里。它不等于“必然易失”，但在现代通用计算机语境中，RAM 通常指 **DRAM 主内存**。

### 1. DRAM：用电荷保存一位，因此需要刷新

DRAM（Dynamic RAM）一个存储单元可概念化为“晶体管 + 微小电容”：

```text
电容有足够电荷  -> 表示一种逻辑状态
电容电荷不足    -> 表示另一种逻辑状态
```

电荷会随时间泄漏。即使系统持续供电，内存控制器也必须周期性地读取并重写 DRAM 的行，以恢复电荷，这就是 **refresh（刷新）**。断电后没有电源维持电荷，内容很快消失，因此 DRAM 是易失性存储。

DRAM 单元很小、密度高、每 bit 成本低，适合做数 GB 到数百 GB 的主内存；代价是单次访问需要激活行、读写列、预充电等步骤，延迟比 SRAM 高。DDR、LPDDR、HBM 是不同封装、通道和传输方式下的 DRAM 家族，并不改变“动态电荷存储、需要刷新”的基本性质。

### 2. SRAM：不需要刷新，但更适合做 Cache

SRAM（Static RAM）通常用多个晶体管构成双稳态电路；只要有电，它无需周期刷新即可保持状态。它通常更快，但每 bit 占用更多晶体管、面积更大、成本更高，所以不适合廉价地扩展为大量主内存。

这解释了常见分工：

```text
CPU L1/L2/L3 Cache  -> SRAM：小、快、贵
主内存 DIMM/LPDDR   -> DRAM：大、较慢、便宜
```

SRAM 仍然是易失性存储。`static` 这个词描述的是无需刷新，不是“断电仍然保存”。

### 3. “随机访问”不代表所有位置同样快

DRAM 的软件接口表现为按地址读取或写入：`load`、`store` 可以访问任意有效地址。但硬件内部有 bank、row、column、行缓冲和内存控制器调度：命中当前已打开行的访问通常比切换到另一行快。

所以 RAM 的“random”是相对于顺序介质的地址可达性，不是承诺每个地址、每一时刻都有完全相同的固定延迟。Cache 命中、NUMA 节点、内存争用、DRAM 行状态都会让实际延迟不同。

## 四、ROM：从真正不可改到可更新固件

ROM 是 Read-Only Memory。它的共同目标是非易失保存内容，但“怎么写入”在不同 ROM 家族中差异很大。

| 类型 | 写入方式 | 擦除/修改方式 | 典型用途 |
| --- | --- | --- | --- |
| Mask ROM | 芯片制造时掩膜固化 | 基本不可修改 | SoC Boot ROM、固定微码/表 |
| PROM | 出厂后可由专用设备一次编程 | 通常不可擦除 | 一次性配置、较早设备 |
| EPROM | 紫外线照射后整体擦除 | 擦除后重编程 | 早期可重编程固件 |
| EEPROM | 电擦除 | 可较小粒度擦写，速度/寿命有限 | 小型配置、校准数据 |
| Flash | 电擦除 | 通常按 sector/block 擦除，再按 page 编程 | 固件、嵌入式系统、SSD |

严格说，Flash 不是传统意义上“永远只读”的 ROM；但因其非易失、常用于存放启动程序或固件，人们仍常把它宽泛地归入 ROM 一侧。更准确的叫法是 **non-volatile memory（NVM，非易失性存储）**。

现代 PC 的 UEFI/BIOS 固件通常保存在可更新的非易失存储中，Flash 是最常见的物理实现；UEFI 的平台初始化规范也将 Flash 描述为固件卷最常见的非易失仓库。[UEFI Platform Initialization：Firmware Devices](https://uefi.org/specs/PI/1.8A/V3_Design_Discussion.html)

### 1. Flash 为什么不能当成普通 RAM

Flash 写入前通常需要先把一个 sector 或 block 擦除到已知状态，再把数据按 page 编程。它与 RAM 的差异包括：

- **擦除粒度大**：不能像对 `int` 赋值那样随意改一个字节；为了改少量数据，可能需要读出整块、修改、擦除、再整块写回。
- **擦写更慢**：读取通常很快，编程和擦除显著更慢。
- **寿命有限**：单元可承受的擦写次数有限，需要 wear leveling（磨损均衡）等策略。
- **写入失败模型不同**：掉电、坏块、部分写入都需要校验、日志、冗余或双镜像方案处理。

因此“固件能升级”不等于“运行中的固件变量应该每次变化都写回 Flash”。例如启动计数、配置变更和升级状态通常要控制写入次数，并设计掉电恢复流程。

### 2. NOR Flash 与 NAND Flash

两者都属于 Flash，但常见定位不同：

| 特征 | NOR Flash | NAND Flash |
| --- | --- | --- |
| 常见用途 | 主板/设备固件、启动代码 | SSD、UFS、eMMC、大容量存储卡 |
| 读取特点 | 常适合随机读取；部分设备支持直接映射执行 | 高吞吐块/页访问，通常经控制器和 FTL 管理 |
| 容量/成本倾向 | 容量较小、每 bit 成本较高 | 容量大、每 bit 成本较低 |
| 启动角色 | 常被 CPU/SoC 用于早期启动 | 常在控制器和启动链准备后加载更大镜像 |

这只是常见工程取舍，不是物理定律。具体芯片能否 XIP（execute in place，原地执行）、擦除块大小、页大小和寿命，必须看其数据手册。

## 五、从按下电源到运行程序：RAM 与 ROM 怎样协作

下面给出一条典型而非唯一的启动链。x86 PC、ARM SoC、RISC-V 开发板细节不同，但“先有少量非易失启动代码，再初始化 RAM，再装载更大软件”的结构极其普遍：

```text
1. 复位
   CPU 的 PC 被硬件设到架构/芯片规定的复位入口。

2. Boot ROM 或固件 Flash 中的最早代码开始执行
   此时 DRAM 控制器、时钟、引脚和外设可能尚未初始化。

3. 早期固件初始化硬件
   配置时钟、引脚、内存控制器，训练/初始化 DRAM。

4. RAM 可用
   固件获得栈、临时堆和更大的工作空间；可将后续阶段复制/解压到 RAM。

5. 加载 bootloader 与操作系统
   从 Flash、SSD、网络或其他介质读取镜像到 RAM，建立页表和运行环境。

6. 操作系统运行
   进程代码、数据、内核、页缓存和驱动工作区主要位于 RAM；持久文件仍在 SSD/HDD/Flash。
```

关键因果关系是：**主内存 DRAM 自己往往也需要初始化，所以 CPU 不能一上电就假定可以把栈、全局变量和复杂 C 代码放进 DRAM。**最早阶段通常使用 Boot ROM、片上 SRAM 或极小的暂存区；DRAM 训练完成后才进入正常的“RAM 很大、C 程序可以自由使用栈”的世界。

在 PC 上，平台固件为操作系统加载器提供启动环境和接口；UEFI 定义的正是 OS 与平台固件在启动过程中的接口模型，而非规定所有厂商内部必须采用同一种 Flash 或 DRAM 初始化实现。[UEFI Specification Introduction](https://uefi.org/specs/UEFI/2.9_A/01_Introduction.html)

## 六、程序的代码、全局变量、栈和堆最终放在哪里

把 C/C++ 程序编译并链接后，ELF 等可执行文件通常按段组织：

| 段/区域 | 文件中的初始来源 | 进程运行时通常位于哪里 | 是否应被普通代码修改 |
| --- | --- | --- | --- |
| `.text` | 可执行文件或共享库 | RAM 中映射的代码页 | 通常否，`R/X` |
| `.rodata` | 可执行文件或共享库 | RAM 中映射的只读页 | 否，通常 `R` |
| `.data` | 文件中已初始化字节 | RAM 中的可写数据页 | 是 |
| `.bss` | 文件只记录大小，装载时清零 | RAM 中的可写数据页 | 是 |
| 栈 | 运行时创建 | RAM | 是，按调用增长/收缩 |
| 堆 | 分配器和 OS 按需提供 | RAM | 是 |

这张表能修正一个常见误会：`.text` 被标为只读或可执行，并不说明它在物理 ROM 中。操作系统通常将 SSD/HDD 中的程序文件按需读入 RAM，再用页表将对应页设置为不可写、可执行；“只读”在这里是**页表权限**，而非物理存储介质名称。

共享库和文件映射更能说明这一点：多个进程可把同一个程序文件的只读代码页映射到各自虚拟地址空间，并共享同一批 RAM 物理页；若某进程对可写私有数据页写入，内核可按 Copy-on-Write 机制为它分配新的 RAM 页。

## 七、RAM、ROM、缓存、SSD 与“内存”这个词

中文里“内存”在日常语境通常指 DRAM 主内存；但在计算机体系结构语境，寄存器和缓存也是存储器，Flash 也是一种半导体存储器。为了避免沟通错位，最好明确使用下列词：

| 想表达的对象 | 更准确的说法 |
| --- | --- |
| 插在主板上的 DIMM、笔记本的 LPDDR | 主内存、DRAM、RAM |
| CPU L1/L2/L3 | Cache、SRAM 缓存 |
| BIOS/UEFI 所在芯片 | 固件 Flash、SPI NOR Flash、NVM；仅在确属只读时称 ROM |
| 系统盘 | SSD（通常以 NAND Flash 为介质）或 HDD |
| 断电仍能保存的所有介质 | 非易失存储/NVM，不能一概叫 ROM |

同样，“运行内存不足”和“磁盘空间不足”是不同问题：前者说明可供当前进程、内核和页缓存使用的 RAM 不够，可能触发 swap、内存回收或 OOM；后者说明持久文件系统无空间，即使 RAM 仍然很多也不能继续创建文件。

## 八、几个常见问题

### 1. RAM 断电后一定立刻变成全零吗？

不应这样理解。DRAM 断电后电荷会消散，数据不再可靠；残余信息消失的速度受温度、断电方式和硬件条件影响。操作系统在分配页面给不同进程前通常必须按安全策略清零，不能把“断电或回收后应该自然全零”当作隔离机制。

### 2. 为什么 BIOS/UEFI 能升级，名字里却常带 ROM？

这是历史名称保留。早期固件确实常放在真正不可修改的 ROM；现代主板更常用可擦写 Flash，所以升级工具能够擦除并重新编程固件。更新失败或掉电可能让机器无法完成早期启动，这正是固件更新通常强调电源稳定、签名验证、恢复模式或双 BIOS 的原因。

### 3. SSD 是 ROM 吗？

不是一个适合的工程称呼。SSD 的 NAND Flash 是非易失、可擦写介质，但 SSD 还包含控制器、纠错码、地址映射层、磨损均衡和垃圾回收；它向操作系统暴露的是块设备，而非传统 ROM 接口。

### 4. ROM 中的程序能否直接执行？

可能，但不是必然。若芯片将 ROM/NOR Flash 映射到 CPU 可取指的地址空间，早期代码可 XIP；若介质通过块协议访问，通常先复制到 RAM 再执行。即便可以 XIP，程序的可写数据、栈和堆仍需要 RAM。

### 5. 断电后为什么有些设置还在，有些没了？

需要跨越断电保存的设置会被写入非易失存储，如 Flash/NVRAM；仅为当前运行准备的变量留在 RAM。UEFI 也明确区分带 `NON_VOLATILE` 属性的变量和只在正常内存中、不会跨电源周期保留的变量。[UEFI Runtime Services：变量的易失与非易失属性](https://uefi.org/specs/UEFI/2.9_A/08_Services_Runtime_Services.html)

## 总结

RAM 与 ROM 的关键不在名字，而在其物理与软件边界：

- **RAM** 在现代机器里通常指 DRAM 主内存：容量大、可频繁随机读写、断电丢失；SRAM 更快但更贵，常用于 Cache。
- **传统 ROM** 真正只读；而现代固件多存放在可升级的 **Flash** 中。Flash 非易失，却有擦除粒度、擦写速度和寿命限制，不能当普通 RAM 使用。
- **启动过程**先依赖 Boot ROM/Flash 中的少量代码，完成 DRAM 初始化后才获得正常 RAM，随后再把 bootloader 和操作系统装载到 RAM。
- 程序的 `.text`、`.rodata`、`.data`、栈和堆在运行时通常都在 RAM；其中的“只读”主要来自页表权限，不代表物理位于 ROM。
- SSD、HDD、Flash、RAM 和 Cache 都是存储体系的一部分，却不能只凭“能否读写”混称为同一种东西。

以后遇到“这段数据放在哪里”的问题，依次问它是否需断电保存、谁会修改、访问粒度与频率如何、CPU 在哪个启动阶段需要它，答案通常比一句“放 RAM 还是 ROM”准确得多。
