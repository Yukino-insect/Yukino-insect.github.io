在 RISC-V 汇编中看到下面三行时，很容易把它们与 `jal`、`add` 一起都当作“CPU 指令”。但这并不正确：`.text` 和 `.global` 是**汇编伪指令**，`jal_ins:` 是**标签定义**；三者用于组织目标文件、命名地址并参与链接，本身不会被 CPU 执行。

```asm
.text
.global jal_ins
jal_ins:
```

它们共同表达的是：**在代码段当前位置定义一个名为 `jal_ins` 的对外可见入口。** 随后的 `jal`、`add` 和 `jr` 才会被汇编成机器码并由处理器执行。

本文以一段 RISC-V 示例为线索，说明这三种写法各自解决什么问题，以及它们与跳转、函数返回和链接过程之间的关系。

## 一、先区分：指令、伪指令与标签

汇编源文件里并非每一行都会变成一条机器指令。至少应分清下面三类内容。

| 类别 | 示例 | 谁处理 | 是否生成可执行机器码 |
| --- | --- | --- | --- |
| ISA 指令 | `jal`、`add`、`jalr` | CPU 按 ISA 语义执行 | 是 |
| 汇编伪指令 | `.text`、`.global`、`.word` | 汇编器或链接器 | 通常否；数据定义例外会生成数据 |
| 标签 | `jal_ins:`、`imm_l1:` | 汇编器与链接器 | 否 |

因此，阅读汇编时不应只盯着助记符。先分辨“这行是在让 CPU 做事”，还是“这行是在告诉工具如何放置、命名和导出代码”，后续很多概念就不会混在一起。

## 二、`.text`：选择放置指令的代码段

```asm
.text
```

`.text` 表示接下来的内容应放入目标文件的 **`.text` 节（section）**。该节通常保存可执行指令，链接器在最终可执行文件或固件镜像中会把它安排到相应的代码区域。

例如：

```asm
.text
add a0, a1, a2
ret
```

这里的两条指令属于 `.text` 节。与其并列的常见节包括：

| 节名 | 常见用途 |
| --- | --- |
| `.text` | 可执行机器指令 |
| `.rodata` | 只读数据，例如字符串常量、只读查找表 |
| `.data` | 有初始值的全局或静态数据 |
| `.bss` | 无显式初始值的全局或静态数据，装载时通常清零 |

例如下面的代码把字符串与指令放入不同节：

```asm
.section .rodata
message:
    .asciz "hello\n"

.text
.global main
main:
    la a0, message
    ret
```

`.text` 不等于“CPU 从这一行开始执行”。它只是切换当前输出节；真正从哪里开始运行，要由程序入口、调用指令、启动代码或加载器决定。将某段内容放进代码节，不会让处理器自动跳到那里。

### 节、内存段与源文件顺序不是同一回事

源文件里 `.text` 写在 `.data` 前面，并不保证运行时内存也以同样顺序出现。汇编器先将内容组织成目标文件中的节；链接器再依据链接脚本和平台规则，合并多个目标文件的节并决定最终地址、对齐、访问权限等。

可以把过程概括为：

```text
汇编源文件
  ├─ .text 中的指令 ─┐
  ├─ .rodata 中的数据 ├─→ 目标文件的各个节 ─→ 链接器布局 ─→ 可执行文件 / 固件
  └─ .data 中的数据 ─┘
```

因此，`.text` 是“放入哪一个目标文件节”的说明；它与操作系统装载时的内存映射有关，但不应简单等同于某个固定物理地址。

## 三、`jal_ins:`：为当前位置定义一个地址名称

```asm
jal_ins:
```

冒号表示一个**标签定义**。它把当前位置的地址命名为 `jal_ins`。标签本身不占指令空间，也不会生成一条额外的 `nop` 或其他机器码。

例如：

```asm
start:
    addi a0, zero, 1
next:
    addi a0, a0, 1
```

若链接后 `start` 位于地址 `P`，且两条普通 RISC-V 指令均为 4 字节，则可近似表示为：

```text
start = P
next  = P + 4
```

汇编器记录的是“符号名与位置”的对应关系。后面写：

```asm
jal ra, start
```

所表达的就是“跳转到符号 `start` 对应的地址”。源代码不必手工计算地址差；汇编器和链接器会在能够确定最终布局时完成编码或重定位。

### 标签不是函数专属语法

`jal_ins:` 常作为函数入口标签，但标签本身并不代表“函数”。它也可以标记循环起点、分支目标、表格数据、异常入口或节内任意位置：

```asm
loop:
    addi t0, t0, -1
    bnez t0, loop

table:
    .word 10, 20, 30
```

是否是函数取决于代码约定、符号类型、调用方式和周围语义，而不是标签后面恰好有一个冒号。

### 本地标签与全局符号

汇编器通常还支持数字本地标签，例如：

```asm
1:
    addi t0, t0, -1
    bnez t0, 1b
```

其中 `1b` 表示“向后（backward）找到最近的 `1:` 标签”，`1f` 表示“向前（forward）找到最近的 `1:` 标签”。它适合短小的局部控制流，避免给每个循环都起一个在整个文件内独一无二的名字。

而 `jal_ins` 这样的具名符号更适合函数入口或需要被其他代码引用的位置。可见范围还会受汇编器和目标格式影响；在 ELF 工具链里，以 `.L` 开头的名字通常被当作汇编器局部标签，不会作为普通外部符号保留下来。

## 四、`.global jal_ins`：让符号能被其他目标文件解析

```asm
.global jal_ins
```

`.global`（GNU 汇编器中也常见 `.globl`）把 `jal_ins` 声明为**全局符号**。这里的“全局”主要是链接层面的可见性：其他目标文件可以引用这个符号，链接器可以用当前文件中的定义来解析该引用。

典型的两个源文件如下。

`jal_ins.s`：

```asm
.text
.global jal_ins
jal_ins:
    ret
```

`main.s`：

```asm
.text
.global main
.extern jal_ins
main:
    jal ra, jal_ins
    ret
```

`main.s` 中的 `.extern jal_ins` 表示该符号在别处定义；`jal_ins.s` 中的 `.global jal_ins` 则提供该定义。链接器把二者匹配起来，修正 `jal ra, jal_ins` 所需的跳转偏移，最终使调用到达正确地址。

若没有 `.global jal_ins`，`jal_ins:` 仍然可以在**当前汇编文件**中使用：

```asm
.text
jal_ins:
    jal ra, jal_ins
```

但它默认不会成为供其他目标文件解析的外部定义。跨文件引用时，链接器可能报告未定义符号。

### `.global` 不会自动生成函数，也不会改变地址

`.global jal_ins` 只改变符号绑定属性，不会：

- 生成任何 CPU 指令；
- 为 `jal_ins` 分配额外内存；
- 自动建立栈帧或保存寄存器；
- 自动使其成为程序的启动入口；
- 自动保证它遵循某种函数调用约定。

它解决的仅仅是“链接器能否把其他文件中的 `jal_ins` 引用解析到这里”。函数调用协议仍须由程序员、编译器和 ABI 共同遵守。

如果希望在 ELF 符号表中进一步明确其为函数，手写汇编还可能写成：

```asm
.text
.global jal_ins
.type jal_ins, @function
jal_ins:
    ret
.size jal_ins, .-jal_ins
```

`.type` 与 `.size` 有利于调试器、反汇编器和工具识别符号范围，但它们同样不改变 CPU 对指令的执行语义。

## 五、结合 `jal` 示例看真实控制流

题目：

```asm
.text
.global jal_ins
jal_ins:
    jal a0, imm_l1
    add x0, x0, x0
    add x0, x0, x0

imm_l1:
    jal a0, imm_l2

imm_l2:
    jr ra
```

RISC-V 的 `jal` 基本形式为：

```text
jal rd, target
```

其语义可概括为：

```text
x[rd] ← 当前 PC + 4
PC    ← target
```

也就是说，`jal` 同时完成两件事：把下一条顺序指令地址写入 `rd`，然后跳转到目标地址。在机器码层面，目标通常编码为相对当前 PC 的带符号偏移；汇编中直接写标签即可，由汇编器和链接器处理偏移与重定位。

假设 `jal_ins` 的地址为 `P`，且此处没有压缩指令，地址关系为：

| 地址 | 标签或指令 | 执行效果 |
| --- | --- | --- |
| `P` | `jal_ins: jal a0, imm_l1` | `a0 ← P + 4`，跳转到 `P + 12` |
| `P + 4` | `add x0, x0, x0` | 被前一条 `jal` 跳过，不执行 |
| `P + 8` | `add x0, x0, x0` | 被前一条 `jal` 跳过，不执行 |
| `P + 12` | `imm_l1: jal a0, imm_l2` | `a0 ← P + 16`，跳转到 `P + 16` |
| `P + 16` | `imm_l2: jr ra` | 跳转至 `ra` 中保存的地址 |

这里有三个必须说清的细节。

### 1. `jal a0, imm_l1` 写入的是 `P + 4`

第一条 `jal` 不是把 `imm_l1` 的地址写入 `a0`，而是把**这条 `jal` 的下一条顺序指令地址**写入 `a0`。因此它写入的是 `P + 4`，即第一条 `add` 的地址。

目标 `imm_l1` 的地址被写入 PC，处理器从那里继续取指。把“链接地址”与“跳转目标地址”混为一谈，是理解 `jal` 时最常见的错误之一。

### 2. 第二条 `jal` 覆盖了 `a0`

到达 `imm_l1` 后：

```asm
jal a0, imm_l2
```

会把 `a0` 改写为第二条 `jal` 的下一条顺序地址，也就是 `imm_l2` 的地址。由于 `imm_l2` 就紧接在当前指令之后，这条跳转的目标恰好也是顺序下一条；控制流不绕路，只是执行了一次“把返回地址写进 `a0`”的动作。

`a0` 是 RISC-V ABI 中第一个参数寄存器，也常用于保存函数返回值。用它作为 `jal` 的链接寄存器在指令层面完全合法，但在遵循标准 ABI 的普通函数中通常不合适：它会覆盖参数或返回值。教学实验可以这样写，真实接口应谨慎使用。

### 3. `jr ra` 使用的是 `ra`，而不是 `a0`

`jr ra` 是常见伪指令，等价于：

```asm
jalr x0, 0(ra)
```

其中 `ra` 是寄存器 `x1`，按 ABI 约定保存函数的返回地址；`x0` 恒为零，写入它的链接地址会被丢弃。因此 `jr ra` 只跳回调用者，不再记录新的返回地址。标准写法 `ret` 通常也是这个含义。

如果调用者通过：

```asm
jal ra, jal_ins
```

进入 `jal_ins`，调用指令会先将调用点的下一条指令地址写入 `ra`。函数内部两条 `jal a0, ...` 只改写 `a0`，没有改写 `ra`；最后的 `jr ra` 因而仍能返回调用者。

这也说明原代码中 `a0=imm_l2 的地址` 的说法不准确。第二条 `jal` 写入 `a0` 的确是 `P + 16`，而它刚好等于 `imm_l2` 的地址，只是因为 `imm_l2` 恰好位于该 `jal` 的下一条顺序位置；这不是 `jal` 写入目标地址的规则。

## 六、`nop`、`x0` 与示例中的两条 `add`

```asm
add x0, x0, x0
```

RISC-V 的 `x0` 永远读为零，对 `x0` 的写入也会被忽略。因此，这条指令计算 `0 + 0` 后尝试写回 `x0`，不会产生可观察效果，可视为功能上的空操作。

不过，RISC-V 规范中通常使用的标准 `nop` 编码对应：

```asm
addi x0, x0, 0
```

两者在这段代码里都没有有效计算结果，但机器编码不同。汇编器中的 `nop` 伪指令会选择标准的空操作编码；若没有实验要求，直接写 `nop` 更清楚：

```asm
    jal a0, imm_l1
    nop
    nop
```

而在本例里，这两条空操作又被前一条无条件跳转跳过，主要用于观察 `jal` 的控制流和链接地址，并不是函数逻辑所必需的内容。

## 七、一个更符合普通函数约定的写法

如果目标只是“定义一个能被别处调用并正常返回的函数”，最小版本可以写成：

```asm
.text
.global jal_ins
.type jal_ins, @function
jal_ins:
    ret
.size jal_ins, .-jal_ins
```

若要演示函数内部调用另一个标签，且最终仍由 `ra` 返回，则需注意内部 `jal ra, ...` 会覆盖原调用者的返回地址。下面使用 `s0` 临时保存原 `ra`，以演示这个关系：

```asm
.text
.global jal_ins
.type jal_ins, @function
jal_ins:
    addi sp, sp, -16
    sd ra, 8(sp)

    jal ra, helper

    ld ra, 8(sp)
    addi sp, sp, 16
    ret
.size jal_ins, .-jal_ins

helper:
    addi a0, a0, 1
    ret
```

该例假设 RV64 环境，因此用 `sd`、`ld` 保存和恢复 64 位寄存器。若是 RV32，应改用 `sw`、`lw` 并采用相应的栈帧大小。真正的非叶子函数通常必须保存 `ra`，因为它也要使用 `ra` 调用别的函数；这是调用约定的要求，并不是 `.global` 或标签自动完成的工作。

## 八、从源文件到可执行文件：三者分别在哪一步发挥作用

将上述概念放入构建流程，可以得到更完整的图景：

```text
汇编源文件 .s
  │
  ├─ `.text`：指定后续指令进入哪个节
  ├─ `jal_ins:`：建立“名称 → 节内位置”的符号
  └─ `.global jal_ins`：将该符号标记为可供外部解析
  │
汇编器
  │  生成目标文件 .o：机器码、节信息、符号表、重定位记录
  │
链接器
  │  合并各 .o 的节，解析全局符号，并修正跨文件引用
  ▼
可执行文件、共享库或裸机固件
```

当跳转目标与当前指令处于同一可确定位置时，汇编器常可立即算出偏移；当目标来自其他目标文件、共享库或位置无关代码时，则可能留下重定位记录，交给静态链接器或动态加载器在更晚阶段修正。写标签而非硬编码地址，正是为了让这套机制能够可靠工作。

## 九、把陌生的汇编源文件拆成四类行

以后遇到一份新的 `.s` 或 `.S` 文件，最实用的第一步不是逐个查指令，而是先把每一行归类。RISC-V GNU 风格汇编大致由以下四类内容组成：

```asm
    .section .rodata        # 1. 伪指令：告诉工具怎样组织输出
name:                       # 2. 标签：给当前位置或数据位置命名
    .asciz "demo"           # 3. 数据定义：在当前节写入字节
    addi a0, a0, 1          # 4. 指令或伪指令：形成一条或多条机器指令
```

注释不属于程序内容。GNU 风格 RISC-V 汇编中通常以 `#` 开始；不同汇编器可能也支持其他注释形式。`.s` 通常直接交给汇编器，`.S`（大写）通常会先经过 C 预处理器，因此可使用 `#include`、`#define` 和条件编译。文件后缀是构建规则的约定，不是 RISC-V 指令集的一部分。

可以用下面的速查表判断一行的角色：

| 看到的形式 | 首先应想到什么 | 示例 |
| --- | --- | --- |
| 以 `.` 开头 | 汇编器指令、节属性、数据定义或选项 | `.text`、`.word`、`.p2align` |
| 以 `:` 结尾 | 标签定义；该名称对应当前位置 | `loop:`、`message:` |
| 普通助记符加操作数 | 真实 ISA 指令，或汇编器提供的别名/伪指令 | `add`、`ret`、`li` |
| 仅出现一个名字 | 对符号的引用，可能是地址、常量或重定位目标 | `call printf`、`la a0, message` |

这套分类并不只适用于 RISC-V；Arm、x86、MIPS 的汇编文件也有相同的大框架。真正变化的是指令语法、伪指令名称、目标文件格式和 ABI 细节。

### 一份小型汇编文件的通用骨架

下面的例子同时出现了节、常量、数据、全局符号、函数和局部控制流。无需先理解每条指令，先认出它们分别属于哪一层即可。

```asm
.equ BUFFER_SIZE, 64

.section .rodata
message:
    .asciz "hello\n"

.text
.global print_message
.type print_message, @function
print_message:
    addi sp, sp, -16
    sd ra, 8(sp)

    la a0, message
    call puts

    ld ra, 8(sp)
    addi sp, sp, 16
    ret
.size print_message, .-print_message
```

这里的 `.equ` 给数值常量命名，`message:` 给数据地址命名，`print_message:` 给函数入口地址命名；三者看起来都像“名字”，但含义并不相同。特别是 `.size print_message, .-print_message` 中的 `.` 表示当前位置，故右侧是“当前位置减去函数起始位置”，即函数所占的字节数。`

## 十、看到不同的节与数据定义时，应如何理解

`.text` 只是最常见的节名之一。源文件的很多“不是指令”的内容，实际是在描述字节该被放到哪里、以什么形式放置。

### 1. 用 `.section` 建立或选择节

`.text`、`.data` 等可看作常见节的简写；更通用的形式是：

```asm
.section .rodata
.section .text.startup
.section .data
```

项目可能把启动代码、普通代码、只读表、异常处理信息分别放进不同节。是否以及如何把这些节合并、排到什么地址，由链接脚本或系统默认链接规则决定。见到 `.text.startup` 不必怀疑它是新指令；它只是一个名字更具体的代码节。

### 2. 为什么 `.section .rodata` 与 `.section .text` 会反复出现

`.section` 是**有状态的“当前位置切换”指令**，不是只能在文件开头写一次的声明。汇编器始终维护一个“当前节”；后续的指令、标签和数据定义都追加到当前节中。再次写：

```asm
.section .rodata
message_a:
    .asciz "first"

.section .text
function_a:
    ret

.section .rodata
message_b:
    .asciz "second"

.section .text
function_b:
    ret
```

应理解为下图，而不是创建了两份彼此独立的 `.rodata` 和 `.text`：

```text
.rodata 节：message_a 的字节 → message_b 的字节
.text   节：function_a 的指令 → function_b 的指令
```

第二次 `.section .rodata` 只是把当前输出位置切回已经存在的 `.rodata` 节，在其先前内容之后继续写入；第二次 `.section .text` 也是同理。节没有“代码块结束”的花括号，切换后会一直保持，直到又遇到另一条选择节的伪指令。

这在**编译器生成的汇编**中尤其常见。编译器在输出一个函数时切入 `.text`，遇到该函数需要的字符串、跳转表或浮点常量时切入 `.rodata`，随后再回到 `.text` 输出下一个函数。它按产生内容的时机交错打印，并不意味着运行时会在“执行代码一半时自动跳去执行只读数据”。运行时的布局仍由汇编器、链接器和加载器统一处理。

还可能见到更细的节名：

```asm
.section .rodata.str1.1
.section .text.startup
.section .text.unlikely
```

它们是不同的**输入节名**，常用来表达字符串对齐、启动路径、冷路径等属性。链接器通常会根据链接脚本把同类输入节合并到合适的输出段；例如多个 `.text.*` 输入节常被放入最终的可执行代码区域，但这不是单靠节名就绝对保证的，最终仍以链接脚本和平台规则为准。

若手写汇编时只想临时切去放一小段数据，许多 GNU 汇编器还支持成对的：

```asm
.text
function:
    # 函数代码

    .pushsection .rodata
local_message:
    .asciz "hello"
    .popsection

    # 此处已恢复到先前的 .text 节
    ret
```

`.pushsection` 会保存当前节并切换到指定节，`.popsection` 恢复先前保存的节；`.previous` 则用于切回最近的前一个节。它们并非所有汇编器方言都完全相同，但看到这类写法时，可以把它理解成“临时离开当前节，再回到原处”，而不是函数调用或控制流跳转。

### 3. 数据定义是在“写入字节”，不是赋值语句

常见的 GNU 汇编数据伪指令如下：

| 写法 | 在当前位置放入的内容 | 常见用途 |
| --- | --- | --- |
| `.byte 0x12` | 1 字节 | 标志、原始字节 |
| `.half 0x1234` | 2 字节 | 16 位数据 |
| `.word 0x12345678` | 4 字节 | 32 位整数、表项 |
| `.dword 0x0123456789abcdef` | 8 字节 | 64 位数据、地址表项 |
| `.asciz "abc"` | 字符串字节和末尾 `0` | C 风格字符串 |
| `.zero 32` | 32 个零字节 | 保留并清零的空间 |

例如：

```asm
.section .rodata
numbers:
    .word 10, 20, 30
text:
    .asciz "abc"
```

这不是“给 `numbers` 变量赋值”。它表示在 `numbers` 所在位置连续写入 3 个 32 位数；`text` 紧跟在这些字节之后。若代码读取 `numbers`，还要使用加载指令，并按实际元素宽度和字节序解释内存。

### 4. 对齐用于满足地址和性能约束

数据和指令经常需要按 2、4、8、16 等边界对齐。GNU 汇编中，`.p2align n` 表示将当前位置向上填充到 `2^n` 字节边界：

```asm
.p2align 3       # 下一个对象从 8 字节边界开始
table:
    .dword 1, 2
```

你也会看到 `.align`。它在不同目标架构、汇编器方言中的参数解释可能不完全相同：有的把参数看作字节数，有的看作 2 的幂。阅读或编写跨工具链代码时，优先查当前汇编器文档，或使用语义更明确的 `.p2align`，不要靠经验硬猜。

### 5. `.bss` 与 `.data` 的区别是“文件中是否需要保存初值”

```asm
.data
counter:
    .word 0

.bss
.p2align 2
buffer:
    .zero 1024
```

两者运行时都需要可写内存，但 `.data` 中的初始字节需要包含在程序或镜像文件中；`.bss` 表示一大片零初始化空间，文件通常只记录大小，加载器或启动代码负责得到清零后的内存。裸机环境能否自动清零取决于启动代码，不能仅凭看到 `.bss` 就理所当然地假定一切已经准备好了。

## 十一、名字不只有标签：常量、符号绑定与可见性

汇编里的“名称”必须继续区分，否则见到 `.extern`、`.weak`、`.hidden` 一类内容时仍会迷路。

### 1. 地址符号与数值常量

```asm
buffer:
    .zero 64

.equ BUFFER_SIZE, 64
```

`buffer` 代表某个位置的地址；`BUFFER_SIZE` 代表数值 `64`。前者的位置可能因链接布局而改变，后者只是汇编阶段可参与表达式计算的常量。

```asm
    li a1, BUFFER_SIZE   # 将数值 64 放入 a1
    la a0, buffer        # 将 buffer 的地址放入 a0
```

`li` 与 `la` 的区别正是“常量值”与“地址”的区别。它们都是常见伪指令，不能仅按英文直觉把二者都理解成“加载”。

### 2. 绑定决定链接器如何看待同名符号

| 写法 | 常见含义 |
| --- | --- |
| `.global name` / `.globl name` | 导出全局定义，或声明全局引用 |
| `.local name` | 将符号限定为本目标文件内部使用 |
| `.weak name` | 声明弱符号；与强定义冲突时通常让强定义优先 |
| `.hidden name` | 在 ELF 共享对象中限制符号对外部链接单元的可见性 |
| `.extern name` | 表明定义来自别处；GNU 汇编通常可从未定义引用自行推断，未必需要显式写出 |

这些指令主要面向目标文件和链接器，不改变指令的算术语义。弱符号和隐藏可见性常见于库、启动代码、操作系统和大型工程；初学时至少应记住：它们讨论的是“这个名字能否、应由谁、以什么范围被解析”，不是“CPU 怎样跳转”。

### 3. `.type`、`.size` 是工具可读的元信息

```asm
.type handler, @function
handler:
    ret
.size handler, .-handler
```

这能帮助 `readelf`、`objdump`、调试器和性能分析工具区分函数与普通对象，并知道函数范围。缺少这些元信息时，机器码通常仍可执行；但反汇编、栈回溯或符号展示的体验可能更差。也就是说，它们服务于工具链可理解性，不能替代真实的函数调用约定。

## 十二、伪指令、真实指令与“不要擅自数 PC”

RISC-V 的基础整数指令编码大多是 32 位，但汇编源文件中的一行不保证只生成 4 字节。原因有三类。

### 1. 一些易读写法是伪指令

| 汇编写法 | 常见真实含义 | 说明 |
| --- | --- | --- |
| `mv rd, rs` | `addi rd, rs, 0` | 寄存器复制 |
| `nop` | `addi x0, x0, 0` | 标准空操作 |
| `ret` | `jalr x0, 0(ra)` | 从 `ra` 返回 |
| `jr rs` | `jalr x0, 0(rs)` | 跳转到寄存器地址，不保存链接地址 |
| `j target` | `jal x0, target` | 无条件跳转，不保存链接地址 |
| `li rd, imm` | 一条或多条指令 | 装载立即数，取决于数值大小 |
| `la rd, symbol` | 通常为一组 PC 相对或 GOT 相关指令 | 取得符号地址，取决于链接模型 |
| `call symbol` | 通常为一组可重定位的调用序列 | 用于范围更大或需链接修正的调用 |

例如 `li a0, 42` 可以很短，但 `li a0, 0x123456789abcdef0` 在 RV64 下需要多条真实指令拼出完整常量。`la` 也绝不等于“从内存加载数据”；它取得的是地址，并且具体展开会受位置无关代码和链接松弛影响。

### 2. 压缩指令会改变机器码长度

若启用了 RISC-V `C` 扩展，某些操作可以编码为 16 位压缩指令。于是相邻的汇编行可能分别占 2 字节或 4 字节。源代码中看起来的一行一条，与最终的地址差并不必然一致。

这正是前文地址表专门写明“假设没有压缩指令”的原因。分析某段二进制的真实 PC、断点或跳转偏移时，应看反汇编结果和实际地址，而不要把“每一行都是 4 字节”当作永久规律。

### 3. 汇编器和链接器可能重写某些序列

RISC-V 工具链可对某些地址计算或调用序列进行 **relaxation（链接松弛）**：链接器在知道最终距离后，可能把较通用的长序列缩短为更紧凑的编码。反过来，距离超出单条指令表示范围时，汇编器也会采用更长的序列。

因此，当你需要精确判断一行汇编最终占几个字节时，可靠顺序是：

1. 判断它是否为真实 ISA 指令还是伪指令；
2. 确认目标 ISA/扩展，例如 RV32I、RV64GC；
3. 确认是否启用压缩指令、位置无关代码和链接松弛；
4. 查看最终 ELF 的反汇编与重定位信息，而不是只看 `.s` 文件。

`objdump -dr file.o` 常可同时显示反汇编和重定位位置；`readelf -S -s -r file.o` 可分别查看节表、符号表和重定位表。这些工具输出的细节不必一次背完，但它们能把“汇编器究竟生成了什么”变成可检查的事实。

## 十三、地址、分支范围与重定位：为什么有时写法会变长

标签让人可以写出 `jal ra, function`，但硬件并不是在指令里存一个无限宽的绝对地址。RISC-V 把跳转目标或地址的一部分编码在有限位数的立即数中，因此距离与链接方式会影响最终机器码。

### 1. `jal` 适合相对较近的跳转

`jal` 的 J 型立即数按字节偏移解释，最低位隐含为零，可表达约正负 1 MiB 范围内的 PC 相对跳转。它非常适合函数调用和无条件跳转，但不能直接覆盖任意远处的地址。

条件分支的立即数字段更小，范围通常约为正负 4 KiB。遇到很远的条件目标，汇编器、编译器或手写代码一般会采用“反转条件 + 远跳转序列”等方式，而不是指望一条分支指令突破编码位数限制。

### 2. `auipc` 与 `jalr` 是常见的远地址组合

你以后很可能会在反汇编中看到：

```asm
1:
    auipc t0, %pcrel_hi(target)
    jalr  ra, %pcrel_lo(1b)(t0)
```

概念上，它先用 `auipc` 把“当前 PC 加上目标地址的高位部分”放入 `t0`，再由 `jalr` 加上低位部分并跳转。`%pcrel_hi`、`%pcrel_lo` 是给汇编器和链接器看的重定位表达式，不是 CPU 寄存器或普通函数调用；其中 `1b` 用来让低位重定位与前面的 `auipc` 成对关联。

真实工具链有更严格的配对规则、临时标签和可能的松弛优化；阅读时先抓住核心即可：**一条指令放不下完整的地址或偏移时，工具链会使用多条指令并留下重定位信息。**

### 3. 位置无关代码不等于没有地址

共享库和现代可执行文件常使用位置无关代码（PIC/PIE）。它们仍然访问地址，只是不把“程序一定装载在某个固定绝对地址”写死在机器码中，而是优先通过 PC 相对计算、全局偏移表（GOT）或过程链接表（PLT）等机制在装载时得到正确地址。

所以看到 `auipc`、`%pcrel_hi`、`@plt`、`@got_pcrel_hi` 一类标记时，可以先判断：这通常是地址可重定位、跨模块调用或动态链接的痕迹，而不是某种新的 CPU 运算。

## 十四、函数能否正确返回，还取决于 ABI

指令集只规定 `jal` 怎样写寄存器、`jalr` 怎样修改 PC；“哪个寄存器放参数”“谁负责保存寄存器”“栈如何对齐”是 ABI（应用二进制接口）规定的。不同 ISA、操作系统和浮点/向量配置的 ABI 细节会不同，但 RISC-V 常见整数 ABI 的核心分工如下。

| 寄存器类别 | 常见别名 | 一般责任 |
| --- | --- | --- |
| 固定零寄存器 | `zero` / `x0` | 永远为零，写入丢弃 |
| 返回地址 | `ra` / `x1` | 调用者用 `jal ra, ...` 写入；被调用函数若继续调用别人，通常要先保存 |
| 栈指针 | `sp` / `x2` | 指向当前栈帧，函数必须恢复它 |
| 临时寄存器 | `t0`～`t6` | 调用者保存；被调函数可自由改写 |
| 保存寄存器 | `s0`～`s11` | 被调函数若使用，返回前必须恢复 |
| 参数/返回值 | `a0`～`a7` | 传递整数参数；`a0`、`a1` 常放返回值，调用后不保证保留 |

于是遇到函数序言和尾声时，可以这样读：

```asm
addi sp, sp, -16     # 为当前函数留出栈空间，保持所需对齐
sd   ra, 8(sp)       # 本函数要继续 call，先保存调用者返回地址
sd   s0, 0(sp)       # 本函数若使用 s0，也需保存旧值

# ... 函数主体 ...

ld   s0, 0(sp)       # 恢复调用者原来的 s0
ld   ra, 8(sp)       # 恢复最终应返回的位置
addi sp, sp, 16      # 释放本函数栈帧
ret                  # 跳回 ra
```

这比把它背成固定模板更可靠：先问该函数是否调用别的函数、是否改写了被调用者保存寄存器、是否需要局部变量或溢出的参数空间，再判断哪些保存与恢复是必需的。叶子函数若不调用其他函数，往往无需保存 `ra`；非叶子函数通常需要。优化器还可能省略帧指针、调整栈帧布局或内联函数，因此反汇编不一定长得像教科书。

## 十五、面对下一段陌生汇编时的阅读顺序

最后给出一套可重复使用的阅读流程。它比从第一条指令开始逐字翻译更有效。

1. **确定环境。** 看文件是 RISC-V、Arm 还是 x86；是 RV32 还是 RV64；有无 `C`、浮点、向量等扩展；目标是 Linux、裸机还是某个操作系统内核。
2. **先找节与入口。** 找 `.text`、`.section`、`.global`、`.type`，再找标签，确定哪些是函数、启动入口、只读数据或全局对象。
3. **分离工具链语句与机器指令。** 所有 `.` 开头的内容、`:` 标签、重定位修饰符和宏，都不要当作 CPU 正在执行的指令。
4. **建立符号表。** 为每个关键名字标注“地址标签、数值常量、外部函数、局部跳转目标”中的一种；看到 `la`、`call`、`jal` 时回头查它引用的符号。
5. **沿控制流而非文本顺序阅读。** 无条件跳转会跳过一些行；条件分支有两条路径；调用会进入另一段代码再经 `ret` 返回；异常和中断还会改变常规路径。
6. **按 ABI 追踪寄存器。** 尤其留意 `ra`、`sp`、`a0`～`a7` 以及 `s` 寄存器。只有知道调用约定，才能判断一次寄存器覆盖是正常、必要还是错误。
7. **遇到地址算不清时查看产物。** 源码中的 `li`、`la`、`call`、压缩指令和链接松弛都可能改变实际布局；用反汇编、符号表和重定位表验证，不要臆测地址。

可以把它压缩成一句检查口诀：

```text
先分节和标签，再分伪指令与真指令；
先看控制流和 ABI，地址不明就看重定位与反汇编。
```

## 十六、总结

- `.text` 是汇编伪指令，用来选择代码所在的目标文件节；它不表示自动开始执行。
- `jal_ins:` 定义标签，将当前位置命名为 `jal_ins`；标签不生成机器指令，也不局限于函数入口。
- `.global jal_ins` 将这个符号导出为全局符号，使其他目标文件可在链接时引用它；它不自动创建函数、栈帧或入口点。
- 标签、`.equ` 常量、`.word` 数据和 `.p2align` 对齐都属于“组织地址与字节”的语言，不能与 CPU 指令混为一谈。
- `jal rd, target` 将当前指令的下一条顺序地址写入 `rd`，再跳转到 `target`。它不会把目标标签地址写入 `rd`；`jr ra` 通常等价于 `jalr x0, 0(ra)`。
- 一行汇编未必只对应一条、甚至未必对应 4 字节机器码。伪指令、压缩指令、重定位和链接松弛都会影响最终形式。
- 跨函数代码还要遵守 ABI：`ra`、`sp`、参数寄存器、临时寄存器和保存寄存器各有不同责任。
- 阅读未知汇编时，先建立“节—符号—控制流—ABI—最终机器码”的层次，再分析单条指令。这样下一次换成 `.rodata`、`.weak`、`la`、`auipc` 或带栈帧的函数时，也能知道它为什么会出现在那里。
