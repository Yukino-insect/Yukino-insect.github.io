写下 `int n = 42` 时，代码里出现的是一个带有类型的值；内存里真正保存的却只是一串 0 和 1。理解两者之间的关系，是理解整数、浮点数和字符编码的共同起点。

## 比特、字节和地址

比特（bit）只有 0 和 1 两种状态。现代通用计算机通常以 8 个比特组成一个字节（byte），并把字节作为最小可寻址单位：一个地址通常指向一个字节，而不是一个单独的比特。严格地说，C 标准中的 `char` 大小定义为 1 个 C 字节，C 字节包含多少位由 `CHAR_BIT` 决定；在今天常见的平台上它通常是 8 位。

如果地址宽度为 32 位，理论上可表示 $2^{32}$ 个不同地址；在字节编址机器上，这意味着最多寻址 $2^{32}$ 个字节，也就是 4 GiB 的地址空间。地址空间不等于实际安装的内存，页表、设备映射和权限还会进一步决定某个地址是否可访问。

## 类型描述什么

一个语言类型至少规定三件事：

- 一组允许的值，例如 `int` 的整数集合；
- 一种或多种表示方式，例如补码或 IEEE 754；
- 对这些值允许执行的操作，例如整数加法或浮点除法。

类型并不是内存中的标签。大多数机器内存只保存字节，不会在每个字节旁边自动写上“这是 `int`”。类型信息可能在编译期被消除，也可能由运行时对象头、描述符或垃圾回收器保留。

## 同样的位，不同的解释

下面 32 个比特可以解释为无符号整数 `1065353216`，也可以按照 IEEE 754 单精度解释为浮点数 `1.0`：

```text
00111111100000000000000000000000
```

CPU 不需要先扫描内存确认“它到底是什么类型”。执行 `add` 整数指令时，算术逻辑单元按整数规则处理；执行浮点加法指令时，浮点单元按符号、指数和尾数处理。**运算指令已经携带了主要的解释选择**，编译器负责把源代码中的类型转换成合适的指令。

## 为什么布尔量通常占一个字节

逻辑上，一个布尔值只需要 1 位。但如果每个布尔值都单独占 1 位，CPU 读取和修改它就必须执行位提取、掩码和写回；而 1 字节寻址更直接，也更容易满足对齐和原子访问要求。因此 C 的 `_Bool`、Java 的 `boolean` 数组实现，以及许多运行时通常会把单个布尔值放在至少一个字节中。具体数组是否压缩，仍由语言和实现决定。

## 语言为什么不统一大小

Java 规定了 `int` 为 32 位、`long` 为 64 位，便于跨平台复现；Python 的 `int` 是带符号位长度的对象，可以在内存允许时继续增长；C/C++ 只规定最小范围和相对顺序，`int` 的实际宽度由 ABI 和平台决定。LP64 Unix 约定 `long` 和指针为 64 位，但 Windows 常见的 LLP64 约定仍让 `long` 为 32 位。

可以把几种常见语言的默认取向概括成下面这样（具体对象布局仍以实现文档为准）：

| 语言 | 常见整数模型 | 字符模型 | 类型信息通常在哪里 |
| --- | --- | --- | --- |
| Java | 固定宽度，`int` 32 位、`long` 64 位 | UTF-16 代码单元 `char` | 字节码验证、对象头和运行时 |
| Python | `int` 按需扩展 | `str` 是 Unicode 文本 | 每个对象的运行时结构 |
| C/C++ | 受 ABI 约束，`int` 宽度可能不同 | `char` 为 1 个 C 字节 | 多数在编译期，少量由对象/库保留 |

因此，跨语言或跨机器交换二进制数据时，不应把“本机 `int`”当作协议类型，而应明确写出位宽、字节序和编码。

### 常见基础类型：先分“值域”与“对象布局”

初学时最容易把语言关键字直接等同于内存字节数。更可靠的读法是先问：这个类型的**值域和运算规则**是什么，再问当前实现用多少字节、有没有对象头和对齐填充。

| 语言 | 常见基础数据类型 | 规格中稳定的事实 | 不能想当然的事实 |
| --- | --- | --- | --- |
| C | `_Bool`、`char`、各类整数、`float`、`double`、指针 | `char` 是 1 个 C 字节；整数最小范围有规定 | `int`、`long`、指针不保证同宽；`char` 是否有符号由实现决定 |
| C++ | C 的算术类型，另有 `wchar_t`、`char8_t` 等 | `char8_t` 表示 UTF-8 代码单元类型 | `std::string` 不携带“这是 UTF-8”的运行时标记 |
| Java | `byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean` | 前六类数值宽度固定；`char` 是 16 位 UTF-16 代码单元 | `boolean` 的对象/数组布局不是语言规范承诺的 1 位 |
| Python | `bool`、`int`、`float`、`complex`、`str`、`bytes` | `bool` 是 `int` 的子类；`int` 可扩展精度；`str` 是 Unicode 文本 | 一个 Python 值是对象，不是裸寄存器整数；内部布局属于实现细节 |
| JavaScript | `boolean`、`number`、`bigint`、`string`、`symbol` 等 | `number` 是 IEEE 754 双精度浮点；`BigInt` 与 `number` 不可直接混算 | `string.length` 计 UTF-16 代码单元，不等于用户看见的字符数 |

例如 Java 的 `byte` 是有符号 8 位，范围为 `-128` 到 `127`；协议中的一个 0 到 255 的字节不能直接被它的十进制打印迷惑，常要用 `b & 0xFF` 取得无符号数值。Python 的 `bytes` 则是 0 到 255 的不可变字节序列，`str` 是文本；`"中".encode("utf-8")` 是显式跨越文本到字节的边界。C/C++ 的 `char` 既能参与字符和原始对象表示访问，却不自动等于任何一种 Unicode 字符。

### 空值、引用和值也属于类型语义

“类型”不只决定数字范围。Java 的 `int` 是值类型，不能为 `null`；`Integer` 是对象引用，可以为 `null`，还带有对象身份和装箱成本。Python 名称绑定到对象，`x = 1` 与 `y = x` 不会复制一块名为“整数变量”的固定内存。C 的指针值是地址，`NULL` 不是普通对象；解引用无效地址是内存安全错误，不是某种特殊整数计算。

这一区分直接影响数据格式。网络协议中的“字段不存在”“字段值为 0”“字段为 null”应分别有明确编码；不要因为本地语言恰有一个默认值，就让接收端猜测业务语义。

## 一个可运行的观察实验

下面的 C 程序通过 `memcpy` 观察同一组比特的两种解释。`memcpy` 用来避免直接把 `float*` 强转为 `int*` 带来的别名规则问题：

```c
#include <stdint.h>
#include <stdio.h>
#include <string.h>

int main(void) {
    float value = 1.0f;
    uint32_t bits = 0;
    memcpy(&bits, &value, sizeof value);
    printf("%u\n", bits);
    return 0;
}
```

在使用 IEEE 754 单精度且采用常见位序的机器上，输出为 `1065353216`。这里没有发生数值转换；只是把同样的 4 个字节复制到另一个类型的对象中，再按整数格式打印。

## 小结

- 内存保存的是比特，类型规定如何解释和操作这些比特。
- CPU 通过不同的机器指令选择整数路径或浮点路径，类型通常不会作为运行时标签存在于普通内存中。
- 字节大小、对齐和 ABI 是语言实现的工程选择，不能仅凭语言名称推断。
- 基础类型应同时说明值域、编码、运算和空值语义；对象的实际布局与跨系统协议字段是两回事。
