整数可以用有限位数精确表示一个范围内的每个值，浮点数则把有限位数分给“数量级”和“有效数字”，因此它能表示很大的范围，却必然存在间隔和舍入误差。

## 科学计数法的机器版本

二进制浮点数通常写成：

$$
(-1)^s × 1.f × 2^{e-bias}
$$

其中 $s$ 是符号位，$f$ 是尾数字段，$e$ 是存储的指数，`bias` 是偏置值。IEEE 754 单精度使用 1 位符号、8 位指数、23 位尾数，实际有效精度为 24 位，因为正规数隐含最高位 1。

以 `1.0` 为例，符号为 0，指数为 127（真实指数 0），尾数全 0；拼出的 32 位正是：

```text
0 01111111 00000000000000000000000
```

指数全 0 用于 0 和非正规数，指数全 1 用于无穷大与 NaN。这些特殊编码让除零、溢出和下溢能够传播，而不是悄悄变成普通数字。

## 为什么 `0.1 + 0.2` 不等于 `0.3`

十进制的 $0.1$ 在二进制中是无限循环小数，无法在 23 位尾数内精确保存。存储时要按照舍入模式选取最接近的可表示值；`0.2` 和 `0.3` 也分别发生舍入。两次舍入后的近似值相加，结果可能落在 `0.3` 的相邻可表示数上。

```python
result = 0.1 + 0.2
print(result)          # 0.30000000000000004
print(result == 0.3)   # False
```

这不是 Python 特例，而是 IEEE 754 二进制浮点的必然结果。金融金额通常使用整数分、十进制定点库或数据库的 DECIMAL，而不是直接用二进制 `float`。

## 浮点加法由谁执行

编译器把源代码中的浮点表达式翻译成目标架构的浮点指令；CPU 内的 FPU（Floating-Point Unit）负责对齐指数、执行尾数加法、规格化和舍入。现代 CPU 可能把 FPU 集成在核心中，也可能使用 SIMD 向量寄存器一次处理多个浮点数。

语言运行时一般不逐位“解码”浮点数。它只需把值放入寄存器或内存，再发出对应指令；加载和存储硬件负责搬运比特，FPU 根据指令格式解释它们。

## 精度、范围和误差传播

单精度约有 7 位十进制有效数字，双精度约有 15～16 位。数值越大，相邻可表示数之间的间隔越大；当一个很小的数加到极大的数上时，可能被舍入掉。比较浮点结果时，常用绝对误差和相对误差的组合，而不是直接使用 `==`。

```python
import math

print(math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-12, abs_tol=1e-12))
```

容差并不是越大越好：它应当由数据量纲、算法误差预算和业务允许范围共同确定。

## 整数与浮点路径如何区分

`int` 和 `float` 的内存位模式可能长度相同，但编译后的指令不同。整数加法使用整数 ALU，浮点加法使用 FPU；寄存器文件、调用约定和指令编码会记录操作数属于哪条路径。若源代码显式转换 `int` 到 `float`，编译器会插入转换指令，完成精确范围内的数值转换和必要的舍入。

## 小结

- 浮点数把有限位数分配给指数和有效数字，换来范围却牺牲部分精度。
- IEEE 754 规定编码、特殊值和舍入；FPU 按浮点指令执行运算。
- 误差来自表示和每一步舍入，比较与金额计算必须使用合适的数值策略。
