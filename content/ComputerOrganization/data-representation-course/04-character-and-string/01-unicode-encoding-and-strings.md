“字符占几个字节”这个问题本身缺少上下文。字符是人类可识别的抽象单位，码点是字符在某个字符集中的编号，编码才规定如何把码点变成字节。

## 字符集与编码不是一回事

Unicode 为字符分配码点，例如字母 `A` 是 U+0041，汉字“中”是 U+4E2D。码点只是一个整数，不携带“占用几个字节”或“用十六进制还是十进制书写”的物理属性。

UTF-8 是一种编码：它把码点映射为 1～4 个字节。U+0041 编码为 `41`；U+4E2D 编码为 `E4 B8 AD`。同一个码点也可以使用 UTF-16 或 UTF-32 编码，字节序列会不同。

## UTF-8 的结构

UTF-8 用首字节的高位模式表示序列长度：

```text
0xxxxxxx                         1 字节
110xxxxx 10xxxxxx                2 字节
1110xxxx 10xxxxxx 10xxxxxx       3 字节
11110xxx 10xxxxxx 10xxxxxx 10xxxxxx  4 字节
```

“中”的码点 U+4E2D 写成二进制后，填入三字节模板，就得到 `E4 B8 AD`。续字节以 `10` 开头，使解码器可以判断边界并拒绝许多非法序列。

## 语言中的字符和字符串

- C 的 `char` 是一个字节，字符串通常是以 `\0` 结尾的字节数组；它本身不保证是 UTF-8。
- Java 的 `char` 是 16 位 UTF-16 代码单元，一个 Unicode 码点可能需要两个 `char`（代理项对）。
- Python 3 的 `str` 是 Unicode 文本抽象，内部存储策略由实现选择；编码成文件或网络字节时必须显式指定 `utf-8` 等编码。

因此，“字符串长度”也有多种含义：字节数、代码单元数量、Unicode 码点数量，甚至用户感知的字素簇数量。表情符号和组合音标很容易让这几个数字不同。

## 文件和网络中的字符串

编辑器保存文件时，通常把内存中的文本按选定编码转换成字节写入文件；操作系统文件系统只负责保存字节，不理解这些字节是不是文字。程序读取文件后，必须使用同一编码解码，否则就会出现乱码或解码异常。

HTTP 也传输字节。`Content-Type: text/plain; charset=utf-8` 之类的声明，是在协议层告诉接收方应该用哪种字符编码解释正文；它不是 TCP 的功能，TCP 只保证字节序列按可靠、有序的方式到达。

## 一个最小实验

```python
text = "A中"
data = text.encode("utf-8")
print(len(text))       # 2 个 Unicode 码点
print(len(data))       # 4 个 UTF-8 字节
print(data.hex())      # 41e4b8ad
print(data.decode("utf-8"))
```

如果把 `data` 按 `latin-1` 解码，得到的仍是一串合法字符，但含义已经改变；这说明“没有报错”不代表编码正确。

## BOM、字节序与边界

UTF-16 和 UTF-32 可能需要 BOM（Byte Order Mark）指示字节序；UTF-8 通常不需要 BOM，但某些编辑器会写入它。处理文本时应把编码边界放在 I/O 层：进入程序时解码为统一文本，离开程序时再编码；不要让业务逻辑到处猜测字节编码。

## 小结

- Unicode 码点是抽象编号，UTF-8/UTF-16/UTF-32 才是字节编码。
- 字符串长度必须说明单位：字节、代码单元、码点还是字素簇。
- 文件系统和 TCP 只搬运字节，编码声明与正确解码由编辑器、库和应用协议负责。
