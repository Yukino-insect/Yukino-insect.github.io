补码的价值不只是“可以表示负数”。更重要的是，正数和负数都可以直接交给同一套二进制加法器。只是固定宽度运算有三条不能含糊的规则：先把操作数对齐到相同位宽；结果只写回低位；最后把 carry-out 和溢出分开判断。

本文建立在[《有符号整数如何编码：原码、反码、补码与真值》](03-signed-integer-encodings.md)之上，并用下面这道题贯穿说明：

```text
[X]补 = 01010101B
[Y]补 = 10101010B
[Z]补 = 1000111111111111B
```

其中 $X$、$Y$ 是 8 位补码，$Z$ 是 16 位补码。

## 一、固定宽度加法：只保留低 w 位

对 $w$ 位寄存器，硬件写回的结果是：

$$
(A+B)\bmod 2^w
$$

加法器可以产生第 $w+1$ 位，但寄存器只能保存低 $w$ 位。最高位之外的进位称为 **carry-out**，写回结果时将它丢弃，是固定宽度的正常规则。

```text
  11111111   （补码 -1；无符号 255）
+ 00000001   （+1）
----------
1 00000000
```

最终写回 `00000000`。因此，**丢弃 carry-out 是位宽规则；溢出则是数学结果无法在指定范围内表示。**两者相关，却不是同一个概念。

## 二、补码加法：直接逐位相加

补码加法不需要先转回原码。只要两个操作数已处于相同位宽，像普通二进制一样逐列相加即可。

题中三数的真值为：

```text
X：01010101₂ = 85
Y：10101010₂ = -86
Z：1000111111111111₂ = -28673
```

### 例一：X + Y

`X`、`Y` 都是 8 位：

```text
  01010101   X = 85
+ 10101010   Y = -86
----------
  11111111
```

`11111111` 是 8 位补码 -1：

```text
[X + Y]补 = 11111111B
X + Y = -1
```

-1 落在 8 位补码范围 -128 到 127 内，因此没有溢出。

## 三、补码减法：减去 B 等于加上 -B

补码的加法逆元满足：

$$
A-B=A+(-B)=A+(\sim B+1)
$$

这里的 $\sim B+1$ 是对减数的**全部当前位**取反加一。它将减法交回同一套加法器完成。

```text
B     = 00000101  （+5）
-B    = 11111011  （-5）

A - B = A + (-B)
```

### 位宽不一致时：先做符号扩展

题中的 $Y$ 为 8 位、$Z$ 为 16 位，不能直接竖式计算。补码有符号数扩展到更宽位数时，必须重复原符号位：

- 非负数首位为 0，左侧补 0；
- 负数首位为 1，左侧补 1。

所以：

```text
Y 的 8 位补码 ：10101010
Y 的 16 位补码：1111111110101010
```

“位数不齐就补 1”并不正确；只有负的补码需要补 1。正数 `01010101` 扩为 16 位应是：

```text
0000000001010101
```

符号扩展保证补码真值不变；将负数错误地零扩展会改变它的真值。

### 例二：Y - Z

先改写为：

$$
Y-Z=Y+(-Z)
$$

对 16 位 `Z` 全字取反加一：

```text
 Z：1000111111111111  （-28673）
-Z：0111000000000001  （+28673）
```

将符号扩展后的 `Y` 相加：

```text
  1111111110101010   Y = -86
+ 0111000000000001   -Z = 28673
------------------
1 0110111110101011
```

丢弃第 17 位的 carry-out，留下：

```text
[Y - Z]补 = 0110111110101011B
Y - Z = 28587
```

十进制验算是：

$$
-86-(-28673)=28587
$$

结果 28587 在 16 位补码范围 -32768 到 32767 内。这里虽然出现并丢弃了 carry-out，**却没有有符号溢出**。

## 四、什么才叫溢出

溢出是先按数学整数求出结果，再发现它超出目标编码的范围。

| 目标类型 | w 位可表示范围 |
| --- | --- |
| 无符号 | $0\sim2^w-1$ |
| 补码有符号 | $-2^{w-1}\sim2^{w-1}-1$ |

同一组比特相加，按无符号和按补码解释，溢出结论可能不同。

### 无符号加法：carry-out 就是溢出

无符号加法的数学和超过 $2^w-1$ 时溢出；对加法而言，这等价于产生 carry-out：

```text
8 位无符号：
  11111111  （255）
+ 00000001  （1）
----------
1 00000000  （写回 0，无符号溢出）
```

### 补码加法：同号相加却得到异号

补码加法只有两种溢出情形：

| 加数符号 | 结果符号 | 是否溢出 |
| --- | --- | --- |
| 正 + 正 | 负 | 是 |
| 负 + 负 | 正 | 是 |
| 正 + 负 | 任意 | 否 |

例如：

```text
  01111111  （127）
+ 00000001  （1）
----------
  10000000  （按补码为 -128）
```

数学结果 128 不能由 8 位补码表示，故溢出。注意这一例没有 carry-out。

反例：

```text
  11111111  （-1）
+ 00000001  （1）
----------
1 00000000  （0）
```

它有 carry-out，却没有有符号溢出。所以绝不能用“是否丢弃了进位”判断补码溢出。

### CPU 的进位判断式

设 $c_{w-1}$ 是进入符号位的进位，$c_w$ 是离开符号位的进位。补码加法溢出标志为：

$$
V=c_{w-1}\oplus c_w
$$

两个进位不同，补码加法就溢出。这与“同号相加，结果异号”完全等价。

### 补码减法的溢出

从真值符号看，两个异号数相减时，若结果符号与被减数不同，就发生溢出。例如 4 位：

```text
  0111  （ 7）
- 1111  （-1）
------
  1000  （按补码为 -8）
```

数学结果应是 8，但 4 位补码最大只能表示 7。它等价于 `7 + 1`，所以溢出。

## 五、零扩展、符号扩展与截断

同一组 8 位 `10101010` 的扩展结果取决于它原本的类型：

| 原本类型 | 扩展到 16 位 | 真值 |
| --- | --- | ---: |
| 无符号 | `0000000010101010` | 170 |
| 补码有符号 | `1111111110101010` | -86 |

缩窄则是直接丢弃高位，相当于保留模 $2^k$ 的低 $k$ 位。16 位的 257：

```text
0000000100000001  →  00000001
```

截为 8 位后是 1。截断保留的是位模式，不保证原数学真值仍能表示。对有符号数，若被丢弃的高位并非结果符号位的重复，就已经损失了原值。

## 六、移位与语言类型的边界

移位同样是固定宽度位操作。逻辑右移左补 0；补码算术右移通常补符号位。负奇数算术右移通常向负无穷取整，而许多语言的整数除法向零截断，因此不能把负数右移简单视为 `/2`。进制转换、二进制小数与移位的详细关系见[《进制、位权与二进制小数：数字如何写成比特》](02-number-systems-and-base-conversion.md)。

硬件产生低 $w$ 位结果和状态标志，语言再决定程序能否依赖溢出后的值：

- C/C++ 的无符号运算按模 $2^w$；有符号溢出不能作为可移植行为依赖。
- Java 的固定宽度整数会保留低位；需检查时可使用 `Math.addExact` 等 API。
- Python 的普通 `int` 自动扩展，但写二进制协议、调用原生库或存入固定宽度字段时仍须先验范围。

## 七、解题检查清单

1. 写出每个操作数的位宽与补码真值。
2. 确定结果位宽；不一致时先符号扩展。
3. 将减法改写为“加上减数的全字取反加一”。
4. 在结果位宽内相加，carry-out 不写回。
5. 按补码解释留下的位模式。
6. 最后按范围或符号规则判断是否发生有符号溢出。

## 八、总结

- 补码加法直接逐位相加；结果只保留目标位宽的低位。
- 减法通过 $A-B=A+(\sim B+1)$ 统一为加法。
- 位宽不一致时，补码负数补 1、非负数补 0；不是一律补 1。
- 丢弃 carry-out 是固定宽度写回规则，不等于有符号溢出。
- 无符号加法溢出看 carry-out；补码加法溢出看同号相加是否得到异号结果，或看符号位两侧进位的异或。
- 本题的 `Y-Z` 丢弃了第 17 位进位，但最终 28587 仍在 16 位补码范围内，所以没有溢出。
