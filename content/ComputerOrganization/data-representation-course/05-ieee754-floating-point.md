整数可以用有限位数精确表示一个范围内的每个值，浮点数则把有限位数分给“数量级”和“有效数字”，因此它能表示很大的范围，却必然存在间隔和舍入误差。

## 科学计数法的机器版本

二进制浮点数通常写成：

$$
(-1)^s × 1.f × 2^{e-bias}
$$

其中 $s$ 是符号位，$f$ 是尾数字段，$e$ 是存储的指数，`bias` 是偏置值。IEEE 754 单精度使用 1 位符号、8 位指数、23 位尾数，实际有效精度为 24 位，因为正规数隐含最高位 1。

以 `1.0` 为例，符号为 0，指数为 127（真实指数 0），尾数全 0；拼出的 32 位正是：

```text
0 01111111 00000000000000000000000
```

指数全 0 用于 0 和非正规数，指数全 1 用于无穷大与 NaN。这些特殊编码让除零、溢出和下溢能够传播，而不是悄悄变成普通数字。

## 为什么 `0.1 + 0.2` 不等于 `0.3`

十进制的 $0.1$ 在二进制中是无限循环小数，无法在 23 位尾数内精确保存。存储时要按照舍入模式选取最接近的可表示值；`0.2` 和 `0.3` 也分别发生舍入。两次舍入后的近似值相加，结果可能落在 `0.3` 的相邻可表示数上。

```python
result = 0.1 + 0.2
print(result)          # 0.30000000000000004
print(result == 0.3)   # False
```

这不是 Python 特例，而是 IEEE 754 二进制浮点的必然结果。金融金额通常使用整数分、十进制定点库或数据库的 DECIMAL，而不是直接用二进制 `float`。

## 浮点加法由谁执行

编译器把源代码中的浮点表达式翻译成目标架构的浮点指令；CPU 内的 FPU（Floating-Point Unit）负责对齐指数、执行尾数加法、规格化和舍入。现代 CPU 可能把 FPU 集成在核心中，也可能使用 SIMD 向量寄存器一次处理多个浮点数。

语言运行时一般不逐位“解码”浮点数。它只需把值放入寄存器或内存，再发出对应指令；加载和存储硬件负责搬运比特，FPU 根据指令格式解释它们。

## 特殊值不是异常：零、非正规数、无穷大和 NaN

以 binary32（通常称 `float`）为例，指数全为 0 或全为 1 的编码不再按普通的 `1.f × 2^e` 解释：

| 指数 | 尾数 | 值 | 工程含义 |
| --- | --- | --- | --- |
| 全 0 | 全 0 | `+0` 或 `-0` | 符号可保留方向信息；数值比较时两者通常相等 |
| 全 0 | 非 0 | 非正规数 | 牺牲部分精度，让接近 0 的数平滑下溢而非突然归零 |
| 全 1 | 全 0 | `+∞` 或 `-∞` | 例如有限非零数除以零的常见结果 |
| 全 1 | 非 0 | NaN | 无效运算的结果，例如 `0.0 / 0.0` |

NaN（Not a Number）不是一个可用于普通相等判断的值。IEEE 754 规定 NaN 与任何值比较都不相等，连它自身也是如此；应使用语言提供的 `isnan`/`isNaN` 检查。把 NaN 当作数据库里的 `NULL` 也不正确：前者是浮点格式中的特殊数值，后者表示字段缺失，两者的比较、索引和序列化规则分别由不同层决定。

## 舍入、ULP 与“很小的数消失”

默认的常见舍入模式是“舍入到最近值，恰好居中时取偶数”（round to nearest, ties to even）。它避免统计上总向上偏，但不保证每次业务计算都符合直觉。一次浮点运算会先得到精确数学结果，再舍入到当前格式中最接近的可表示数。

在某个数附近，两个相邻浮点数的间隔称为 ULP（unit in the last place）。binary32 只有 24 位有效二进制位；数值越大，ULP 越大。当把一个远小于当前 ULP 的数加到大数上，它可能完全不改变结果：

```python
value = 1.0e16
print((value + 1.0) - value)  # 0.0，双精度也无法在此数量级保留 1
```

另一种常见现象是灾难性消去：两个非常接近的大数相减后，前面许多有效位抵消，剩下结果的相对误差可能很大。数值算法常通过改变公式、从小到大求和、使用补偿求和或提高精度缓解它；把显示精度调得更长并不会让已经舍入丢失的位回来。

## 数值类型的选择与序列化边界

- 计数、ID 和位标志使用整数，先选清楚位宽与溢出策略。
- 金额、税率等十进制规则的业务，使用最小货币单位整数或十进制 `Decimal` / 数据库 `DECIMAL`；不要期望二进制 `double` 恰好表示 `0.01`。
- 科学计算、图形、机器学习通常用 binary32/binary64，并把可接受误差写成算法的一部分。
- JSON 的数字是文本记号，接收端可能解析成 binary64、任意精度整数或十进制数。超过 JavaScript 安全整数范围的 ID 不应以普通 JSON number 交给浏览器，应使用字符串或明确的大整数协议。

`float32` 与 `float64` 之间转换不是“改一下容器大小”。从双精度缩到单精度会重新舍入；把浮点格式的原始字节跨网络发送还要同时规定字节序与 NaN/无穷大的业务处理。若协议只说“传一个浮点数”，接收端只能猜测精度，猜测当然不能算协议。

## 精度、范围和误差传播

单精度约有 7 位十进制有效数字，双精度约有 15～16 位。数值越大，相邻可表示数之间的间隔越大；当一个很小的数加到极大的数上时，可能被舍入掉。比较浮点结果时，常用绝对误差和相对误差的组合，而不是直接使用 `==`。

```python
import math

print(math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-12, abs_tol=1e-12))
```

容差并不是越大越好：它应当由数据量纲、算法误差预算和业务允许范围共同确定。

## 整数与浮点路径如何区分

`int` 和 `float` 的内存位模式可能长度相同，但编译后的指令不同。整数加法使用整数 ALU，浮点加法使用 FPU；寄存器文件、调用约定和指令编码会记录操作数属于哪条路径。若源代码显式转换 `int` 到 `float`，编译器会插入转换指令，完成精确范围内的数值转换和必要的舍入。

## 小结

- 浮点数把有限位数分配给指数和有效数字，换来范围却牺牲部分精度。
- IEEE 754 规定编码、特殊值和舍入；FPU 按浮点指令执行运算。
- 误差来自表示和每一步舍入，比较与金额计算必须使用合适的数值策略。
