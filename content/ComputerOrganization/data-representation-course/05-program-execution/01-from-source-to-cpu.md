在编辑器里输入的字符，和 CPU 最终执行的指令，中间隔着多个转换阶段。每一层都可能重新解释或重新编码数据，弄清边界后，才能判断问题究竟出在文件、编译器还是运行时。

## 编辑器保存的是字节

编辑器内部通常维护文本缓冲区，并在保存时按 UTF-8 等编码写入文件。`.c`、`.java` 或 `.py` 文件对操作系统而言都只是字节序列；文件扩展名主要供工具选择处理方式，并不是文件系统内置的类型标签。

## 编译器如何保留类型信息

以 C 为例，预处理器展开宏和头文件，编译器进行词法、语法和类型检查，再把表达式翻译为中间表示和目标机器指令。`int a + b` 会生成整数加法路径；`float a + b` 会生成浮点路径。类型大多在编译期完成职责，运行时只留下指令、布局和必要的元数据。

Java、C# 等语言先编译成字节码或中间语言，再由虚拟机解释、即时编译（JIT）或混合执行。Python 通常先生成字节码，再由解释器执行；Python 对象会保留类型和引用计数等运行时信息，所以一个 `int` 对象的内存开销远大于裸机器整数。

## 链接器和加载器做什么

编译器生成的目标文件通常还包含未解析的符号。链接器把多个目标文件和库合并，完成符号解析、重定位，并生成 ELF、Mach-O 或 PE 等可执行文件。加载器启动程序时，把代码段、只读数据段和可写数据段映射到进程虚拟地址空间，设置入口地址，然后跳转到运行时启动代码。

```text
源文件（编码后的字节）
  -> 预处理 / 编译 / 汇编
  -> 目标文件
  -> 链接器
  -> 可执行文件
  -> 加载器映射到虚拟内存
  -> CPU 取指、译码、执行
```

## CPU 如何区分数据和指令

CPU 并不会为内存中的每个字节贴上“代码”或“数据”标签。程序计数器指向的地址会被取指单元按当前 ISA 解码；加载/存储指令则把某个地址当作数据。操作系统通过页表权限把代码页设为可执行、数据页设为不可执行（NX），帮助阻止一部分错误跳转和攻击，但这仍不是“类型识别”。

## 系统调用与运行时

程序访问文件、网络或终端时，通常调用标准库，标准库再通过系统调用进入内核。内核检查地址和权限，操作驱动与文件系统，最后把结果复制或映射回用户空间。Java、Python 等运行时还会在这条链上增加垃圾回收、异常、线程调度和对象管理。

## 小结

- 编辑器、编译器、链接器、加载器和 CPU 各自负责一次转换或解释。
- 类型主要在编译期影响指令选择和布局；运行时是否保留类型信息取决于语言实现。
- CPU 通过取指路径和指令编码区分操作，不会凭比特内容猜测数据类型。
