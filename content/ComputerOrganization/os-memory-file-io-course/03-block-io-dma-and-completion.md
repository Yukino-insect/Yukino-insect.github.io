文件系统最终会给出一个 LBA 范围，但 LBA 不是 CPU 地址。块设备把稳定存储抽象为一串固定大小的逻辑块；驱动把“读这些 LBA”转换为控制器理解的命令，设备再把数据送入 RAM。

## 一、控制路径与数据路径

```text
CPU/内核：分配缓冲页、填写描述符、提交命令、处理完成
设备控制器：读取介质、通过 DMA 写入目标 RAM、写入完成状态
```

CPU 会访问设备寄存器或内存中的提交队列，告诉 NVMe、SATA 等控制器：读写的 LBA、长度、以及可 DMA 的目标缓冲区在哪里。控制器不会得到任意进程指针；内核必须固定相应页面、建立适用于设备的 DMA 映射，并在有 IOMMU 时配置 I/O 页表与权限。

## 二、DMA 不等于绕过操作系统

DMA（直接内存访问）表示数据不经 CPU 一字节一字节复制；它不表示设备拥有不受约束的内存权限。内核仍负责：

- 选择并锁定 I/O 期间不能被回收的物理页；
- 将可能不连续的页面组织为 DMA 描述符列表；
- 处理缓存一致性、IOMMU 和错误；
- 在完成后更新页缓存、页表或唤醒等待线程。

设备 DMA 写入的常是页缓存页或内核准备的 I/O 缓冲页。普通 `read` 随后仍要将需要的字节安全复制到用户缓冲区；用户程序并不会突然获得一根“磁盘指针”。

## 三、完成为何要通知 CPU

提交命令后，线程可等待、调度其他任务，或在高性能场景轮询完成队列。设备完成时通常写入完成队列并触发中断；内核的快速处理部分确认结果、回收请求并安排后续工作。一次中断不必对应一块数据，一次请求也可能包含多个块。

机械盘的寻道与旋转、SSD 的闪存转换层、队列合并和调度策略都被隐藏在块接口之下。主机通常只承诺 LBA 的读写语义，而不指定“第几个 NAND 页”或“哪条磁道”。

## 四、总结

- CPU 用队列和寄存器操作控制器；普通 load/store 不能直接读取磁盘 LBA。
- DMA 将大块数据搬到 RAM，内核仍控制缓冲页、权限与完成语义。
- 中断或轮询把设备完成转换为内核可处理的事件。
