文件系统面对的不是 CPU 虚拟地址，而是一串块设备逻辑块。它的工作是把人类可读的名称和连续的文件字节，组织为可持久化、可恢复的块分配关系。

## 一、路径解析先找到文件对象

`/home/alice/a.txt` 不是磁盘地址。内核逐级查询目录；目录是一种保存“名称 -> 文件标识”的特殊文件。Unix 风格系统常以 inode 标识文件，NTFS 则以 MFT 记录保存等价元数据。解析成功后，`open` 创建打开文件状态并给进程一个小整数文件描述符；后续 `read(fd, ...)` 不必重新扫描整条路径。

文件元数据通常保存类型、权限、长度、时间、链接计数及内容位置。一个文件可有多个硬链接名；已打开的文件即使被改名或取消目录项，仍可由打开引用继续访问。

## 二、文件偏移变成 LBA

若块大小是 4 KiB，文件偏移 8192 对应文件内逻辑块 2。inode 中的 extent、间接块或分配表再把它变成设备 LBA。extent 用“起始块 + 连续长度”描述范围，能高效表示连续分配；碎片化文件则有多个范围，但对应用仍是一串连续字节。

```text
文件偏移 8192
  -> 文件逻辑块 2
  -> extent 中的第 2 块
  -> 分区内 LBA 123456
```

SSD 内部再由 FTL 把 LBA 映射到闪存介质；这不是文件系统也不是 CPU 页表的职责。

## 三、空闲空间是一套账，不是“全零块”

创建或扩展文件时，文件系统通过位图、空闲范围树或空闲链表寻找未分配块。块内容全为零不能证明空闲，刚删除的块还可能保留旧数据；所有权只能由元数据判断。一次分配还需要同步更新数据范围、文件长度、目录项和空闲空间账本。

断电若发生在这些更新中间，就可能出现同一块被重复引用或文件引用丢失。日志文件系统把相关元数据作为事务记录，写时复制文件系统则先写入新节点再原子切换根。两者主要解决文件系统一致性，不能自动满足应用的“业务已永久保存”语义。

## 四、总结

- 路径解析得到文件对象，文件偏移经元数据得到 LBA；两者都不是 CPU 地址。
- inode/MFT、目录、extent 和空闲空间结构共同构成文件系统的索引与账本。
- 日志/写时复制防止元数据在崩溃后自相矛盾，但不替应用选择持久化边界。
