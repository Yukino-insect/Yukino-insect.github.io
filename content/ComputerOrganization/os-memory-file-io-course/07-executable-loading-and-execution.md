可执行文件并不是“整块复制进 CPU”。它先是文件系统中的一个普通文件；装载器读取 ELF、PE 等格式的头和可装载段，再建立具有不同权限的虚拟内存区域。

## 一、文件偏移、虚拟地址与物理地址

ELF 的可装载段同时记录文件中的偏移和期望虚拟地址。装载时，`.text` 往往映射为 `R-X`，只读数据为 `R--`，可写数据、堆和栈为 `RW-`；未初始化的 `.bss` 没有等量的文件内容，初次使用时获得零页。PIE 和共享库还会因装载基址发生变化。

文件偏移用于找到文件字节，虚拟地址用于 CPU 取指和访问数据，物理地址仅在某页真正驻留 RAM 后由页表给出。不要将它们相加或当成同一种地址。

## 二、按需装载与第一次取指

内核设置初始 PC 为程序入口的虚拟地址，但并不必须先读完整个可执行文件。CPU 取第一条指令时，若 `.text` 页未在内存，发生文件缺页：内核根据 ELF 段得到文件偏移，检查页缓存，必要时经文件系统、LBA、驱动和 DMA 将页读入，然后在页表中设置该页的可执行映射。原取指指令重试后，才沿着 ITLB、指令 Cache 和内存层次获得机器码。

多个进程运行同一个未改动程序时，可以共享只读代码页；它们的栈、堆和私有可写数据则各自独立。这正是文件页、页缓存和页表共享能同时节省内存并保持隔离的例子。

## 三、代码和数据只是不同的使用方式

磁盘和 DRAM 中都是字节。文件格式、页权限和 CPU 访问路径赋予它们角色：PC 驱动取指，load/store 指令计算有效地址访问数据；MMU 阻止从不可执行页取指或向只读代码页写入。所谓代码“到 CPU”，实际是指令字节被逐步取入指令 Cache、译码与执行流水线，而不是永久存放在某个叫 CPU 的盒子里。

## 四、课程总结

- 虚拟内存翻译 CPU 地址，文件系统翻译文件偏移，块 I/O 把设备数据搬到 RAM。
- 页缓存是文件内容在 RAM 中的共享会合点；`read` 复制，`mmap` 建页表映射。
- 程序执行是文件映射缺页、DMA、页表和 CPU 取指的组合，而不是从磁盘直接执行。
- 以后遇到“这个地址在哪里”的问题，先问它是文件偏移、LBA、虚拟地址、物理地址还是 DMA 地址；剩下的推理通常就不会走错层。
