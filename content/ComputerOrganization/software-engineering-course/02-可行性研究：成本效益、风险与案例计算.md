可行性研究发生在承诺大量开发成本之前，回答的不是“系统怎样编码”，而是**问题是否值得解决、是否能在约束内解决，以及哪个方案更合适**。可行性报告给管理者一个继续、调整或终止项目的依据；它不是把需求规格书提前重写一遍。

## 一、四类可行性

| 类型 | 核心提问 | 图书借阅系统示例 |
| ---- | -------- | ---------------- |
| 技术可行性 | 现有技术、设备、人员能否实现 | 是否能与校园统一认证和扫码设备集成 |
| 经济可行性 | 收益是否覆盖成本、何时回收 | 节省的人工工时是否大于开发和运维成本 |
| 操作可行性 | 组织、流程、用户是否愿意且能够使用 | 馆员能否在借还窗口完成新流程 |
| 法律/进度可行性 | 是否合规、是否能按期限完成 | 个人信息保护、开学前上线的硬期限 |

有的教材还将社会可行性单列。答题时最好按题目采用的分类名称作答，但内容要落到可验证的约束，而不是只写“可行”。

## 二、候选方案与推荐理由

可行性研究应至少比较两个可操作方案。例如：

- 方案 A：部署在图书馆机房，使用已有服务器；初始投入低，但异地访问与容灾能力较弱。
- 方案 B：使用学校统一云平台；初始迁移和安全审批成本较高，但可复用统一认证、备份和监控。
- 方案 C：继续人工台账；几乎没有开发成本，但无法消除统计滞后、错账和读者自助查询问题。

推荐不是简单选择“成本最低”。如果方案 A 便宜却无法满足“开学高峰 500 人同时查询”和数据备份要求，它就不满足关键约束。正确写法是：先列硬约束，再以成本、收益、风险等指标比较满足约束的方案。

## 三、成本与收益的计算

成本包括一次性开发、采购、培训、数据迁移，也包括每年运行、维护、云资源和支持成本。收益既可直接量化（减少人工、减少纸张、减少错账损失），也可说明难以量化的收益（读者满意度、报表及时性、审计能力）。

### 1. 投资回收期

若初始投资为 120 万元，每年净收益为 40 万元，且忽略资金时间价值，则静态投资回收期为：

$$
P = \frac{120}{40} = 3\text{ 年}
$$

若每年收益不相等，应逐年累加净现金流，找出累计值首次非负的时点。不要把“总收益”误作“净收益”；应先扣除当年的运行成本。

### 2. 净现值 NPV

设初始投入为 $C_0$，第 $t$ 年净现金流为 $CF_t$，折现率为 $r$，则：

$$
NPV = -C_0 + \sum_{t=1}^{n}\frac{CF_t}{(1+r)^t}
$$

经典计算：某系统初始投入 100 万元，未来三年每年净收益 45 万元，折现率 10%。

$$
NPV=-100+\frac{45}{1.1}+\frac{45}{1.1^2}+\frac{45}{1.1^3}
\approx 11.9\text{ 万元}
$$

NPV 大于零表示按给定折现率衡量，该方案创造正的净价值。比较互斥方案时，须在相同口径、相同年限和相同折现率下比较，不能只看未经折现的收益总额。

### 3. 盈亏平衡分析

若固定成本为 $F$，每处理一笔业务的可变成本为 $v$，每笔业务带来的收益或节约为 $p$，盈亏平衡业务量为：

$$
Q = \frac{F}{p-v}
$$

前提是 $p>v$。若单位边际收益不为正，增加业务量不会弥补固定成本；把公式机械代入得到负数，并不是一个“神奇的盈利结论”。

## 四、风险分析不是一句“注意风险”

风险应包含原因、概率、影响、触发器、应对和责任人。以“统一认证接口延期”为例：

| 项目 | 内容 |
| ---- | ---- |
| 风险 | 身份认证接口在联调截止日前不可用 |
| 影响 | 登录、权限验证无法验收，开学上线延期 |
| 概率/影响 | 中 / 高 |
| 预警信号 | 接口文档未确认、测试账号未发放 |
| 缓解措施 | 第 1 周完成接口探测；预留本地模拟与手工账号兜底 |
| 应急措施 | 降级为校内账号导入，待接口恢复后同步 |

风险规避、缓解、转移和接受的区别也常被考察：不接入不稳定的第三方服务是规避；增加重试和备用通道是缓解；购买保险或合同约定赔偿是转移；低影响风险不专门投入资源是接受。接受不等于假装风险不存在，仍需明确监控条件。

## 五、案例题作答模板

若题目要求写可行性结论，可使用以下结构：

1. **问题与边界**：人工台账导致借阅状态滞后、统计耗时；本项目覆盖借还、查询、报表，不改造采购系统。
2. **硬约束**：需对接统一认证；开学前上线；读者信息受权限和审计约束。
3. **方案比较**：列出每种方案的技术、成本、进度与风险，不只列优点。
4. **量化依据**：给出成本、年净收益、回收期或 NPV 的算式和单位。
5. **推荐与前提**：推荐某方案，并写出成立条件与首要风险控制措施。

可行性研究的价值正在于它允许一个项目在投入尚小的时候被否决或重定向。这并不消极；比起完成一个从一开始就不满足约束的系统，早一点得出这个结论要理性得多。
