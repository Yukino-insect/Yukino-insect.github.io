学习计算机组成原理时，常会看到一句定义：**存储周期是连续两次独立存储器操作之间所需的最小时间**，并且它通常不小于存取时间。于是一个很自然的疑问出现了：第一次已经把数据读出来了，为什么不能马上再读一次？是不是因为 DRAM 要刷新？

核心结论是：**不能无限制地紧接着发起下一次访问，是因为存储器内部和外部接口都需要完成一次访问后的收尾、恢复和时序交接；DRAM 刷新只是 DRAM 特有的另一项周期性维护，不能用来解释所有存储周期。** SRAM 也有存储周期，ROM 也有读周期；因此根本原因不是“刷新”本身，而是现实电路不是可以瞬间切换、同时服务任意请求的数学对象。

## 一、先把三个容易混淆的时间分开

教材、芯片手册和 CPU 总线时序图有时都写“周期”，但讨论的对象并不相同。

| 名称 | 从哪里量到哪里 | 回答的问题 |
| --- | --- | --- |
| 存取时间 | 一次访问开始，到读数据有效或写入完成 | 这一次要等多久才能得到结果？ |
| 存储周期 | 一次访问开始，到下一次访问可安全开始 | 请求最密能隔多久发一次？ |
| 总线周期 | CPU 或总线主设备完成一次总线传输的时序区间 | 地址、控制、数据如何在总线上交接？ |

以读操作为例，CPU 先给出地址和读控制，存储器经过地址译码、选中存储单元、放大信号后，把数据送到数据线。**从开始到数据稳定有效的延迟**是存取时间，记作 `tACC`。CPU 在这一时刻已经可以采样数据，但存储器未必已经回到“可以接受全新地址”的状态。

存储器还可能需要撤销字线、恢复位线电平、断开输出驱动器、释放内部共享通路，并满足地址和控制信号的建立/保持要求。等这些条件满足，下一次彼此独立的访问才可以开始。这个“开始到下一次开始”的下限是存储周期，常记作 `tRC` 或教材中的 `T_M`。因此在简单的非流水存储器模型中，通常有：

```text
存储周期 ≥ 存取时间
```

总线周期又是另一层。它可能包含地址阶段、命令阶段、数据阶段、等待状态和应答阶段；总线本身还要解决谁能驱动数据线的问题。一个总线周期可以比芯片的存取时间长，也可以借助突发传输、流水线和多个存储体，让多个请求在时间上重叠。不能看到两处都叫“周期”，就把它们当成同一个数。

## 二、一次读操作内部究竟发生了什么

把内存想成“地址一到，抽屉立刻弹出数据”很方便，但它忽略了抽屉内部的机构。无论是 SRAM 还是 DRAM，读操作都至少包含信号传播和共享线路的切换。

一个简化的读过程可以写成：

```text
给出地址与读命令
  → 地址译码，选择行和列
  → 存储单元对位线产生很小的电压或电流差异
  → 感应放大器判定 0 或 1
  → 输出缓冲器把数据驱动到数据总线
  → 撤销选择、恢复内部线路、释放输出
```

地址译码器、字线、位线和输出缓冲器都是具有电阻、电容和传播延迟的电路。位线往往连接许多单元，电容较大；信号必须等到足以可靠区分 `0` 与 `1`，感应放大器才能作出判断。访问结束后，下一次访问若要换一行、换方向或换地址，旧状态还必须被清掉或恢复到规定初始电平。否则旧地址残留的电荷、尚未释放的输出驱动器或未稳定的位线都可能使下一次读到错误值。

所以“读到数据”不等于“所有硬件立即空闲”。就像餐厅把一盘菜递到你手中，不代表灶台、锅具和出菜口已经完成清理并可以无条件接下下一单；类比当然不严密，但足以说明两段时间为何不同。

## 三、读完以后能不能立刻再读

可以，但“立刻”必须理解为**满足该器件和该接口规定的最小间隔之后**，而不是在同一个瞬间再塞入一个完全无关的请求。

早期组成原理中的单体主存通常按串行模型讲解：CPU 发起一次读，等待数据返回，待一个存储周期结束后才发起下一次。若存储周期是 `100 ns`、存取时间是 `70 ns`，则数据可能在第 `70 ns` 出现，但下一次独立访问仍要等到第 `100 ns` 开始。剩下的 `30 ns` 并不是 CPU “什么也没做”的逻辑规定，而是硬件恢复和接口时序的预算。

现代机器不会如此朴素地浪费每一段空隙。内存控制器会：

- 对同一行中的连续数据使用突发读，一次命令连续传回多个数据块；
- 把地址、命令和前一笔的数据传输做成流水，重叠不同阶段；
- 交错使用多个 bank 或多个存储体，让一个 bank 恢复时，另一个 bank 工作；
- 先从 Cache 命中时直接返回，根本不访问 DRAM；
- 按时序规则重排多个未完成请求，提高吞吐量。

这并没有取消存储周期，而是把“一个单体一次只能做一件事”的限制隐藏在 bank、通道、队列和控制器之后。对某一个正忙的 bank 来说，仍必须满足相应的时序参数；只是系统整体可以同时让别的资源继续干活。

## 四、SRAM：没有刷新，仍然需要周期

SRAM 单元通常由交叉耦合的晶体管锁存状态，只要供电存在，就能保持 `0` 或 `1`，不需要像 DRAM 那样定期刷新。可是 SRAM 仍有访问时间和读/写周期。

读 SRAM 时，也要预充电位线、打开字线、让存储单元轻微拉动位线、由感应电路判定并输出；写 SRAM 时，则要由写驱动器强制改变单元状态，并留出足够的写脉冲宽度和恢复时间。异步 SRAM 的数据手册会明确给出地址到数据有效、读周期、写周期、输出使能/禁止等参数。它们已经足以证明：**存储周期不是 DRAM 刷新的同义词。**

高速 CPU Cache 多由 SRAM 构成，也仍受时钟、阵列端口数、标签比较、读写冲突和电路延迟约束。所谓“一周期命中”是对某种频率和某级 Cache 设计的性能承诺，不是 SRAM 在物理上不需要时间。

## 五、DRAM 的恢复与刷新：相关，却应当分开

DRAM 将一位数据存为电容上的少量电荷。读一个单元时，单元与位线共享电荷，最初只产生微小电压差；感应放大器把它放大为完整的 `0` 或 `1`。这个放大过程同时会把正确电平写回单元，因此 **DRAM 的普通读本身具有恢复性，传统上常被称为破坏性读出后再恢复**。

一次典型 DRAM 访问大致是：激活一行（`ACTIVATE`）→ 等待行数据被感放器可靠建立 → 读取某一列（`READ`）并输出突发数据 → 关闭该行并预充电（`PRECHARGE`）。不同阶段受 `tRCD`、CAS 延迟、`tRAS`、`tRP`、列到列间隔等参数限制。若下一次仍访问已打开的同一行，控制器可以形成 row hit，连续读列的间隔较短；若要改访问另一行，必须先满足该行最短激活时间，再预充电，最后才能激活新行。常见的行周期 `tRC` 正是“激活一行到可再次激活该 bank”的约束之一。

**刷新（refresh）是另一件事。** 即使某行长时间无人访问，电容电荷也会漏失，控制器必须按规定周期刷新所有行，以免数据消失。刷新会占用 bank 或更大的 DRAM 资源，并造成一段不可正常访问的时间，因此确实会影响延迟和带宽。但它不是“每次读后必须等一个存储周期”的普遍原因：SRAM 没有刷新，仍有周期；而 DRAM 某次读后的等待，更多直接来自行激活、数据传输、恢复和预充电等本次操作时序。

## 六、读写交替时，为什么等待可能更多

同方向的连续读和读写交替的成本并不一样。数据总线通常不能同时由内存和 CPU 驱动：读时由内存驱动数据线，写时由 CPU 或内存控制器驱动。若刚读完就写，必须先让内存停止驱动，再由写端接管；反过来从写切回读也需要等待数据方向翻转。这叫**总线转向（bus turnaround）**，用于避免两个输出端同时强推不同电平，形成电气冲突。

此外，写操作可能需要写恢复时间，DRAM 还要满足写后预充电等限制。因此“连续读是否可以很快”和“读后能否立刻写”是两个问题；后者往往需要更严格的间隔。教材把它们概括成统一的存储周期，是为了先建立安全的时序模型，而非声称所有访问都耗时完全相同。

## 七、应当怎样理解教材中的存储周期

在组成原理题目中，若未特别说明 Cache、bank 交叉、突发传输或同步 DRAM 时序，通常按以下模型判断即可：一次主存读/写开始后，必须等一个存储周期，才能对同一存储体开始下一次独立访问；存取时间表示结果最早可用的时刻，存储周期表示该存储体的最高启动频率。

现实中的内存控制器会把大量细节封装起来，CPU 发出的 load/store 也未必直接成为一次 DRAM 命令。但底层限制并没有消失，只是以 Cache miss 延迟、内存带宽、bank 冲突、读写转向和刷新停顿等形式表现出来。

## 八、总结

- **存取时间**关心“这次什么时候拿到数据”；**存储周期**关心“下一次最早什么时候能开始”；两者不能混为一谈。
- 一次读操作后的恢复、预充电、地址和输出交接，使得数据已经有效时，存储器仍可能尚未能接受新请求。
- SRAM 不需要刷新却仍有读写周期，因此存储周期的根本原因不是 DRAM 刷新，而是电路和接口的实际时序。
- DRAM 的行激活、感应放大、恢复、预充电以及周期性刷新都带来额外约束；刷新只是其中一类后台维护操作。
- 现代系统借助 Cache、突发、流水和多 bank 交错提升整体吞吐量，但对单个资源而言，时序边界依然必须遵守。
