二进制乘除并不神秘。计算机没有背诵乘法表；它利用二进制位只有 `0` 和 `1` 的特点，把乘法拆成**移位与加法**，把除法拆成**比较、减法与移位**。真正的硬件实现会做得更快，但核心思想没有改变。

## 一、先理解二进制的位权

十进制中，`347 = 3×100 + 4×10 + 7`；二进制中，每向左一位，位权就乘以 2：

```text
10110₂ = 1×2⁴ + 0×2³ + 1×2² + 1×2¹ + 0×2⁰ = 22₁₀
```

因此，在不溢出的前提下：

- 左移一位相当于乘以 `2`；
- 右移一位相当于除以 `2`，但有符号数必须区分算术右移与逻辑右移；
- 某个乘数位为 `1`，就把被乘数左移相应位数后加进结果；为 `0` 则不加。

## 二、无符号乘法：移位加法

计算 `1011₂ × 1101₂`，也就是 `11 × 13`。从乘数的最低位开始观察：

```text
              1011        被乘数 = 11
            × 1101        乘数 = 13
            ------
              1011         第 0 位为 1：1011 << 0
             0000          第 1 位为 0
            101100         第 2 位为 1：1011 << 2
           1011000         第 3 位为 1：1011 << 3
          -------
          10001111₂ = 143₁₀
```

把它写成公式就是：

```text
1011₂ × 1101₂
= 1011₂ × (1×2⁰ + 0×2¹ + 1×2² + 1×2³)
= (1011₂<<0) + (1011₂<<2) + (1011₂<<3)
```

### 串行乘法器如何工作

最朴素的硬件不必真的保存所有“部分积”。它可以维护三个寄存器：被乘数、乘数、累加器。

```text
accumulator = 0
while 乘数尚有位：
    若乘数最低位为 1：accumulator += 被乘数
    被乘数左移一位
    乘数逻辑右移一位
```

每一轮只检查一位，所以 `n` 位乘数最多要 `n` 轮。ALU 中的加法器负责相加，移位器负责移动位，控制器负责重复该步骤。它面积小、原理直白，却不算最快。

### 更快的乘法器

现代 CPU 常用并行的部分积压缩树（例如 Wallace tree）、Booth 编码以及流水线乘法器。它们的共同目标是：一次生成并压缩多行部分积，减少串行相加的层数。软件层面仍可以把结果理解为“移位后的被乘数相加”；电路层面只是把这个过程并行化了。

## 三、有符号乘法：补码与符号扩展

CPU 通常以**二进制补码**表示有符号整数。`n` 位补码的最高位是符号位：最高位为 `0` 表示非负，为 `1` 表示负数。

在做乘法前，较窄的操作数往往要先**符号扩展**到目标宽度：正数在左侧补 `0`，负数在左侧补 `1`。例如 4 位 `-3` 是 `1101₂`，扩展为 8 位后是 `11111101₂`，数值仍是 `-3`。

直接按无符号方式逐位相乘也能配合额外校正得到正确结果，但对连续的 `1` 位会产生很多部分积。Booth 编码会把一串 `1` 改写为加一次、减一次，例如：

```text
00111100₂ = 01000000₂ - 00000100₂
```

这样乘数中连续的 `1` 不必逐位累加。理解它时不必被电路名称吓住：减法在补码里就是“加上相反数”。

### 溢出不能忽略

两个 `n` 位整数相乘，完整积最多需要 `2n` 位。例如 8 位无符号 `255 × 255 = 65025`，需要 16 位保存。若只保留低 8 位，结果会按 `2⁸` 取模；这不是“算错”，而是可表示范围被截断。不同语言对有符号溢出的规定不同，不能把 CPU 的截断行为直接当作所有语言层面的语义。

## 四、无符号除法：恢复余数法

除法可以看成逐位决定商。以 `13 ÷ 3` 为例，`13 = 1101₂`，`3 = 0011₂`。从被除数最高位向最低位扫描：每拿到一位，就把当前余数左移并接上该位；若余数不小于除数，便减去除数，并把商的当前位写为 `1`。

```text
初始：余数 R = 0，商 Q = 0，除数 D = 3

读入 1：R = 1；R < 3，商位为 0
读入 1：R = 3；R >= 3，R = 3 - 3 = 0，商位为 1
读入 0：R = 0；R < 3，商位为 0
读入 1：R = 1；R < 3，商位为 0

Q = 0100₂ = 4，R = 1
```

所以 `13 = 3×4 + 1`。这正是整数除法的基本关系：

```text
被除数 = 除数 × 商 + 余数
```

### 为什么叫“恢复余数”

硬件常先尝试 `R - D`：

- 结果非负，说明本位商可以是 `1`，保留减法结果；
- 结果为负，说明本位商应为 `0`，再把 `D` 加回去，恢复原余数。

非恢复除法会把“减错后加回”的动作与下一轮合并，减少一些操作。更高性能的除法器还会用 SRT、倒数近似和迭代算法；但它们依然围绕“估计商、修正余数”展开。

## 五、有符号除法与右移的区别

有符号整数除法首先要规定**商向哪里取整**。许多现代语言和 CPU 的整数除法采用“向零截断”：

```text
-13 / 3 = -4，余数为 -1
```

它满足 `-13 = 3×(-4) + (-1)`。而数学中的向下取整会得到 `-5`，这两种规则不可混用。

右移也不是任意整数除法的完全替代品：

- 无符号数逻辑右移，等价于向下取整的除以 `2^k`；
- 补码负数的算术右移会在左侧补 `1`，通常趋向负无穷；
- 语言中的 `/ 2^k` 若规定向零截断，则负奇数时可能和算术右移不同。

例如 `-3` 算术右移一位通常为 `-2`，而“向零截断”的 `-3 / 2` 为 `-1`。编译器只有证明语义一致时，才能安全地把除法换成移位。

## 六、小数如何处理

定点数会约定二进制小数点的位置。若 Q 格式约定小数点后有 `f` 位，则整数 `X` 表示真实值 `X / 2^f`。两个定点数相乘后小数位数翻倍，结果需右移 `f` 位恢复尺度；相除时则要先把被除数左移 `f` 位以保留精度。

浮点数则把一个数拆为符号、有效数和指数。浮点乘法大致是“有效数相乘、指数相加、符号异或”，浮点除法则是“有效数相除、指数相减、符号异或”，最后再规格化和舍入。它比整数运算复杂得多，也会引入舍入误差。

## 七、总结

- 二进制左移对应乘以 2；乘法本质是选择性地累加左移后的被乘数。
- 除法本质是从高位到低位比较余数与除数，决定每一位商并更新余数。
- 补码、符号扩展、溢出和取整规则决定有符号运算是否符合预期。
- 现代乘除法器会高度并行、流水化或迭代优化，但没有脱离移位、加减、比较这些基本操作。
