键盘按键、网卡收到报文、磁盘完成 DMA、定时器到点，都会用中断通知 CPU。既然中断的价值是及时响应，那么 CPU、操作系统乃至中断控制器为什么还要“屏蔽中断”？这并不是把事件粗暴地扔掉，而是在一小段不能被异步打断的时间内，**暂缓接收某些中断，等状态恢复一致后再处理已经挂起的请求**。

核心结论是：**屏蔽中断（interrupt masking）是让某类可屏蔽中断暂时不能被投递或响应的机制。它可以针对一个中断源、一个优先级范围或当前 CPU 的全部普通外部中断；它的目的通常是保护临界区、完成时序严格的硬件操作、控制中断嵌套或降低无意义的中断负载。**屏蔽既不等于关闭机器，也不等于停止设备；更不等于已经安全地解决了多核并发。

## 一、先看中断从哪里到哪里

外部设备并不直接修改 CPU 的程序计数器。设备先通过一根 IRQ 线，或通过 MSI/MSI-X 这类总线消息，向**中断控制器**提出请求；控制器记录请求的挂起状态、查掩码和优先级，并在合适时机把它投递给一个 CPU。CPU 则在指令边界等架构允许的位置，保存必要现场并跳入中断入口。

```text
设备产生事件
    │ IRQ 线或中断消息
    ▼
中断控制器：pending、mask、优先级、目标 CPU
    │ 可投递
    ▼
CPU：本地中断允许状态 / 优先级阈值
    │ 可响应
    ▼
中断处理程序
```

因此“屏蔽”可能发生在不同位置，含义也不同：

| 层次 | 典型作用 | 会影响什么 |
| ---- | -------- | ---------- |
| 中断源或中断控制器 | 屏蔽某个 IRQ 号 | 该设备的请求不再投递，通常仍可记为 pending |
| CPU 本地 | 临时禁止当前核接收普通外部中断 | 当前核不进入可屏蔽 IRQ 处理；其他核不受影响 |
| 优先级门槛 | 只允许更高优先级的中断 | 低优先级请求留待稍后 |

不同架构的名字各不相同。例如 x86 有 `IF`（Interrupt Flag）控制可屏蔽外部中断的全局允许状态；中断控制器也有逐源掩码位。Arm、RISC-V 和各类嵌入式控制器使用不同状态位和优先级寄存器，但思路相同。不要把某个指令名背成普遍规律，先问清楚：**是在谁那里屏蔽、屏蔽哪一类中断、解除后请求保存在哪里。**

## 二、可屏蔽中断与不可屏蔽中断

日常讨论的“关中断”通常指**可屏蔽中断**（maskable interrupt）。网卡、磁盘、键盘和普通定时器 IRQ 一般属于这一类，因为它们可以稍后处理。CPU 会提供一种全局允许位或优先级规则，让内核在需要时推迟它们。

**不可屏蔽中断**（NMI）则设计给极少数不能轻易忽略的事件，例如严重硬件故障通知、看门狗、某些调试或性能监控事件。NMI 不受普通的“开/关中断”位控制；它同样能打断代码，所以 NMI 处理程序必须格外短小，并避免随意取得普通锁。

还要把外部中断与同步异常分开。除零、非法指令、缺页等异常由当前指令直接造成，不能靠关闭普通 IRQ 来回避；系统调用则是程序主动请求内核服务。它们可能复用相似的入口机制，却不属于“设备在外面敲门”的可屏蔽中断。

## 三、为什么需要暂时屏蔽

### 1. 保护被同一 CPU 中断路径访问的临界区

设想普通内核代码正在修改一个队列：它已更新尾指针，却还没有把新节点链接好。恰在这两条操作之间，网卡中断到来；中断处理程序也要遍历或修改该队列，就会看到一个不完整状态。

```text
普通内核代码：持有队列锁，修改队列到一半
       │
       └─ 本 CPU 的 IRQ 到来，处理程序也想获取同一把锁
              │
              └─ IRQ 自旋等待；能释放锁的普通代码却无法继续
```

这不是普通的“两人抢锁”，而是**同一个 CPU 把自己打断后等待自己**。常见做法是在普通代码取得这种“会被本地 IRQ 使用的锁”前，保存并临时关闭本地中断；释放锁后再恢复原来的中断状态。这样中断不会在临界区中间插入，而会处于 pending，离开临界区后再被处理。

关键限制是：这种做法只阻止**本 CPU**的普通可屏蔽中断。另一颗 CPU 仍然可能访问同一队列，所以多核共享数据仍需要自旋锁、原子操作或其他同步；关本地中断不是多核锁的替代品。

### 2. 让中断入口和设备协议保持可控

CPU 刚进入中断时，要保存寄存器、建立内核栈和判断中断来源。若同级中断在这套工作尚未完成时无限嵌套，现场和栈都可能被破坏。许多架构或内核会在中断入口暂时禁止同级可屏蔽中断，待最基本的现场保存完成后，再按策略恢复。

设备也常有必须遵守的确认顺序。例如驱动需要读取完成队列、更新消费者索引、清除设备状态，再通知控制器“本次 IRQ 已完成”。过早重新允许该来源，或在状态尚未确认时反复进入处理程序，可能造成重复处理、中断风暴或遗漏完成项。这里屏蔽保护的不是抽象的“代码片段”，而是一段**硬件与驱动共同约定的状态转换**。

### 3. 控制嵌套和优先级

中断也有轻重缓急。低优先级的网络收包处理不应无限阻止高优先级的实时控制或紧急故障通知；反过来，允许所有中断互相嵌套也会令栈深度、重入和最坏时延难以分析。

于是系统可能设置优先级阈值：当前处理低优先级 IRQ 时，只暂缓同级或更低级请求，仍允许更高级请求进入。也可能采用更简单的策略：硬中断期间一律不嵌套，尽快完成顶半部后统一恢复。两种策略的取舍是响应延迟与实现复杂度，不存在凭空更“先进”的唯一答案。

### 4. 避免没有实际收益的频繁打断

高速网卡或存储设备可能在极短时间内完成很多项工作。若每一项都立即触发一次中断，CPU 会反复保存现场、跳转、恢复现场，真正处理数据的时间反而变少。驱动会暂时屏蔽该队列的 IRQ，转而轮询一批 DMA 描述符；队列清空或处理到预算上限后再重新开启通知。这是常说的中断合并、NAPI 式轮询等设计背后的基本想法：**通知表示“有工作”，不是“一次通知只能处理一件工作”。**

## 四、屏蔽时事件会不会丢失

不能只回答“会”或“不会”，必须看触发语义、控制器和设备的状态保存方式。

- **电平触发**：设备在“仍有未处理原因”时持续保持请求有效。即使暂时屏蔽，解除后控制器通常还能看到该电平并再次投递；但驱动必须真正清除设备原因，否则会反复中断。
- **边沿触发**：设备用一次电平跳变表示事件。控制器若只为该 IRQ 保留一个 pending 位，则同一来源在已经 pending 时又发生多次边沿，未必能逐个计数。可靠驱动不能把“收到几个 IRQ”当作“发生了几件工作”，而应读取设备完成队列或状态寄存器。
- **消息中断**：MSI 等消息通常也会经过控制器或本地中断逻辑的挂起和仲裁；具体是否合并、何时重发，仍取决于平台实现与设备协议。

所以屏蔽期间，通常保存的是“这个来源需要处理”的**状态**，而非无限容量的事件日志。高性能设备会把每个报文、描述符完成或错误详情放进自己的 ring buffer；IRQ 只是提醒 CPU 去取。这才是既能推迟处理又不丢数据的合理分工。

## 五、屏蔽应当短，并且必须成对恢复

关闭可屏蔽中断的代价是延迟：定时器、网络收包、磁盘完成、调度唤醒都会更晚发生。时间过长时，设备队列可能积压甚至溢出，实时任务可能错过期限，系统还可能表现为鼠标卡顿、网络抖动或软锁死。它不是一个适合包住复杂计算、文件 I/O 或等待锁的“大括号”。

正确的范围通常只包含必须原子的几条操作：保存先前状态，进入极短临界区，释放资源，再恢复原状态。尤其不要不加判断地“开启中断”：调用者进入临界区前本来可能已经关闭了中断；正确行为是恢复它原先的状态，而不是替调用者改变策略。

```text
保存当前本地 IRQ 状态
暂时屏蔽必要范围
    修改必须一致的共享状态
恢复先前 IRQ 状态
```

操作系统常将这些细节封装为带 `irqsave` / `irqrestore` 含义的锁接口或平台原语。普通应用程序没有权限直接执行这类操作，也不应该试图这样做；应用需要的是互斥锁、原子变量、事件循环等用户态并发工具。

## 六、容易混淆的说法

### “屏蔽中断就是让设备停下来”

不对。设备可能继续 DMA、继续积累接收数据或保持错误状态；只是请求暂时不被 CPU 服务。因而驱动必须知道设备队列容量和恢复后的补救方式。

### “关中断就没有竞态条件”

不对。它只影响可屏蔽中断，通常还只影响当前 CPU。NMI、其他 CPU、DMA 设备，以及普通线程之间的竞争仍须按各自的并发模型处理。

### “中断必须立刻处理，否则一定丢数据”

也不对。中断控制器的 pending 状态和设备队列就是为短暂延后而存在的。不过它们都有限制；延后多久安全，需要由硬件触发方式、队列深度和实时性要求共同决定。

## 七、总结

- 屏蔽中断是推迟**可屏蔽** IRQ 的投递或响应，可按中断源、优先级或当前 CPU 的全局状态实施。
- 它主要用于保护本地中断会重入的临界区、完成设备确认时序、控制嵌套优先级，以及把高频工作批量化。
- 屏蔽不等于丢弃：请求通常会 pending；但 pending 往往只是状态位，边沿事件可能合并，真正的数据应从设备队列读取。
- 本地关中断不能取代多核同步，更管不住 NMI 和其他 CPU。
- 中断关闭时间应尽可能短，并恢复进入前的状态；把长时间工作延后处理，才不会为了“安全”把系统的响应能力一并关掉。

理解时可以始终追问三件事：**是谁发出 IRQ、请求在屏蔽期间保存在哪里、解除屏蔽后谁以什么顺序处理它。**把这三件事分开，“为什么要屏蔽中断”就不再像一句矛盾的话了。
