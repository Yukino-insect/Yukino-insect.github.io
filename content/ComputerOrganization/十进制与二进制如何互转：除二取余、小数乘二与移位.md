“十进制转二进制时，整数部分除 2 取余，小数部分乘 2 取整；这和左右移有什么关系？”它们确实都在利用二进制的位权 `2^k`，但扮演的角色不同：**除二取余与乘二取整是把一个十进制写法换成二进制写法的算法；移位是已经以二进制位保存的数，在位模式上移动。**二者的数学基础相同，不能因此混成一个操作。

## 一、任何进制都是按位权展开

十进制整数 `347` 的含义是：

```text
347₁₀ = 3×10² + 4×10¹ + 7×10⁰
```

二进制整数 `10110` 的含义是：

```text
10110₂ = 1×2⁴ + 0×2³ + 1×2² + 1×2¹ + 0×2⁰ = 22₁₀
```

二进制小数点右侧的位权则依次是 `2^-1`、`2^-2`、`2^-3`：

```text
10.101₂ = 1×2¹ + 0×2⁰ + 1×2^-1 + 0×2^-2 + 1×2^-3
        = 2 + 0.5 + 0.125
        = 2.625₁₀
```

所以在二进制中向左跨过一位，相当于整体乘以 2；向右跨过一位，相当于整体除以 2。这正是下面所有方法的根。

## 二、整数部分：为什么“除 2 取余”要从下往上读

对一个非负整数 `N` 做除法，必能写成：

```text
N = 2 × Q + R，其中 R 只能是 0 或 1
```

`R` 就是 `N` 的最低二进制位。理由是所有更高位的项都含有因子 `2`，除以 2 后没有余数，只有 `2^0` 位决定奇偶。

以 `45₁₀` 为例：

| 被除数 | 商 | 余数（当前最低位） |
| --- | --- | --- |
| 45 ÷ 2 | 22 | 1 |
| 22 ÷ 2 | 11 | 0 |
| 11 ÷ 2 | 5 | 1 |
| 5 ÷ 2 | 2 | 1 |
| 2 ÷ 2 | 1 | 0 |
| 1 ÷ 2 | 0 | 1 |

余数出现的顺序是从低位到高位：`1 0 1 1 0 1`，因此必须倒过来读：

```text
45₁₀ = 101101₂
```

这不是记忆技巧，而是每次除法都剥掉最低位的必然结果。最后一次余数是最高位，因为那时商已经降到 0。

### 用移位看同一件事

若 `N` 已经存成无符号二进制整数，右移一位正是在计算：

```text
N >> 1 = floor(N / 2)
N & 1  = N 除以 2 的余数
```

例如：

```text
N      = 101101₂ = 45
N >> 1 = 010110₂ = 22
N & 1  = 1
```

这就是“除 2 取余”在二进制机器中的直接位操作版本：最低位被 `& 1` 取出，右移得到下一轮的商。注意它只对无符号整数或已明确采用向下取整规则的非负整数如此直接；负数的右移需要单独讨论。

## 三、整数反向转换：为什么不断“乘 2 加当前位”

已知二进制字符串，要转回十进制，可从左向右累计：

```text
value = value × 2 + 当前位
```

以 `101101₂` 为例：

```text
初始 value = 0
读 1：0×2 + 1 = 1
读 0：1×2 + 0 = 2
读 1：2×2 + 1 = 5
读 1：5×2 + 1 = 11
读 0：11×2 + 0 = 22
读 1：22×2 + 1 = 45
```

从左边再接上一位，相当于原先所有位权都乘 2，再加新最低位。这与十进制从左向右读数时的 `value = value × 10 + digit` 是同一个 Horner 法则，只是基数由 10 改为 2。

## 四、小数部分：为什么是“乘 2 取整数”

设 `0 ≤ F < 1` 是小数部分。将它乘以 2：

```text
2F = B + F'
```

其中整数部分 `B` 只能是 `0` 或 `1`，它恰好是二进制小数点后的第一位；剩下的 `F'` 再乘 2，就得到第二位，如此重复。因此二进制小数位应从上到下读取，不需要倒序。

以 `0.625₁₀` 为例：

| 当前小数 | 乘以 2 | 取出的整数位 | 剩余小数 |
| --- | --- | --- | --- |
| 0.625 | 1.25 | 1 | 0.25 |
| 0.25 | 0.5 | 0 | 0.5 |
| 0.5 | 1.0 | 1 | 0 |

所以：

```text
0.625₁₀ = 0.101₂
```

再看 `10.625₁₀`，整数与小数分开处理后合并：

```text
10₁₀     = 1010₂
0.625₁₀  = 0.101₂
10.625₁₀ = 1010.101₂
```

### 为什么有些小数永远算不完

十进制的 `0.1` 不能用有限位二进制精确表示：

```text
0.1₁₀ = 0.0001100110011...₂
```

它会循环，原因与 `1/3` 在十进制中写成 `0.333...` 完全一样：分母中含有不能被当前进制基数消掉的因子。一个最简分数在二进制中能有限表示，当且仅当它的分母是 `2` 的幂；例如 `5/8` 可以，`1/10` 不可以，因为 `10 = 2 × 5` 还含因子 `5`。

因此计算机的浮点数保存 `0.1` 时通常只能保存一个邻近的二进制近似值。`0.1 + 0.2` 偶尔显示出很长的小数尾巴，不是计算机突然不会加法，而是输入值一开始就不是精确的有限二进制数。

## 五、左右移究竟在改变什么

对一个 `n` 位无符号位模式：

```text
左移：  b(n-1)...b1b0 << 1  → b(n-2)...b1b0 0
右移：  b(n-1)...b1b0 >> 1  → 0 b(n-1)...b1
```

左移使每个保留下来的 `1` 的位权翻倍，所以在不丢失高位时等价于乘 `2`；逻辑右移使每个 `1` 的位权减半，等价于向下取整除以 `2`。

```text
00101101₂ = 45
00101101 << 1 = 01011010₂ = 90
00101101 >> 1 = 00010110₂ = 22
```

但固定宽度寄存器会丢弃左移溢出的高位：

```text
8 位：10000000₂ << 1 = 00000000₂
```

数学上的 `128 × 2 = 256`，需要第 9 位；8 位寄存器只能保留低 8 位。所以“左移一位等于乘 2”必须附带条件：结果在目标位宽内可表示，或你明确接受模 `2^n` 回绕。

## 六、有符号数右移与除法为何容易出错

补码负数通常使用**算术右移**：左侧补符号位 `1`，保持符号。例如 8 位：

```text
-3 = 11111101₂
-3 算术右移 1 位 → 11111110₂ = -2
```

这相当于向负无穷取整：`floor(-3 / 2) = -2`。然而许多编程语言的整数除法是向零截断，`-3 / 2 = -1`。所以负奇数上，算术右移与语言的 `/ 2` 可能不同。

逻辑右移则始终左补 `0`。若把负数按补码位模式做逻辑右移，通常会得到一个巨大的正数；它适合无符号位操作，不适合表达带符号除法。语言是否提供逻辑右移、负数右移的精确定义，都应以该语言规范为准。

## 七、进制转换本身不改变数值

`45₁₀`、`101101₂` 与 `0x2D` 表示的是同一个数学整数，只是书写系统不同：

```text
45₁₀ = 101101₂ = 0x2D
```

真正改变值的是运算、截断、舍入或改变解释规则，而不是把“十进制”写成“二进制”。程序源代码中的 `45` 是人方便阅读的十进制字面量，编译器会把它编码成目标机器所需的二进制位；CPU 并不执行“十进制模式”。

十六进制在调试中常见，是因为一位十六进制刚好对应四位二进制：`0x2D = 0010 1101₂`。这使寄存器、地址、掩码的位边界一目了然，远比把几十位二进制全部写出来耐看一些。

## 八、总结

- 整数的除二取余每次取得最低二进制位，因此余数要倒序读；在无符号机器整数中，它对应 `N & 1` 与 `N >> 1`。
- 二进制转十进制可从左到右重复“乘 2 加当前位”。
- 小数的乘二取整每次取得下一位小数，因此整数位按产生顺序读；分母含非 2 因子的分数会产生无限循环二进制小数。
- 左移、右移直接操作已保存的二进制位；左移乘 2、右移除 2 都受位宽、溢出、符号与取整规则限制。
- 进制只是记数法，不会改变数值；CPU 底层处理的是二进制位，而不是十进制字符。
