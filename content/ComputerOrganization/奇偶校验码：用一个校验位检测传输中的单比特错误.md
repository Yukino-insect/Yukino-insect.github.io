数字电路和通信链路传送的并不是“可靠的 0 和 1”，而是有可能被噪声、干扰或硬件瞬态翻转的物理信号。若一个字节 `01001101` 在传输后悄悄变成 `01000101`，接收方若只看数据本身，通常无从知道其中一位已经改变。**奇偶校验码（parity code）**的做法很朴素：为一段数据额外附加 1 个校验位，使整个码字中 `1` 的个数保持为约定的奇数或偶数；接收方重新计数，便能发现不符合约定的结果。

它只增加 1 位，硬件实现也很简单，因此常被用来说明差错检测的基本思想。不过，“简单”并不等于“万能”：奇偶校验能保证检出任意奇数个比特错误，却不能发现偶数个比特同时出错，也不能定位或纠正错误。若不把这条边界说清楚，背规则当然很方便，理解却多少有些敷衍。

## 一、为什么数据传输需要校验

从寄存器到内存、从设备到控制器、从网卡到网线，数据都要经过实际的电子或电磁通路。理想模型中的比特只有 `0` 和 `1`，实际电路还会受到许多因素影响：

- 传输线串扰、电源波动和电磁干扰，可能使接收端把电平判断错；
- 存储单元可能因辐射或器件瞬态发生位翻转；
- 接插件接触不良、时钟边界不稳定等问题，也可能造成采样错误。

假设发送方原本要发送 4 位数据 `1011`。若第三位在途中从 `1` 变为 `0`，接收方会得到 `1001`。这两个位串都完全符合二进制数据的形式，接收端不能仅凭“它看起来合法”判断是否出错。

因此，发送方需要加入一些与原数据有关、但可以由接收方再次计算的信息。接收方把**收到的数据**重新计算一遍，并与收到的校验信息比较：

```text
发送方：原始数据 ──> 计算校验信息 ──> 数据 + 校验信息
                                            │
                                          传输通路
                                            │
接收方：收到的数据 + 校验信息 ──> 重新计算并检查 ──> 通过 / 报错
```

奇偶校验码就是最小的一类这种机制。它不记录每一位应是什么，只记录整段数据中 `1` 的个数是奇数还是偶数。

## 二、先认识校验位、数据位与码字

设原始数据共有 `k` 位，写作：

$$
d_{k-1}d_{k-2}\ldots d_1d_0
$$

奇偶校验会再添加一个校验位 `p`。连同校验位一起发送的 `k + 1` 位序列称为**码字（codeword）**。校验位放在最高位、最低位，还是单独走一根线路，是具体协议或硬件布局的选择；只要发送方和接收方采用相同约定，校验原理并不改变。

需要分清三个名字：

| 名称 | 含义 | 例子 |
| --- | --- | --- |
| 数据位 | 真正要表达业务或指令内容的位 | `1011` |
| 校验位 | 为检测错误而额外加入的位 | `1` |
| 码字 | 数据位和校验位合在一起的传输单位 | `10111` |

校验位本身也可能在途中翻转。好在接收方不需要知道“究竟是数据位错了还是校验位错了”才能报警：只要整体奇偶性被破坏，就应视为本次接收有错。

## 三、偶校验：让 `1` 的总数为偶数

**偶校验（even parity）**规定：数据位与校验位合起来，`1` 的总数必须是偶数。

令数据位中 `1` 的个数为 `w`，它也常被称作该数据的汉明重量。偶校验位的规则是：

$$
p = w \bmod 2
$$

这里 `w mod 2` 的结果只有两种：

- `w` 为偶数时，`p = 0`，不改变 `1` 的个数；
- `w` 为奇数时，`p = 1`，把总数补成偶数。

### 1. 手算例子

以数据 `1011001` 为例，其中有 4 个 `1`：

```text
数据位：  1 0 1 1 0 0 1
1 的个数：4（偶数）
偶校验位：0
码字：    1 0 1 1 0 0 1 0
```

若数据为 `1011011`，其中有 5 个 `1`，则应补上 `1`：

```text
数据位：  1 0 1 1 0 1 1
1 的个数：5（奇数）
偶校验位：1
码字：    1 0 1 1 0 1 1 1
```

第二个码字共有 6 个 `1`，仍为偶数。接收端只要统计完整码字中 `1` 的数量，发现不是偶数便判定校验失败。

### 2. 用异或理解偶校验

手工计数直观，但电路通常不会真的实现一个“逐个加一的大计数器”。因为异或 `XOR` 恰好具有所需性质：一串位中 `1` 的个数为奇数时，所有位异或的结果是 `1`；为偶数时结果为 `0`。

对数据位做逐位异或：

$$
p = d_{k-1} \oplus d_{k-2} \oplus \cdots \oplus d_0
$$

所得 `p` 就是偶校验位。以 `1011011` 为例：

```text
1 ⊕ 0 ⊕ 1 ⊕ 1 ⊕ 0 ⊕ 1 ⊕ 1 = 1
```

于是附加 `p = 1` 后，完整码字的异或值为 `0`：

$$
d_{k-1} \oplus \cdots \oplus d_0 \oplus p = 0
$$

这正是接收端的检查条件。若结果为 `1`，表示收到的码字中 `1` 的数量为奇数，偶校验失败。

## 四、奇校验：让 `1` 的总数为奇数

**奇校验（odd parity）**的规则刚好相反：完整码字中 `1` 的总数必须是奇数。

因此，当数据位中 `1` 的数量已经是奇数时，校验位取 `0`；当它是偶数时，校验位取 `1`。可写作：

$$
p = 1 - (w \bmod 2)
$$

仍以 `1011001` 为例，数据中有 4 个 `1`，为偶数。使用奇校验时必须添加 `1`：

```text
数据位：  1 0 1 1 0 0 1
1 的个数：4（偶数）
奇校验位：1
码字：    1 0 1 1 0 0 1 1
```

收到这个码字后，接收端应验证完整码字的异或结果是否为 `1`：

$$
d_{k-1} \oplus \cdots \oplus d_0 \oplus p = 1
$$

偶校验和奇校验的检错能力完全相同，区别仅在于对合法码字的约定不同。一个链路必须预先约定使用哪一种；若发送端使用偶校验、接收端却按奇校验判断，那么即使没有任何传输错误，也会稳定地报错——这倒是相当诚实地暴露了双方没有达成共识。

| 方案 | 合法码字中 `1` 的总数 | 接收端完整异或结果 |
| --- | --- | --- |
| 偶校验 | 偶数 | `0` |
| 奇校验 | 奇数 | `1` |

## 五、它究竟能检测哪些错误

奇偶校验码的核心性质并非“能检测一位错误”这么狭窄，而是：**它能检测任意奇数个比特翻转。**

原因很简单。每翻转一位，码字中 `1` 的总数就会增加 1 或减少 1，奇偶性必然改变；翻转奇数次后，奇偶性仍与原来相反。因此合法码字必然变成不合法码字。

### 1. 单比特错误必然能发现

假设使用偶校验，原码字为：

```text
发送：10110010    共有 4 个 1，合法
接收：10100010    第 4 位由 1 变为 0，共有 3 个 1，非法
```

接收端得到奇数个 `1`，检查失败。无论翻转的是哪一位，哪怕恰好是校验位，也同样会被发现。

### 2. 任意奇数位错误也能发现

如果有 3 位、5 位或其他奇数位同时翻转，每次翻转都会切换一次奇偶性；切换奇数次后，状态仍会从“偶”变成“奇”，或从“奇”变成“偶”。所以检查仍不通过。

### 3. 偶数位错误可能完全漏检

若刚好有两位同时翻转，一位 `1 → 0`、另一位 `0 → 1`，`1` 的总数甚至不会改变；即使两位变化方向相同，总数改变 `2`，奇偶性也仍然相同。接收端会把错误码字误当成正确码字。

```text
发送：10110010    4 个 1，偶校验合法
接收：10010011    两位翻转后仍有 4 个 1，偶校验仍合法
```

上例接收结果显然不同于发送内容，却仍能通过偶校验。这不是实现不够仔细，而是 1 个校验位所包含的信息量天然有限。

## 六、从码距看奇偶校验的能力边界

若把每个合法码字看作一个二进制向量，两个码字对应位置不同的位数称为它们的**汉明距离（Hamming distance）**。奇偶校验码中任意两个不同的合法码字，其汉明距离至少为 2。

这是因为合法码字都具有同一种奇偶性。只改动 1 位会改变奇偶性，因此绝不可能从一个合法码字变成另一个合法码字；至少修改 2 位，才可能仍落在合法码字集合中。

最小汉明距离为：

$$
d_{min} = 2
$$

一般而言，最小距离为 `d_min` 的码最多能保证检测 `d_min - 1` 位错误。因此奇偶校验码最多保证检测：

$$
d_{min} - 1 = 1
$$

位错误，也就是任何单比特错误。这个公式说的是“保证”，并不与前面“也能检测 3 位、5 位等奇数位错误”矛盾：它们也会被检测到，只是对两位错误已经不能保证，因此整体保证能力只能写为 1 位。

纠错需要更大的距离。若要保证纠正 1 位错误，合法码字之间至少应相距 3；否则接收端看到一个非法码字时，可能离两个不同的合法码字同样近，无法判断原本是哪一个。奇偶校验的最小距离只有 2，所以它只能报警，不能指出是哪一位错了，更不能可靠地把它改回来。

## 七、检错、定位与纠错不是同一件事

“校验失败”只说明收到的内容不符合规则。它并不自动回答错误位在哪里，也不能保证知道原始数据是什么。下面的区别需要牢牢记住：

| 能力 | 奇偶校验码是否具备 | 含义 |
| --- | --- | --- |
| 检测单比特错误 | 是 | 知道本次传输或存储出现异常 |
| 定位单比特错误 | 否 | 无法确定具体哪一位翻转 |
| 纠正单比特错误 | 否 | 无法可靠恢复原始数据 |
| 保证检测双比特错误 | 否 | 两位同时翻转可能仍通过检查 |

例如，收到一个偶校验失败的 8 位码字时，任何一位翻转都可能使它恢复为偶校验合法码字。仅根据“总数不对”这一条信息，接收端没有理由认定应修改第 2 位而不是第 7 位。擅自翻转某一位并称之为纠错，只是把一个已知错误换成一个无法验证的新猜测。

要做到单比特纠错，经典做法是使用多个、覆盖不同数据位集合的校验位，即**汉明码**；要以更高概率检测多位和突发错误，通信协议常使用 CRC；内存系统中则常见 ECC 码。这些方案增加了冗余位数，换来了更强的检错或纠错能力。

## 八、奇偶校验在计算机系统中的位置

奇偶校验并不只属于教科书。它适合错误率较低、希望以极低成本快速发现异常的场景，例如某些串行通信格式、早期总线或简单硬件接口。在异步串口的常见帧格式中，校验位可以被配置为无校验、偶校验或奇校验：

```text
起始位 | 数据位（通常 5～9 位） | 可选校验位 | 停止位
```

不过，现代系统中需要更可靠保护的通路通常不会只依靠一位奇偶校验：

- 网络帧常使用 CRC，以更好地发现多位及连续突发错误；
- 服务器内存可使用 ECC，在一定范围内纠正单比特错误并报告更严重错误；
- 磁盘、SSD 和分布式存储会叠加校验和、纠删码或副本机制，处理介质错误与节点故障。

它们并不是把奇偶校验“淘汰”了，而是在风险更高、错误模式更复杂的地方，采用更多冗余位来获得更高保障。信息不会凭空增加；想知道得更多，就必须发送或保存更多校验信息。

## 九、做题与实现时的常见误区

### 1. 只数数据位，不数校验位

判断一个**已接收的码字**是否符合奇偶校验时，必须统计数据位和校验位的总和。校验位正是为了改变整体奇偶性而加入的；把它排除在外，检查自然失去意义。

### 2. 把“偶校验位”理解成校验位必须为 `0`

“偶”修饰的是**整个码字中 `1` 的个数**，不是校验位的取值。数据中已有奇数个 `1` 时，偶校验位恰好应为 `1`。

### 3. 认为奇偶校验只能检测一位错误

更准确的表述是：它保证检测任意单比特错误，并且实际上能检测任意奇数个比特错误；它无法保证检测偶数个比特错误。

### 4. 把校验失败等同于“数据位一定错了”

校验位本身也可能翻转。奇偶校验失败只能说明完整码字的传输或存储出现了奇数个错误，不能指出错误位置，更不能断定业务数据一定被改动。

### 5. 认为通过校验就一定没有错误

通过校验只能说明“收到的码字具有约定的奇偶性”。若发生了偶数位翻转，错误码字仍可能通过。因此校验通过不是绝对正确的证明，而是在该校验规则下未发现异常。

## 十、总结

奇偶校验码用 1 个额外比特记录一段数据中 `1` 的数量是奇数还是偶数。它的规则很简单，却已经完整展示了差错控制编码的基本交换：增加少量冗余，换取发现部分错误的能力。

- **偶校验**要求完整码字中 `1` 的个数为偶数；**奇校验**要求其为奇数。
- 发送端可用逐位异或生成校验位，接收端对完整码字再次异或即可检查。
- 每次比特翻转都会改变奇偶性，所以它能检测任意奇数个错误，尤其是所有单比特错误。
- 偶数个比特同时翻转可能保持原奇偶性，因此会漏检；它也不能定位或纠正错误。
- 若需要更强的保障，应根据场景选择汉明码、ECC、CRC、校验和或纠删码等机制。

理解奇偶校验最重要的不是背出“奇数补 0、偶数补 1”之类的局部规则，而是看清它只携带了一位关于整体的摘要信息。正因为信息量只有这么多，它能迅速发现某些异常，却不可能告诉我们全部真相；这并不神秘，只是代价与能力一一对应而已。
