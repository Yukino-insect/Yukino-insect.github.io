计算机刚启动时，操作系统并没有一张凭空出现的“所有文件位置表”，也没有从每个内存单元逐字节扫描出空闲空间。它依靠固件、启动加载器和持久化在磁盘上的文件系统元数据，逐步建立两套账本：一套描述磁盘上的分区、文件和空闲块，另一套描述物理内存中的页框、保留区和分配状态。

这篇文章先给出全景流程。后续文章再分别展开文件定位、磁盘空闲空间和页表创建。

## 二、启动链路中每一层知道什么

按下电源键后，CPU 从平台规定的入口开始执行固件代码。现代 PC 通常是 UEFI，较老的平台可能使用 BIOS。固件负责完成最初的硬件初始化，并把启动所需的信息交给启动加载器。

一个简化的启动链路如下：

```text
CPU 复位
  -> 固件（UEFI/BIOS）初始化硬件
  -> 选择启动设备和启动项
  -> 启动加载器读取内核镜像
  -> 加载器准备内存布局等启动参数
  -> 内核建立临时页表并进入自己的初始化代码
  -> 内核识别设备、读取文件系统元数据、挂载根文件系统
  -> 启动第一个用户空间进程
```

固件并不理解 Linux、Windows 或 macOS 的全部文件语义。它只需要知道如何找到一个可执行的启动程序。例如 UEFI 可以读取 EFI 系统分区中的文件；启动加载器再负责读取内核镜像和初始文件系统。

## 三、操作系统如何知道有哪些磁盘和内存

内核启动早期会枚举总线和设备，识别 SATA、NVMe、USB 等存储控制器，然后为每个控制器加载相应驱动。驱动把设备暴露成块设备：可以按逻辑块号读取或写入一段固定大小的数据。

磁盘本身不会把“这里是某个文件”作为电信号告诉内核。文件系统格式已经把这些信息写在磁盘的固定位置或可定位的元数据区域中，例如：

- 分区表描述每个分区从哪个逻辑块开始、长度是多少；
- 文件系统的超级块描述文件系统类型、块大小和关键元数据位置；
- 目录、索引节点、分配表或运行列表记录文件名与数据块之间的关系；
- 空闲空间位图或空闲块树记录哪些块可以再次分配。

因此，挂载文件系统本质上是：读取并校验这些元数据，把磁盘上的持久化结构转换成内核可以查询和更新的内存结构。

内存则不同。固件会通过 ACPI、UEFI 内存映射等接口告诉内核哪些物理地址范围是可用 RAM，哪些范围被固件、设备或保留区占用。内核据此建立早期页分配器，再切换到完整的物理页分配器。

## 四、文件位置和空闲空间是两本账

用户问“文件在哪里”和“哪里可以写入”，看起来像同一个问题，实际上对应两类元数据：

| 问题 | 主要数据结构 | 作用 |
| ---- | ------------ | ---- |
| 文件内容在哪里 | 目录项、inode/MFT、extent 或分配表 | 把文件名解析为文件对象，再定位数据块 |
| 哪些块可以使用 | 位图、空闲链表、空闲空间树 | 分配新文件或扩展文件时选择块 |

读取一个文件通常只需要查询前一类结构；创建或扩展文件时还要修改后一类结构。文件删除也不是简单地抹掉每个数据字节，而是更新目录、文件元数据和空闲空间记录，使这些块以后可以被重新分配。

## 五、页表不是物理内存的空闲表

内核为每个进程建立页表，回答的是“这个进程访问某个虚拟地址时，应映射到哪个物理页框，以及允许做什么”。它不是全局的空闲页清单。

全局物理内存状态由内核的页框元数据和分配器维护。分配器知道哪些页框保留给内核、哪些页框在空闲链表中、哪些页框属于页缓存或某个进程。页表只在分配成功后记录具体的虚拟页到物理页框映射。

所以启动时通常有两个相关但不同的过程：

1. 根据固件内存图，建立“哪些物理页可管理”的范围。
2. 为内核和进程建立页表，把需要访问的虚拟地址映射到这些页框。

关于页表层级、缺页和地址转换，可继续阅读[虚拟内存](虚拟内存.md)与[多级页表](多级页表.md)。

## 六、把整个问题串起来

一次典型的文件读取会穿过两套管理结构：

```text
路径字符串
  -> 目录索引找到文件元数据
  -> 文件元数据找到逻辑文件块
  -> 文件系统把逻辑块转换为设备逻辑块
  -> 块设备驱动发起 I/O
  -> 数据进入页缓存或用户缓冲区
  -> 进程通过虚拟地址访问这份数据
  -> MMU 根据页表把虚拟地址转换为物理地址
```

文件系统解决“磁盘上的内容如何组织”，内存管理解决“运行中的数据如何放进 RAM 并受到保护”。两者在页缓存、内存映射文件和交换空间等机制处发生联系，但不能把它们混成一张表。

## 七、总结

- 启动加载器负责把内核带入内存，内核随后接管设备和资源管理。
- 文件位置来自磁盘上持久化的文件系统元数据，而不是操作系统临时扫描出来的。
- 磁盘空闲空间由独立的分配结构记录，通常是位图、链表或树。
- 物理内存可用范围来自固件提供的内存映射；页框分配器再维护运行时状态。
- 页表负责虚拟地址翻译和权限控制，不负责充当全局空闲页总账本。
