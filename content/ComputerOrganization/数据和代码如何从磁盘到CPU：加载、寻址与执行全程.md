“代码应该执行，数据应该被操作”，这是编程语言中的正确区分；但在物理世界里，两者都是比特。磁盘、DRAM 和总线不会看着一串 `0100 1000` 就自动判断它是指令还是文本。**它在何处、由哪条 CPU 指令取用、页表给了什么权限，才决定了它在当前上下文中扮演代码还是数据。**

下面以现代采用虚拟内存的计算机为背景，沿着可执行文件和它读取的数据，走完“磁盘 → 主存 → CPU → 运算”的链路。不同 CPU 和操作系统的细节会不同，但层次关系基本相同。

## 一、代码和数据到底如何被区分

同一个字节序列可以有不同解释。`0x41` 可被当作字符 `A`、无符号整数 65，或者某条指令编码的一部分。硬件并没有一个给每个比特贴上“代码”或“数据”标签的通用开关。

实际上的区分来自几个层面：

| 层面 | 区分方式 |
| ---- | -------- |
| 文件格式 | ELF、PE、Mach-O 的段/节表标出代码段、只读数据段、可写数据段等 |
| 装载器与虚拟内存 | 将它们映射到不同虚拟页，并设置 `R/W/X` 权限 |
| CPU 访问路径 | 取指单元按 `PC` 读取指令；执行后的 load/store 指令按其有效地址读取或写入数据 |
| 编译器与 ABI | 规定哪些地址放函数、全局变量、栈、堆以及如何调用 |

例如典型进程会把 `.text` 映射为“可读、可执行、不可写”，把 `.data` 和堆映射为“可读、可写、不可执行”。CPU 的 MMU 检查权限：从不可执行页取指会触发保护异常，向只读代码页写入也会失败。NX/DEP、W^X（一个页尽量不要同时可写和可执行）正是用来缓解“把数据当代码执行”的安全风险。

这不是绝对物理隔离。某些运行时会生成机器码，先申请可写页写入字节，再改为可执行；调试器也可能修改代码页。关键仍是受操作系统与页权限控制的解释，而非字节天生的身份。

## 二、磁盘上：文件不是连续的“代码区”

程序文件首先是文件系统中的一个文件。以 SSD 为例，应用程序通常只看到文件偏移量；文件系统把文件偏移映射为文件系统块或 extent（连续逻辑块范围），块设备驱动再把它变成设备的 **LBA（Logical Block Address，逻辑块地址）** 请求。

```text
文件偏移
  -> 文件系统的文件块 / extent
  -> 块设备 LBA 范围
  -> SSD 控制器的闪存转换层 FTL
  -> NAND 闪存页（读取单位）/ 擦除块（擦除单位）
```

这里最容易混淆的是两套“块”：

- **文件系统块**：文件系统分配文件内容的单位，常见 4 KiB。
- **LBA 逻辑块**：主机对磁盘发起读写时使用的逻辑编号，常见扇区大小为 512 B 或 4 KiB。
- **NAND 页与擦除块**：SSD 内部真实介质单位。主机通常看不到某个 LBA 对应哪一页 NAND；FTL 会因磨损均衡、垃圾回收而调整映射。

若是 HDD，LBA 同样是主机看到的逻辑地址，但控制器再把它转换为盘片、磁道、扇区等物理位置。现代操作系统和程序一般操作 LBA，不直接指定“第几条磁道”。因此，“从磁盘哪个物理单元加载”最严谨的回答是：主机指定的是**逻辑块/LBA**；最终的物理介质位置由设备控制器决定。

## 三、程序启动：从可执行文件建立虚拟地址空间

用户双击程序或 shell 执行命令后，操作系统创建进程并读取可执行文件的头部。以 ELF/PE 为例，装载器关注的是**可装载段**，不是源代码文件中的函数名。

```text
可执行文件中的段              进程中的典型页权限
.text（机器指令）             R-X
.rodata（常量、字符串）       R--
.data（已初始化全局变量）     RW-
.bss（未初始化全局变量）      RW-，文件中通常不占实际内容
```

装载器不一定立刻把整个文件复制进 RAM。它更常做的是：为这些段建立虚拟内存区域（VMA），在页表中登记“某个虚拟页的后备来源是该文件的某个文件偏移”，并把入口地址设为初始 `PC`。栈、堆、动态链接器及共享库也会获得各自的虚拟区域。

这就是按需分页。刚启动的进程拥有看似完整的地址空间，但其中许多页尚未占用物理页框。

## 四、磁盘数据怎样真正进入主存：设备 DMA

假设 CPU 第一次取 `.text` 中某页指令，MMU 发现该虚拟页尚不存在，于是产生**缺页异常**。内核确认访问合法，找到该页对应的文件偏移和 LBA，随后把一次读请求交给 NVMe、SATA 或其他存储驱动。

读取的主角通常不是 CPU 一字节一字节搬运，而是 **DMA（Direct Memory Access）**：

1. 内核挑选一个空闲物理页框，或准备页缓存中的目标缓冲区。
2. 驱动在设备的提交队列中写入描述符，描述符含有 LBA、长度和目标缓冲区的 DMA 地址；NVMe 还会使用 PRP/SGL 等列表描述非连续内存。
3. 设备控制器从介质读取数据，通过 PCIe 等互连，直接 DMA 写入该物理页框。
4. 设备完成后以中断或轮询完成队列通知 CPU；内核核验结果、更新页缓存和页表，把该虚拟页标记为 present。
5. CPU 重新执行刚才因缺页而未完成的取指或 load 指令。

DMA 地址并不简单等于任意进程虚拟地址。设备需要可在总线上访问的地址；内核要确保缓冲区在 I/O 期间有效。若系统启用 IOMMU，DMA 地址还要经过 IOMMU 的映射和权限检查，既可让设备使用 I/O 虚拟地址，也避免设备任意写物理内存。

CPU 仍参与“发起、配置、完成处理和页表更新”，但大块数据传输由设备搬运。否则 CPU 会沦为一名非常昂贵的搬运工，这当然不合算。

## 五、页缓存、文件映射与普通读取

通过 `read()` 读取文件时，内核通常先检查**页缓存（page cache）**。命中则把缓存内容复制到用户缓冲区，或通过其他机制交付；未命中则对相应文件页发起设备 I/O，设备 DMA 到页缓存，再完成读取。

使用 `mmap()` 时，文件页可直接映射进进程虚拟地址空间。第一次访问仍可能缺页；但调入后，进程的该虚拟页就映射到页缓存中的物理页框。可执行文件的代码段也是同一思想的典型应用。多个进程执行同一个程序时，它们可共享同一批只读代码物理页，而各自的栈和可写数据页保持独立。

## 六、CPU 怎样得到代码和数据的地址

### 取指地址：PC

CPU 有一个**程序计数器**（PC；x86 常称 RIP）。它保存下一条待取指令的**虚拟地址**。取指单元使用该地址访问指令缓存：

```text
PC（虚拟地址）
 -> ITLB / 页表翻译
 -> 指令缓存 L1I
 -> 更低级缓存 L2/L3
 -> DRAM（必要时）
 -> 取指、译码
```

在现代 CPU 中，L1I 与 L1D 往往分离，因此“代码”和“数据”常进入不同一级缓存；L2/L3 可能统一。不过缓存保存的仍是普通字节，分离的是访问通路和性能设计，不是给字节施加本体论判决。

### 数据地址：指令的有效地址

数据地址不是由 PC 直接给出的，而是由已经译码的 load/store 指令计算出来。地址生成单元（AGU）常计算：

```text
有效虚拟地址 = 基址寄存器 + 变址寄存器 × 比例因子 + 位移
```

例如 C 语言的 `a[i]`，编译后大致会先取得数组基地址，再用 `i × 元素大小` 加上基址。全局变量可能用 PC 相对寻址；栈上局部变量常用栈指针或帧指针加偏移；堆对象的地址则来自寄存器里保存的指针。立即数、寄存器、重定位表和调用约定共同决定地址从哪里来。

## 七、从主存到 CPU：一次取指和一次读数据

CPU 执行的地址一般是虚拟地址。MMU 先查询 TLB：取指查 ITLB，数据访问查 DTLB（具体实现可以不同）。TLB 命中后，虚拟页号被转换为物理页框号，页内偏移原样保留；未命中则硬件页表遍历器或内核协助查页表。

物理地址随后被送往缓存层次：

```text
load 的有效虚拟地址
 -> DTLB
 -> L1D cache
 -> L2 / LLC
 -> 内存控制器
 -> DRAM bank、row、column
```

若 L1D 命中，缓存行（常见 64 B，取决于机器）被读出，目标字节再经选择与对齐后返回执行单元。若一路未命中，内存控制器向 DRAM 发出激活、读等命令，取回整条缓存行并填入缓存；这比寄存器运算慢得多。若目标虚拟页不在主存，才退回上一节所说的缺页与磁盘 I/O 路径。

## 八、进入 CPU 之后，代码和数据分别在哪里

不宜把 CPU 想成两只静止的盒子：一只装代码，一只装数据。以一个典型乱序处理器为例，数据与指令会流经不同但相互配合的结构。

| 对象 | 常见停留位置 | 后续处理 |
| ---- | ------------ | -------- |
| 指令字节 | L1I、取指缓冲、译码队列 | 被译码为操作；复杂 ISA 还会拆为微操作（uop） |
| 微操作 | uop 缓存/队列、重排序缓冲、调度器 | 等待操作数与执行资源，之后按架构语义提交 |
| 操作数数据 | 通用/浮点/向量寄存器、物理寄存器文件、load buffer | 送到整数 ALU、浮点单元、向量单元或地址生成单元 |
| 读取结果 | 物理寄存器、旁路网络、缓存行 | 供后续指令使用，最终在提交时成为可见状态 |
| 待写内存的数据 | store buffer | 在允许的时机写入 L1D，再按缓存一致性协议向外传播 |

译码器读出操作码、寄存器编号、寻址方式和立即数。寄存器重命名消除不必要的“同名寄存器”假依赖；调度器可以让已准备好的指令先执行；重排序缓冲保证异常和程序可见结果仍像按原程序顺序发生。于是，一条 `add` 的两个数据通常来自寄存器或旁路网络，进入 ALU 后产生结果；一条 `load` 则先由 AGU 求地址，再向缓存系统请求数据。

## 九、把全过程串起来

下面是一条“执行函数并读取数组元素”的压缩时间线：

```text
磁盘中的可执行文件
 -> 文件系统把文件偏移映射为逻辑块 / LBA
 -> 存储设备按描述符 DMA 到物理页框（缺页时）
 -> 内核建立或更新虚拟页 -> 物理页框的页表映射
 -> PC 给出函数指令的虚拟地址，取指单元经 ITLB、L1I 取得指令
 -> 译码器产生 load/add 等微操作
 -> AGU 用寄存器中的数组基址和下标算出数据虚拟地址
 -> DTLB、L1D（或更低层/DRAM）返回数组元素
 -> 执行单元运算，结果写入物理寄存器或 store buffer
```

## 十、总结

- 代码和数据在存储介质上都只是字节；文件格式、虚拟内存权限和 CPU 的访问方式赋予它们不同角色。
- 主机用文件偏移、文件块和 LBA 描述需要读取的内容；SSD/HDD 控制器才负责落到具体物理介质位置。
- 缺页时，内核配置设备，设备通常通过 DMA 将数据写进物理页框，随后内核更新页表。
- PC 提供取指地址；load/store 指令通过寄存器、位移等计算数据的有效地址。二者都先由 MMU/TLB 翻译，再经缓存和 DRAM 访问。
- 指令在取指、译码、微操作与调度结构中流动；数据在缓存、寄存器、执行单元及 store buffer 中流动。现代 CPU 的高性能来自让这些路径尽可能重叠，而不是让所有东西排队等候。
