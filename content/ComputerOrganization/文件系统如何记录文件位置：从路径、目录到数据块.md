当用户打开 `/home/alice/report.txt` 或 `D:\blog\README.md` 时，操作系统最终必须回答两个问题：这个名字对应哪个文件对象？文件对象的内容位于磁盘的哪些逻辑块？答案不在文件名本身，而在文件系统维护的多层元数据中。

## 一、路径不是磁盘地址

路径是给人和程序使用的命名方式。它由目录名和文件名组成，不能直接拿来驱动磁盘读写。

例如：

```text
/home/alice/report.txt
```

内核会从根目录开始逐级查找：

```text
根目录
  -> home 目录项
  -> alice 目录项
  -> report.txt 目录项
  -> 文件元数据对象
```

目录本身也是一种特殊文件。它的内容不是普通文本，而是一组“名称 -> 文件标识”的记录。不同文件系统对文件标识的称呼不同，Unix 风格文件系统常称为 inode 号，Windows NTFS 使用 MFT 记录等价地保存文件元数据。

## 二、文件元数据记录了什么

文件元数据通常至少包含：

- 文件类型：普通文件、目录、符号链接或设备文件；
- 权限、所有者、时间戳和链接计数；
- 文件逻辑长度；
- 文件内容对应的数据块或 extent；
- 用于校验、日志和扩展属性的其他信息。

可以把它简化成如下结构：

```text
文件标识  12345
类型      普通文件
长度      9000 字节
数据范围  [1000..1003], [8000..8001]
权限      rw-r--r--
```

这里的“数据范围”不一定是连续的。文件系统会根据磁盘上实际分配到的块，用多个范围描述文件内容，这种范围通常称为 extent。小文件也可能直接把少量数据放在文件元数据中，以减少额外寻址。

## 三、文件偏移如何变成磁盘块

程序读取文件时使用的是文件偏移，例如从第 8192 字节开始读取。文件系统需要先把这个偏移转换成文件内的逻辑块号，再查文件元数据得到设备上的物理逻辑块号。

假设块大小为 4096 字节：

```text
文件偏移 8192
  -> 文件内逻辑块号 2
  -> 查 extent 或分配表
  -> 设备逻辑块号 1002
  -> 读取该块
```

如果文件跨越多个 extent，转换过程会先定位包含该文件偏移的 extent，再计算块号。文件系统对外隐藏了这种碎片化，程序看到的仍是一串从 0 开始的连续字节。

## 四、不同文件系统的实现差异

不同文件系统的字段名称不同，但要解决的问题相同。

| 文件系统家族 | 文件元数据的典型形式 | 数据块定位方式 |
| ------------ | -------------------- | -------------- |
| ext4 等 Unix 文件系统 | inode | extent 树或间接块 |
| NTFS | MFT 记录 | 运行列表（data run） |
| FAT | 目录项与文件分配表 | FAT 链表 |
| APFS 等现代文件系统 | 文件记录与树结构 | extent、对象映射和写时复制 |

FAT 的分配表会把一个文件的块串成链；extent 则更适合表示连续范围，例如“从第 1000 块开始连续 64 块”。现代文件系统还常使用 B 树或其他索引结构，让目录和大文件查找不必线性扫描。

## 五、硬链接、符号链接和打开文件

文件名与文件对象不是一一对应的。

- **硬链接**：多个目录项指向同一个文件元数据对象，因此可以有多个名字；
- **符号链接**：目录项指向一个保存目标路径的特殊文件；
- **打开文件描述符**：进程打开文件后，内核保存一份打开状态，包括当前偏移、访问模式和引用的文件对象。

这解释了为什么文件重命名后，已经打开的程序仍然可以继续读写：进程持有的是文件对象的引用，而不是每次读操作都重新解析完整路径。

## 六、操作系统启动时如何使用这些信息

文件系统元数据通常分布在几个已知或可推导的位置。内核挂载分区时会：

1. 读取分区表，确定分区边界；
2. 读取超级块或等价的卷头，确认文件系统类型、块大小和版本；
3. 读取根目录所需的索引和元数据；
4. 建立内核中的缓存对象；
5. 必要时检查日志或恢复未完成的元数据更新。

之后，访问一个新路径时，内核通常先查目录项缓存和 inode 缓存，只有缓存未命中才向块设备发起读取。也就是说，操作系统不是每次查看文件都从磁盘开头重新扫描。

## 七、文件删除后数据去哪了

删除文件通常分成几步：从目录中移除名称，减少文件元数据的引用计数，并把不再被引用的数据块标记为空闲。若仍有进程打开该文件，数据块可能暂时不能回收；待最后一个引用关闭后，文件系统才真正释放它们。

因此，“目录里看不到文件”不等于“磁盘上的每个字节已经被清零”。删除主要是修改元数据和空闲空间记录，旧数据可能在被新文件覆盖前仍残留在块中。

## 八、总结

- 路径是命名，目录把名称映射到文件标识。
- inode、MFT 记录或类似结构保存文件长度、权限和数据块位置。
- 文件偏移先转换为文件内逻辑块，再转换为设备逻辑块。
- 文件可以是碎片化的，extent 或分配表对程序隐藏了这种细节。
- 挂载时读取并缓存文件系统元数据，后续查找通常依靠缓存和索引，而不是全盘扫描。
