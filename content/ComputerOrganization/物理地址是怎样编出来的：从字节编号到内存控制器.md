“计算机如何给内存编物理地址”可以拆成两层：第一层是**软件和 CPU 怎样给可访问的存储位置编号**；第二层是**硬件怎样让一个物理地址最终落到某根内存条、某个缓存行或某个设备寄存器**。把它们混成“每个内存颗粒里存着自己的地址”，就会走偏。地址是访问者放在请求中的编号，不是每个字节额外携带的身份证。

## 一、地址首先是一串用于选择位置的二进制位

现代通用机通常采用**字节编址**：每一个字节都有一个连续地址，访问 4 字节 `int` 或 8 字节 `long` 时，指令给出的是起始字节地址。

```text
物理地址    存放的一个字节
0x0000       0x48
0x0001       0x65
0x0002       0x6C
0x0003       0x6C
0x0004       0x6F
```

若从地址 `0x0000` 读取 4 个字节，得到怎样的整数还取决于字节序：小端机器会把 `0x48` 作为最低有效字节，大端机器则相反。**地址负责说明“从哪里取”；数据类型、访问宽度与字节序负责说明“怎样解释取到的字节”。**

历史上也存在按字编址的机器，或设备寄存器有自己的对齐限制，因此“一个地址永远等于一个字节”不是宇宙定律；但 x86、Arm、RISC-V 等常见通用平台都以字节为基本编址单位。

地址字段若有 `p` 位，理论上最多能区分 `2^p` 个字节位置。例如 32 位物理地址空间最多覆盖 `2^32 = 4 GiB` 个字节位置。CPU 的通用寄存器是 64 位，并不必然意味着实际物理地址也用了完整 64 位；处理器实现会规定可用的物理地址位数，未实现的高位不能任意使用。

## 二、物理地址空间不全是 RAM

从 CPU 视角，物理地址空间是一段编号范围。硬件会根据地址把请求路由到不同目标：

```text
CPU / 缓存
     │ 物理地址 + 读写请求
     ▼
互连 / 地址译码
 ├── 地址范围 A ──> DRAM（普通内存）
 ├── 地址范围 B ──> PCIe 设备的 MMIO 寄存器
 ├── 地址范围 C ──> 固件 ROM 或保留区域
 └── 地址范围 D ──> 可能没有任何响应的空洞
```

这就是为什么“物理地址”不必等于“某个真实 RAM 字节”。显卡、网卡、NVMe 控制器等设备可以把控制寄存器映射到某段物理地址，CPU 对该地址执行普通 load/store，硬件则把请求送到设备而非 DRAM。这叫**内存映射 I/O**（MMIO）。

开机时，固件与平台描述会向操作系统报告哪些物理范围可用、哪些被保留、哪些被设备占用。x86 平台常通过固件内存映射（如 E820/UEFI 信息）获得，其他平台可能通过设备树或 ACPI。操作系统据此建立物理内存地图，绝不会把 `0` 到最大地址的所有编号都当成可自由分配的 RAM。

## 三、DRAM 内部怎样从地址定位到真正的存储单元

当一个物理地址被路由到 DRAM，内存控制器会把地址位拆解成若干字段，大致选择：

```text
物理地址的一些位
   ↓ 地址映射 / 交织规则
通道 → DIMM / rank → bank → row → column → 字节位置
```

- **通道（channel）**：多通道内存可并行传输，提高带宽。
- **rank / bank**：内存条和 DRAM 芯片内部的可并行组织单元。
- **row / column**：DRAM 单元按行列组织；打开一行后再读取其中列。
- **突发传输与缓存行**：CPU 常一次移动一个缓存行（常见为 64 字节），并非每条 load 都只碰一个孤立字节。

具体哪几位表示 bank、行、列，甚至地址如何在不同通道间交织，是内存控制器和平台的实现策略；不同 CPU、内存代际和 BIOS 配置可能不同。它往往会有意把连续缓存行分散到多个通道或 bank，借此提高并行度。因此不要把“高位是行、低位是列”的简图当作所有机器永恒不变的接线图。

DRAM 本身也不会给每个单元存一份完整地址。地址译码电路接收地址信号，选择一条行、一列和对应的数据线；这和酒店房间不需要在房门里保存“我是 1208”才能被前台定位，是同一种编号与选择的关系。

## 四、操作系统怎样管理这些物理位置：以页框为单位

逐字节分配内存既昂贵又不利于地址翻译。操作系统通常把可用物理 RAM 分成固定大小的**物理页框**（page frame），常见基本页大小为 4 KiB。

若页大小为 4 KiB：

```text
4 KiB = 2^12 字节
物理地址 = 物理页框号 PFN × 2^12 + 页内偏移
```

也可以写成位拼接：

```text
物理地址
┌───────────────────────┬──────────────┐
│ 物理页框号（PFN）      │ 页内偏移 12 位 │
└───────────────────────┴──────────────┘
```

例如物理页框号为 `0x12345`，页内偏移为 `0x678`：

```text
物理地址 = 0x12345 × 0x1000 + 0x678 = 0x12345678
```

内核维护空闲页框、已分配页框、保留页框以及与文件缓存等用途关联的元数据。分配一块页内存，本质上是在可用 PFN 集合中找一页或连续页；内核分配器再可在页内切分出更小对象。NUMA 机器还会记录页属于哪个内存节点，尽量让 CPU 使用本地内存，减少跨节点访问延迟。

## 五、程序地址如何到达物理地址

应用程序通常不给物理地址编号，也不直接看到它。它产生的是**虚拟地址**，CPU 中的 MMU 使用当前页表把虚拟页号转换为物理页框号，页内偏移保持不变：

```text
虚拟地址
┌───────────────────┬──────────────┐
│ 虚拟页号 VPN       │ 页内偏移 12 位 │
└───────────────────┴──────────────┘
            │ 页表 / TLB 查询
            ▼
物理地址
┌───────────────────┬──────────────┐
│ 物理页框号 PFN     │ 同一个偏移 12 位 │
└───────────────────┴──────────────┘
```

例如虚拟地址 `0x0000000040123456` 的低 12 位是 `0x456`。若页表把它所在的虚拟页映射到物理页框 `0x1ABCD`，最终物理地址就是：

```text
0x1ABCD000 + 0x456 = 0x1ABCD456
```

页表项除了 PFN 还包含有效位、读写执行权限、用户/内核权限、访问位、脏位等。若映射不存在或权限不允许，MMU 触发异常，内核决定这是合法的按需分配/缺页，还是应终止进程的非法访问。正是这条机制让多个进程可以各自使用虚拟地址 `0x400000`，却对应不同物理页，彼此隔离。

“物理地址 = 页框基址 + 偏移”是在分页层的表达，并不否认内存控制器随后还会把该地址分解为通道、bank、行和列。前者回答操作系统如何管理 RAM；后者回答硬件如何驱动 DRAM。

## 六、缓存、DMA 与 IOMMU

CPU 发出的物理地址通常先查询缓存。若命中 L1/L2/L3 缓存，数据根本不需要访问 DRAM；只有未命中时才经互连和内存控制器到达内存条。因此“物理地址”是 CPU 内存层次使用的全局坐标，不是“肯定会立刻点亮某个 DRAM 单元”的同义词。

外设通过 DMA 直接读写内存时，也需要可用的地址。现代系统常由 **IOMMU** 为设备再做一层 DMA 地址转换与隔离，防止设备任意读写所有 RAM。它的思想与 CPU 的 MMU 类似，但服务对象是 I/O 设备。是否存在、如何配置则取决于平台和操作系统。

## 七、常见误解与总结

1. **物理地址不等于内存条上的顺序标签。** 内存控制器可交织、重排地址位；连续物理地址未必落在同一颗 DRAM 芯片的连续位置。
2. **虚拟地址不是物理地址的“别名”。** 它需要页表翻译，且不同进程同一虚拟地址可映射不同页框。
3. **物理地址空间不全是 RAM。** MMIO、固件、保留洞和不存在的范围都可能占据地址空间。
4. **地址不是数据的一部分。** 一个字节不会自带“我的地址”；地址来自发起访问的 CPU/设备请求和地址译码。

常见机器以字节地址组织物理地址空间，操作系统以物理页框管理其中可用的 RAM，MMU 负责把虚拟地址翻译为页框加页内偏移；随后缓存和内存控制器才决定数据究竟从哪里返回。这个分层过程看起来多了一些手续，但正是它让隔离、共享、设备访问和高带宽内存能够同时成立。
