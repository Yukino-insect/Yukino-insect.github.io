“CPU 如何确认物理内存或磁盘上的物理地址？”这个问法里混进了三种不同的“地址”。先把结论说在前面：

> CPU 并不会先查询“`0x12345678` 属于哪根内存条”的名册。它在一次读写请求中送出一串地址位；互连和内存控制器用预先设计好的译码规则解释这些位，并把请求送到对应硬件。磁盘则是另一套体系：CPU/驱动通常提交**逻辑块号**（LBA）给磁盘控制器，控制器才决定数据实际位于哪个扇区或 NAND 闪存页。

这和寄存器编号的原理其实很接近。假设一条简化指令写着 `add r1, r2, r3`：指令中的 `001`、`010`、`011` 是几个比特，CPU 的**寄存器译码器**据此接通寄存器组中的第 1、2、3 个端口。内存访问中，地址值也是一串比特；只是它通常不是固定写在指令里的一个小编号，而是由寄存器、立即数和页表翻译计算出来，之后交给更大范围的地址译码网络。没有哪一个内存字节需要保存“我叫 `0x12345678`”的标签。

## 一、一次内存读写中，CPU 实际做了什么

以类似 `load r1, [r2 + 8]` 的指令为例。这里的写法只用来说明过程，各种 ISA 的具体语法不同。

1. CPU 从指令中译出：源寄存器编号为 `r2`、位移为 `8`、目标寄存器编号为 `r1`。这一步正是“通过寄存器编号确认寄存器”。
2. 寄存器组的译码器读出 `r2` 的**内容**。若其中是 `0x0000_0000_4012_3000`，地址生成单元把它加上 `8`，得到虚拟地址 `0x0000_0000_4012_3008`。
3. MMU/TLB 用当前进程的页表把虚拟页翻译为物理页框。例如，虚拟页映射到物理页框 `0x1ABCD`，于是得到物理地址 `0x1ABCD008`。在未启用分页的早期启动代码或某些简单系统中，这一步可以是恒等映射或不存在。
4. CPU 把“读还是写、数据大小、物理地址、写数据（如果有）”作为请求送入缓存/片上互连。缓存命中就直接返回数据；未命中时，请求才抵达内存控制器。
5. 内存控制器按自己的地址映射把 `0x1ABCD008` 的若干位分给通道、rank、bank、行和列，发出 DRAM 命令，最后把读出的字节返回给 CPU。

```text
指令中的寄存器编号         寄存器内容 + 位移
        │                         │
        ▼                         ▼
寄存器译码器 ──────────> 地址生成单元 ──> 虚拟地址
                                             │
                                      MMU / TLB / 页表
                                             ▼
                                        物理地址请求
                                             │
                             缓存命中 ───────┼───────> 返回数据
                                             │ 缓存未命中
                                             ▼
                                    内存控制器地址译码
                                             ▼
                                  DRAM 的通道 / bank / 行 / 列
```

所以要特别区分：**寄存器编号是“选哪个寄存器”的编码；寄存器内容可能恰好是“地址这个数值”。** CPU 用前者读出后者，随后用后者发起内存访问。把两者都叫“地址”只会让问题越说越糊涂——虽然这倒是相当常见。

## 二、地址首先是一串用于选择位置的二进制位

现代通用机通常采用**字节编址**：每一个字节都有一个连续地址，访问 4 字节 `int` 或 8 字节 `long` 时，指令给出的是起始字节地址。

```text
物理地址    存放的一个字节
0x0000       0x48
0x0001       0x65
0x0002       0x6C
0x0003       0x6C
0x0004       0x6F
```

若从地址 `0x0000` 读取 4 个字节，得到怎样的整数还取决于字节序：小端机器会把 `0x48` 作为最低有效字节，大端机器则相反。**地址负责说明“从哪里取”；数据类型、访问宽度与字节序负责说明“怎样解释取到的字节”。**

历史上也存在按字编址的机器，或设备寄存器有自己的对齐限制，因此“一个地址永远等于一个字节”不是宇宙定律；但 x86、Arm、RISC-V 等常见通用平台都以字节为基本编址单位。

地址字段若有 `p` 位，理论上最多能区分 `2^p` 个字节位置。例如 32 位物理地址空间最多覆盖 `2^32 = 4 GiB` 个字节位置。CPU 的通用寄存器是 64 位，并不必然意味着实际物理地址也用了完整 64 位；处理器实现会规定可用的物理地址位数，未实现的高位不能任意使用。

## 三、物理地址空间不全是 RAM

从 CPU 视角，物理地址空间是一段编号范围。硬件会根据地址把请求路由到不同目标：

```text
CPU / 缓存
     │ 物理地址 + 读写请求
     ▼
互连 / 地址译码
 ├── 地址范围 A ──> DRAM（普通内存）
 ├── 地址范围 B ──> PCIe 设备的 MMIO 寄存器
 ├── 地址范围 C ──> 固件 ROM 或保留区域
 └── 地址范围 D ──> 可能没有任何响应的空洞
```

这就是为什么“物理地址”不必等于“某个真实 RAM 字节”。显卡、网卡、NVMe 控制器等设备可以把控制寄存器映射到某段物理地址，CPU 对该地址执行普通 load/store，硬件则把请求送到设备而非 DRAM。这叫**内存映射 I/O**（MMIO）。

开机时，固件与平台描述会向操作系统报告哪些物理范围可用、哪些被保留、哪些被设备占用。x86 平台常通过固件内存映射（如 E820/UEFI 信息）获得，其他平台可能通过设备树或 ACPI。操作系统据此建立物理内存地图，绝不会把 `0` 到最大地址的所有编号都当成可自由分配的 RAM。

## 四、从物理地址到 DRAM 芯片：硬件究竟怎样接线

这一节才是问题的落点。前面说“地址译码”并不等于解释完成；必须知道谁在译码、译码结果变成了什么电信号、DRAM 又怎样响应该信号。

### 1. 内存控制器是把编号变成电信号的硬件

在现代 PC 和服务器中，内存控制器通常集成在 CPU 封装内（或 SoC 内），而不再是早期主板北桥中的独立芯片。CPU 核心提交的物理地址请求经片上互连到它；控制器中有组合逻辑、寄存器和调度器，至少完成三件事：

1. **地址译码**：根据机器启动时建立的内存配置，把物理地址划分为通道、rank、bank、行、列和突发内偏移。
2. **命令调度**：考虑哪个 bank 已打开哪一行、何时满足 DRAM 的时序限制，决定先发激活、读、写还是预充电命令。
3. **信号驱动**：在选定内存通道的实际引脚上驱动时钟、命令/地址信号，并在数据线（DQ）上收发数据。

所以“物理地址”在 CPU 一侧是一串比特；到内存控制器出口，它已被翻译成“使用通道 1、选中 rank 0、对 bank 3 激活行 R、再从列 C 读取”的一连串硬件动作。CPU 核心不需要知道某根 PCB 走线通向哪颗芯片；这是内存控制器及主板布线的职责。

```text
CPU 核心 / 最后一级缓存未命中
             │ 物理地址 PA + 读写请求
             ▼
      CPU 内的内存控制器（IMC）
             │ 译码、排队、时序调度
      ┌──────┼───────────────────────┐
      │      │                       │
      ▼      ▼                       ▼
通道 0 的引脚  通道 1 的引脚       ……
      │      │
      ▼      ▼
DIMM 插槽 / 内存条上的走线
      │
      ▼
被选中 rank 中的多个 DRAM 芯片
      │
      ▼
bank → 行译码器与行缓冲 → 列选择器 → DQ 数据线
```

一条 DIMM（通常所说的内存条）不是一个能保存全部数据的“大芯片”，而是一块 PCB，上面焊着多颗 DRAM 芯片、SPD 配置 EEPROM，以及可能存在的寄存器/缓冲器。主板把每个内存通道的信号线接到相应 DIMM 插槽；控制器选择通道，本质上就是从相应那组物理引脚发送信号。

### 2. DIMM、rank 与 DRAM 芯片分别被怎样选中

同一通道上的 DIMM 和 DRAM 芯片会共享相当一部分命令/地址线，但控制器会用 **chip select（CS）** 等选择信号指定一个 rank。一个 rank 是一组一起响应命令、共同提供一个内存数据宽度的 DRAM 芯片；例如常见的非 ECC、64 位数据通道可能由 8 颗各提供 8 位数据的 x8 芯片组成。这个例子只是常见组织方式，不是尺寸和芯片数的规定；x4、x16 芯片、ECC 额外数据位、多 rank DIMM 都会改变组合。

被选中的 rank 中，多颗芯片并不是各自保存一份相同数据。它们同时收到相同的命令、bank、行、列信息，各自只在 DQ 数据总线上提供自己负责的那几位；控制器把这些位拼成一个 64 位（或带 ECC 的更宽）数据传输。因此，物理地址的“字节位置”有时还隐含在一次突发传输的偏移及不同芯片的数据位中，不能把它想成地址只挑中一颗芯片里的一个孤立字节。

```text
内存控制器发给某个通道
  命令 / 地址线：ACT、READ、WRITE、bank、row、column 等信息
  rank 选择线：  CS 选中 rank 0 或 rank 1
  数据线：       DQ[63:0]（以 64 位非 ECC 通道为例）

rank 0 内的 x8 DRAM 芯片
  芯片 0  ──> DQ[7:0]
  芯片 1  ──> DQ[15:8]
  …
  芯片 7  ──> DQ[63:56]
```

实际 DDR 代际的引脚和命令编码会不同：有的把激活作为专门命令，有的增加 bank group，有的把一个 DIMM 通道再拆成更窄的子通道。共同点没有变：**内存控制器译出字段，借由实际的选择线和命令/地址线让正确的芯片响应。**

### 3. 一颗 DRAM 芯片内部怎样选中一个存储单元

DRAM 单元大致是“一个晶体管加一个电容”。电容是否带电代表 0 或 1，但电荷会泄漏，因此需要周期性刷新。芯片内部把大量单元排成二维阵列，并有以下硬件：

- **bank**：相对独立的阵列/行缓冲资源，多个 bank 可以交错工作。
- **行译码器（row decoder）**：接收行号，驱动对应的一根字线（wordline）。该行全部单元的电容与位线相连。
- **感测放大器 / 行缓冲（sense amplifier / row buffer）**：感测极微弱的电荷差，放大为稳定 0/1；这个过程也把数据写回单元，所以读 DRAM 行不是简单地“无损观察”电容。
- **列译码器与列多路复用器**：接收列号，从已经打开并留在行缓冲中的一整行里接出需要的列到 I/O 电路。

因此一次典型读取不是把完整物理地址平行送进 DRAM 芯片：

```text
1. 控制器对选定 rank/bank 发 ACT（activate）+ 行号 R
   └─ 芯片的行译码器接通第 R 根字线；整行进入该 bank 的行缓冲。

2. 控制器在满足时序后发 READ + 列号 C
   └─ 芯片的列选择器从行缓冲取出列 C 附近的数据，按 DDR 突发传输到 DQ 线。

3. 必要时控制器发 PRE（precharge）
   └─ 关闭当前行，使该 bank 能激活另一行。
```

这也解释了“行命中”为何更快：若同一个 bank 的行 R 已在行缓冲中，控制器不必再发 ACT，只需要合适的 READ/WRITE。反过来，访问另一行需要先关闭或切换已打开的行，这就是常说的 row conflict。它不是抽象软件概念，而是行缓冲与位线确实存在的物理成本。

### 4. 物理地址的位到底怎样变成这些选择信号

不存在一张所有电脑通用的“第 17 位永远是 bank、第 28 位永远是行”的表。内存控制器按 CPU 型号、DDR 代际、安装的 DIMM/rank 数、通道配置和固件设置建立地址映射。一部分低位对应字节和突发内偏移；其余位会被控制器分配给列、bank、行、rank 和通道。控制器还常把某些位异或后作为 bank/channel 选择，以便连续缓存行分散到不同资源，提高带宽。

下面仅是一个**虚构的示意映射**，目的是展示“位被拿去驱动什么”，不是可以拿去反推你电脑地址的规则：

```text
物理地址 PA 的部分位
┌──────────────┬─────────┬────────┬────────┬────────┬──────────────┐
│ 高位          │ row     │ channel│ rank   │ bank   │ column / burst│
└──────────────┴─────────┴────────┴────────┴────────┴──────────────┘
                                │         │        │          │
                                │         │        │          └─> READ/WRITE 的列字段
                                │         │        └─> DRAM 的 bank 选择字段
                                │         └─> 控制器输出对应 rank 的 CS
                                └─> 控制器使用对应通道的一组引脚
                                           row ─────> ACT 命令中的行字段
```

这里的关键不是某一位的编号，而是映射**从机器上电并识别内存拓扑后就固定为硬件规则**。例如某个请求的 `channel` 字段为 1，控制器便把命令送到通道 1 的导线；`rank` 字段为 0，便断言 rank 0 的 CS；`bank`、`row`、`column` 字段则分别进入 DRAM 命令。于是所谓“确定物理地址”，在硬件层面就是这些译码器和导线把一个二进制数确定地变成唯一的一组选择与命令信号。

## 五、操作系统怎样管理这些物理位置：以页框为单位

逐字节分配内存既昂贵又不利于地址翻译。操作系统通常把可用物理 RAM 分成固定大小的**物理页框**（page frame），常见基本页大小为 4 KiB。

若页大小为 4 KiB：

```text
4 KiB = 2^12 字节
物理地址 = 物理页框号 PFN × 2^12 + 页内偏移
```

也可以写成位拼接：

```text
物理地址
┌───────────────────────┬──────────────┐
│ 物理页框号（PFN）      │ 页内偏移 12 位 │
└───────────────────────┴──────────────┘
```

例如物理页框号为 `0x12345`，页内偏移为 `0x678`：

```text
物理地址 = 0x12345 × 0x1000 + 0x678 = 0x12345678
```

内核维护空闲页框、已分配页框、保留页框以及与文件缓存等用途关联的元数据。分配一块页内存，本质上是在可用 PFN 集合中找一页或连续页；内核分配器再可在页内切分出更小对象。NUMA 机器还会记录页属于哪个内存节点，尽量让 CPU 使用本地内存，减少跨节点访问延迟。

## 六、程序地址如何到达物理地址

应用程序通常不给物理地址编号，也不直接看到它。它产生的是**虚拟地址**，CPU 中的 MMU 使用当前页表把虚拟页号转换为物理页框号，页内偏移保持不变：

```text
虚拟地址
┌───────────────────┬──────────────┐
│ 虚拟页号 VPN       │ 页内偏移 12 位 │
└───────────────────┴──────────────┘
            │ 页表 / TLB 查询
            ▼
物理地址
┌───────────────────┬──────────────┐
│ 物理页框号 PFN     │ 同一个偏移 12 位 │
└───────────────────┴──────────────┘
```

例如虚拟地址 `0x0000000040123456` 的低 12 位是 `0x456`。若页表把它所在的虚拟页映射到物理页框 `0x1ABCD`，最终物理地址就是：

```text
0x1ABCD000 + 0x456 = 0x1ABCD456
```

页表项除了 PFN 还包含有效位、读写执行权限、用户/内核权限、访问位、脏位等。若映射不存在或权限不允许，MMU 触发异常，内核决定这是合法的按需分配/缺页，还是应终止进程的非法访问。正是这条机制让多个进程可以各自使用虚拟地址 `0x400000`，却对应不同物理页，彼此隔离。

“物理地址 = 页框基址 + 偏移”是在分页层的表达，并不否认内存控制器随后还会把该地址分解为通道、bank、行和列。前者回答操作系统如何管理 RAM；后者回答硬件如何驱动 DRAM。

## 七、磁盘没有可由 CPU 直接使用的“物理字节地址”

内存是**字节可寻址**的：一条 CPU load/store 可以针对物理地址 `0x1ABCD008` 读写一个或几个字节。磁盘不是这样。CPU 不能执行一条类似 `load r1, [disk:0x1ABCD008]` 的指令，然后让某个盘片位置自行出现；这既不符合 I/O 总线协议，也会把毫秒级磁盘操作荒唐地塞进纳秒级的指令执行模型。

操作系统中的正常磁盘读写链路大致如下：

```text
应用：读文件的第 N 个字节
  ↓ 文件系统：文件偏移 → 文件的逻辑块
  ↓ 块层：逻辑块 → 设备的 LBA（Logical Block Address）
  ↓ 驱动：把“读/写、LBA、长度、内存缓冲区地址”提交给控制器
  ↓ SATA / NVMe 等控制器：执行 I/O
  ↓ 介质内部映射：LBA → 实际介质位置
```

这里的 **LBA 是设备对主机承诺的连续块编号**，块通常是 512 字节或 4 KiB；它不是 CPU 物理地址空间的一部分。驱动会通过 MMIO 寄存器或内存中的命令队列告诉控制器请求参数。设备完成后，通常使用 DMA 把数据写入主内存中驱动提供的缓冲区；若启用了 IOMMU，设备使用的 DMA 地址还可能先经过 IOMMU 翻译。

“实际介质位置”也取决于设备类型：

- **HDD**：早期接口曾向主机暴露柱面/磁头/扇区（CHS），但现代主机几乎总使用 LBA。磁盘固件处理 LBA 到盘片物理扇区的映射、坏扇区替换和磁道布局；外圈和内圈的扇区布局也未必相同。
- **SSD**：LBA 与 NAND 闪存物理页之间的对应关系由 SSD 的 FTL（Flash Translation Layer）维护。垃圾回收、磨损均衡和坏块处理会让同一 LBA 在不同时间落到不同 NAND 页。因此主机看见的是稳定的逻辑编号，所谓“某个数据的固定物理地址”往往根本不存在。

NVMe 控制器的寄存器确实会映射在 CPU 物理地址空间的一小段 MMIO 范围内，但那只是“如何向控制器下命令”的地址；它绝不是整块 SSD 内容在 CPU 地址空间中的映射。把这两种地址混为一谈，是此处最容易出现、也最没有必要的误会。

## 八、缓存、DMA 与 IOMMU

CPU 发出的物理地址通常先查询缓存。若命中 L1/L2/L3 缓存，数据根本不需要访问 DRAM；只有未命中时才经互连和内存控制器到达内存条。因此“物理地址”是 CPU 内存层次使用的全局坐标，不是“肯定会立刻点亮某个 DRAM 单元”的同义词。

外设通过 DMA 直接读写内存时，也需要可用的地址。现代系统常由 **IOMMU** 为设备再做一层 DMA 地址转换与隔离，防止设备任意读写所有 RAM。它的思想与 CPU 的 MMU 类似，但服务对象是 I/O 设备。是否存在、如何配置则取决于平台和操作系统。

## 九、常见误解与总结

1. **物理地址不等于内存条上的顺序标签。** 内存控制器可交织、重排地址位；连续物理地址未必落在同一颗 DRAM 芯片的连续位置。
2. **寄存器编号不等于寄存器保存的数值。** 指令以编号选中寄存器；被读出的数值才可能参与形成地址。
3. **虚拟地址不是物理地址的“别名”。** 它需要页表翻译，且不同进程同一虚拟地址可映射不同页框。
4. **物理地址空间不全是 RAM。** MMIO、固件、保留洞和不存在的范围都可能占据地址空间。
5. **磁盘 LBA 不是内存物理地址。** LBA 是主机与存储设备之间的逻辑块编号，设备内部的位置映射由控制器管理。
6. **地址不是数据的一部分。** 一个字节不会自带“我的地址”；地址来自发起访问的 CPU/设备请求和地址译码。

若只记住一句话，应当是：**CPU 不是“查出”内存或磁盘地址，而是生成一个地址/块号并发送请求；接收请求的硬件按各自的译码或映射规则完成定位。** 对内存，这个编号最终经内存控制器变成 DRAM 的行列选择；对磁盘，CPU 交给控制器的是 LBA，控制器再自行定位介质。两者都不是存储单元携带地址标签，只是内存的访问粒度和延迟使它看起来更像 CPU 指令的一部分而已。
