## 一、页表由谁创建

页表不是 RAM 芯片自带的硬件表格，而是操作系统放在内存中的数据结构。CPU 中的 MMU 只会按照当前页表根指针遍历这些结构。

在 RISC-V、ARM64、x86-64 等架构中，都有一个控制寄存器或寄存器组保存当前地址空间的页表根。切换进程时，内核切换这个根指针，并根据架构要求刷新或隔离 TLB。

## 二、启动早期的临时页表

CPU 复位后，系统可能先以物理地址或非常有限的映射运行。内核镜像被加载后，启动代码通常会创建一套临时页表，至少映射：

- 内核当前执行的代码和数据；
- 启动栈；
- 访问设备所需的内存映射区域；
- 过渡阶段需要的固件或引导信息。

启用这套页表后，内核可以在稳定的虚拟地址布局中继续初始化。随后它会获得更完整的内存布局和设备信息，创建正式的内核页表，并切换过去。

## 三、内核如何知道哪些物理内存可用

固件或启动加载器会提供物理内存映射，标明可用 RAM、固件保留区、ACPI 数据、设备内存和其他不可分配区域。内核先排除自身镜像、启动参数、初始内存盘和设备映射占用的范围，再把剩余 RAM 切分成固定大小的物理页框。

这一步形成的是物理内存管理器的初始账本，而不是某个进程的页表：

```text
固件内存图
  -> 排除内核、设备和保留区
  -> 生成可管理物理页框集合
  -> 初始化页框元数据与空闲分配器
```

关于页框状态、引用计数和共享映射，可阅读[物理内存如何知道哪些页被占用：页表、页框分配器与共享映射](物理内存如何知道哪些页被占用：页表、页框分配器与共享映射.md)。

## 四、内核页表和进程页表的区别

内核页表描述内核需要访问的虚拟地址布局；进程页表则描述一个用户进程的代码、数据、堆、栈和共享库等区域。许多系统会让每个进程的页表包含一部分内核映射，以便系统调用和中断处理能够快速进入内核；也有系统采用更严格的内核页表隔离。

无论采用哪种设计，页表都不是一次性填满的数组。现代系统使用多级页表，只为实际使用的虚拟地址范围分配中间层级，从而避免为巨大的空洞地址空间浪费内存。

## 五、进程创建时如何建立页表

当内核创建一个新进程时，通常会：

1. 分配进程控制块和新的地址空间描述对象；
2. 分配页表根以及需要的中间页表页；
3. 映射程序的代码、只读数据和数据段；
4. 建立用户栈、堆和共享库的虚拟地址范围；
5. 根据策略预先映射少量页面，其余页面采用按需分页；
6. 设置读、写、执行和用户/内核权限位；
7. 在线程第一次运行前，把页表根装入 CPU 的地址空间寄存器。

加载可执行文件时，内核通常不会把整个文件一次性复制到连续物理内存。它会记录某些虚拟页与可执行文件的偏移关系，等页面第一次被访问时，再从文件读取并建立映射。

## 六、第一次访问时才分配物理页

以匿名堆内存为例，`malloc` 或内存映射可能先只扩大合法虚拟地址范围，并没有立即分配每个物理页框。进程第一次写入某个页面时：

```text
访问虚拟地址
  -> 页表项不存在或不可写
  -> CPU 触发缺页异常
  -> 内核检查地址和权限
  -> 物理页分配器取出空闲页框
  -> 清零页面并写入页表项
  -> 刷新必要的 TLB 项
  -> 重新执行原指令
```

如果访问的是文件映射，内核会从文件或页缓存取得内容；如果是交换出去的匿名页，则从交换空间调入；如果地址不属于任何合法区域，则向进程报告访问错误。

## 七、页表怎样参与回收

物理页回收时，内核不能只把页框标为空闲。它必须先撤销所有指向该页框的页表项，处理共享映射和引用计数，并让处理器丢弃可能缓存的旧 TLB 映射。否则，进程可能继续通过旧虚拟地址访问已经分配给别人的页面。

这说明页表和物理页分配器是协作关系：分配器决定“给谁一个物理页框”，页表记录“这个进程通过哪个虚拟页使用它”。任何一方单独工作都无法保证内存安全。

## 八、页表本身也占用内存

页表页也是物理内存中的普通页框，只是用途特殊。创建大量进程、映射大量稀疏地址或频繁建立销毁映射时，页表本身会消耗可观的 RAM。内核需要把页表页纳入物理页元数据管理，并在地址空间销毁时回收它们。

## 九、总结

- 启动代码先建立临时页表，内核初始化后再切换到正式内核页表。
- 固件内存图决定哪些物理范围可管理，页框分配器负责运行时空闲和占用状态。
- 创建进程时建立页表结构，但很多物理页面采用按需分配。
- 页表记录虚拟页到物理页框的映射、存在位和权限，不是全局空闲页表。
- 回收页框前必须撤销页表映射并处理 TLB，否则会破坏隔离和安全。
