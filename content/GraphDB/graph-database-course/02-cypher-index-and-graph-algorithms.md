上一章建立了很小的社区图。本章先把 Cypher 的查询形状讲清楚，再讨论为什么“能查到”不代表“查得动”。开始前确认 Neo4j 容器仍在运行，并已写入上一章数据。

## Cypher 的三个基本动作

**模式匹配（pattern matching）**是声明你要寻找的节点和关系形状；`MATCH` 要求必须匹配，`OPTIONAL MATCH` 则在没有连接时保留左侧结果并返回空值。**过滤（filtering）**用 `WHERE` 约束属性、标签或关系条件。**投影（projection）**用 `RETURN` 选择字段、聚合和排序。

```cypher
MATCH (p:Person)-[:JOINED]->(c:Club)
WHERE c.name CONTAINS '会'
RETURN p.name AS person, c.name AS club
ORDER BY person;
```

预期得到每位成员和小组的两列结果。`WHERE` 中的属性过滤应尽量和起点一起使用；先匹配全图再过滤，通常会白白扩大中间结果。

## 路径查询：必须写出边界

**可变长度路径**写作 `[:FOLLOWS*1..3]`，意思是沿 `FOLLOWS` 走一到三跳。它很符合“朋友的朋友”这类问题，却也会随着分支数和跳数急速膨胀。用上章数据执行：

```cypher
MATCH path = (:Person {id: 'p-001'})-[:FOLLOWS*1..3]->(other:Person)
RETURN other.name, length(path) AS hops;
```

预期只返回小林和一跳。生产查询应同时具备：明确的起点、关系类型、最大跳数和必要的标签。不要写无上限的 `[*]`；在有环且分支多的图中，它可能消耗大量内存和时间。

如果你只需“是否存在一条路径”，不必返回整条路径；如果需要最短路径，可考虑 `shortestPath`，但同样要限制关系类型和范围。

## 先读计划，再谈优化

`EXPLAIN` 只显示计划，不执行；`PROFILE` 会执行并显示每个算子的实际行数、数据库命中和耗时。先运行：

```cypher
PROFILE
MATCH (p:Person {id: 'p-001'})-[:JOINED]->(c:Club)
RETURN c.name;
```

预期计划从按 `Person.id` 的索引查找开始，随后展开关系。若你删除上一章的约束，计划可能改为标签扫描；小数据看不出差异，大数据会明显变慢。优化前先回答三个问题：起点是否足够小？扩展了多少关系？最终返回前是否已经过滤？

## 约束和索引分别解决什么

**约束**保护数据规则，例如“人员 ID 唯一”；它是正确性工具。**索引**加速按属性定位的查找；它是性能工具。Neo4j 的唯一约束通常会建立支撑索引，但不要因此以为每个查询都会更快：沿关系扩展的成本仍由图形结构决定。

为常按名称检索的小组创建普通索引：

```cypher
CREATE INDEX club_name IF NOT EXISTS
FOR (c:Club) ON (c.name);

SHOW INDEXES;
```

预期可看到索引从创建中变为在线。常见错误是为每个属性盲目建索引；索引会占空间并拖慢写入。应依据真实查询入口和 `PROFILE` 决定。

## 聚合与去重：不要把中间行数带到最后

同一个人经多条路径被发现时，结果会重复。`DISTINCT` 去除重复行，`collect(DISTINCT x)` 收集去重列表：

```cypher
MATCH (:Person {id: 'p-001'})-[:FOLLOWS*1..2]->(p)-[:JOINED]->(c)
RETURN p.name, collect(DISTINCT c.name) AS clubs;
```

预期每个人只有一行。注意 `DISTINCT` 也要计算成本；优先缩小路径和起点，不能把它当作无条件的“性能按钮”。

## 图算法：先明确指标，再选择算法

图算法不是神奇推荐器。它把某个数学定义应用到一张明确的图投影上。**图投影（projection）**是从数据库中选出参与算法的节点、关系和属性后得到的内存图；它避免算法无意读取不相关数据。

常见例子：

- **PageRank**：连接重要性递归传递，可用于影响力或依赖关键度的候选排序；
- **最短路径 / Dijkstra**：寻找权重最小的路线，权重必须有业务含义；
- **社区发现**：按连接密度分组，适合探索，不自动等于真实组织；
- **中心性**：衡量节点位于路径或连接中心的程度，不能直接当作风险结论。

如果安装了 Neo4j Graph Data Science（GDS）库，可先列出可用过程：

```cypher
CALL gds.list() YIELD name
RETURN name
LIMIT 10;
```

预期返回过程列表；若报“procedure not found”，说明当前容器没有安装 GDS，这是正常情况。算法扩展不是 Community 容器的默认组成，不要在教程数据上假装它已经存在。安装后也应先估算内存、创建命名投影、运行算法、写回或流式返回，最后删除投影。

## 常见错误

- **无界路径。** 给 `*` 写最大跳数，并从可索引起点出发。
- **误读 PROFILE。** 首先看实际行数和 DB Hits，而非只盯总耗时。
- **用算法替代规则。** PageRank 得分是信号，不是授权、风控或业务审批结论。
- **将方向忽略得太早。** `--` 会匹配两个方向；关系方向本身有语义时请写箭头。

## 小结

Cypher 的核心是“以模式描述连接”。正确的路径边界、稳定的查询起点和执行计划，是图查询可控的基础。索引帮助定位起点，图算法帮助回答特定结构问题；二者都不能替代清晰的数据模型。
