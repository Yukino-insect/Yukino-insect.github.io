TCP 报文，也叫 TCP Segment，是传输层用于可靠传输数据的基本单位。

面试中如果被问“TCP 报文头有哪些字段”，不要只背字段名。更好的回答方式是：先说 TCP 头部的核心字段，再解释这些字段分别服务于连接管理、可靠传输、流量控制和差错校验。

## 一、TCP 报文结构

一个 TCP 报文大致由两部分组成：

```text
TCP 头部
TCP 数据
```

TCP 数据部分承载应用层协议内容，例如 HTTP 请求、HTTP 响应、MySQL 协议数据等。

TCP 头部最小 20 字节，最大 60 字节。之所以长度可变，是因为存在 Options 选项字段。

## 二、TCP 头部字段

### 1. 源端口和目的端口

```text
Source Port      16 位
Destination Port 16 位
```

端口用于标识主机上的进程或服务。

例如：

```text
客户端 51523 -> 服务端 443
```

IP 地址负责找到主机，端口负责找到主机上的应用。

### 2. 序列号

```text
Sequence Number 32 位
```

序列号表示当前 TCP 报文段中第一个数据字节的编号。

TCP 是字节流协议，它不是按“消息”编号，而是按字节编号。序列号用于：

1. 保证数据按顺序重组。
2. 发现丢包。
3. 支持重传。

在 SYN 报文中，序列号表示初始序列号 ISN。

### 3. 确认号

```text
Acknowledgment Number 32 位
```

确认号表示接收方期望收到的下一个字节序号。

例如确认号是：

```text
ACK = 1001
```

含义是：

```text
1000 及之前的字节我都收到了，下次请从 1001 开始发。
```

确认号只有在 `ACK` 标志位为 1 时有效。

### 4. 数据偏移

```text
Data Offset 4 位
```

表示 TCP 头部长度。

因为 TCP 头部可能携带 Options，所以接收方需要知道头部从哪里结束、数据从哪里开始。

### 5. 保留位

保留给未来扩展，正常情况下应为 0。

### 6. 标志位

常见标志位包括：

| 标志位 | 作用 |
| --- | --- |
| `SYN` | 建立连接，同步初始序列号 |
| `ACK` | 确认号有效 |
| `FIN` | 正常关闭连接的一个方向 |
| `RST` | 重置连接 |
| `PSH` | 尽快把数据交给应用层 |
| `URG` | 紧急指针有效 |
| `ECE` | 显式拥塞通知相关 |
| `CWR` | 拥塞窗口减少相关 |
| `NS` | ECN 扩展相关 |

面试中最重要的是：

```text
SYN、ACK、FIN、RST
```

它们分别对应连接建立、确认、关闭和异常重置。

### 7. 窗口大小

```text
Window Size 16 位
```

窗口大小表示接收方当前还能接收多少数据，用于 TCP 流量控制。

如果接收方处理不过来，可以通告更小的窗口，甚至通告 0 窗口，让发送方暂停发送。

实际窗口大小还可能结合 Window Scale 选项扩大。

### 8. 校验和

```text
Checksum 16 位
```

用于检测 TCP 报文在传输过程中是否出现错误。

TCP 校验和会覆盖 TCP 头部、数据以及伪首部。伪首部来自 IP 层信息，用来增强校验能力。

### 9. 紧急指针

```text
Urgent Pointer 16 位
```

只有 `URG` 标志位为 1 时才有效。

现代应用中很少使用这个字段。

### 10. 选项和填充

Options 是可变长度字段，常见选项包括：

1. MSS：最大报文段长度。
2. Window Scale：窗口扩大因子。
3. SACK Permitted：允许选择性确认。
4. Timestamp：时间戳，用于 RTT 估算和防止旧报文干扰。

Padding 用来把 TCP 头部补齐到 32 位对齐。

### 11. 数据

数据部分承载应用层内容。

例如 HTTP 请求：

```http
GET /index.html HTTP/1.1
Host: example.com
```

会作为 TCP 数据部分传输。

## 三、TCP 报文类型

严格来说，TCP 头部格式是统一的。所谓“报文类型”，主要是根据标志位组合和连接状态来区分。

### 1. SYN 报文

用于发起连接。

特点：

```text
SYN = 1
ACK = 0
```

客户端在三次握手第一步发送 SYN，并携带客户端初始序列号。

### 2. SYN + ACK 报文

用于响应连接请求。

特点：

```text
SYN = 1
ACK = 1
```

服务端确认客户端初始序列号，同时发送自己的初始序列号。

### 3. ACK 报文

用于确认收到的数据或确认连接建立。

特点：

```text
ACK = 1
```

连接建立后，大多数 TCP 报文都会带 ACK。

### 4. 数据报文

用于传输应用层数据。

特点通常是：

```text
ACK = 1
Data 不为空
```

例如 HTTP 请求和响应都通过这类 TCP 报文承载。

### 5. FIN 报文

用于正常关闭连接的一个方向。

特点：

```text
FIN = 1
```

TCP 是全双工协议，所以一个方向关闭后，另一个方向仍可能继续发送数据。

### 6. RST 报文

用于异常重置连接。

常见场景：

1. 访问未监听的端口。
2. 连接状态异常。
3. 应用强制关闭连接。
4. 收到不符合当前连接状态的报文。

RST 不是优雅关闭，而是直接告诉对方：这个连接不能继续用了。

### 7. PSH 报文

`PSH` 表示希望接收方尽快把数据交给应用层。

它不是“立刻发送”的意思。发送时机仍然受 TCP 栈、Nagle 算法、拥塞控制等影响。

## 四、序列号和确认号示例

假设客户端发送 100 字节数据：

```text
Seq = 1000
Len = 100
```

服务端收到后返回：

```text
Ack = 1100
```

含义是：

```text
1000 ~ 1099 的数据我收到了，下一个请发 1100。
```

如果中间丢了一段，接收方可以通过 ACK 和 SACK 告诉发送方缺哪些数据，从而触发重传。

## 五、TCP 如何承载 HTTP

HTTP 是应用层协议，TCP 是传输层协议。

发送 HTTP 请求时，层次大致是：

```text
HTTP 请求内容
  -> 放入 TCP 数据部分
  -> 加上 TCP 头部
  -> 加上 IP 头部
  -> 加上以太网帧头
  -> 发到网络中
```

接收方再反向拆包，最终把 HTTP 数据交给 Web 服务器处理。

## 六、面试时怎么回答

可以这样说：

> TCP 头部最小 20 字节，主要字段包括源端口、目的端口、序列号、确认号、数据偏移、标志位、窗口大小、校验和、紧急指针和选项。端口用于定位应用，序列号和确认号用于可靠传输，SYN、ACK、FIN、RST 等标志位用于连接管理，窗口大小用于流量控制，校验和用于错误检测，选项中常见 MSS、窗口扩大、SACK 和时间戳。

## 七、一句话总结

TCP 报文头不是一堆孤立字段。端口解决进程定位，序列号和确认号解决可靠传输，标志位解决连接状态，窗口大小解决流量控制，校验和解决错误检测。
