系统代理模式的核心作用是：**让遵守系统代理设置的应用，把网络请求先交给本机代理程序，再由代理程序决定直连还是转发。**

以 Clash 这类代理客户端为例，它通常会在本机监听一个端口，例如：

```text
127.0.0.1:7890
```

浏览器请求目标网站前，会先把请求发给这个本地端口。后续是否直连、走代理、走哪个节点，由代理程序根据规则决定。

## 一、没有代理时流量怎么走

假设访问：

```text
https://www.example.com
```

没有开启代理或 VPN 时，大致流程是：

```text
浏览器
  -> 操作系统网络栈
  -> 网卡
  -> 默认网关
  -> 运营商网络
  -> 目标服务器
```

操作系统会根据路由表决定数据包发给谁。

在 Windows 上可以查看路由表：

```bash
route print
```

通常会有一条默认路由：

```text
0.0.0.0/0 -> 默认网关
```

意思是：凡是不属于本地网段、也没有更精确路由的流量，都交给默认网关。

默认网关通常是路由器，例如：

```text
192.168.1.1
```

所以没开代理时，普通公网流量会直接从网卡发往路由器，再进入运营商网络。

## 二、没开代理时运营商能看到什么

如果访问的是 HTTPS 网站，运营商和中间网络通常能看到：

1. 你连接的目标 IP。
2. 连接时间和数据包大小。
3. 部分握手信息，例如 SNI，具体取决于 TLS 配置。

但看不到：

1. HTTP 请求头。
2. Authorization。
3. Cookie。
4. 请求体和响应体。
5. 页面具体内容。

HTTPS 保护的是应用层内容，不是隐藏所有网络元数据。

## 三、系统代理模式是什么

开启系统代理模式后，代理软件会修改操作系统的代理设置。

在 Windows 中可以查看：

```text
设置 -> 网络和 Internet -> 代理
```

常见配置类似：

```text
HTTP 代理：127.0.0.1:7890
HTTPS 代理：127.0.0.1:7890
```

此时浏览器访问网站的链路变成：

```text
浏览器
  -> 系统代理设置
  -> 127.0.0.1:7890
  -> 代理客户端
  -> 直连或远程代理服务器
  -> 目标网站
```

这里的 `127.0.0.1` 是本机回环地址。请求先发给本机代理程序，不是直接发到公网。

## 四、Clash 大致做了什么

Clash 可以理解成：

```text
本地代理服务器 + 规则引擎 + 流量转发器
```

它通常做三件事。

### 1. 在本机监听代理端口

例如：

```text
127.0.0.1:7890
```

这个端口可以提供 HTTP 代理或 SOCKS5 代理能力。

### 2. 修改系统代理设置

开启系统代理模式后，Clash 会把系统代理指向自己的本地端口。

于是遵守系统代理的软件会把请求交给 Clash。

### 3. 按规则决定走向

规则可能长这样：

```yaml
rules:
  - DOMAIN-SUFFIX,google.com,Proxy
  - DOMAIN-SUFFIX,baidu.com,DIRECT
```

含义是：

```text
访问 google.com -> 走代理节点
访问 baidu.com  -> 直连
```

所以代理软件不是简单地“所有流量都转发到远程服务器”，而是可以根据域名、IP、地理位置、进程等规则选择路径。

## 五、系统代理和 TUN 模式的区别

### 1. 系统代理模式

系统代理主要影响遵守系统代理设置的软件，例如多数浏览器、部分命令行工具和桌面应用。

它不一定影响：

1. 某些游戏。
2. 某些自带网络栈的客户端。
3. 不读取系统代理配置的程序。
4. 部分命令行工具。

优点是简单，风险较低。

### 2. TUN 模式

TUN 模式会创建虚拟网卡，并通过路由表把更多流量导入代理程序。

链路类似：

```text
应用程序
  -> 操作系统路由表
  -> TUN 虚拟网卡
  -> 代理客户端
  -> 直连或远程代理服务器
```

它更像 VPN，可以接管更多应用的流量。

优点是覆盖范围更广，缺点是配置复杂，路由、DNS 或虚拟网卡异常时更容易影响全局网络。

### 3. 透明代理

Linux 或软路由环境中还可能使用透明代理，通过 `iptables`、`nftables` 或路由规则拦截流量。

这种方式常见于网关设备，而不是普通桌面系统。

## 六、代理会解密 HTTPS 吗

默认情况下，代理软件不能解密 HTTPS 内容。

对于 HTTPS 请求，它通常只知道：

1. 目标域名或目标 IP。
2. 端口。
3. 连接大小和时间。
4. 加密后的数据流。

真正的 HTTP 请求头、Cookie、token 和响应内容仍然在 TLS 加密里面。

只有开启 HTTPS MITM，并且在系统中安装代理软件生成的根证书后，代理才有能力解密 HTTPS。

这类模式风险很高，通常只适合调试、企业安全审计或受控环境。普通使用不建议随便开启。

## 七、为什么关了代理还上不了网

常见原因包括：

1. 系统代理设置还指向 `127.0.0.1:7890`，但代理程序已经退出。
2. PAC 脚本地址还残留。
3. TUN 虚拟网卡没有关闭。
4. 路由表没有恢复。
5. DNS 被改成了不可用地址。
6. 浏览器或命令行工具单独配置了代理。

可以按下面顺序排查。

### 1. 查看系统代理

Windows 设置中查看：

```text
设置 -> 网络和 Internet -> 代理
```

命令行查看 WinHTTP 代理：

```bash
netsh winhttp show proxy
```

注意：浏览器常用的是 WinINET 代理设置，`netsh winhttp` 查看的是 WinHTTP 代理，两者不是完全同一个东西。

### 2. 查看虚拟网卡

进入：

```text
控制面板 -> 网络适配器
```

检查是否有：

```text
TAP-Windows Adapter
Wintun
Clash Tun
```

### 3. 查看路由表

```bash
route print
```

确认默认路由是否仍然指向正常网关。

### 4. 查看 DNS

```bash
ipconfig /all
```

确认 DNS 服务器是否正常。

## 八、Clash 和 VPN 的区别

| 对比项 | Clash 系统代理 | Clash TUN | 传统 VPN |
| --- | --- | --- | --- |
| 工作层级 | 应用层代理为主 | 网络层虚拟网卡 | 网络层虚拟网卡 |
| 是否修改系统代理 | 是 | 不一定 | 通常不依赖 |
| 是否创建虚拟网卡 | 否 | 是 | 是 |
| 覆盖范围 | 遵守代理的软件 | 大部分 IP 流量 | 大部分 IP 流量 |
| 控制粒度 | 规则很细 | 规则很细 | 通常按路由和策略 |

## 九、一句话总结

系统代理模式不是让电脑“变成代理服务器”，而是把应用请求先交给本机代理客户端。代理客户端再根据规则决定直连还是转发。它影响的是遵守系统代理的软件；如果要接管几乎所有流量，通常需要 TUN 或 VPN 这类虚拟网卡方案。
