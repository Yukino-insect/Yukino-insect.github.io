SSH 是一种用于远程登录和安全通信的协议。它常用于登录 Linux 服务器、执行远程命令、传输文件以及建立端口转发。

## 一、SSH 解决什么问题

如果直接通过明文协议远程登录，账号、密码和执行内容都可能被网络中的中间人看到。SSH 会在客户端和服务端之间建立加密通道，避免登录凭证和传输内容被明文暴露。

常见登录方式有两种：

1. 密码登录。
2. 密钥登录。

生产环境更推荐密钥登录，并关闭密码登录，减少暴力破解风险。

## 二、密钥登录的基本过程

密钥登录依赖一对密钥：

1. 私钥：保存在客户端本地，不能泄露。
2. 公钥：放到服务器用户目录的 `~/.ssh/authorized_keys` 中。

登录时，服务端会验证客户端是否持有与公钥匹配的私钥。私钥不会被直接发送到网络中，服务端通过挑战和签名验证客户端身份。

## 三、常见文件

客户端常见文件：

```text
~/.ssh/id_rsa
~/.ssh/id_rsa.pub
~/.ssh/config
```

服务端常见文件：

```text
~/.ssh/authorized_keys
/etc/ssh/sshd_config
```

`authorized_keys` 保存允许登录当前用户的公钥。`sshd_config` 用于配置 SSH 服务端行为，例如是否允许密码登录、是否允许 root 登录、监听端口等。

## 四、免密登录不是没有认证

免密登录并不是跳过认证，而是把密码认证换成了密钥认证。如果私钥没有设置口令，那么登录时看起来不需要输入密码，但认证仍然发生了。

为了安全，私钥文件应限制权限：

```bash
chmod 600 ~/.ssh/id_rsa
chmod 700 ~/.ssh
```

如果私钥泄露，攻击者就可能直接登录服务器。因此私钥应避免上传到代码仓库，也不应通过聊天工具随意传输。
