平时说的网络证书，通常指 HTTPS 使用的 **SSL/TLS 服务器证书**。

它的核心作用不是“加密网页内容”这么简单，而是解决三个问题：

1. 证明你访问的服务器确实属于这个域名。
2. 帮助客户端和服务器安全协商加密密钥。
3. 防止中间人伪装成目标网站。

## 一、证书里有什么

一张 TLS 服务器证书通常包含：

1. 域名信息，例如 `example.com`、`www.example.com`。
2. 服务器公钥。
3. 证书有效期。
4. 签发者，也就是 CA。
5. 证书用途，例如服务器身份认证。
6. 签名算法和 CA 的数字签名。

证书本身通常是公开的。真正需要保密的是服务器私钥。

## 二、CA 是什么

CA，全称 Certificate Authority，中文叫证书颁发机构。

浏览器和操作系统会预置一批受信任的根证书。只要网站证书能够沿着证书链一路验证到受信任的根 CA，浏览器就认为这张证书可信。

证书链大致是：

```text
网站证书
  -> 中间 CA 证书
  -> 根 CA 证书
  -> 浏览器或操作系统信任库
```

这套机制的意思是：

> 浏览器不认识每一个网站，但它信任一些 CA；如果 CA 证明这个证书属于某个域名，浏览器就接受这个证明。

## 三、浏览器如何验证证书

访问下面的网址时：

```text
https://example.com
```

浏览器会在 TLS 握手阶段检查服务器发来的证书：

1. 域名是否匹配。
2. 证书是否在有效期内。
3. 证书链是否完整。
4. 签发 CA 是否受信任。
5. 证书是否被吊销。
6. 证书用途是否允许用于服务器认证。

如果任何关键校验失败，浏览器就会提示证书错误或直接阻止访问。

## 四、证书和 HTTPS 加密的关系

证书里有服务器公钥。客户端会通过 TLS 握手确认：

1. 服务器确实持有对应私钥。
2. 当前访问的域名和证书匹配。
3. 后续通信可以使用协商出的会话密钥加密。

也就是说，证书主要负责身份认证和密钥协商的可信基础。真正加密大量 HTTP 数据时，通常使用握手后协商出来的对称密钥。

## 五、为什么老电脑或 IE 容易打不开 HTTPS 网站

学校机房、老旧办公电脑、旧版 IE 打不开某些 HTTPS 网站，常见原因有几类。

### 1. 网站证书本身有问题

例如：

1. 证书过期。
2. 域名不匹配。
3. 证书链缺失。
4. 使用自签名证书。

如果是网站证书本身有问题，通常多数现代浏览器也会提示异常。

### 2. 系统根证书库太旧

浏览器验证证书需要依赖信任库。如果 Windows 长期不更新，可能缺少新的根证书或中间证书。

结果就是：网站证书本身没问题，但这台电脑不信任它。

### 3. 浏览器或系统不支持现代 TLS

老版本 IE 和旧系统可能不支持：

1. TLS 1.2 或 TLS 1.3。
2. 新的加密套件。
3. SNI。
4. 新的证书链算法。

很多新网站已经禁用 TLS 1.0 和 TLS 1.1。旧浏览器因此会在握手阶段失败。

### 4. 企业代理或安全设备拦截

在公司或学校网络里，有些安全设备会进行 HTTPS 检查。它会给浏览器签发一个本地代理证书。

如果电脑没有安装对应的企业根证书，浏览器就会认为连接被中间人攻击，从而报错。

## 六、根证书从哪里来

根证书通常来自：

1. 操作系统预置。
2. 浏览器自己的根证书计划。
3. 系统更新或浏览器更新。
4. 企业环境中手动安装的内部根证书。

不同浏览器和不同系统的实现不完全相同，所以同一个网站可能出现“Chrome 能打开，IE 打不开”的情况。

## 七、一句话总结

网络证书的作用是证明服务器身份，并为 HTTPS 的安全密钥协商提供可信基础。证书不只是为了加密，更重要的是防止用户在不知情的情况下连接到伪造网站。
