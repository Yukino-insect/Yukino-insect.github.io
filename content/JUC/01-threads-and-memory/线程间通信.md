线程间通信是指多个线程之间通过某种机制协作，控制执行顺序或传递状态。Java 中常见方式包括 `wait`、`notify`、`notifyAll`、`Condition`、阻塞队列和并发工具类。

## 一、wait 和 notify

`wait`、`notify`、`notifyAll` 定义在 `Object` 上，而不是 `Thread` 上。这是因为它们依赖对象监视器锁，也就是 `synchronized` 使用的那把锁。

使用规则是：调用 `wait` 或 `notify` 前，线程必须先持有该对象的监视器锁。

```java
synchronized (lock) {
    while (!ready) {
        lock.wait();
    }
}
```

`wait` 会释放当前持有的锁，并让线程进入等待状态。`notify` 会唤醒一个等待线程，`notifyAll` 会唤醒所有等待线程。

## 二、为什么要用 while

等待条件时应使用 `while`，而不是 `if`：

```java
synchronized (lock) {
    while (!ready) {
        lock.wait();
    }
    doSomething();
}
```

原因是线程被唤醒后，不代表条件一定成立。可能发生虚假唤醒，也可能其他线程已经先一步消费了条件。

## 三、sleep 不会释放锁

`Thread.sleep` 只是让当前线程暂停一段时间，不会释放已经持有的锁。

`Object.wait` 会释放锁，并等待其他线程唤醒。

这是两者最重要的区别。

## 四、Condition

`Condition` 是 `Lock` 体系下的等待通知机制，常和 `ReentrantLock` 一起使用：

```java
lock.lock();
try {
    while (!ready) {
        condition.await();
    }
} finally {
    lock.unlock();
}
```

相比 `wait` 和 `notify`，`Condition` 可以为同一把锁创建多个等待队列，表达能力更强。

## 五、实践建议

业务开发中优先使用更高层的并发工具，例如 `BlockingQueue`、`CountDownLatch`、`Semaphore`、`CompletableFuture`。它们比直接使用 `wait` 和 `notify` 更不容易出错。

只有在实现底层同步组件或需要精确控制等待队列时，才建议直接使用等待通知机制。
