线程池创建后要正确关闭。否则应用可能无法退出，或者关闭时直接丢任务。线程池关闭不是一句 `shutdown()` 就万事大吉，至少要理解它和 `shutdownNow()`、`awaitTermination()` 的区别。

## 一、三个核心方法

| 方法 | 作用 |
| --- | --- |
| `shutdown()` | 不再接收新任务，继续执行已经提交的任务 |
| `shutdownNow()` | 不再接收新任务，尝试中断正在执行的任务，并返回队列中未执行的任务 |
| `awaitTermination(timeout, unit)` | 阻塞等待线程池关闭完成，直到超时或终止 |

`shutdownNow()` 不是强制杀死线程。它只是对工作线程调用 `interrupt`。如果任务内部不响应中断，例如一直吞掉 `InterruptedException`，线程仍然可能继续运行。

## 二、推荐关闭模板

```java
public static void shutdownGracefully(ExecutorService executor) {
    executor.shutdown();
    try {
        if (!executor.awaitTermination(60, TimeUnit.SECONDS)) {
            List<Runnable> droppedTasks = executor.shutdownNow();
            System.err.println("Dropped tasks: " + droppedTasks.size());

            if (!executor.awaitTermination(30, TimeUnit.SECONDS)) {
                System.err.println("Executor did not terminate");
            }
        }
    } catch (InterruptedException e) {
        executor.shutdownNow();
        Thread.currentThread().interrupt();
    }
}
```

这个流程的意图很简单：

1. 先温和关闭，不再接收新任务。
2. 等待一段时间，让已提交任务自然完成。
3. 如果超时，再尝试中断。
4. 当前线程被中断时，恢复中断标记。

## 三、任务要响应中断

线程池是否能优雅关闭，不只取决于线程池，也取决于任务代码。

```java
executor.execute(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        try {
            doOneRound();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            break;
        }
    }
});
```

如果任务里有阻塞调用，要么让它能抛出 `InterruptedException`，要么提供其他停止机制。吞掉中断异常却继续循环，是关闭流程里很常见的麻烦来源。

## 四、为什么不关闭会影响 JVM 退出

线程池默认创建的是非守护线程。只要 JVM 中还有非守护线程存活，进程就不会退出。

因此，临时创建的线程池要在使用完后关闭。Spring 托管的线程池通常由容器负责销毁，但仍然建议配置清楚销毁流程，避免应用停机时任务被粗暴打断。

## 五、总结

- `shutdown()` 是优雅关闭，`shutdownNow()` 是尝试中断。
- `awaitTermination()` 用来等待关闭完成，不会主动发起关闭。
- 任务必须正确处理中断，否则线程池很难真正停下。
- 关闭线程池时要保留中断标记，这是对调用方最基本的礼貌。
