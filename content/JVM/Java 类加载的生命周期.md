类加载不是简单地把 `.class` 文件读进内存。JVM 需要先找到类的二进制字节流，再验证它是否合法，给类变量分配默认值，把符号引用解析成直接引用，最后执行静态初始化逻辑。

理解类加载时，最容易混淆的是两件事：

- **类初始化**：初始化 `static` 字段和静态代码块。
- **对象初始化**：`new` 对象时初始化实例字段和执行构造方法。

它们发生在不同阶段。把这两件事分开，很多“为什么字段已经有值”的问题就不再神秘。

## 一、类加载生命周期

Java 类的生命周期可以表示为：

```text
加载 -> 验证 -> 准备 -> 解析 -> 初始化 -> 使用 -> 卸载
```

其中验证、准备、解析统称为**连接**。

```text
加载
  |
  v
连接：验证 -> 准备 -> 解析
  |
  v
初始化
  |
  v
使用
  |
  v
卸载
```

通常情况下，加载、验证、准备、初始化会按顺序开始。解析阶段则不一定完全固定，它可能在初始化之前发生，也可能为了支持动态绑定而推迟到运行期。

## 二、加载

加载阶段主要做三件事：

1. 通过类的全限定名获取定义此类的二进制字节流。
2. 把字节流代表的静态存储结构转换为方法区中的运行时数据结构。
3. 在堆中生成一个 `java.lang.Class` 对象，作为访问该类元数据的入口。

二进制字节流不一定只来自本地 `.class` 文件，也可以来自：

- Jar 包。
- 网络。
- 动态代理生成的字节码。
- 运行时生成的类。
- 自定义类加载器读取的其他来源。

所以类加载器的价值不只是“读文件”，而是给 JVM 提供一种可扩展的类来源机制。

## 三、连接

连接包含验证、准备、解析三个阶段。

### 1. 验证

验证阶段确保字节码符合 JVM 规范，不会破坏虚拟机安全。

常见验证内容包括：

- 文件格式验证：魔数、版本号、常量池结构是否合法。
- 元数据验证：类继承关系、字段和方法是否合法。
- 字节码验证：操作数栈、跳转指令、类型转换是否安全。
- 符号引用验证：引用的类、字段、方法是否可访问。

验证是 JVM 安全模型的重要组成部分。否则，一个恶意构造的 class 文件就可能绕过 Java 语言层面的限制。

### 2. 准备

准备阶段为**类变量**分配内存，并设置默认初始值。

这里的类变量指被 `static` 修饰的变量，不包括实例字段。

```java
public class Demo {
    private static int count = 10;
    private int value = 20;
}
```

在准备阶段：

- `count` 会被分配内存，并先得到默认值 `0`。
- `value` 是实例字段，不在类加载准备阶段处理。
- `count = 10` 这种显式赋值通常在初始化阶段执行。

有一个例外：如果字段是编译期常量，例如 `static final int SIZE = 10`，它的值可能在准备阶段就被放入常量值属性中。

### 3. 解析

解析阶段把常量池中的**符号引用**替换成**直接引用**。

符号引用是一种描述性引用，例如：

```text
java/lang/String
java/io/PrintStream.println:(Ljava/lang/String;)V
```

直接引用则是 JVM 能直接定位到目标的引用，例如方法表入口、字段偏移量或内存地址相关结构。

解析可能发生在类初始化之前，也可能在某次真正使用某个符号引用时才发生，这与 JVM 实现和动态绑定有关。

## 四、初始化

初始化阶段执行类构造器 `<clinit>`。它由编译器自动收集以下内容生成：

- `static` 字段的显式赋值。
- `static {}` 静态代码块。

示例：

```java
public class Demo {
    static int a = 1;

    static {
        a = 2;
    }
}
```

初始化结束后，`a` 的值是 `2`。

类初始化有几个特点：

- JVM 会保证一个类的 `<clinit>` 在多线程环境下只被一个线程执行。
- 父类通常会先于子类初始化。
- 接口初始化规则与类不同，只有真正用到接口中非常量字段时，才更可能触发接口初始化。

## 五、什么时候触发初始化

类不会因为被加载就一定立刻初始化。常见主动使用场景包括：

- 创建类实例：`new Demo()`。
- 访问或设置类的静态字段，编译期常量除外。
- 调用类的静态方法。
- 使用反射调用类。
- 初始化子类时，父类需要先初始化。
- JVM 启动时包含 `main` 方法的主类会被初始化。

下面这种代码通常不会触发 `ConstClass` 初始化，因为 `HELLO` 是编译期常量，编译后可能已经进入调用方常量池：

```java
public class ConstClass {
    public static final String HELLO = "hello";
}

public class Test {
    public static void main(String[] args) {
        System.out.println(ConstClass.HELLO);
    }
}
```

但如果字段不是编译期常量，就可能触发初始化：

```java
public class Demo {
    public static final long VALUE = System.nanoTime();
}
```

## 六、类加载器与双亲委派

类加载器负责加载类。常见层次如下：

```text
Bootstrap ClassLoader
          |
Platform ClassLoader / Extension ClassLoader
          |
Application ClassLoader
          |
Custom ClassLoader
```

JDK 8 及以前常说扩展类加载器 `Extension ClassLoader`；JDK 9 之后模块系统引入，扩展机制被移除，平台类加载器 `Platform ClassLoader` 承担相关职责。

### 1. 双亲委派模型

双亲委派的过程是：

1. 子类加载器收到类加载请求。
2. 先把请求委派给父加载器。
3. 父加载器继续向上委派。
4. 顶层加载器无法加载时，再逐级向下尝试。

这个模型的好处是：

- 保证核心类优先由 JVM 标准加载器加载。
- 避免应用自己伪造或覆盖 `java.*` 核心类。
- 降低同一个类被多个加载器重复加载造成的混乱。

### 2. 类的唯一性

在 JVM 中，判断两个类是否相同，不只看全限定名，还要看加载它们的类加载器。

也就是说：

```text
同一个 class 文件 + 不同 ClassLoader = JVM 眼中的不同类
```

这也是 Web 容器、插件系统、热部署框架会大量使用自定义类加载器的原因。它们可以用类加载器隔离不同应用或不同插件的类。

## 七、对象创建与实例字段初始化

类加载解决的是“类能不能被 JVM 使用”；对象创建解决的是“实例如何在堆上形成”。

`new` 一个对象时，大致过程是：

```text
检查类是否已加载
 -> 分配对象内存
 -> 内存清零
 -> 设置对象头
 -> 执行 <init>
```

因为对象内存会先清零，所以实例字段即使没有显式赋值，也有默认值：

| 类型 | 默认值 |
| ---- | ------ |
| `byte`、`short`、`int`、`long` | `0` |
| `float`、`double` | `0.0` |
| `boolean` | `false` |
| `char` | `\u0000` |
| 引用类型 | `null` |

示例：

```java
class A {
    int x = 10;
    String s = "hi";

    {
        x = 20;
    }

    A() {
        x = 30;
    }
}
```

创建 `new A()` 时的顺序是：

1. 分配对象内存，并清零：`x = 0`，`s = null`。
2. 执行实例字段显式赋值和实例代码块，按源码顺序执行：`x = 10`，`s = "hi"`，然后 `x = 20`。
3. 执行构造方法：`x = 30`。

最终结果是：

```text
x = 30
s = "hi"
```

所以，实例字段有默认值不是类加载阶段赋予的，而是对象创建时内存清零带来的。

## 八、类卸载

类卸载发生在方法区或元空间回收时。一个类想被卸载，通常需要同时满足：

- 该类的所有实例都已经不可达。
- 加载该类的 `ClassLoader` 已经不可达。
- 该类对应的 `Class` 对象没有被任何地方引用。

普通应用中的系统类、业务主类通常很难被卸载。类卸载更多出现在：

- Web 应用重新部署。
- 插件卸载。
- 动态脚本或动态代理大量生成类。
- 自定义类加载器隔离业务模块。

如果类加载器被线程上下文、静态集合、缓存或 `ThreadLocal` 引用住，就可能导致类无法卸载，进而出现元空间泄漏。

## 九、总结

类加载可以抓住这几条主线：

- 加载负责把字节流变成 JVM 内部类元数据。
- 连接负责验证安全性、准备类变量默认值、解析符号引用。
- 初始化负责执行 `static` 显式赋值和静态代码块。
- 对象创建负责实例字段默认值、实例代码块和构造方法。
- 类的唯一性由“全限定名 + 类加载器”共同决定。
- 类卸载的关键往往不是对象本身，而是加载它的 `ClassLoader` 是否能被回收。

一句话收束：**类加载初始化的是类，对象创建初始化的是实例。把这条边界分清，类加载问题就已经少了一半。**
