逃逸分析是 JIT 编译器的一种优化分析手段，用来判断对象的引用是否会逃出当前方法或当前线程。如果对象不会逃逸，JIT 就有机会做更激进的优化。

## 一、什么是逃逸

对象逃逸指的是对象引用被当前作用域之外的代码持有。例如：

```java
private Object field;

public void method() {
    Object obj = new Object();
    field = obj;
}
```

这里 `obj` 被赋值给成员变量，方法结束后仍可能被其他代码访问，因此它发生了逃逸。

如果对象只在方法内部使用，没有返回、没有赋值给外部字段、没有传给可能保存引用的方法，就可能被认为没有逃逸。

## 二、JIT 可以做哪些优化

逃逸分析本身不是优化结果，它只是分析前提。基于分析结果，JIT 可能做以下优化：

1. 标量替换：把对象拆成若干字段变量，不再真实分配对象。
2. 锁消除：对象没有线程逃逸时，移除不必要的同步锁。
3. 栈上分配：理论上可把对象分配到栈上，但 HotSpot 更常见的效果是标量替换。

需要注意，很多资料会把逃逸分析直接说成“对象分配到栈上”。这个说法过于简化。实际优化是否发生，要看 JIT 编译结果、代码形态和运行时条件。

## 三、示例

```java
public int sum() {
    Point point = new Point(1, 2);
    return point.x + point.y;
}
```

如果 `Point` 对象没有逃出 `sum` 方法，JIT 可能直接把它拆成两个局部变量 `x` 和 `y`，从而避免真实对象分配。

## 四、实践意义

逃逸分析提醒我们：短生命周期对象未必一定会造成严重 GC 压力，JIT 可能已经优化掉其中一部分。但业务代码不应为了猜测逃逸分析而写得晦涩。

优先保证代码清晰，再通过 JMH、GC 日志和性能分析工具确认瓶颈。只有在热点路径确实有问题时，才需要围绕对象分配做针对性优化。
