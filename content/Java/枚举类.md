Java 的 `enum` 不是简单的整数常量。每一个枚举常量，本质上都是该枚举类型的一个固定实例。

```java
enum OrderStatus {
    NEW,
    PROCESSING,
    SUCCESS,
    FAILED
}
```

这里的 `NEW`、`PROCESSING`、`SUCCESS`、`FAILED` 都是 `OrderStatus` 的实例，只是这些实例由编译器和 JVM 管理，不能随便 `new`。

## 一、枚举常量是什么

枚举常量可以理解为 `public static final` 实例。

概念上类似：

```java
public final class OrderStatus {
    public static final OrderStatus NEW = new OrderStatus();
    public static final OrderStatus PROCESSING = new OrderStatus();

    private OrderStatus() {
    }
}
```

真实的 `enum` 由编译器生成更多代码，并且继承自 `java.lang.Enum`。

枚举不能手动创建新实例：

```java
new OrderStatus(); // 不合法
```

这保证了枚举值集合是固定的。

## 二、枚举构造方法

枚举可以有字段和构造方法。

```java
enum OrderStatus {
    NEW(0, "待处理"),
    PROCESSING(1, "处理中"),
    SUCCESS(2, "成功"),
    FAILED(3, "失败");

    private final int code;
    private final String description;

    OrderStatus(int code, String description) {
        this.code = code;
        this.description = description;
    }

    public int getCode() {
        return code;
    }

    public String getDescription() {
        return description;
    }
}
```

构造方法默认是 `private`，即使不写也是私有的。枚举构造方法不能是 `public`。

使用：

```java
OrderStatus status = OrderStatus.NEW;

System.out.println(status.getCode());
System.out.println(status.getDescription());
```

## 三、枚举实例什么时候创建

枚举常量实例在枚举类初始化时创建。

触发类初始化的常见行为：

- 第一次访问枚举常量。
- 调用枚举的静态方法。
- 反射主动加载。

初始化过程可以粗略理解为：

```text
按源码顺序创建枚举常量实例
 -> 生成并填充保存所有常量的内部数组
 -> 执行 static 代码块
 -> 类初始化完成
```

所以在 `static` 代码块中调用 `values()` 是可行的，因为枚举常量已经创建。

```java
enum Status {
    NEW,
    DONE;

    static {
        System.out.println(values().length);
    }
}
```

## 四、values 和 valueOf

每个枚举类都会由编译器生成 `values()` 方法。

```java
OrderStatus[] statuses = OrderStatus.values();
```

`values()` 是静态方法，返回所有枚举常量。

```java
for (OrderStatus status : OrderStatus.values()) {
    System.out.println(status.name());
}
```

还可以使用 `valueOf`：

```java
OrderStatus status = OrderStatus.valueOf("NEW");
```

如果名称不存在，会抛出 `IllegalArgumentException`。

```java
OrderStatus.valueOf("UNKNOWN"); // IllegalArgumentException
```

`valueOf` 匹配的是枚举常量名，不是自定义 `code` 或 `description`。

## 五、name 和 ordinal

枚举继承自 `Enum`，常见方法：

```java
status.name();
status.ordinal();
```

`name()` 返回枚举常量名：

```java
OrderStatus.NEW.name(); // "NEW"
```

`ordinal()` 返回定义顺序，从 0 开始。

```java
OrderStatus.NEW.ordinal(); // 0
```

工程中不要把 `ordinal()` 存入数据库或作为业务编码。

原因：

- 枚举顺序一变，含义就变。
- 中间插入新枚举会影响后续编号。
- 可读性差。

更稳的是显式定义 `code`。

```java
private final int code;
```

## 六、根据 code 查枚举

常见写法：

```java
enum OrderStatus {
    NEW(0, "待处理"),
    PROCESSING(1, "处理中"),
    SUCCESS(2, "成功"),
    FAILED(3, "失败");

    private static final Map<Integer, OrderStatus> CODE_MAP;

    static {
        Map<Integer, OrderStatus> map = new HashMap<>();
        for (OrderStatus status : values()) {
            map.put(status.code, status);
        }
        CODE_MAP = Collections.unmodifiableMap(map);
    }

    private final int code;
    private final String description;

    OrderStatus(int code, String description) {
        this.code = code;
        this.description = description;
    }

    public static Optional<OrderStatus> fromCode(int code) {
        return Optional.ofNullable(CODE_MAP.get(code));
    }
}
```

使用：

```java
OrderStatus.fromCode(1)
    .ifPresent(System.out::println);
```

如果不想使用 `Optional`，也可以返回 `null` 或抛异常。关键是团队要统一语义。

## 七、switch 中使用枚举

枚举很适合和 `switch` 配合。

```java
String text = switch (status) {
    case NEW -> "待处理";
    case PROCESSING -> "处理中";
    case SUCCESS -> "成功";
    case FAILED -> "失败";
};
```

如果所有枚举都覆盖，通常可以不写 `default`。以后新增枚举值时，编译器会提醒补分支。

如果写了 `default`：

```java
String text = switch (status) {
    case NEW -> "待处理";
    default -> "其他";
};
```

新增枚举值时，编译器可能不会提醒你漏处理。方便和安全有时会站在两边，别每次都选方便。

## 八、枚举可以实现接口

枚举可以实现接口。

```java
interface CodeEnum {
    int getCode();
}

enum OrderStatus implements CodeEnum {
    NEW(0),
    SUCCESS(1);

    private final int code;

    OrderStatus(int code) {
        this.code = code;
    }

    @Override
    public int getCode() {
        return code;
    }
}
```

这适合统一处理多个业务枚举。

```java
static <E extends Enum<E> & CodeEnum> Optional<E> findByCode(
    Class<E> enumType,
    int code
) {
    for (E item : enumType.getEnumConstants()) {
        if (item.getCode() == code) {
            return Optional.of(item);
        }
    }
    return Optional.empty();
}
```

不过不要为了抽象而抽象。枚举少、规则简单时，每个枚举自己写 `fromCode` 更直接。

## 九、EnumSet 和 EnumMap

JDK 为枚举提供了专用集合。

`EnumSet`：

```java
EnumSet<OrderStatus> finished = EnumSet.of(
    OrderStatus.SUCCESS,
    OrderStatus.FAILED
);
```

判断：

```java
if (finished.contains(status)) {
    System.out.println("订单已结束");
}
```

`EnumMap`：

```java
EnumMap<OrderStatus, String> textMap = new EnumMap<>(OrderStatus.class);
textMap.put(OrderStatus.NEW, "待处理");
textMap.put(OrderStatus.SUCCESS, "成功");
```

它们比普通 `HashSet` / `HashMap` 更适合枚举 key，性能和语义都更好。

## 十、总结

枚举可以这样记：

```text
枚举常量是固定实例
构造方法默认 private
values() 是编译器生成的静态方法
valueOf() 按枚举名称查找
不要用 ordinal 做业务编码
需要业务编码时显式定义 code
枚举集合优先考虑 EnumSet 和 EnumMap
```

枚举适合表达固定、有限、语义明确的状态集合。它比散落的整数常量更安全，也更容易被编译器检查。
