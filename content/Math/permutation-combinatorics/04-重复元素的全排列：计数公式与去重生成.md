当输入是 `[1,1,2]` 时，朴素全排列程序把两个 `1` 当作不同下标，会走出 $3!=6$ 条搜索路径；但打印出的值序列只有 `112`、`121`、`211` 三种。这里必须区分“交换两个位置上的相同副本”这一过程，和“最终显示出来的不同序列”这一结果。多数题目需要的是后者。

## 一、多重集合排列的计数公式

设总共有 $n$ 个元素，其中第 $1$ 类元素重复 $c_1$ 次，第 $2$ 类重复 $c_2$ 次，……，第 $r$ 类重复 $c_r$ 次，且：

$$
c_1+c_2+\cdots+c_r=n.
$$

不同值序列的数量为：

$$
\frac{n!}{c_1!c_2!\cdots c_r!}.
$$

推导很直接：先暂时给相同元素贴上不同标签，全部排列有 $n!$ 个。固定一个最终值序列后，第一类元素的 $c_1$ 个标签能在自己的位置内部交换 $c_1!$ 种，且不会改变显示结果；各类独立相乘。故每个不同结果被重复计算 $c_1!\cdots c_r!$ 次。

例如 `AABC` 有：

$$
\frac{4!}{2!}=12
$$

种不同排列，而不是 $24$ 种。

## 二、不能先生成再用集合去重

当然可以把朴素生成的结果放进 `set`，最后由集合去重；但这会无意义地构造并保存重复项。若输入有很多相同元素，浪费会很明显。正确方向是让搜索树一开始就不生成等价分支。

这里的关键观察是：在同一递归层（同一位置）选择第一个还没用的 `1` 与选择第二个还没用的 `1`，后续可得到的值序列完全相同。因此同层相同值只保留一次选择即可。

## 三、排序加跳过规则

先排序，使相同值相邻。扫描候选项时，若当前值与前一个相同，且前一个相同值尚未被当前前缀使用，则跳过当前项：

```cpp
#include <algorithm>
#include <vector>

using namespace std;

void dfs(const vector<int>& nums, vector<bool>& used,
         vector<int>& path, vector<vector<int>>& ans) {
    if (path.size() == nums.size()) {
        ans.push_back(path);
        return;
    }

    for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
        if (used[i]) continue;

        if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) {
            continue;
        }

        used[i] = true;
        path.push_back(nums[i]);
        dfs(nums, used, path, ans);
        path.pop_back();
        used[i] = false;
    }
}

vector<vector<int>> uniquePermutations(vector<int> nums) {
    sort(nums.begin(), nums.end());
    vector<bool> used(nums.size(), false);
    vector<int> path;
    vector<vector<int>> ans;
    dfs(nums, used, path, ans);
    return ans;
}
```

规则中最容易被机械背错的是 `!used[i - 1]`。它的语义不是“相同元素永远只能选一个”，而是“在**同一层**，后一个相同值不能抢在前一个之前作为代表”。若前一个 `1` 已经在当前前缀里，继续选后一个 `1` 正是组成 `11...` 所必需的，不能跳过。

以 `[1a,1b,2]` 为例，根层先选择 `1a`；根层再试图选择 `1b` 时，`1a` 未被使用，二者将产生相同的一批值序列，故跳过。可是在前缀已经是 `[1a]` 的下一层，`1a` 已被使用，选择 `1b` 合法，从而能生成 `112`。

## 四、另一种写法：频次数组

若元素范围适合哈希表或有序映射，也可记录每种值还剩几次。每层遍历“值种类”而不是“元素下标”，天然没有重复分支。

```python
from collections import Counter

def unique_permutations(nums):
    count = Counter(nums)
    path = []
    ans = []

    def dfs():
        if len(path) == len(nums):
            ans.append(path.copy())
            return

        for value in sorted(count):
            if count[value] == 0:
                continue
            count[value] -= 1
            path.append(value)
            dfs()
            path.pop()
            count[value] += 1

    dfs()
    return ans
```

这份写法的状态更贴近数学对象：`count[value]` 就是多重集合中该值尚未使用的副本数。元素种类远少于元素总数时，它的分支结构也更清晰。

## 五、复杂度与适用边界

不同结果数是：

$$
M=\frac{n!}{\prod_j c_j!}.
$$

输出所有结果的时间下界为 $\Omega(nM)$。去重搜索避免了朴素算法的重复叶子，但并不会让大量**真实不同**的结果凭空消失。若只需数量，直接计算上式；若需要按字典序找第 $k$ 个，还可进一步结合阶乘与剩余频次做选择，而无需输出前面的所有项。

## 六、总结

- 重复元素的不同全排列数是 $n!/(c_1!\cdots c_r!)$。
- “先生成再集合去重”正确但通常低效；更好的做法是在同层阻止等价选择。
- 排序后的跳过条件 `nums[i] == nums[i-1] && !used[i-1]` 只排除同层重复，不妨碍同一值出现多次。
- 频次数组写法直接表示多重集合，尤其适合解释和扩展。
