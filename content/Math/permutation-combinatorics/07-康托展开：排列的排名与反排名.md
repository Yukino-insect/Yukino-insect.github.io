康托展开（Cantor expansion）把 $n$ 个不同元素的一个排列，映射为 $[0,n!-1]$ 中唯一的整数。它不是神秘的“排列哈希”：它本质上就是字典序排列的 0-based 下标，用阶乘进制记录“每一位前面还有多少个未使用且更小的元素”。

## 一、从字典序分块重新理解公式

设排列为：

$$
p=(p_1,p_2,\ldots,p_n),
$$

元素取自有序集合，例如 $1,2,\ldots,n$。在第 $i$ 个位置之前，设尚未使用且小于 $p_i$ 的元素数为 $c_i$。若把该位置换成任意一个更小的可用元素，剩下的 $n-i$ 个位置有 $(n-i)!$ 种自由排列；因此这一位跳过了：

$$
c_i(n-i)!
$$

个字典序更小的排列。全部相加：

$$
\operatorname{rank}(p)=\sum_{i=1}^{n}c_i(n-i)!.
$$

其中 $0\le c_i\le n-i$。这正是阶乘进制：第一位权重 $(n-1)!$，最后一位权重 $0!=1$。

## 二、手算一个排名

求排列 $(3,1,4,2)$ 在 $\{1,2,3,4\}$ 的字典序 0-based 编号。

| 位置 | 当前值 | 尚未使用且更小的值 | $c_i$ | 权重 | 贡献 |
| ---- | ------ | ------------------ | ----- | ---- | ---- |
| 1 | 3 | 1、2 | 2 | $3!=6$ | 12 |
| 2 | 1 | 无 | 0 | $2!=2$ | 0 |
| 3 | 4 | 2 | 1 | $1!=1$ | 1 |
| 4 | 2 | 无 | 0 | $0!=1$ | 0 |

因此：

$$
\operatorname{rank}(3,1,4,2)=12+0+1+0=13.
$$

这也可用字典序块验证：前缀小于 `3` 的 `1...`、`2...` 各有 $3!=6$ 个，共跳过 $12$ 个；固定 `3,1` 后，第三位若选 `2`，最后一位有一种排列，再跳过 $1$ 个；下一项就是 `3142`。

## 三、反康托展开：从编号恢复排列

给定 $k\in[0,n!-1]$，维护升序未使用列表。对权重 $(n-1)!,(n-2)!,\ldots,0!$，依次计算：

$$
q=\left\lfloor\frac{k}{(n-i)!}\right\rfloor,
\qquad k\leftarrow k\bmod(n-i)!.
$$

选择未使用列表中下标为 $q$ 的元素，删除它，继续下一位。

例如 $n=4,k=13$：

- $13/3!=2$，从 `[1,2,3,4]` 取下标 $2$ 的 `3`，余数 $1$；
- $1/2!=0$，从 `[1,2,4]` 取 `1`，余数 $1$；
- $1/1!=1$，从 `[2,4]` 取 `4`，余数 $0$；
- 剩下 `2`。

恢复为 `3142`，恰与上节排名互为反向过程。

```python
from math import factorial

def unrank(n, k):
    if not 0 <= k < factorial(n):
        raise ValueError("k 超出 0-based 排名范围")

    remaining = list(range(1, n + 1))
    answer = []
    for size in range(n - 1, -1, -1):
        block = factorial(size)
        index, k = divmod(k, block)
        answer.append(remaining.pop(index))
    return answer
```

`remaining.pop(index)` 是线性移动，所以该简洁版本为 $O(n^2)$。当 $n$ 只是十几、几十时通常足够；若 $n$ 很大，应维护“每个值是否未使用”的树状数组，用前缀和寻找第 `index + 1` 个未使用值，可将每层操作降至 $O(\log n)$，总计 $O(n\log n)$。

## 四、用树状数组计算排名

对排列从左到右扫描。若树状数组记录还未使用的值（初始每个位置为 $1$），那么：

$$
c_i=\operatorname{query}(p_i-1)
$$

就是当前可用且小于 $p_i$ 的元素个数。计入 $c_i(n-i)!$ 后，将 `p_i` 的计数减一。这里树状数组并不理解排列；它只高效维护动态集合的前缀计数。

```cpp
struct Fenwick {
    vector<int> tree;
    explicit Fenwick(int n) : tree(n + 1) {}
    void add(int i, int delta) {
        for (; i < static_cast<int>(tree.size()); i += i & -i) tree[i] += delta;
    }
    int sum(int i) const {
        int result = 0;
        for (; i > 0; i -= i & -i) result += tree[i];
        return result;
    }
};
```

若排列元素不是 $1\ldots n$，先对值做坐标压缩，保留它们的相对大小即可。因为字典序只依赖大小比较，不依赖具体数值。

## 五、范围、溢出与重复元素边界

康托展开的标准形式只适用于元素互异。若含重复值，多个带标签的排列对应同一个值序列，排名必须按多重集合排列数重新计算各块大小，不能继续生搬 $c_i(n-i)!$。

此外，$20!$ 已超过有符号 64 位整数上限。若需要精确排名更长的排列，应使用大整数；若问题只问排名模某个数，可以在每步取模，但这不再是可逆编号，因为不同排名可能模后相同。

## 六、系列总结

- 加法、乘法原理决定怎样计数；排列与组合由“顺序是否重要”分界。
- 全排列可由回溯或字典序生成，但 $n!$ 的输出规模决定了枚举边界。
- 重复元素需除以重复阶乘，并在搜索中跳过同层等价选择。
- 逆序数描述排列的颠倒结构，相邻交换每次改变其奇偶性。
- 康托展开用阶乘进制给不同元素的排列做双向编号，适合排名、反排名和状态压缩。

至此，“全排列”不再只是一段递归模板。它是一组彼此咬合的概念：计数回答有多少，生成回答怎样列出，字典序回答谁在前后，逆序数回答结构如何变化，康托展开则把整个排列空间压缩成可计算的整数坐标。理解这条链，才算真正把这个主题握在手里。
