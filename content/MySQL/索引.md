索引是数据库为了提高查询效率而维护的数据结构。它的本质是用额外的存储空间换取更少的数据扫描。

## 一、为什么需要索引

如果没有索引，数据库执行查询时通常需要扫描整张表。数据量较小时问题不明显，数据量达到百万、千万级后，全表扫描会带来明显的 IO 和 CPU 开销。

索引可以帮助数据库快速定位满足条件的数据行，减少扫描范围。

## 二、为什么常用 B+ 树

MySQL InnoDB 常用 B+ 树作为索引结构，主要原因是：

1. 树高低，可以减少磁盘页读取次数。
2. 叶子节点有序，适合范围查询。
3. 叶子节点之间有链表，适合顺序扫描。
4. 非叶子节点只保存索引键和指针，可以容纳更多分支。

相比红黑树，B+ 树更适合磁盘页模型。相比 Hash，B+ 树不仅支持等值查询，也支持范围查询和排序。

## 三、索引失效

索引失效通常不是索引真的消失，而是优化器认为无法高效使用索引，或使用索引的成本不划算。

常见原因包括：

1. 对索引列使用函数或表达式。
2. 字段类型和查询参数类型不一致。
3. 联合索引没有满足最左前缀原则。
4. 前置模糊查询，例如 `like '%abc'`。
5. 查询返回数据比例太高，优化器选择全表扫描。

例如字符串字段和数字比较时，MySQL 可能进行隐式类型转换。转换发生在字段侧时，索引就可能无法正常使用。

## 四、深度分页

深度分页也是常见性能问题：

```sql
select *
from orders
order by id
limit 1000000, 10;
```

数据库需要先找到前面的一百万行，再丢弃它们，只返回后面的十行。偏移量越大，成本越高。

常见优化方式是基于游标或上一页最后一个 ID 查询：

```sql
select *
from orders
where id > 1000000
order by id
limit 10;
```

## 五、总结

索引能显著提高查询效率，但它也会增加写入成本和存储成本。设计索引时要围绕真实查询条件、排序方式和数据分布，而不是看到字段就加索引。
