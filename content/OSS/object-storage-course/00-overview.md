你在电脑上保存一张照片时，通常只需要选择一个目录；程序会把路径、权限、磁盘空间这些细节替你处理。可一旦文件需要被网页、后台任务和多个服务同时访问，事情立刻变得复杂：机器换了怎么办？上传一半断网怎么办？谁有权读取？误删能不能找回？

对象存储就是为这类问题准备的网络数据服务。本课程从零解释它解决什么问题，再用一个本地 S3 兼容服务亲手完成上传、读取和恢复实验。RustFS 与 MinIO会作为可替换的实验实现出现；你学到的是 Bucket、S3 API、权限和恢复方法，而不是某个项目的部署细节。

## 先建立直觉：文件系统不够用时发生了什么

文件系统把数据组织成目录和文件，并提供随机修改、重命名和本机权限。它很适合操作系统和单台服务器。对象存储则通过 HTTP 把每份数据作为一个**对象**交给远程服务保存；客户端用一个名字请求整个对象或某个字节范围，并为请求附带身份凭据。

| 问题 | 本地文件系统的常见答案 | 对象存储的答案 |
| --- | --- | --- |
| 如何定位数据 | `C:\\data\\report.pdf` 这样的路径 | `bucket + key` |
| 谁能访问 | 主机用户和文件权限 | 访问密钥、临时凭据、策略、预签名 URL |
| 服务怎样读取 | 挂载同一块盘或复制文件 | HTTP/S3 API |
| 海量文件如何扩展 | 管理磁盘、共享文件系统 | 服务按对象管理容量与副本 |
| 误删怎样处理 | 取决于备份或回收站 | 版本、删除标记、生命周期、备份 |

对象存储不是“更大的网盘”，也不是数据库表。它最适合图片、音视频、PDF、备份包、构建产物、日志归档等大块或不可变内容。频繁修改同一个文件中间几个字节、需要目录级原子重命名、需要事务查询时，应考虑文件系统、关系型数据库或其他专用系统。

## 课程完成后，你能实际做到什么

- 说清 Bucket、Key、Object、Prefix、Metadata、ETag 和 Version 分别是什么，避免把 Prefix 误当目录、把 ETag 误当永远可靠的 MD5。
- 在本机启动 S3 兼容对象存储，用 AWS CLI 或 `mc` 创建 bucket、上传、列举、下载、范围读取和删除，并核对预期结果。
- 用 Python `boto3` 编写有超时、完整性校验、失败清理和预签名 URL 的上传下载代码；理解大文件为什么要 multipart upload。
- 为普通应用设计最小权限、CORS、版本与生命周期，并做一次“误删后恢复”和“备份后恢复”的演练。

## 实验准备与安全边界

准备 Docker Desktop、Python 3.10+，以及 AWS CLI v2 或 MinIO Client（`mc`）之一即可。后文的 access key 和 secret key 都是**仅限本机实验**的临时口令；不要复用公司、云账号或生产环境密钥，更不要把真实口令提交到 Git、写进截图或贴进工单。

PowerShell 中可先检查工具：

```powershell
docker version
python --version
aws --version       # 使用 AWS CLI 时
mc --version        # 使用 mc 时
```

课程统一使用一个新建的实验 bucket，例如 `os-lab-alice-2026`。bucket 名在同一服务中通常必须唯一；不要用业务 bucket 测试删除和生命周期。对象 key 建议使用可读、可筛选的命名：

```text
raw/acme/2026/10/8f4d/source.pdf
derived/acme/2026/10/8f4d/preview.png
backup/inventory/2026-10-02/manifest.json
```

斜杠只是 key 名的一部分，控制台将它画成“文件夹”只是方便人类浏览。每次实验都应保存命令输出、上传前后 SHA-256、`head-object` 结果和恢复记录；看到控制台有一个文件，并不能证明权限、完整性和恢复能力正确。
