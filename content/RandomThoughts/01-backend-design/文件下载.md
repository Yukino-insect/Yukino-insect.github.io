在服务器上提供文件下载，最朴素的做法是把文件放到 Web 目录，然后直接暴露 URL。但生产环境通常不建议这么做，尤其是文件需要权限控制时。

更稳妥的结构是：

```text
文件存私有目录 -> 应用做鉴权授权 -> Nginx 或对象存储负责传输
```

应用负责判断“能不能下载”，基础设施负责“高效地把文件传出去”。职责清楚，系统才不会一边鉴权一边艰难地搬文件。

## 方案一：X-Accel-Redirect

Nginx 的 `X-Accel-Redirect` 可以让后端完成鉴权后，把真实文件传输交给 Nginx。

文件放在私有目录：

```bash
/data/downloads/private/
```

目录不要直接暴露给外部访问：

```bash
sudo mkdir -p /data/downloads/private
sudo chown -R appuser:appgroup /data/downloads/private
sudo chmod 750 /data/downloads/private
```

Nginx 配置内部路径：

```nginx
server {
    listen 443 ssl;
    server_name example.com;

    location /_protected_files/ {
        internal;
        alias /data/downloads/private/;
        autoindex off;
        limit_rate 2m;
    }
}
```

关键是 `internal`。外部用户不能直接访问 `/_protected_files/...`，只能由后端响应头触发内部跳转。

Spring Boot 示例：

```java
@GetMapping("/api/files/{fileId}/download")
public ResponseEntity<Void> download(@PathVariable Long fileId,
                                     LoginUser loginUser) {
    FileMeta file = fileService.getFile(fileId);

    if (!filePermissionService.canDownload(loginUser.getId(), fileId)) {
        throw new AccessDeniedException("无权下载该文件");
    }

    String internalPath = "/_protected_files/" + file.getRelativePath();
    String filename = URLEncoder.encode(file.getOriginalName(), StandardCharsets.UTF_8)
            .replace("+", "%20");

    HttpHeaders headers = new HttpHeaders();
    headers.add("X-Accel-Redirect", internalPath);
    headers.add(HttpHeaders.CONTENT_DISPOSITION,
            "attachment; filename*=UTF-8''" + filename);

    return ResponseEntity.ok().headers(headers).build();
}
```

注意：`relativePath` 不应该来自用户输入直接拼接，而应该来自数据库中的受控元数据。

## 路径穿越

下载接口最需要防的是路径穿越。

危险请求可能长这样：

```text
/api/download?path=../../../../etc/passwd
```

不要相信用户传入的文件路径。推荐设计：

```text
用户传 fileId -> 后端查文件记录 -> 得到受控 relativePath -> 返回下载
```

如果确实需要处理路径，也要做规范化校验：

```java
Path baseDir = Paths.get("/data/downloads/private").toRealPath();
Path target = baseDir.resolve(relativePath).normalize();

if (!target.startsWith(baseDir)) {
    throw new AccessDeniedException("非法文件路径");
}
```

## 方案二：对象存储签名 URL

如果文件放在 OSS、S3、MinIO 这类对象存储里，可以由后端生成短时有效的签名 URL。

流程：

```text
1. 前端请求后端下载接口。
2. 后端鉴权。
3. 后端生成有效期很短的 signed URL。
4. 前端跳转 signed URL 下载。
5. 对象存储负责实际传输。
```

返回示例：

```json
{
  "downloadUrl": "https://oss.example.com/private/report.pdf?signature=...",
  "expiresIn": 300
}
```

这种方式适合大文件下载、跨区域分发、CDN 加速。签名 URL 有效期不要太长，最好配合权限、IP、下载次数或业务审计。

## 方案三：应用直接流式输出

小文件或内网文件，也可以由应用直接输出：

```java
@GetMapping("/api/files/{fileId}/download")
public void download(@PathVariable Long fileId, HttpServletResponse response) throws IOException {
    FileMeta file = fileService.getFile(fileId);
    Path path = fileStorage.resolve(file.getRelativePath());

    response.setContentType("application/octet-stream");
    response.setHeader(HttpHeaders.CONTENT_DISPOSITION,
            "attachment; filename=\"" + file.getOriginalName() + "\"");

    try (InputStream inputStream = Files.newInputStream(path);
         OutputStream outputStream = response.getOutputStream()) {
        inputStream.transferTo(outputStream);
    }
}
```

这种方式实现简单，但大文件会占用应用线程和带宽，不适合作为高并发下载主方案。

## 下载接口清单

设计下载功能时至少考虑：

- 鉴权：用户是否能下载这个文件。
- 授权：文件是否属于当前业务范围。
- 路径安全：防止路径穿越。
- 文件名编码：兼容中文和空格。
- Range 请求：大文件是否支持断点续传。
- 限速限频：避免被刷。
- 审计日志：谁在什么时候下载了什么。
- HTTPS：保护下载链接和身份凭证。
- 过期策略：临时链接必须有有效期。

## 小结

私有文件下载不要直接暴露真实路径。小文件可以应用流式输出，大文件和高并发下载更适合交给 Nginx 或对象存储。后端应该掌握权限判断，传输层负责高效发送。各做各的事，系统就不至于显得太辛苦。
