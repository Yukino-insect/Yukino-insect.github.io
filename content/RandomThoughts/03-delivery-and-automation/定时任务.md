定时任务用于在预定时间或固定间隔自动执行逻辑。它常见于清理数据、生成报表、刷新缓存、发送通知、同步第三方数据等场景。

定时任务看起来简单：加个 `@Scheduled` 就行。真正麻烦的是并发、幂等、集群重复执行、失败重试和监控。轻视这些问题，任务就会在凌晨两点替你证明它们存在。

## Spring Scheduling

Spring Boot 中使用定时任务，通常先开启调度能力：

```java
@Configuration
@EnableScheduling
public class SchedulingConfig {
}
```

然后在方法上添加 `@Scheduled`：

```java
@Component
public class ReportTask {

    @Scheduled(cron = "0 0 2 * * ?")
    public void generateDailyReport() {
        reportService.generateDailyReport();
    }
}
```

`@Scheduled` 常用三种触发方式：

| 参数 | 含义 |
| --- | --- |
| `fixedRate` | 以上一次开始时间为基准，固定频率执行 |
| `fixedDelay` | 以上一次结束时间为基准，延迟一段时间再执行 |
| `cron` | 按 Cron 表达式执行 |

## fixedRate 和 fixedDelay

`fixedRate` 看开始时间：

```java
@Scheduled(fixedRate = 5000)
public void syncTask() {
    // 每 5 秒触发一次
}
```

`fixedDelay` 看结束时间：

```java
@Scheduled(fixedDelay = 5000)
public void syncTask() {
    // 上一次执行结束 5 秒后，再触发下一次
}
```

如果任务执行时间不稳定，`fixedDelay` 更容易避免堆积。如果任务需要严格频率，例如采集指标，可以考虑 `fixedRate`，但要评估执行时间超过间隔后的行为。

默认情况下，Spring 的调度线程池通常不是为高并发任务准备的。要控制并发能力，应该显式配置线程池：

```java
@Bean
public ThreadPoolTaskScheduler taskScheduler() {
    ThreadPoolTaskScheduler scheduler = new ThreadPoolTaskScheduler();
    scheduler.setPoolSize(8);
    scheduler.setThreadNamePrefix("scheduler-");
    scheduler.setWaitForTasksToCompleteOnShutdown(true);
    scheduler.setAwaitTerminationSeconds(30);
    return scheduler;
}
```

## Cron 表达式

Spring 常用 Cron 表达式由 6 个字段组成，也可以带第 7 个年份字段：

```text
秒 分 时 日 月 周 [年]
```

常见例子：

| 表达式 | 含义 |
| --- | --- |
| `0 0/5 * * * ?` | 每 5 分钟执行一次 |
| `0 0 2 * * ?` | 每天凌晨 2 点执行 |
| `0 0 9,18 * * ?` | 每天 9 点和 18 点执行 |
| `0 0/10 9-17 * * ?` | 每天 9 点到 17 点每 10 分钟执行 |
| `0 30 10 ? * MON-FRI` | 周一到周五 10:30 执行 |
| `0 0 0 L * ?` | 每月最后一天 0 点执行 |

`日` 和 `周` 两个字段容易冲突，所以经常用 `?` 表示“不指定”。

## 动态任务

如果 Cron 表达式需要从数据库或配置中心读取，可以实现 `SchedulingConfigurer`。

```java
@Configuration
@EnableScheduling
public class DynamicSchedulingConfig implements SchedulingConfigurer {

    @Override
    public void configureTasks(ScheduledTaskRegistrar registrar) {
        registrar.addTriggerTask(
                () -> taskService.execute(),
                context -> {
                    String cron = taskConfigService.getCron();
                    return new CronTrigger(cron).nextExecutionTime(context);
                }
        );
    }
}
```

动态任务适合运营可配置的任务。只是别忘了校验 Cron 表达式，否则配置错一次，任务不是狂奔就是沉睡。

## 异步执行

`@Scheduled` 负责触发，`@Async` 负责异步执行。两者可以组合：

```java
@Scheduled(fixedRate = 1000)
@Async("taskExecutor")
public void collectMetrics() {
    metricsService.collect();
}
```

线程池配置：

```java
@Configuration
@EnableAsync
public class AsyncConfig {

    @Bean("taskExecutor")
    public Executor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);
        executor.setMaxPoolSize(8);
        executor.setQueueCapacity(1000);
        executor.setThreadNamePrefix("async-task-");
        executor.initialize();
        return executor;
    }
}
```

异步可以提高吞吐，但也会带来新问题：同一个任务可能并发执行。任务内部必须考虑线程安全、幂等和重复处理。

## 集群重复执行

在单机应用里，`@Scheduled` 只执行一次。到了多节点部署，每个节点都会执行同一个任务。

解决方式：

- 只在一个专门的任务节点开启调度。
- 使用分布式锁，例如 Redis、数据库锁、ZooKeeper。
- 使用调度平台，例如 Quartz、XXL-JOB、ElasticJob。
- 让任务本身幂等，允许重复触发但不重复产生业务影响。

简单的 Redis 锁思路：

```java
Boolean locked = redis.opsForValue()
        .setIfAbsent("lock:daily-report", nodeId, Duration.ofMinutes(30));

if (!Boolean.TRUE.equals(locked)) {
    return;
}

try {
    reportService.generate();
} finally {
    releaseLockSafely("lock:daily-report", nodeId);
}
```

释放锁时要确认锁仍属于当前节点，不能直接删除。否则任务超时后锁被别人拿到，你再删除，就等于替别人开门。

## 任务设计原则

定时任务最好满足这些要求：

- 幂等：重复执行不会产生错误结果。
- 可重试：短暂失败可以安全重试。
- 可观测：有日志、指标、耗时、成功失败计数。
- 可中断：应用关闭时能优雅停止。
- 可补偿：错过执行窗口后能补跑。
- 有超时：避免任务永久卡住。

任务执行日志建议记录：

- taskName
- triggerTime
- startTime
- endTime
- status
- errorMessage
- traceId

## Quartz

Spring Scheduling 适合轻量任务。Quartz 更适合复杂调度场景：

- 任务持久化。
- 暂停、恢复、删除任务。
- 集群调度。
- Misfire 策略。
- 更复杂的 Trigger 管理。

如果只是每天凌晨清理一次数据，用 Spring Scheduling 足够。如果要做一个可配置任务平台，再考虑 Quartz 或专门的调度系统。

## 小结

定时任务的重点不是“怎么让它按时跑”，而是“它失败、重复、并发、超时、部署多节点时会怎样”。单机小任务用 `@Scheduled` 很好；集群关键任务要考虑锁、幂等、监控和补偿。半夜出问题的任务，通常白天就已经写好了。
