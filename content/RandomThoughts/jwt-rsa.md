JWT 常用于无状态登录和服务间身份传递。结合 RSA 时，通常指使用私钥签名 JWT，再用公钥验证 JWT。

## 一、签名不是加密

常见 JWT 是 JWS，也就是签名 token。它的 payload 可以被客户端解码看到，因此不要把密码、密钥、身份证号等敏感信息放进 JWT。

签名的作用是防篡改。只要攻击者没有私钥，就无法伪造合法签名。

## 二、JWT 与 RSA 的流程

典型流程如下：

1. 认证服务校验用户名和密码。
2. 校验成功后，认证服务使用 RSA 私钥签名 JWT。
3. 客户端保存 JWT。
4. 请求业务服务时携带 JWT。
5. 业务服务使用 RSA 公钥验证签名。
6. 验证通过后读取用户身份和权限信息。

业务服务只需要公钥，不需要访问认证服务，也不需要持有私钥。

## 三、JWT 加 Redis

完全无状态 JWT 的问题是主动失效困难。例如用户退出登录、管理员强制下线、权限变更后，已签发的 JWT 在过期前仍可能有效。

因此可以结合 Redis 保存 token 状态、黑名单或用户版本号。这样会牺牲一部分无状态特性，但换来主动控制能力。

## 四、选择建议

如果系统更重视横向扩展和服务间独立校验，可以使用 JWT 加 RSA，并设置较短过期时间。

如果系统更重视强制下线、单点登录状态控制和权限即时生效，可以使用 Redis 保存登录态，或在 JWT 方案中加入黑名单和版本校验。

总结来说，JWT 加 RSA 解决的是“可信签名”和“分布式验证”问题，不等于自动解决所有登录态管理问题。
