软件行业常用 C 端、B 端、G 端描述服务对象，也会用 B2C、B2B、C2C、O2O 描述交易关系。理解这些概念，有助于判断产品形态、销售方式和系统设计重点。

这些词不只是商业缩写，它们会直接影响系统怎么做。服务对象不同，权限、部署、数据模型、运营方式都会不同。

## 按服务对象划分

| 类型 | 含义 | 典型产品 | 系统重点 |
| --- | --- | --- | --- |
| C 端 | Consumer，个人消费者 | 短视频、社交、电商、在线音乐、个人网盘 | 体验、增长、留存、推荐、支付转化 |
| B 端 | Business，企业或组织 | CRM、ERP、OA、SaaS、财务系统、供应链系统 | 权限、流程、审计、报表、配置能力 |
| G 端 | Government，政府或政务机构 | 政务平台、监管系统、公共服务平台 | 合规、安全、稳定、内网部署、审计留痕 |

C 端产品更关心用户是否愿意继续用，B 端产品更关心组织流程能不能跑通，G 端产品更关心是否符合规范和长期稳定运行。

## To C

`To C` 面向个人用户。

特点：

- 用户数量大。
- 使用场景碎片化。
- 对体验和性能敏感。
- 增长、活动、推荐、风控很重要。
- 商业化常见于广告、会员、付费内容、交易抽佣。

系统设计上通常关注：

- 高并发。
- 缓存。
- 推荐系统。
- 内容审核。
- 活动系统。
- 支付和风控。
- A/B 测试。

## To B

`To B` 面向企业客户。

特点：

- 客户数量可能不多，但单客户价值高。
- 销售、实施、培训、售后链路长。
- 需求更重流程和管理。
- 客户常要求定制化。
- 数据准确性和权限边界非常重要。

系统设计上通常关注：

- 多租户。
- 组织架构。
- 角色权限。
- 审批流程。
- 操作日志。
- 数据导入导出。
- 字段、表单、流程配置。

B 端系统里，“能不能配置”经常比“页面好不好看”更重要。当然，难看的系统也不会因此变得合理，它只是拥有了另一个问题。

## To G

`To G` 面向政务客户。

特点：

- 常涉及招投标和项目制交付。
- 强调合规、安全和稳定。
- 可能需要内网部署。
- 对审计、留痕、数据隔离要求高。
- 可能涉及国产化适配、等保、信创环境。

系统设计上通常关注：

- 权限分级。
- 数据安全。
- 操作审计。
- 接口规范。
- 部署环境适配。
- 长期运维。
- 灾备和容灾。

## 交易关系

服务对象描述的是“卖给谁”或“服务谁”，交易关系描述的是“谁和谁交易”。

| 模式 | 含义 | 例子 |
| --- | --- | --- |
| B2C | 企业对消费者 | 电商平台自营商品卖给个人 |
| B2B | 企业对企业 | 企业软件、SaaS、供应链平台 |
| C2C | 消费者对消费者 | 二手交易、个人卖家平台 |
| O2O | 线上到线下 | 外卖、到店服务、线上预约线下履约 |

一个产品可能同时有多个属性。例如外卖平台既有 C 端用户，也有 B 端商家，还涉及 O2O 履约。概念不是拿来贴标签的，而是帮助分析系统复杂度。

## 同一功能的差异

同样是“用户系统”，不同端的重点会完全不同。

| 场景 | 用户系统重点 |
| --- | --- |
| C 端 | 注册登录、第三方登录、用户画像、会员体系 |
| B 端 | 企业、部门、岗位、角色、数据权限 |
| G 端 | 实名认证、单位层级、权限审批、审计追溯 |

同样是“消息系统”：

| 场景 | 消息系统重点 |
| --- | --- |
| C 端 | 推送到达率、点击率、频控、个性化 |
| B 端 | 待办、审批通知、站内信、企业微信/邮件集成 |
| G 端 | 公文流转、短信通知、留痕、送达确认 |

## 小结

C 端、B 端、G 端不是简历上的装饰词，而是产品和系统设计的起点。先弄清服务对象，再谈架构设计。否则你可能会用 C 端思路做 B 端流程系统，最后得到一个既不灵活也不顺手的东西，倒是很公平地让所有人都不满意。
