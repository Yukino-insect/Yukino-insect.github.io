Redis 主从复制用于把主节点的数据同步到从节点。它的核心目标不是让从节点在每一个瞬间都和主节点绝对一致，而是在较低开销下提供读扩展、故障切换基础和数据冗余能力。

## 一、同步过程

Redis 主从同步主要分为全量同步和增量同步。

全量同步通常发生在从节点第一次连接主节点、复制偏移量无法继续衔接、复制积压缓冲区中的历史数据已经被覆盖等场景。此时主节点会生成 RDB 快照，并把快照发送给从节点。从节点加载快照后，再继续接收主节点在快照生成期间产生的写命令。

增量同步发生在从节点短暂断线后重新连接主节点，并且主节点的复制积压缓冲区中仍然保留着从节点缺失的那段命令。此时从节点只需要根据复制偏移量补齐缺失数据，不必重新加载完整快照。

## 二、关键概念

主从复制依赖三个概念：

1. 复制 ID：标识一次主节点复制历史。
2. 复制偏移量：记录主从双方已经同步到的位置。
3. 复制积压缓冲区：主节点保存最近写命令的环形缓冲区。

如果从节点重连时复制 ID 能对应上，并且缺失偏移量仍在复制积压缓冲区内，就可以做增量同步。否则只能退回全量同步。

## 三、同步不是强一致

Redis 主从复制默认是异步的。主节点写入成功后，不会等待所有从节点确认才返回客户端。因此在主节点刚写完、从节点尚未同步完成的短时间窗口内，读从库可能读到旧数据。

如果业务对一致性要求很高，不能简单地把所有读流量都放到从节点。常见做法是：

1. 强一致读仍然访问主节点。
2. 允许短暂延迟的查询访问从节点。
3. 监控主从复制延迟，延迟过大时临时摘除从节点读流量。
4. 使用 `WAIT` 命令提高写入被从节点确认的概率，但它仍不等同于严格分布式事务。

## 四、实践注意点

主从复制要重点关注复制积压缓冲区大小。如果缓冲区太小，从节点稍微断线久一点就可能无法增量同步，只能全量同步，进而带来磁盘、网络和 CPU 压力。

在生产环境中，还应关注以下指标：

1. 主从复制延迟。
2. 全量同步发生频率。
3. 从节点重连次数。
4. 主节点网络出口带宽。
5. RDB 生成对磁盘和 CPU 的影响。

总结来说，Redis 主从复制的本质是基于复制偏移量的异步命令传播机制。它适合提升读能力和可用性，但不能把它误解成强一致的数据同步方案。
