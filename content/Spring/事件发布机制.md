Spring 事件发布机制用于在同一个应用进程内解耦业务逻辑。发布方只负责发布事件，监听方根据事件类型执行后续动作，双方不需要直接依赖。

## 一、基本模型

Spring 事件机制主要包含三部分：

1. 事件对象：描述发生了什么。
2. 事件发布器：通常是 `ApplicationEventPublisher`。
3. 事件监听器：使用 `@EventListener` 或实现监听接口。

示例：

```java
public record UserCreatedEvent(Long userId) {
}
```

发布事件：

```java
applicationEventPublisher.publishEvent(new UserCreatedEvent(userId));
```

监听事件：

```java
@EventListener
public void onUserCreated(UserCreatedEvent event) {
    // 发送欢迎消息或初始化用户配置
}
```

## 二、同步和异步

默认情况下，Spring 事件监听是同步执行的。也就是说，发布事件的方法会等待监听器执行完成。

如果希望异步执行，可以结合 `@Async` 和线程池配置：

```java
@Async
@EventListener
public void onUserCreated(UserCreatedEvent event) {
    // 异步处理
}
```

异步事件可以降低主流程耗时，但异常处理、线程池容量和上下文传递都要额外关注。

## 三、事务边界

如果事件和数据库事务有关，应考虑 `@TransactionalEventListener`。

例如希望用户创建事务提交成功后再发送消息，可以使用：

```java
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void afterCommit(UserCreatedEvent event) {
    // 事务提交后执行
}
```

这样可以避免事务回滚后，监听器却已经执行了外部动作。

## 四、和 MQ 的区别

Spring 事件只适合同一个 JVM 进程内的解耦。它不适合跨服务通信，也不具备消息队列那样的持久化、重试、消费确认和削峰能力。

如果事件需要跨服务传递，或者要求失败重试和可靠投递，应使用 MQ、发件箱模式等方案。

## 五、总结

Spring 事件适合做进程内解耦，例如发送通知、记录审计、初始化附属数据。它不是分布式消息系统，不能用来替代 MQ。
