Vue 项目变复杂，首先复杂在组件。一个页面里可能有筛选区、列表、卡片、弹窗、表单、分页、空状态、加载状态。如果全写在一个文件里，后续维护会很难。

组件化的目标不是把文件拆多，而是让职责变清楚。

## 一、组件边界

适合拆组件的情况：

- 模板超过一屏，阅读困难。
- 某块 UI 有独立业务含义。
- 需要复用。
- 有明确输入和输出。
- 内部状态可以独立管理。

不适合拆的情况：

- 只有两三行简单结构。
- 拆完后父子之间传参更复杂。
- 组件没有独立语义，只是为了显得“工程化”。

抽象要服务维护，不要服务自我感动。

## 二、props

父组件向子组件传数据。

```vue
<PostCard
  :post="post"
  :show-actions="true"
/>
```

子组件：

```ts
type Props = {
  post: PostCard
  showActions?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  showActions: true
})
```

props 是只读的。子组件不应该直接修改父组件传进来的对象，除非团队明确约定并知道后果。

## 三、emits

子组件通过事件通知父组件。

```vue
<PostCard
  :post="post"
  @like="handleLike"
/>
```

子组件：

```ts
const emit = defineEmits<{
  like: [postId: number]
}>()

function onLikeClick() {
  emit('like', props.post.id)
}
```

这样父组件仍然掌握业务决策权。子组件只负责表达用户行为。

## 四、v-model 组件

自定义组件也可以支持 `v-model`。

```vue
<SearchBox v-model="keyword" />
```

子组件：

```ts
const model = defineModel<string>({
  required: true
})
```

模板：

```vue
<input v-model="model">
```

`v-model` 适合输入类组件。对于复杂业务动作，仍然推荐明确事件名，如 `submit`、`remove`、`refresh`。

## 五、插槽

插槽让父组件传入一段模板。

```vue
<BaseCard>
  <template #header>
    <h3>文章标题</h3>
  </template>

  <p>正文内容</p>
</BaseCard>
```

子组件：

```vue
<article class="card">
  <header>
    <slot name="header"></slot>
  </header>
  <main>
    <slot></slot>
  </main>
</article>
```

插槽适合封装布局骨架，让内容由调用方决定。

## 六、作用域插槽

子组件可以把数据传给插槽内容。

```vue
<DataList :items="posts">
  <template #default="{ item }">
    <PostCard :post="item" />
  </template>
</DataList>
```

子组件：

```vue
<template>
  <div>
    <slot
      v-for="item in items"
      :key="item.id"
      :item="item"
    ></slot>
  </div>
</template>
```

作用域插槽适合封装列表逻辑、表格列、弹窗内容等高级场景。

## 七、provide 与 inject

多层组件传递公共数据时，可以使用 `provide` 和 `inject`。

父级：

```ts
provide('theme', theme)
```

后代组件：

```ts
const theme = inject<Ref<string>>('theme')
```

它适合主题、表单上下文、局部组件树共享状态。不建议拿它替代 Pinia 做全局状态。

## 八、组合函数复用逻辑

当多个组件共享逻辑，而不是共享 UI，就用组合函数。

```ts
export function usePagination() {
  const page = ref(1)
  const pageSize = ref(20)

  function resetPage() {
    page.value = 1
  }

  return {
    page,
    pageSize,
    resetPage
  }
}
```

组合函数适合：

- 分页。
- 加载状态。
- 弹窗开关。
- 表单校验。
- 请求状态。
- 事件监听。

## 九、组件设计检查清单

- 组件是否有清晰职责？
- props 是否足够少且语义明确？
- emits 是否表达用户行为，而不是内部细节？
- 插槽是否真的必要？
- 状态属于当前组件还是父组件？
- 组件是否依赖过多全局对象？

## 十、练习

拆一个文章列表页：

```text
PostListPage
 -> SearchBar
 -> PostList
 -> PostCard
 -> EmptyState
 -> LoadMoreButton
```

要求：

- 搜索关键字由页面维护。
- `PostCard` 只接收文章并发出点赞事件。
- 空状态组件不依赖业务接口。
- 分页逻辑放到组合函数。

这样拆完，页面才像页面，组件才像组件。
