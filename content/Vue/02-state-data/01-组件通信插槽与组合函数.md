Vue 项目变复杂，首先复杂在组件。一个页面里可能有筛选区、列表、卡片、弹窗、表单、分页、空状态、加载状态。如果全写在一个文件里，后续维护会很难。

组件化的目标不是把文件拆多，而是让职责变清楚。

## 一、组件边界

适合拆组件的情况：

- 模板超过一屏，阅读困难。
- 某块 UI 有独立业务含义。
- 需要复用。
- 有明确输入和输出。
- 内部状态可以独立管理。

不适合拆的情况：

- 只有两三行简单结构。
- 拆完后父子之间传参更复杂。
- 组件没有独立语义，只是为了显得“工程化”。

抽象要服务维护，不要服务自我感动。

## 二、props

父组件向子组件传数据。

```vue
<PostCard
  :post="post"
  :show-actions="true"
/>
```

子组件：

```ts
type Props = {
  post: PostCard
  showActions?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  showActions: true
})
```

props 是只读的。子组件不应该直接修改父组件传进来的对象，除非团队明确约定并知道后果。

## 三、emits

子组件通过事件通知父组件。

```vue
<PostCard
  :post="post"
  @like="handleLike"
/>
```

子组件：

```ts
const emit = defineEmits<{
  like: [postId: number]
}>()

function onLikeClick() {
  emit('like', props.post.id)
}
```

这样父组件仍然掌握业务决策权。子组件只负责表达用户行为。

## 四、v-model 组件

自定义组件也可以支持 `v-model`。

```vue
<SearchBox v-model="keyword" />
```

子组件：

```ts
const model = defineModel<string>({
  required: true
})
```

模板：

```vue
<input v-model="model">
```

`v-model` 适合输入类组件。对于复杂业务动作，仍然推荐明确事件名，如 `submit`、`remove`、`refresh`。

## 五、插槽

插槽让父组件传入一段模板。

```vue
<BaseCard>
  <template #header>
    <h3>文章标题</h3>
  </template>

  <p>正文内容</p>
</BaseCard>
```

子组件：

```vue
<article class="card">
  <header>
    <slot name="header"></slot>
  </header>
  <main>
    <slot></slot>
  </main>
</article>
```

插槽适合封装布局骨架，让内容由调用方决定。

## 六、作用域插槽

子组件可以把数据传给插槽内容。

```vue
<DataList :items="posts">
  <template #default="{ item }">
    <PostCard :post="item" />
  </template>
</DataList>
```

子组件：

```vue
<template>
  <div>
    <slot
      v-for="item in items"
      :key="item.id"
      :item="item"
    ></slot>
  </div>
</template>
```

作用域插槽适合封装列表逻辑、表格列、弹窗内容等高级场景。

## 七、provide 与 inject

多层组件传递公共数据时，可以使用 `provide` 和 `inject`。

父级：

```ts
provide('theme', theme)
```

后代组件：

```ts
const theme = inject<Ref<string>>('theme')
```

它适合主题、表单上下文、局部组件树共享状态。不建议拿它替代 Pinia 做全局状态。

## 八、组合函数复用逻辑

当多个组件共享逻辑，而不是共享 UI，就用组合函数。

```ts
export function usePagination() {
  const page = ref(1)
  const pageSize = ref(20)

  function resetPage() {
    page.value = 1
  }

  return {
    page,
    pageSize,
    resetPage
  }
}
```

组合函数适合：

- 分页。
- 加载状态。
- 弹窗开关。
- 表单校验。
- 请求状态。
- 事件监听。

## 九、组件设计检查清单

- 组件是否有清晰职责？
- props 是否足够少且语义明确？
- emits 是否表达用户行为，而不是内部细节？
- 插槽是否真的必要？
- 状态属于当前组件还是父组件？
- 组件是否依赖过多全局对象？

## 十、拆组件时的工程判断

组件拆分不是把一个文件切成几块，而是把“变化原因”隔离开。搜索框因为输入逻辑变化而改，文章卡片因为展示规则变化而改，分页因为加载策略变化而改。它们不应该互相牵连。若拆完之后每个组件都要知道所有业务细节，那只是把混乱搬了家。

## 十一、练习讲解：拆一个文章列表页

拆一个文章列表页：

```text
PostListPage
 -> SearchBar
 -> PostList
 -> PostCard
 -> EmptyState
 -> LoadMoreButton
```

要求：

- 搜索关键字由页面维护。
- `PostCard` 只接收文章并发出点赞事件。
- 空状态组件不依赖业务接口。
- 分页逻辑放到组合函数。

这样拆完，页面才像页面，组件才像组件。

### 3. 创建 `src/composables/usePagination.ts`

```ts
import { computed, ref } from 'vue'

export function usePagination(pageSize = 3) {
  const page = ref(1)

  const offset = computed(() => {
    return (page.value - 1) * pageSize
  })

  function nextPage(total: number) {
    const maxPage = Math.ceil(total / pageSize)
    if (page.value < maxPage) {
      page.value++
    }
  }

  function resetPage() {
    page.value = 1
  }

  return {
    page,
    pageSize,
    offset,
    nextPage,
    resetPage
  }
}
```

### 9. 替换 `src/App.vue`

```vue
<script setup lang="ts">
import { computed, ref, watch } from 'vue'
import EmptyState from './components/EmptyState.vue'
import LoadMoreButton from './components/LoadMoreButton.vue'
import PostList from './components/PostList.vue'
import SearchBar from './components/SearchBar.vue'
import { usePagination } from './composables/usePagination'
import type { Post } from './types'

const keyword = ref('')
const { page, pageSize, offset, nextPage, resetPage } = usePagination(3)

const posts = ref<Post[]>([
  { id: 1, title: '组件边界怎么判断', summary: '根据职责和变化原因拆分。', likes: 11, liked: false },
  { id: 2, title: 'props 和 emits 的职责', summary: '父传子数据，子通知父事件。', likes: 6, liked: false },
  { id: 3, title: '插槽适合封装什么', summary: '封装结构，把内容交给调用方。', likes: 4, liked: false },
  { id: 4, title: '组合函数不是工具函数', summary: '组合函数可以拥有响应式状态。', likes: 13, liked: true },
  { id: 5, title: '空状态组件如何设计', summary: '不依赖业务接口，只表达通用状态。', likes: 2, liked: false }
])

const matchedPosts = computed(() => {
  const text = keyword.value.trim().toLowerCase()
  if (!text) {
    return posts.value
  }
  return posts.value.filter((post) => post.title.toLowerCase().includes(text))
})

const visiblePosts = computed(() => {
  return matchedPosts.value.slice(0, offset.value + pageSize)
})

const finished = computed(() => {
  return visiblePosts.value.length >= matchedPosts.value.length
})

watch(keyword, () => {
  resetPage()
})

function handleLike(postId: number) {
  const post = posts.value.find((item) => item.id === postId)
  if (!post) {
    return
  }
  post.liked = !post.liked
  post.likes += post.liked ? 1 : -1
}
</script>

<template>
  <main class="page">
    <h1>文章列表页拆分练习</h1>
    <SearchBar v-model="keyword" @search="resetPage" />
    <EmptyState v-if="visiblePosts.length === 0" />
    <template v-else>
      <PostList :posts="visiblePosts" @like="handleLike" />
      <LoadMoreButton :disabled="finished" @load-more="nextPage(matchedPosts.length)" />
    </template>
  </main>
</template>

<style scoped>
.page {
  display: grid;
  gap: 16px;
  max-width: 820px;
  margin: 0 auto;
  padding: 32px 20px;
}

h1 {
  margin: 0;
  font-size: 26px;
}
</style>
```
