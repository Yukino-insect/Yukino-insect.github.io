很多教程只展示成功路径：输入内容，点击提交，页面完成。真实项目不会这么乖。用户会输空值，网络会失败，权限会过期，列表会为空，接口会返回奇怪数据。

这一篇讨论真实业务页面必须处理的细节。

## 一、表单状态

表单至少包含：

- 字段值。
- 校验错误。
- 提交状态。
- 服务端错误。

```ts
type LoginForm = {
  username: string
  password: string
}

const form = reactive<LoginForm>({
  username: '',
  password: ''
})

const errors = reactive<Partial<Record<keyof LoginForm, string>>>({})
const submitting = ref(false)
```

## 二、表单校验

简单校验可以手写：

```ts
function validateLoginForm() {
  errors.username = form.username.trim() ? '' : '请输入用户名'
  errors.password = form.password ? '' : '请输入密码'

  return !errors.username && !errors.password
}
```

提交：

```ts
async function submit() {
  if (!validateLoginForm()) {
    return
  }

  submitting.value = true
  try {
    await authStore.login(form)
  } finally {
    submitting.value = false
  }
}
```

复杂表单可以使用校验库，但先理解校验流程，不要把库当作遮羞布。

## 三、列表状态

列表页常见状态：

- 首次加载。
- 下拉刷新。
- 加载更多。
- 没有更多。
- 空数据。
- 加载失败。

分页状态：

```ts
const records = ref<PostCard[]>([])
const page = ref(1)
const pageSize = 20
const total = ref(0)
const loading = ref(false)
const refreshing = ref(false)

const finished = computed(() => records.value.length >= total.value)
```

加载更多：

```ts
async function loadMore() {
  if (loading.value || finished.value) {
    return
  }

  loading.value = true
  try {
    const result = await fetchPostPage({
      page: page.value,
      pageSize
    })
    records.value.push(...result.records)
    total.value = result.total
    page.value++
  } finally {
    loading.value = false
  }
}
```

## 四、防重复提交

按钮提交必须防重复。

```vue
<button :disabled="submitting" @click="submit">
  {{ submitting ? '提交中' : '提交' }}
</button>
```

逻辑层也要防：

```ts
async function submit() {
  if (submitting.value) {
    return
  }

  submitting.value = true
  try {
    await save()
  } finally {
    submitting.value = false
  }
}
```

只禁用按钮不够，因为函数也可能被其他路径调用。

## 五、错误态设计

错误处理要分层：

| 层级 | 处理内容 |
| ---- | -------- |
| 请求封装 | 网络错误、状态码、统一响应码 |
| API 模块 | 业务接口语义 |
| Store | 状态回滚、缓存策略 |
| 页面 | 错误展示、重试按钮 |

页面错误提示示例：

```vue
<ErrorView
  v-if="errorMessage"
  :message="errorMessage"
  @retry="loadData"
/>
```

错误态应该给用户下一步动作，例如重试、重新登录、返回上一页。

## 六、空状态

空状态不是错误。

```vue
<EmptyView
  v-if="!loading && posts.length === 0"
  title="暂无内容"
/>
```

常见空状态：

- 搜索无结果。
- 用户还没有发布内容。
- 筛选条件太严格。
- 数据被删除。

文案应该和场景匹配，不要所有页面都写“暂无数据”。这几个字当然方便，只是毫无帮助。

## 七、权限

前端权限控制分两类：

- 页面级权限：能不能进入某个页面。
- 操作级权限：能不能点击某个按钮。

前端可以控制展示，但不能替代后端鉴权。后端接口必须继续校验权限。

前端操作权限示例：

```vue
<button v-if="canEditPost(post)" @click="editPost(post.id)">
  编辑
</button>
```

```ts
function canEditPost(post: PostCard) {
  return authStore.profile?.id === post.authorId || authStore.hasRole('admin')
}
```

## 八、登录过期

请求封装中遇到 401，可以统一处理：

```ts
if (response.status === 401) {
  authStore.logout()
  router.push('/login')
  throw new Error('登录已过期')
}
```

注意防止重复跳转和重复弹窗。全局错误处理要克制，否则用户会被同一个错误提醒轰炸。

## 九、业务页面检查清单

写业务页面时至少问自己：

- 首次加载、提交中、失败、空数据是否都有明确 UI？
- 用户能不能重复点击导致重复提交？
- 前端隐藏按钮后，后端是否仍然校验权限？
- 失败后数据是否会被错误清空？
- 成功后页面跳转、提示、缓存更新是否一致？

这些都不是“细节”。它们是页面能不能交付的分界线。

## 十、练习讲解：发布文章页面

做一个发布文章页面：

- 标题不能为空。
- 内容不少于 10 个字符。
- 提交中禁用按钮。
- 提交失败显示错误。
- 未登录时跳转登录页。
- 提交成功后返回详情页。

这类页面看起来普通，却覆盖了表单、校验、请求、权限、错误和路由。能把普通页面写稳，就是很重要的能力。

### 2. 替换 `src/main.ts`

```ts
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import { createRouter, createWebHistory } from 'vue-router'
import './style.css'
import App from './App.vue'

const routes = [
  { path: '/', redirect: '/posts/create' },
  { path: '/login', component: () => import('./pages/LoginPage.vue') },
  {
    path: '/posts/create',
    component: () => import('./pages/PostCreatePage.vue'),
    meta: { requiresAuth: true }
  },
  { path: '/posts/:id', component: () => import('./pages/PostDetailPage.vue') }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

router.beforeEach((to) => {
  const token = localStorage.getItem('token')
  if (to.meta.requiresAuth && !token) {
    return {
      path: '/login',
      query: { redirect: to.fullPath }
    }
  }
})

createApp(App)
  .use(createPinia())
  .use(router)
  .mount('#app')
```

### 3. 创建 `src/api/posts.ts`

```ts
export type CreatePostRequest = {
  title: string
  content: string
}

export async function createPostApi(form: CreatePostRequest): Promise<{ id: number }> {
  await new Promise((resolve) => window.setTimeout(resolve, 500))

  if (form.title.includes('失败')) {
    throw new Error('服务端拒绝了这个标题，请换一个更正常的标题')
  }

  return {
    id: Date.now()
  }
}
```

### 6. 创建 `src/pages/PostCreatePage.vue`

```vue
<script setup lang="ts">
import { reactive, ref } from 'vue'
import { useRouter } from 'vue-router'
import { createPostApi } from '../api/posts'

type FormState = {
  title: string
  content: string
}

const router = useRouter()

const form = reactive<FormState>({
  title: '',
  content: ''
})

const errors = reactive<Partial<Record<keyof FormState, string>>>({})
const serverError = ref('')
const submitting = ref(false)

function validateForm() {
  errors.title = form.title.trim() ? '' : '标题不能为空'
  errors.content = form.content.trim().length >= 10 ? '' : '内容不能少于 10 个字符'

  return !errors.title && !errors.content
}

async function submit() {
  if (submitting.value) {
    return
  }

  serverError.value = ''

  if (!validateForm()) {
    return
  }

  submitting.value = true
  try {
    const result = await createPostApi({
      title: form.title.trim(),
      content: form.content.trim()
    })
    router.push(`/posts/${result.id}`)
  } catch (error) {
    serverError.value = error instanceof Error ? error.message : '提交失败'
  } finally {
    submitting.value = false
  }
}
</script>

<template>
  <main class="page">
    <h1>发布文章</h1>

    <form class="form" @submit.prevent="submit">
      <label>
        标题
        <input v-model.trim="form.title" :aria-invalid="Boolean(errors.title)" />
      </label>
      <p v-if="errors.title" class="field-error">{{ errors.title }}</p>

      <label>
        内容
        <textarea v-model="form.content" :aria-invalid="Boolean(errors.content)" rows="6"></textarea>
      </label>
      <p v-if="errors.content" class="field-error">{{ errors.content }}</p>

      <p v-if="serverError" class="server-error">{{ serverError }}</p>

      <button :disabled="submitting" type="submit">
        {{ submitting ? '提交中...' : '提交' }}
      </button>
    </form>
  </main>
</template>
```
