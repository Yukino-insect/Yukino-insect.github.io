项目能在本地运行，只是最低要求。上线后还要面对网络、设备、缓存、兼容、接口波动和用户操作。工程成熟度体现在这些不顺利的时候。

## 一、性能优化先看瓶颈

不要一上来就“优化”。先判断慢在哪里：

- 首屏资源太大。
- 接口响应慢。
- 列表渲染太多。
- 图片太大。
- 重复请求。
- 计算逻辑过重。
- 不必要的组件重渲染。

没有定位的优化，通常只是把代码改得更复杂。

## 二、列表优化

长列表常见问题是一次渲染太多 DOM。

基本做法：

- 分页加载。
- 懒加载更多。
- 虚拟列表。
- 图片懒加载。
- 避免在模板中执行复杂函数。

不推荐：

```vue
<PostCard
  v-for="post in heavyTransform(posts)"
  :key="post.id"
  :post="post"
/>
```

推荐：

```ts
const visiblePosts = computed(() => {
  return heavyTransform(posts.value)
})
```

模板只使用结果：

```vue
<PostCard
  v-for="post in visiblePosts"
  :key="post.id"
  :post="post"
/>
```

## 三、图片优化

图片常见问题：

- 尺寸远大于展示区域。
- 没有压缩。
- 列表中一次加载太多。
- 缺少占位和失败图。

组件应该处理基本状态：

```vue
<img
  :src="src"
  :alt="alt"
  loading="lazy"
  @error="handleError"
>
```

图片路径也要统一处理，避免接口返回相对路径、绝对路径、空字符串时页面表现不一致。

## 四、避免重复请求

常见重复请求来源：

- `watch` 依赖设置不当。
- 页面多次进入重复加载。
- 按钮没有防抖。
- 滚动到底触发多次加载。

防抖：

```ts
let timer: ReturnType<typeof setTimeout> | undefined

function debounceSearch() {
  clearTimeout(timer)
  timer = setTimeout(() => {
    loadPosts()
  }, 300)
}
```

对于关键请求，可以使用请求中的标记：

```ts
if (loading.value) {
  return
}
```

## 五、错误监控

前端错误包括：

- JS 运行错误。
- Promise 未捕获错误。
- 接口错误。
- 资源加载失败。
- 白屏。

至少要在关键位置记录错误：

```ts
window.addEventListener('error', event => {
  console.error('运行错误', event.error)
})

window.addEventListener('unhandledrejection', event => {
  console.error('未处理 Promise 错误', event.reason)
})
```

真实生产环境通常会接入监控平台。没有监控的前端上线，就像关着灯走楼梯，运气好不代表方式对。

## 六、测试策略

优先测试这些内容：

- 纯工具函数。
- 复杂组合函数。
- Pinia action。
- 表单校验。
- 权限判断。
- 关键组件交互。

示例测试对象：

```ts
export function canEditPost(userId: number, postAuthorId: number, roles: string[]) {
  return userId === postAuthorId || roles.includes('admin')
}
```

这类逻辑非常适合单元测试，因为输入输出明确。

## 七、构建检查

上线前至少运行：

```bash
npm run type-check
npm run lint
npm run build
```

构建后检查：

- 产物是否生成。
- 页面是否能刷新访问。
- 静态资源路径是否正确。
- 接口地址是否是生产环境。
- source map 是否符合发布策略。

## 八、部署注意事项

SPA 项目如果使用 history 路由，服务器需要回退到 `index.html`。否则刷新深层路由会 404。

Nginx 示例：

```text
location / {
  try_files $uri $uri/ /index.html;
}
```

静态资源建议设置缓存，HTML 则不要缓存太久，否则用户可能拿到旧入口文件。

## 九、uni-app 发布检查

跨端项目还要检查：

- H5、App、小程序平台差异。
- 条件编译是否正确。
- 平台 API 是否可用。
- 图片和文件上传策略。
- 包体积限制。
- 小程序权限配置。

跨端不是“一套代码到处完美运行”，而是“一套代码在差异中尽量复用”。这点若不承认，后面会吃很多苦。

## 十、上线前清单

- 所有关键页面有 loading、empty、error。
- 表单有校验和防重复提交。
- token 过期能处理。
- 列表分页不会重复加载。
- 构建命令通过。
- 生产接口地址正确。
- 路由刷新正常。
- 控制台没有明显错误。

能跑只是开始，能被稳定使用才是交付。
