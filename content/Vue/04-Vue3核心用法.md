Vue 的核心思想是：把页面拆成组件，把会变化的数据变成响应式状态，再让模板根据状态自动渲染。你不需要手动拿 DOM 节点改文本、改 class、改列表；你只需要改数据，Vue 负责把界面同步到正确状态。

现代 Vue 3 工程通常大量采用组合式 API 与 `<script setup lang="ts">`。这是当前 Vue 3 项目里非常主流的写法，尤其适合 TypeScript、Pinia 和组合函数一起使用。

## 一、单文件组件

Vue 单文件组件通常由三部分组成：

```vue
<script setup lang="ts">
const title = '帖子列表'
</script>

<template>
  <view>{{ title }}</view>
</template>

<style scoped>
view {
  color: #222;
}
</style>
```

三部分职责：

| 区域 | 职责 |
| ---- | ---- |
| `script` | 数据、函数、生命周期、导入依赖 |
| `template` | 页面结构和渲染逻辑 |
| `style` | 当前组件样式 |

`lang="ts"` 表示脚本使用 TypeScript。`scoped` 表示样式作用域限制在当前组件。

## 二、script setup

传统 Vue 组件需要写：

```ts
export default {
  setup() {
    const count = ref(0)
    return { count }
  },
}
```

`<script setup>` 简化后：

```vue
<script setup lang="ts">
import { ref } from 'vue'

const count = ref(0)
</script>

<template>
  <view>{{ count }}</view>
</template>
```

在 `<script setup>` 中声明的变量和函数，可以直接在模板中使用。

项目首页 `src/pages/index/index.vue` 就是这种写法：

```ts
const active = ref<PostListSort>('rec')
const hotToday = ref<HotItem[]>([])
const pageReady = ref(false)
```

这些状态直接服务模板中的 tab、热榜、loading 和列表。

## 三、ref

`ref` 用来创建响应式值。

```ts
const count = ref(0)
count.value++
```

在脚本中要通过 `.value` 访问，在模板中会自动解包：

```vue
<text>{{ count }}</text>
```

常见用途：

- 当前 tab。
- loading 状态。
- 输入框内容。
- 接口返回列表。
- 弹窗显示状态。

示例：

```ts
const loading = ref(false)

async function submit() {
  loading.value = true
  try {
    await save()
  } finally {
    loading.value = false
  }
}
```

这里 `finally` 很重要。无论请求成功还是失败，都要关闭 loading。

## 四、reactive

`reactive` 用来创建响应式对象：

```ts
const form = reactive({
  title: '',
  content: '',
})

form.title = '新标题'
```

`ref` 和 `reactive` 的选择：

| 场景 | 推荐 |
| ---- | ---- |
| 基础值 | `ref` |
| 数组 | `ref<T[]>([])` |
| 表单对象 | `reactive` 或 `ref<Form>()` |
| 需要整体替换 | `ref` |
| 只修改字段 | `reactive` |

在 TypeScript 项目里，数组常见写法是：

```ts
const topics = ref<string[]>([])
```

这比 `reactive([])` 更容易表达类型，也更适合整体替换接口结果。

## 五、computed

`computed` 用来声明派生状态。它依赖其他响应式数据，并且会缓存结果。

项目首页中：

```ts
const schoolTitle = computed(() => profile.value?.school?.trim() || '河北科技大学')
```

含义是：当 `profile` 变化时，`schoolTitle` 自动重新计算。

瀑布流分列也使用 computed：

```ts
const waterfallColumns = computed(() => splitPostsIntoColumns(posts.value))
const leftCol = computed(() => waterfallColumns.value[0] || [])
const rightCol = computed(() => waterfallColumns.value[1] || [])
```

不要把派生状态再手动存一份：

```ts
const fullName = ref('')
watch(user, () => {
  fullName.value = user.firstName + user.lastName
})
```

这种情况更适合：

```ts
const fullName = computed(() => user.firstName + user.lastName)
```

能用 computed 表达的派生值，就不要用 watch 手动同步。手动同步写多了，状态就会像没收拾过的房间一样，东西都在，但你找不到。

## 六、watch

`watch` 用于监听状态变化并执行副作用。

项目首页中：

```ts
watch(active, async () => {
  try {
    await loadFeedIfNeeded(true)
  } catch (e) {
    ui.showToast(e instanceof ApiError ? e.message : '加载失败')
  }
})
```

这里 `active` 是当前排序 tab。当用户从推荐切到最新时，需要重新加载信息流。这属于副作用，所以用 `watch` 合理。

适合 `watch` 的场景：

- 监听 tab 切换后重新请求。
- 监听搜索词变化后防抖查询。
- 监听弹窗关闭后清理表单。
- 监听路由参数变化后刷新详情。

不适合 `watch` 的场景：

- 只是根据已有状态算一个展示值。
- 可以直接在事件函数中处理。
- 为了弥补状态设计混乱而到处监听。

## 七、模板插值与属性绑定

插值：

```vue
<text>{{ schoolTitle }}</text>
```

属性绑定：

```vue
<image :src="avatarUrl" />
```

`:src` 是 `v-bind:src` 的简写。

动态 class：

```vue
<view class="chTab" :class="{ active: active === t.k }">
</view>
```

动态 style：

```vue
<view :style="{ color: post.liked ? 'var(--brand)' : 'var(--ink-3)' }">
</view>
```

模板表达式应该保持简洁。如果逻辑变复杂，应提取到 `computed` 或函数里。模板不是写业务算法的地方，虽然它看起来好像可以。

## 八、条件渲染

Vue 常用：

```vue
<view v-if="loading">加载中</view>
<view v-else-if="items.length === 0">暂无数据</view>
<view v-else>内容</view>
```

项目 `WaterfallCard.vue` 中：

```vue
<view v-if="hasImg" class="cover">
  <image v-if="isRenderableImageUrl(first.url)" />
  <FauxImage v-else />
</view>
```

这体现了两层判断：

- 帖子是否有图片。
- 图片 URL 是否可直接渲染。

`v-if` 会真正创建或销毁节点。频繁切换但结构稳定时，也可以考虑 `v-show`，不过 uni-app 跨端场景下要结合具体组件表现判断。

## 九、列表渲染

Vue 使用 `v-for` 渲染列表：

```vue
<view v-for="post in posts" :key="post.id">
  {{ post.title }}
</view>
```

`key` 很重要。它帮助 Vue 识别列表项，减少错误复用。

项目首页中：

```vue
<WaterfallCard v-for="p in leftCol" :key="p.id" :post="p" />
```

不要用数组下标作为长期稳定列表的 key：

```vue
<view v-for="(item, index) in items" :key="index">
</view>
```

如果列表会插入、删除、排序，index key 容易导致组件状态错位。只有纯静态列表才勉强可以。

## 十、事件绑定

事件绑定：

```vue
<view @click="handleClick"></view>
```

`@click` 是 `v-on:click` 的简写。

项目中常见：

```vue
<view class="hotCard" @click="navTo('/pages/hot/index')">
</view>
```

阻止事件冒泡：

```vue
<view @tap.stop="like">
</view>
```

在 `WaterfallCard.vue` 里，整个卡片点击会打开详情，但点赞按钮点击不能触发打开详情，所以点赞处使用 `.stop`。

uni-app 中小程序端更常使用 `tap`，Web 中常见 `click`。项目里两者都有出现，写跨端组件时要注意平台事件支持。

## 十一、props

子组件通过 props 接收外部数据。

```ts
const props = defineProps<{ post: Post }>()
```

模板中可以用：

```vue
<WaterfallCard :post="p" />
```

组件内部不要直接修改 props。props 是父组件传来的数据，子组件擅自修改会让数据流变混乱。

如果需要通知父组件修改，使用 emit。

## 十二、emits

子组件通过 emits 向父组件发送事件。

项目 `ImageGrid.vue` 中：

```ts
const emit = defineEmits<{
  (e: 'add'): void
  (e: 'remove', index: number): void
}>()
```

模板中：

```vue
<view class="close-btn" @click.stop="$emit('remove', i)">
</view>
```

父组件可以监听：

```vue
<ImageGrid
  :images="images"
  @add="chooseImage"
  @remove="removeImage"
/>
```

这种模式是 Vue 的典型单向数据流：

```text
父组件传 props 给子组件
子组件 emit 事件通知父组件
父组件更新状态
状态再作为 props 传给子组件
```

## 十三、生命周期

普通 Vue 组件常用生命周期：

```ts
onMounted(() => {})
onUnmounted(() => {})
```

uni-app 页面还提供页面生命周期：

```ts
import { onShow } from '@dcloudio/uni-app'

onShow(() => {
  void refreshHome()
})
```

项目首页使用 `onShow`，因为页面每次展示时都可能需要刷新数据，而不仅仅是首次挂载时。

应用级生命周期在 `App.vue` 中：

```ts
onLaunch(async () => {
  const auth = useAuthStore()
  await auth.restore()
})
```

这是应用启动时恢复登录态的合理位置。

## 十四、组合函数 composable

组合函数用于复用逻辑，通常以 `use` 开头。

项目中有：

```text
src/composables/useLoginGate.ts
```

它的职责大概率是：在点赞、收藏、发布等需要登录的行为前，判断登录状态，如果未登录则打开登录弹窗。

使用方式类似：

```ts
const requireLogin = useLoginGate()

function like() {
  if (!requireLogin('like')) return
  void feed.toggleFlag(props.post.id, 'liked')
}
```

组合函数适合抽取：

- 登录拦截。
- 防抖搜索。
- 弹窗状态。
- 分页加载。
- 文件选择和上传。
- 业务权限判断。

如果一个逻辑被两个以上页面重复，并且包含响应式状态或生命周期，就可以考虑抽成 composable。

## 十五、组件拆分

项目组件目录：

```text
src/components/
  common/
  compose/
  feed/
  layout/
  modals/
  service/
  settings/
```

这种拆分很有价值：

- `common`：通用基础组件，如头像、图标、空状态。
- `feed`：信息流业务组件，如帖子卡片、评论项。
- `compose`：发布编辑相关组件。
- `layout`：布局组件，如底部 tab。
- `modals`：弹窗组件。
- `service`：服务模块组件。

组件不是越细越好。拆分标准应该是：

- 是否有独立职责。
- 是否能降低当前文件复杂度。
- 是否会复用。
- 是否能形成清晰输入和输出。

把三行模板也拆成组件，通常只是制造跳转成本。过度抽象不是专业，是另一种形式的懒。

## 十六、组件状态设计检查清单

写组件时，可以用下面几个问题检查状态设计是否合理：

- 这个状态是否只属于当前组件？
- 父组件是否需要控制它？
- 其他页面是否也要读写它？
- 它是服务端数据、用户输入、派生值，还是临时 UI 状态？
- 失败时是否需要回滚？
- 页面离开后是否应该保留？

一般来说，输入框内容、临时展开状态、当前组件 loading 可以留在组件内；登录态、用户资料、跨页面列表缓存适合放 Pinia；根据已有状态计算出来的展示值应该优先用 `computed`，不要再存一份。

读一个 Vue 工程时，建议从一个页面开始，例如 `pages/index/index.vue`，再顺着它导入的 store、API、组件和工具函数往下看。这样你看到的不是一堆散文件，而是一条真实业务链路。

## 十七、小结

Vue 3 的核心能力可以归纳为：

- 用单文件组件组织页面。
- 用 `ref` 和 `reactive` 声明响应式状态。
- 用 `computed` 表达派生数据。
- 用 `watch` 处理状态变化后的副作用。
- 用模板语法绑定数据、事件、class 和 style。
- 用 props 和 emits 建立父子组件通信。
- 用生命周期处理页面进入、应用启动和资源清理。
- 用 composable 复用有状态逻辑。
