这套教程面向已经有后端基础、需要补齐前端工程能力的开发者。前端并不是“把按钮摆好看”这么简单，当然，如果有人这么理解，那大概只是还没遇到真实项目里的状态同步、跨端兼容、接口治理、构建配置和用户交互细节而已。

本文以 `D:\shenweikeji\HebustForumFrontEnd` 这个项目作为参照。它不是一个孤立的 Vue Demo，而是一个基于 **Vue 3 + TypeScript + Vite + uni-app + Pinia** 的真实前端工程，包含首页信息流、帖子详情、搜索、收藏、用户登录、消息、服务页面、图片上传、跨端请求封装等内容。

## 一、项目技术栈

先把项目轮廓看清楚：

```text
HebustForumFrontEnd/
  package.json
  vite.config.ts
  tsconfig.json
  src/
    main.ts
    App.vue
    pages.json
    api/
    components/
    composables/
    models/
    pages/
    router/
    stores/
    styles/
    utils/
```

核心技术如下：

| 技术 | 在项目中的作用 |
| ---- | -------------- |
| Vue 3 | 组件化开发、响应式状态、页面渲染 |
| TypeScript | 给接口数据、组件参数、store 状态建立类型约束 |
| Vite | 开发服务器、构建工具、环境变量、别名配置 |
| uni-app | 同一套代码适配 H5、微信小程序等平台 |
| Pinia | 全局状态管理，例如登录态、信息流缓存、UI 状态 |
| npm | 安装依赖、运行脚本、维护 `package-lock.json` |

它的 `package.json` 中可以看到这些脚本：

```json
{
  "scripts": {
    "dev:h5": "uni",
    "dev:mp-weixin": "uni -p mp-weixin",
    "build:h5": "uni build",
    "build:mp-weixin": "uni build -p mp-weixin",
    "type-check": "vue-tsc --noEmit"
  }
}
```

这说明项目不是普通浏览器单页应用，而是 **uni-app 跨端项目**。后端同学看它时，不能只按传统 Web 页面理解，还要注意小程序运行时、`uni.request`、`pages.json`、条件编译、跨端组件标签等差异。

## 二、学习路线

推荐按下面顺序阅读。

### 1. JS 与 TS 基础

前端工程的语言基础不是 HTML，而是 JavaScript 和 TypeScript。

要重点掌握：

- `let`、`const`、作用域、闭包
- 对象、数组、解构、展开语法
- 函数、箭头函数、回调
- `Promise`、`async`、`await`
- 模块化 `import` / `export`
- TypeScript 类型、接口、泛型、联合类型、类型推导

在这个项目中，`src/api/http.ts` 的 `request<T>`、`ApiError`、`RequestOptions`，以及 `src/stores/feed.ts` 中的 state、getter、action，都是 JS/TS 语法落地到工程里的典型例子。

### 2. Node.js 与 npm

前端项目不等于运行在 Node.js 上，但现代前端开发强依赖 Node.js 工具链。Node 提供运行环境，npm 管依赖和脚本。

你需要理解：

- Node.js 是什么，和浏览器 JS 有什么区别
- `package.json`、`node_modules`、`package-lock.json` 的职责
- `dependencies` 和 `devDependencies` 的区别
- `npm install`、`npm run`、`npm ci` 的使用场景
- npm、pnpm、yarn、bun 的差异

后端同学可以把 `package.json` 理解成 Maven 的 `pom.xml` 或 Gradle 的 `build.gradle`，但 npm 的依赖安装模型、锁文件和脚本机制有自己的规则。

### 3. HTML、CSS 与浏览器基础

Vue 组件最终仍然要表达页面结构和样式。即使在 uni-app 中写的是 `<view>`、`<text>`、`<scroll-view>`，本质上仍然绕不开布局、盒模型、滚动、定位、响应式和样式作用域。

要重点掌握：

- 语义结构与 DOM 树
- 盒模型、块级元素、行内元素
- Flex、Grid、定位、滚动容器
- 颜色、字体、间距、圆角、阴影
- scoped CSS、CSS 变量、移动端适配

项目中的 `src/styles/tokens.css` 维护了全局设计变量，页面和组件里大量使用 `var(--brand)`、`var(--ink-3)`、`var(--bg-2)` 这类变量，这是工程化 CSS 的基本做法。

### 4. Vue 3 与组合式 API

这个项目几乎所有 Vue 文件都使用：

```vue
<script setup lang="ts">
</script>
```

这是 Vue 3 组合式 API 的主流写法。

你需要掌握：

- 单文件组件 `.vue`
- `ref`、`reactive`、`computed`、`watch`
- `defineProps`、`defineEmits`
- 组件导入与自动导入
- 生命周期
- 模板语法：插值、条件渲染、列表渲染、事件绑定、属性绑定
- 状态提升、组件拆分、组合函数

例如首页 `src/pages/index/index.vue` 用 `ref` 保存当前 tab，用 `computed` 拆分瀑布流左右列，用 `watch` 监听排序变化，用 Pinia store 管全局信息流。

### 5. uni-app 工程实践

uni-app 把 Vue 的写法扩展到多端应用。

这个项目里要重点看：

- `src/pages.json`：声明页面路由、导航栏样式、全局样式
- `src/App.vue`：应用启动生命周期，恢复登录态，注册 401 处理器
- `src/main.ts`：创建 Vue 应用并安装 Pinia
- `uni.request`：跨端 HTTP 请求
- `uni.getStorageSync`、`uni.setStorageSync`：跨端本地缓存
- `scroll-view`、`image`、`view`、`text`：跨端基础组件

如果你只会普通 Vue Web 项目，看 uni-app 时会有些别扭；但它并不神秘，只是把浏览器 API 换成了跨端 API。

## 三、后端同学应该如何理解前端工程

前端项目的复杂度主要不在语法，而在 **状态、数据、交互和构建** 的边界。

### 1. 接口不是直接调

后端写 Controller，前端并不是在每个页面里随手写 `uni.request`。这个项目把请求封装在 `src/api/http.ts`，业务接口再放到 `src/api/*.api.ts`。

这种分层和后端很像：

```text
页面组件
 -> 业务 API 模块
   -> HTTP 基础封装
     -> 后端接口
```

好处是：

- token 注入只写一处
- 401 处理只写一处
- 后端统一响应格式只解析一次
- 文件 URL 归一化只维护一次
- 页面只关心业务数据，不关心请求细节

### 2. 状态需要统一管理

例如首页、详情页、收藏页都可能改变帖子点赞、收藏、蹲帖状态。如果每个页面各存一份数据，页面间很容易不一致。

项目用 `src/stores/feed.ts` 维护信息流缓存，并提供：

- `reload`
- `loadMore`
- `upsert`
- `patchPost`
- `toggleFlag`

这类似后端把共享业务状态收敛到 service 层，而不是让每个接口自己拼一套逻辑。

### 3. 类型是前后端契约的一部分

项目里的 `src/models/post.ts`、`src/models/user.ts`、`src/models/topic.ts` 用 TypeScript 描述前端使用的数据结构。

类型不是装饰品。它能让你在编译阶段发现：

- 接口字段名写错
- 页面使用了不存在的属性
- 某个字段可能为空
- 某个函数参数传错类型
- API 返回值和页面预期不匹配

后端同学可以把 TS 类型理解成前端自己的 DTO 和 VO。

## 四、教程文章结构

这套教程分为以下几篇：

- `01-JS与TS常用语法.md`：讲 JS/TS 语言基础和工程写法。
- `02-Node与npm包管理.md`：讲 Node.js、npm、锁文件和包管理器。
- `03-HTML与CSS基础.md`：讲页面结构、布局、样式和移动端基础。
- `04-Vue3核心用法.md`：讲 Vue 3 组件、响应式、模板和组合式 API。
- `05-uni-app工程结构.md`：讲 `main.ts`、`App.vue`、`pages.json` 和跨端开发。
- `06-接口请求与Pinia状态管理.md`：讲 HTTP 封装、类型建模、状态管理。
- `07-组件化与工程实践.md`：讲组件拆分、表单、图片、样式、调试和构建。

## 五、学习建议

不要试图一口气背完所有 API。前端框架更新很快，死记 API 的性价比不高。更重要的是形成几个稳定判断：

- 页面结构由组件承担。
- 组件内部状态用 `ref`、`computed`、`watch` 组织。
- 跨页面共享状态交给 Pinia。
- 请求细节收敛到 API 层。
- 类型定义是前后端协作契约。
- 样式变量和组件样式要分层管理。
- 构建配置、环境变量和代理属于工程边界。

如果你能从这些角度读懂 `HebustForumFrontEnd`，就已经不只是“会写一点前端”了，而是开始具备参与真实前端工程的能力。至于这是否会让后端岗位变得更卷，答案显然是会。只是既然现实已经这样，我们至少可以体面地掌握它。
